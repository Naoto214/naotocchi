# 実際の住民数と画面幅で決まる表示倍率

森・昼の固定配置で、主人公1体から主人公・恋人・仲間26体まで、1〜28体のホームを個別に起動した。19〜27体を含め、試遊用データに登録された恋人と仲間のIDは、描画された住民のIDと全件一致した。すべての人数で、役割ごとの元の寸法に共通の追加倍率が一度だけ掛かった。[実ブラウザーの測定値](evidence/native-policy.json)

## 18体から19体への境界

人数係数は18体までは0。「段階的に拡大」では19体から `(人数 − 18) / 10`、「一度に拡大」では19体から1になる。375px以上のBで、次の公称倍率と実際の描画が一致した。百分率は元の正式ホームを100%とする。主人公の既存の110%表示はその基準に含まれ、元の設定値も撮影時に確認した。

| 人数 | 段階的・全員への追加 | 段階的・主人公／恋人 | 段階的・仲間 | 一度に・全員への追加 |
|---:|---:|---:|---:|---:|
| 18 | 0% | 120% | 105% | 0% |
| 19 | 1.5% | 121.8% | 106.575% | 15% |
| 20 | 3% | 123.6% | 108.15% | 15% |
| 27 | 13.5% | 136.2% | 119.175% | 15% |
| 28 | 15% | 138% | 120.75% | 15% |

各候補の上限は現行0%、A 10%、B 15%、C 20%。ゲーム内幅を `w` として `t = clamp((w − 320) / 55, 0, 1)` を計算し、追加割合を **上限 × 人数係数 × t²(3 − 2t)** とする。各住民の表示には小数を含む計算結果を渡す。表では読みやすい桁数に丸めている。[計算コード](policy.js) ／ [境界と役割比のテスト](policy.test.cjs)

## 描画結果の照合

Linux Chromium 156.0.8078.79 のタッチ画面エミュレーションを使い、DPR 2、初期ゲーム内寸375×760 CSS px、動きを減らす設定、停止状態で計測した。19体と28体ではゲームを起動したまま、375 → 320 → 321 → 332 → 348 → 360 → 374 → 375 → 390 → 430 → 320 → 375pxの順に実幅を変更した。V5のカメラは画面幅の変更後にも投影を調整するため、その投影が落ち着いた時点で住民の実際のCSS倍率を両軸から読み、カメラと奥行きの補正を取り除いた。

4候補×2方式を同じ位置で切り替え、全400条件、延べ7,384体を照合した。計算式と実CSSで確認できた倍率の最大絶対差は **0.00000618**（1.0が等倍）。各条件の切替前後で住民の足元座標、モデル寸法、奥行きは一致した。原画の見かけの大きさや重なり、歩行とタップの成否は、それぞれの画面・操作検証で扱う。[全条件と測定誤差](evidence/native-policy.json) ／ [測定スクリプト](verify_policy_runtime.py)

測定JSONのSHA-256は `b2203f57695019328f42cdb27ef2ad58059d0b6c142fc56808970690a5c3bf26`。ゲームに配布した倍率計算コードは `8773699e127261bf83369dfa38a4cc548cedfe72835f48007c5ac44c41ddfb34`、その結果を住民の描画に渡す `cast-population.js` は `4939348c99e24a849945f8b1cb64df2e0e119e0c2e7e2d5ed9881930cac79887`。人数と倍率の計測はすべて固定配置で行った。並行して最適化配置の表と外側の試遊画面を更新し、最終配布物ではV3の3,909ファイルをバイト単位で保持して全3,920ファイルを照合した。[配布物の照合](evidence/guard-package.json)
