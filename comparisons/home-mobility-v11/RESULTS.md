## 通知時の足元

V10の森で、同じ原画・同じ体格・同じ投影のパンダの表示要素を置き換えると、足元が地形座標（113.73、370.14）から（120.00、354.18）へ移った。歩行命令はなく、画面上の変位は22.74 CSS pxだった。V11では同じ28体・同じ位置で、差し替え後も変位は0.00 CSS pxだった。本人限定ページのボタンで、両方とも実際のホームの同期処理を呼び出せる。[記録した地形座標と再生結果](evidence/panda-replay-ui.json)

変更は表示要素が置き換わる時に使う画像範囲の測定に限った。装備のない同じ仲間で、住民ID・原画・体格・座標系・画面・投影・ナビゲーションが一致する場合は、確認済みの直前の範囲を引き継ぐ。条件が違う時は、その場の表示から本来の処理で測り直す。本人が歩いた距離には、同期時に起きた座標変化を含めない。[足元の実装](foot.cjs) ／ [差し替えと範囲変更の検査](evidence/foot-guards.json)

## 320pxの森で退路が消える理由

森の4画面幅で、同じ28体の通常配置とV9の調整配置を比べた。0.5 CSS px格子で測った歩行地形の面積は320pxで38,961.75 CSS px²、375pxで44,248.50、390pxで46,709.50、430pxで54,167.25だった。320pxの調整配置では、開幕時に住民の接触範囲が地形の77.01%を覆い、375pxでは71.23%を覆った。ある住民自身の体格・接触条件も加えて「次に足を置ける場所」を調べると、たとえば320pxのタヌキは36,660 CSS px²のうち276 CSS px²にしか新しい足を置けなかった。[地形・占有率の算出条件](SPACE.md)

320px・乱数214・V9の調整配置では、開幕時のタヌキと箱はいずれも、地形と前景だけなら96方位すべてに8px進めた。ほかの27体を元の足位置に戻すと0方位になった。開幕・約5分・10分の各足位置から、48方位と7種類の距離で最大2体が順に安全に歩く範囲を調べても、2体のどちらにも8pxの進路が開かなかった。これは測った距離・方向・順序での結果である。[住民別の道譲り](evidence/space-sequential.json)

新しい標準席には従来の初期配置を使う。V9の配置案も本人限定で選べる。320pxの通常配置とV9配置で2席を同時に少し移す計37,933,056通りを調べ、接触を悪化させず、元の退路を守りながら新しく8px退出できる住民を増やす案は見つからなかった。歩行地形や当たり判定の変更は含めていない。[配置を保持する理由](SPACE.md)

助け手の経路に1回の曲がりを許し、合計32pxまで96方位を試しても、320pxでタヌキと箱に8pxの退路を開ける方位は各0/96だった。375pxのタヌキでは同じ調査で、直線だけの12/96方位が23/96方位まで増えた。この23経路は元の歩行処理で終点まで進め、実移動1,698回の地形・接触・速度検査をすべて通った。狭い場所で複数の助け手を増やす前に、既存の2体までで効果が再現した幅から曲がって譲る方法を比較できる。[途中で曲がって譲った23経路](evidence/space-curved-control.json)

## 住民が歩いていない時に残る配置変更

5分の地域試験では、10体の森・320pxで、パンダが12.22px動いた。同じ10体からブラウザーで再現すると、旧足は床・枠・原画の遮蔽を通り、他の住民とも接触していなかった。主人公が将来使う長めの通路を予約する既存の配置処理が、パンダを移してその通路を新しく開いた。山のハムスターでも同じ理由で9.98pxの変位を再現した。表示要素差し替えだけの補正、成長や本当の再投影、主人公の退路を確保する席替えは、別の原因として記録した。[山の実ブラウザー記録](evidence/matrix-mountain-reflow.json)

## 閲覧制限と保護対象
