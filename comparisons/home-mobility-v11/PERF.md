# 28体の描画・足元同期・入力の測定

森・28体・昼・秋・晴れのネイティブホームを、専用のLinux WebKit（WPE 26.5）で計測した。通常の比較は390×792 CSS px、DPR 2。V10、足元のみを変更したV11、目的地選択も変更したV11最終候補を用いた。すべて表示開始・終了時の住民28体と同じ初期足位置を確認した。[全指標・出典SHA-256](evidence/performance.json) ／ [フレーム間隔一覧](evidence/performance-frames.csv)

**描画の安定した高速化は確認できなかった。** 通常再生のp95はV10からV11最終へ、通常順は116→121ms、逆順は122→112msだった。両順合計では移動開始194→233回、歩行距離1,617.43→2,046.54地形px、交流7→6件。これは各版で自然に選ばれた行動の結果で、移動量を固定した描画の差は下記の480コマ再生で確認した。

## 同じ住民動作を固定した描画

自然な動作では同時に動く住民が平均0.56体、最大2体。4体以上の区間は0/378だった。

320×792pxでは別の通常再生で330実秒間、ゲーム自身が開始した同期の前後を記録した。住民の要素・足位置・投影を読み取る観測の時間は同期の所要時間から除外した。要素差し替えの起きたフレームの表示間隔には観測時間も含む。

通常再生では3版とも、開始約291秒と293〜294秒に仲間26体の表示要素が一括で差し替わった。V10の最初の差し替えでは、ウサギが14.98、パンダが22.74、しっぽのおおいきつねが2.90地形px、同期の前後で移動した。足元のみを修正した版と最終版では、いずれの差し替えでも足位置が維持された。

意図的に26体を同時に差し替えた時の同期p95はV10から最終版へ、通常順12→14ms、逆順20→22ms。差し替えがない場合のp95は2→2ms・3→4ms。通常再生でこの規模の差し替えを観測したのは各版2回だった。

## タッチを離してからの反応

WebKitの実タッチイベントで同じ9組の画面座標に指を置き、指定した本人の選択、足が最初に1地形px動いた時刻、5秒以内の経路終点到着を調べた。応答時間の集計対象はその操作で実際に動いた住民。

| 順序 | 版 | 本人選択 | 動いた | 到着 | 動き始め p50 / 最大 ms | 到着 p50 / 最大 ms |
| --- | --- | --- | --- | --- | --- | --- |
| 通常順 | V10 | 9/9 | 3 | 3 | 28 / 332 | 127 / 581 |
| 通常順 | V11 足元のみ | 9/9 | 3 | 3 | 33 / 316 | 150 / 523 |
| 通常順 | V11 最終 | 9/9 | 3 | 3 | 28 / 258 | 162 / 525 |
| 逆順 | V11 最終 | 9/9 | 3 | 3 | 53 / 293 | 223 / 529 |
| 逆順 | V11 足元のみ | 9/9 | 3 | 3 | 35 / 323 | 160 / 658 |
| 逆順 | V10 | 9/9 | 3 | 3 | 49 / 319 | 204 / 599 |

通常順・逆順とも9件中9件で本人を選択できた。足が動き終点に着いたのは各版3件で、コウモリ・ぷにゅ・タヌキの到着点は一致した。タヌキは即時の受理値がfalseでも、その後に通常の順次処理で歩き始めている。中央値はこの3件の実測で、住民28体全体の操作遅延を代表する値にはできない。
