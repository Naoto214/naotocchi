## 無操作試験で再現した長い停止

通常のお世話を加えず28体D3で動かした先行試験では、最大rAF間隔 **2133.2ms** の直後も文書はvisibleで、住民停止・発話・選択肢・ライフカードのフラグはいずれもfalse。区間内のLong Taskは開始167504.9ms・長さ2140ms、長いrAF間隔の終点は169632.4msで時間が重なる。V2の2199.9msと同程度の停止が再現した。メインスレッドの長時間占有と整合するが、この先行試験では関数帰属を採取しておらず、V3の自然描画が原因だとは判定できない。

360秒時点まで28体を観測した。その後、古い測定器が欠落した数値に対してtoFixedを呼び、計測を中断した。住民数が減ったかどうかを推定で補っていない。後続の600秒試験では欠測をnullにし、ゲームの保存値とrAF初回待ちも取得する。 [先行360秒の記録](evidence/v3-unattended-360s.json)

## D3・28体の10分連続再生

全31観測、住民数は28〜28体、終了時は28体。終了時刻は実時間600.0秒。通常のお世話操作（食事・掃除・治療など）は12回で、全操作を記録した。Canvasは2〜2枚。JSヒープは19.6〜52.1MiB、終了時35.3MiB。歩行216回、接近75回、発話欄に異なるテキスト84件。一時停止フラグが立っていた観測時間は約185.6秒。

最大rAF間隔 **2849.8 ms**。その直後のvisibilityはvisible、住民一時停止=false、発話表示=False、選択肢表示=False。同じ測定区間の最長Long Taskは210.0ms。時刻や事象の並存だけでは新しい演出を停止の原因に特定できない。

負荷行列を止めた状態で600秒を再測定した。ホスト全体の処理は完全には管理できない。240秒以降の区間での最大rAF間隔は2849.8ms、全期間で2秒以上の間隔があった観測区間は2件。V2の長時間試験の単発最長は2199.9ms。今回は操作、ゲーム状態、共有ホスト負荷が完全には一致しない。

## 長いフレームの切り分け

他のブラウザー試験終了後、28体で現行とD3を各30秒測定。Long Animation Frames APIで100ms以上のフレームを採取した。style/layout開始からフレーム終端までにはレイアウト以外の作業も含む。GPU・ネイティブ処理・未掲載のスクリプトに要した時間をこのAPIだけで特定することはできない。

- currentの最大rAF間隔は566.6ms。最長のAPIフレームは437.1ms、style/layout開始後の末尾は2.9ms。報告された長いスクリプトはframe（home-production-diorama.js?v=ecac051a6f90、278.3ms、強制style/layout 1.7ms）、apply（home-production-touch.js?v=df9353d84de4、116ms、強制style/layout 104.4ms）。

同じフレームにおけるモデル更新合計 275.1 ms、背景描画 0.4 ms、住民描画 2.7 ms。CDPのCPUサンプル（主スレッド、2ms間隔）上位は getBoundingClientRect / native:0 (18 samples)、getBoundingClientRect / native:0 (11 samples)、apply / home-production-touch.js?v=df9353d84de4:351 (10 samples)。

- D3の最大rAF間隔は466.7ms。最長のAPIフレームは191.2ms、style/layout開始後の末尾は0.3ms。報告された長いスクリプトはframe（home-production-diorama.js?v=ecac051a6f90、175.1ms、強制style/layout 1.4ms）。

同じフレームにおけるモデル更新合計 172.2 ms、背景描画 0.4 ms、住民描画 2.4 ms。CDPのCPUサンプル（主スレッド、2ms間隔）上位は (idle) / native:0 (7 samples)、segmentSafe / home-route-navigation.mjs?v=9459d7632eb7:4 (7 samples)、getBoundingClientRect / native:0 (6 samples)。

D3で観測した上位5フレームでは、モデル更新が148.5〜172.2ms、背景描画は0.1〜0.6msだった。ここで測った長い更新では既存の住民モデル処理が時間の大半を占めた。10分試験で生じた2849.8msの間隔はこの30秒プロファイルの収録外であり、同じ原因と断定はできない。追加調査では移動・衝突・会話の仕様を固定したまま、経路の安全確認とカメラ・表示矩形の計算回数に着目したい。

これらの区間タイマーは診断用の新規タブでのみ応答スクリプトに差し込み、配信ファイルは変更していない。CPUサンプリング・計測器には負荷があり、上表の通常計測とは別の試験。 [個別の長フレームとスクリプト帰属](evidence/v3-profile.json)

## 測定範囲

実機iPhone Safari、低電力・ProMotion・熱による変動、タッチから実画面への表示時間、全装備・全表情の可読性は未検証。本人端末でB/D3の4体・28体を同じ条件から再生して、顔と装備の読みやすさ、ドラッグ中の引っ掛かり、10分経過時の応答を比較したい。

READMEに従ってローカル配信し、verify_v3.py の第1引数にURL、第2引数に ui / pixels / fade / touch / load / soak / profile、--out に一時JSONの保存先を指定する。ui と pixels は --engine webkit、soak は --soak 600 --care --images /tmp/v3-shots を利用する。
