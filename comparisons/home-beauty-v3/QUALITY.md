## 実操作・位置・切替

- Linux WebKit 26.5。320・375・390・430 CSS pxで正式ホームのカメラ安定後、住民4体、動きを減らす設定で現行/A/B/Cを順に切替。各エフェクトを個別にON/OFFした後も住民4体のDOM座標・倍率が完全一致。背景矩形と粒子レイヤーの配置誤差は0.1 CSS px未満。破棄用フレームの操作前後で、外側のテスト用保存値を保持した。
- WebKitの比較設定から5地域それぞれで四季・4天候・4時間帯の各選択を実操作し、子フレームの適用値を確認。各地域12選択、合計60選択。0.25倍の適用、28体の読み込みと再生、通常保存キーへの書き込みなしを確認した。
- うみ・きおくのみずうみの水面だけをオフスクリーンCanvasに描画。C案、4時間帯、4時点で色の付いたピクセルが領域外に出た数は0。これは指定マスク内への描画検査。原画上の実際の岸とマスクの関係は目視検査に依存する。
- Chromiumで、うみ・4体・B、夏の夕方の雨から冬の夜の雪に変更。背景のCanvas合成アルファが109回の描画で0.00835から1.0まで単調に上昇し、初回から最終まで3.98秒。切替中に住民の歩行・接近・待機の記録を確認した。
- Chromiumで実ポインターによるドラッグ中に目標マーカーが表示された。1体・Bで12回のpointermoveから次のrAFまで4.1〜21.2ms。これはディスプレイの入力から表示までの遅延ではない。

## 継続動作と制約

軽量化前の試作で、うみ・夕方・雨・B・28体を125秒連続動作。歩行85回、接近30回、着座26回、発話テキスト5種以上を記録。Canvasは各観測で2枚。JSヒープの観測範囲は19.3〜51.9 MiB、終了時22.2 MiB。短時間のGC変動を含み、メモリリークや端末発熱の否定には使えない。この試験後に、住民数に応じた背景更新頻度と足元表現を調整し、上表を再計測した。

最終版でも同じうみ・夏・夕・雨、28体・B案を通常速度で10分間連続再生した。20秒ごとの全30観測で28体を維持。内部更新頻度は 22.4〜30.0 回/秒、rAFは 39.7〜59.5 回/秒。rAF間隔の95%点は 16.8〜33.4 ms、単発最長は 2199.9 ms。Canvasは全観測で 2 枚。DOM要素数は 1451〜1471、JSヒープは 19.4〜48.2 MiB、終了時 24.5 MiB。歩行 231 回、接近 61 回、発話テキストを 5 種類以上確認。ページ例外 0 件、HTTPエラー 0 件。460秒から600秒の観測では住民モデルの時計と歩行数が変化せず、画面更新は継続した。停止を生じさせたゲーム状態や外部負荷を特定する情報は採取していない。10分のうち全時間が自律歩行中だったとはいえない。長い停止を含むため、端末での瞬間的な引っ掛かりは引き続き比較したい。 [10分全観測の生データ](evidence/soak-final.json)

今回のWebKitはLinux版。実機Safariでの音声、縦横回転時のアドレスバー、指での入力から表示までの遅延、実機10分以上の熱・電池・メモリ、全進化・装備組合せの読解性は未確認。
