## 経路探索で省いた処理

- 固定された背景のグリッド辺では、同じ方向の同じ辺のポリゴン交差と3px間隔の地形検査を再利用する。使う辺から順に生成し、位置やサイズの変化で新しいナビゲーションが作られるとグリッドも新しくなる。可変の地形を受け取る既存APIは従来の再検査を行う。
- 1回の同期的な移動要求の間だけ、実際の前景ポリゴン・DOM矩形、各住民の接触楕円、同一座標での判定を再利用する。次の住民、再試行、歩行ステップには現在の位置が反映される。すでに接触している席からの脱出には従来と同じ数値許容差を用いる。
- 接近先の選択や経路候補の訪問順、3pxサンプル、歩行速度、時計、モデルの更新頻度は既存のまま。配置済みの住民が移動する順序・接触回避・会話参加者を、以下の固定入力で照合した。

## 実時間の測定方法

各条件を新しいブラウザーコンテキストで開き、比較用ゲームのreadyと実画像のデコードを待った。起動時に複数の画面フィットが発生するため、解決済みのシーンでネイティブモデルを1回再構築してから計時を開始した。各ペアの最初の足位置・順序・大きさを完全一致で照合する。自然に発生する以降のタスク、モデルステップ、目標選択、背景描画、UI更新はそのまま実行する。実時間の更新回数や進んだモデル時間はフレーム遅延の影響を受ける。再開直後の1回は、直前の停止フレームからの差分（上限1秒）を既存ループが受け取る。このため計時開始から約10秒の窓でも、モデル時間が10秒を少し超えることがある。

フレーム単位の試行はrAF間隔を記録する。内訳を測る別試行では、1コールバックのモデル全体、そこに含まれる経路選択、住民DOM描画、背景描画、そのうち自然表現の描画を計時する。内包関係のある値は加算しない。長い間隔には描画コールバック外のゲーム・ブラウザー・OSの待ちも含まれる。

## 再測定

`measure-performance.py` に同じローカル配布物の `/game/population.html` と `/game/finish.html` を `--before`、`--after` で渡す。`--mode sustained --scene forest,390,28 --seconds 180 --repeat 1` が進むDateでの連続稼働、`--mode sustained --profile-sustained --seconds 68` が同じ時計での処理別計時、`--mode clock` が短時間のフレーム間隔、`--mode phases` が内訳、`--mode phases --tasks` が時刻付きの追加調査、`--mode replay` が定ステップの比較。出力ファイルごとにモードと試行条件を固定する。WebKitの実行ファイルは `WEBKIT_PATH` で指定できる。

```sh
python measure-performance.py --engine webkit --mode clock \
  --before http://127.0.0.1:8315/game/population.html \
  --after http://127.0.0.1:8315/game/finish.html \
  --scene forest,430,28 --scene river_lake,375,28 \
  --repeat 2 --seconds 10 --out /tmp/home-finish-clock.json
```
