## 描画の検査

Chromium 156、390 × 792 CSS px、DPR 2、昼、動きを抑える設定で、表示された背景画像を確認して時計と住民を停止した。13地域で元の足元→新しい足元→元の足元を実際に描いた。364体のID・モデル上の足・画面上の足・奥行き・原画矩形・前景マスク・選択の輪郭と、装備の矩形・マスクは各切り替えで一致した。既存の影の中心と画面上の足の差は最大0.036 CSS pxだった。[全13地域の測定値・各住民の原画上の正規化座標・画像SHA-256](evidence/ground-art.json)

影または草の矩形に描画のにじみ3デバイスピクセルを足した範囲で、もり8,047、みずべ8,384、とかい8,070、おうち8,276ピクセルが変わった。全画面でその範囲外に変化は0。ほかの9地域では範囲内を含めて0だった。元に戻した各画面で住民のいる帯を照合し、画素差は0だった。V4の別起動でも同じ364体が同じ足場にいた。V5の保存値を原画幅・高さの小数5桁に丸めているため、V4の生の足座標との差は画面上で最大0.0046 CSS pxあった。[測定コード](ground_qa.py)

Linux WebKit 26.5では同じ端末寸法の夜、重点4地域112体で確認した。もりは草が28→7、みずべは波紋7、とかいは舗装9、おうちは板床20。足元以外の画素差は全画面で0、元に戻した住民の帯の画素差も0。足と影の中心の最大距離は0.101 CSS pxだった。実機iPhoneでの見え方は本人試遊の確認項目として残る。[夜のWebKit実測](evidence/ground-night-webkit.json)

実装は既存の影と森の草に材質を付ける。縮尺・足・当たり判定・前後の並び順にはV5の値を使う。描画コントローラーが保持する地形の投影から、表示した画像の左上・幅・高さに対する足の座標を計算する。カメラと地形の版が同じ間は舞台の矩形を再使用する。既存の住民の描画が変わったときにだけ、その足元の材質を書き換える。[試遊用コントローラーへの追加](ground-render.cjs)・[原画の境界と投影の検査](ground.test.cjs)
