# 住民のドラッグと足元への到達

もりの28体を390×844 CSS pxの縦画面（ゲーム領域390×792）で開き、各住民の足元から中央へ水平12 CSS pxの位置で指を離した。#570 VERSION 4を実際のタッチ入力で再試験すると、本人選択と命令発行は28/28、本人が歩いて終点に到着したのは7/28だった。指を離した位置から4 CSS px以内に到着したのは1/28。版・地域・画面幅別の最終成績と到着時の実座標は操作実測にまとめた。[操作実測](INPUT.md) ／ [V4の28例](https://naotocchi-cast-size.kerzion214.chatgpt.site/evidence/v5/touch/v4-off-forest-chromium-390-forest-28.json.gz)

本人限定の最終版では、接地表現を切り替えた両条件とも本人へ28/28の指示が届いた。歩いて補正終点に着いたのは13/28、指の希望位置から4px以内に着いたのは2/28。V4で歩けた7体は全員が歩き、混雑下で6体が新たに歩けた。本人の実到着と補正終点の差は13件とも0.001px未満。指からの誤差は、到着した人の中央値で6.52→7.04px、最大18.18→11.24pxだった。新たに到着した6体には、希望位置まで約11pxを残す小さな歩行も含む。15件は住民の重なりで進めず、その場で指の方向を見た。[最終版・接地あり](https://naotocchi-cast-size.kerzion214.chatgpt.site/evidence/v5/touch/v5-on-forest-chromium-390-forest-28.json.gz) ／ [最終版・接地なし](https://naotocchi-cast-size.kerzion214.chatgpt.site/evidence/v5/touch/v5-off-forest-chromium-390-forest-28.json.gz)

## 21件を拒んだ理由

| V4で指示を拒んだ21件を調査 | 件数 |
|---|---:|
| 終点がほかの住民の接触楕円に入る | 21 |
| 動き始める前から、対象がほかの住民と重なる | 19 |
| 終点が地形上も歩行不可 | 1 |
| 個別住民の歩行枠の外 | 0 |
| 本人への指示発行に失敗 | 0 |

理由は重複する。地形上も外れた1件は仲間のキツネ。V4の経路決定は混雑時の足運びに重なりを減らす方向を許す一方、補正先の候補には完全に空いた地面を要求していた。ペンギンのように行き先の手前まで歩ける場合や、コウモリのようにすでにある重なりをほどきながら数px進める場合も、8pxの格子と補助格子の完全に空いた点を選べず拒んでいた。全28件で、実際に命令へ渡した座標と画面上の希望位置を逆投影した座標との差は0.001 CSS px未満だった。12px条件の主因は混雑時の経路選択だった。[V4の選択・座標・接触記録](https://naotocchi-cast-size.kerzion214.chatgpt.site/evidence/v5/touch/v4-off-forest-chromium-390-forest-28.json.gz)

## 操作と経路

以下は本人限定試遊版の実装。ビルド時に固定したホームの原本へ差分を適用し、試遊専用のモデルと画面制御を作る。通常公開のホームは元のファイルを使う。[試遊版のネイティブ差分](native)

- 押した住民は以前と同じ判定で選ぶ。指先が開始点から8 CSS px以上動くとドラッグになる。縦横の表示倍率が違う場合、最後の移動イベントが省略されて指を離した場合も、画面上の同じ距離を使う。足元の目標には、指を離した座標を既存の変換で戻して使う。
- 目標までの直線が安全なら、格子間の端数を含むその位置へ歩く。直線が通れない場合は移動V5の経路で元の目標へ回り込めるか調べる。壁やほかの住民を横切る経路は使わない。曲がり角では現在の中継点に足が届いてから次の区間を始める。
- 目標がふさがれている場合、指を離した点に近づける連続した線分を7.5度刻みで調べ、歩ける区間の端を二分探索する。候補を既存の移動V5の経路・前進量と比較して選ぶ。地形、住民ごとの画面内の枠、表示可否、住民間の接触判定はそのまま使う。初期配置ですでに重なる相手に対しては、通過区間のどこでもそれ以上近づかず、歩行中は各歩で実際に間隔が広がる必要がある。
- 2 CSS px未満の移動や、指を離した位置までの距離が縮まらない移動は採らない。補正後も指から24 CSS pxを超えて離れる場合、元の距離の4分の1と12 CSS pxの小さい方以上に距離を縮められたときに限り、途中まで歩く。「補正先に着いた」「指から4px以内に着いた」「遠くから途中まで進んだ」をそれぞれ判定する。
- 進めないときは、対象が指の方向を向いて既存の「見る」姿勢を取る。ほかの住民が動いて通路が開いたときは、元の目標について既存の上限（最大4回、12モデル秒）内で再試行する。動かない住民に囲まれたままなら同じ経路探索を繰り返さない。選び直し、操作中断、期限切れで予約を解除する。
- 通常の移動APIは従来の指定を受け付ける。ホームの指を離した処理が、表示上の足元を指定したことを明示して新しい補正を使う。受理時の座標書き換えはなく、実際の移動は従来の歩行ステップで進む。

## 検証

`node --test comparisons/home-finish-v5/drag.test.mjs` は、タップとの境界、格子間の離し位置、短い迂回、長い迂回、混雑した足元での前進、四隅の表示範囲、進めないときの向き、通路が開いた後の再試行、選び直し・中断・期限切れを検査する。最終配布モデルでドラッグの25件すべてが通った。歩行中に隣人が動いて線分の途中をふさぐ場合、住民の大きさ・地形が変わる場合、元の指示に戻って再試行できる場合を含む。移動V5の既存のルーティング試験14件も、通常の呼び出しで別に実行した。[足元指定の回帰試験](drag.test.mjs)

ブラウザー上の実操作は `verify_touch.py` が記録する。本人への発行、経路の受理、歩行の開始、実際の到着、指と補正終点それぞれからの誤差、接触、足元の瞬間移動を別々に集計する。固定配置の比較では同じ状態を復元して各住民へ独立して指示する。生活中の住民が移動する条件は別の行で確認する。[実測スクリプト](verify_touch.py) ／ [実操作の結果](INPUT.md)
