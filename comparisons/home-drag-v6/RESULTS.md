## 歩けなかった理由

複数の理由が同じ指示に重なる。特に「経路を受理できない」と「指が本人に届いていない」を分けて記録した。

| 条件 | ゲームと画面で確認したこと | V6の扱い |
|---|---|---|
| 指定先が占有されている | 森28体のV5で止まった15件は、すべて別の住民の接触楕円を指していた | 近い代替点と、1体が安全に道を譲った後の経路を調べる |
| 開始時から体が重なる | 同じ15件すべてで出発時点にも重なりがあった | すでにある重なりを増やさず離れる区間だけ歩く。1体で道を空けられない場合は待つ |
| 指定先が歩ける場所の外・遮蔽の奥にある | 森の多尾のキツネでは接触と地形の両方が該当。タヌキとユニコーンの見かけ上の道譲り候補も地形を横断した | 歩行域と前景の判定を保ち、歩ける側で指示に近づく |
| 迂回が必要 | 直線が障害物に当たっても、同じ足位置から道の曲がり角を通れる場合がある | 既存の経路と、角を回れる近隣の候補を検査する |
| 近くに別の安全な地点がある | 占有された指の足元に一番近い格子点だけでは、安全な端数位置や短い回り道を見落とす | 指までの残距離、方向、歩く道の長さ、住民までの余裕で比較する |
| 探索が重い・同じ失敗を繰り返す | 分断された道に向けた10pxの指示で、V5は同じ条件で複数回グラフを調べていた | その1回の指示内で同一条件の結果を再利用する。異なる終点条件と、住民が動いた後は判定し直す |
| 指が届かない・タップとの競合 | 住民の絵が重なると手前の住民が選ばれることがある。画像からステージへ指の追跡を渡す瞬間も確認した | 8 CSS pxのしきい値と通常の選択順を維持し、正当な追跡の移管時は同じドラッグを継続する |
| リアクション・一時停止 | 通常通知やバウンドは住民の自律歩行を一時停止させる。メニュー・誕生・病気・画面非表示等は操作の禁止が必要 | 通常ホームの短い通知・バウンド中の本人へのドラッグだけ最長2.6秒保持する。解除後に元の住民へ一度だけ渡し、別の操作、期限切れ、画面変更では取り消す |

通知中・バウンド中・押してから通知が始まった3ケースでは、指を離した時点で本当に制限が有効だったことを確認した。V6は3件とも解除後に本人へ1回だけ指示し、指の位置に正確に着いた。タップ、背景を押す操作、期限切れ、メニュー、一時停止、キャンセル、新しい指による上書き、最初からの操作禁止を含む8ケースの発行は0件だった。[本編のタッチ記録](INPUT.md)
