# 通知中のドラッグと、進めないときの反応

短い通知が出ている間も、住民の体に指を置いて行き先までドラッグできる。画面上で8 CSS px以上動かした指を離すと、従来の点線の輪で行き先を示す。操作を受け付けるまでの上限は2.6秒。下段の通知1回の標準表示時間は2.5秒である。通知が終わると、最初に押した住民へ元の足元座標を一度だけ渡し、その時点の地形と他の住民で経路を調べる。

対象は通常のホームに出る下段の通知と、住民またはグループの `bounce` 演出。指が本当に住民に当たったドラッグだけを保持する。短いタップ、空き地を押す操作、キーボード操作には従来の判定を使う。通知が出ている間、自律行動には従来の停止条件がかかる。タッチパネルでは、最初に指が当たった画像からステージへポインターの取得先が切り替わる。そのとき画像から届く通知を区別し、途中の指の動きが続くようにした。

孵化祝い、ゲーム・めぐる、メニュー、選択を伴う会話、個性のダイアログ、変身の選択、病気・睡眠・臨終、ムービー、非表示、一時停止中は指示を保持しない。これらが通知やバウンドと同時に起きた場合も同じ扱いになる。保持中に新しいタッチやキー入力が入ったとき、別画面へ移ったとき、ゲームが非表示になったとき、住民の表示先やカメラの座標が変わったとき、期限を過ぎたときは元の指示を取り消す。

## 歩けなかった指示

経路が決まらなかった場合、住民は従来の `look` の姿勢で指の方向を向く。ほかの演出が住民を使っていなければ、既存の小さな `curious` のしぐさも使う。すでに同じ方向を向いている場合にも、指示したことが見えるよう、歩行枠内に収めた指の位置に同じ点線の輪を480ミリ秒残す。輪だけを表示している間、住民の足、歩行中のフラグ、経路の終点は変更しない。道譲りや再探索で本当に歩き始めたら、従来の実経路の目印に切り替える。新しい指示や中断で輪を消す。点滅や新しいアニメーションは加えていない。

## 実際の画面で確認した反応

確定モデル `115c2a98a532` と入力制御 `b724d782d97c` を使用した。Chromium 156で、森の28体を390×792 CSS pxに表示した。V5・V6とも右向きのタヌキに触れ、足元から右12 CSS pxの位置で指を離した。どちらも本人が `look` のまま、歩行中フラグは偽、経路は空、足位置と向きは全フレームで同じだった。新しい自律行動の選択を止め、実際のモデルの時間と歩行処理を進めた。この間にモデル上でV5は3.48秒、V6は6.53秒経過した。V5は指を離した後の9回の描画観測で輪の表示が0回。V6は5回のうち3回で同じ位置に輪を表示し、最後に見えたのは指を離した後301.1ミリ秒、次に観測した836.4ミリ秒の時点で消えていた。測定開始は指を離したイベントがゲームの処理を通ってからで、実装の480ミリ秒は移動を受理できなかった時点から数える。[両版の入力・足・輪・歩行状態の記録](evidence/reaction-browser.json)

同じ実ゲームで、グループのバウンド中にタヌキをマウスで押してステージ外で離すと押下状態が消えた。別の試行では、実タッチで指示の輪が表示されたあと、画面を375×760 CSS pxに変更した。カメラが新しい寸法に合うと保持中の指示は消えた。どちらもその後にモデルへ移動指示を渡した件数は0件。[ステージ外での解放とカメラ変更の記録](evidence/reaction-browser.json)

## 再現

次のテストはビルド済み試遊から実際のゲーム制御を読み込む。通常の入力制限とドラッグの入力制限、通知中に始めた指示、保持中の取り消し、8pxの判定、480ミリ秒の輪と実際の経路への切り替えを検査する。

DRAG6_DIST=/path/to/built/trial node --test reaction.test.cjs
