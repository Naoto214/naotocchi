# V5・V6のドラッグ試遊

本人限定の `/v6/` を開くと、V6のホームが再生される。上部の「V5」「V6」で動作を切り替え、「最初から」で同じ版をやり直せる。「停止」「再生」はその場で切り替わる。設定では13地域、朝・昼・夕・夜、1〜28体を選べる。画面内にあるゲームは常に1つで、住民の選択・ドラッグはゲーム本体が処理する。

## 比較する開始条件

どちらの版も、同じV5の世帯、装備、サイズB、接地表現、E3+、落ち葉Bを使用する。地域・住民数・時間帯を引き継ぎ、秋・晴れで開始する。ゲーム側の保存先は試遊フレームのメモリ内にある。

各版を開くと、まず背景の時計を0秒にして住民の移動を止めたまま、ネイティブの背景描画とカメラ合わせを待つ。カメラ合わせの途中で得た足位置をそのまま残すと、同じ版でも読み込み順によって立ち位置が変わることがあった。そこで、試遊画面から開いた時だけ、確定した地形と本来の住民情報を使って、ネイティブの初期配置を一度だけ計算し直す。主人公・恋人・仲間すべてに、本来の地形の配置規則を使う。住民の動作に使う乱数はV5と同じ214から始まる。配置と描画を終えてからカバーを外し、選択している再生・停止を適用する。

版を切り替えた時は、その条件の開始位置から試せる。切替後は各版が実際のフレーム間隔・操作を受けて進む。URLに `arm=v5|v6`、`region`、`count`、`time`、`paused=0|1` を保存する。

## 確認方法

本ディレクトリで実行する。ブラウザーでの検証はビルド済みの試遊のローカル配信と、PythonのPlaywrightを使用する。

```sh
node --test shell.test.mjs
python -B verify_shell.py http://127.0.0.1:8366 --engine chromium --region river_lake --count 28
python -B verify_shell.py http://127.0.0.1:8366 --engine webkit --region forest --count 19
```

ブラウザーは `--executable`、端末幅と高さは `--width`、`--height` で指定できる。両版で実際に描かれた背景キャンバスのSHA-256、全住民のID・画像・足座標・モデル寸法、時計を照合する。その後V6の再開で自律歩行、V5への切替で初期位置からの再生、時間帯・人数の変更、セーブの分離を確かめる。


Linux WebKit 26.5のもり・19体では、V5の暫定配置をそのまま引き継いだ起動で、同じ背景・カメラでも恋人の足のY座標が128.689と99.173に分かれた。初期配置を確定後の地形で行うようにして、同じ条件で停止したV5→V6→V6再試行、さらに再生中にV5へ戻る操作を行った。全19体のID・画像・足座標・寸法、背景の全画素が一致した。Chromium 156ではみずべ・28体で同じ操作を確認した。いずれも住民が自律歩行を始め、設定した時刻・人数の変更と、外側のストレージとの分離を確認した。[WebKitの記録](evidence/shell-webkit.json) ／ [Chromiumの記録](evidence/shell-chromium.json)
