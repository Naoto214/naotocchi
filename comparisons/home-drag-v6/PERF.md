## 計測条件

比較には実ゲームの `/game/drag-v5.html` と `/game/drag-v6.html` を使用した。両版ともサイズB・線形漸増・配置調整、昼、秋、晴れ、seed 214。Linux WPE WebKit 26.5で画像のデコードが完了した後、実際の住民名簿と地形・画面寸法でモデルを再構築し、計測区間の初期座標・大きさを照合する。すべての住民が通常の描画対象になる。iPhone実機の測定は行っていない。

3分間の試験では、同じ時刻から進む `Date` とネイティブのrAF、タイマーを使う。表示を止める条件はゲーム自身に判定させ、毎フレームの経過と、各分のモデル時間・移動開始数・累積移動距離を記録する。ここでのHzはrAFのコールバック回数を実経過秒で割った値。各分の区切りはその時刻を越えた最初のrAFとした。旧V5の森390px・28体での最長間隔645msは、以前に実施した同じ長さの独立試験値として掲載する。[前回の計測条件と全フレーム](../home-finish-v5/PERF.md)

固定入力の再生には森430px・28体、水辺375px・28体、家390pxの1体・4体・28体を使う。各条件で0.1秒×300ステップ。選択・タップ移動2回、長押し中の時間帯、ブロックと動きを減らす設定を含む。各ステップですべての住民の状態・経路・座標、選択中の住民、モデル統計、乱数呼び出し数、接触中の組数と、発生したイベントの内容・順序を照合する。固定入力には実ドラッグを含めず、`pointerDrop` が有効になっていないことを両版で検査する。移動先の歩行時間、自然な再選択・会話相手、保存領域の試験中の変化も同時に検査する。

## 再現方法

比較用ゲームをローカルで配布し、`WEBKIT_PATH` をWPE WebKitのPlaywright起動スクリプトに向ける。`--base` で配布元を指定できる。出力先には新しいファイル名を指定する。既存ファイルを渡すと完了済みの条件を読み戻す。

```sh
python comparisons/home-drag-v6/measure-performance.py sustained --out /tmp/home-drag-sustained.json
python comparisons/home-drag-v6/measure-performance.py sustained --reverse --out /tmp/home-drag-sustained-reverse.json
python comparisons/home-drag-v6/measure-performance.py trace --out /tmp/home-drag-opening.json
python comparisons/home-drag-v6/measure-performance.py replay --out /tmp/home-drag-replay.json
```
