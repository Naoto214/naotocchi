# 混雑した足元のドラッグ

## もり28体で止まった15件

390×844 CSS pxの縦画面で、V5では28体全員にタッチと指示が届いた。本人の足元から中央へ水平12pxの位置に指を離すと、13体が到着し、15体はその場で向くだけだった。15体は全員、開始時からほかの住民の接触楕円と重なり、希望位置にもほかの住民がいた。多尾のキツネでは希望位置が歩ける地形からも外れていた。元の配置と指示を使ったV6の実操作は、住民本人の歩行、指定位置までの誤差、待機・表情を個別に記録している。[V5実測](../home-finish-v5/INPUT.md) ／ [V6実測](INPUT.md)

| V5で止まった住民 | 足位置を動かす前に分かったこと |
|---|---|
| カワウソ、パンダ、アザラシ | それぞれカタツムリ、ぷにゅ、主人公が自分の足で近くへ少し歩くと、本人にも安全に進める区間ができる。カワウソは12pxの希望位置まで歩ける。 |
| タヌキ、ユニコーン | 住民同士の間隔と画面内の枠だけを調べると、ニワトリまたはハリネズミが約24px歩く案がある。実地形でその区間を調べると歩行不可の部分を横切ったため採用しない。 |
| 多尾のキツネ | 接触の条件だけなら前へ進めても、希望位置への直線は地形に遮られる。 |
| 残り9体 | 確認した近隣の1体だけが24px以内を歩く範囲では、十分に希望位置へ近づく安全な組を見つけられなかった。複数の住民を押し動かす連鎖は行わない。 |

実タッチ28件で、本人が歩いて選択された終点に着いたのはV5の13件からV6の16件に増えた。指を離した時点で歩き始めたのは両版とも13件。追加の3体は近くの1体が譲った後に歩き、カワウソは指から0.00px、パンダは7.51px、アザラシは8.49pxで停止した。指から4px以内に足が止まったのは2件から7件。到着イベントだけを測ると2件から5件で、2件の二段階歩行は通知の抑制時間中に終わった。V6でも12体はその場で応答し、28件を通してリリース時の座標飛びや不正な歩行区間は0件だった。

## 目的地を決める順序

1. 指を離した画面座標を既存の変換で足元に戻す。画面の縦と横の実倍率で距離を測り、格子間の端数も含む希望位置への安全な直線、続いて移動V5の安全な迂回を優先する。
2. 行けない場合は、既存の候補に加え、指の位置を中心に半径2・4・7・11・16・24 CSS pxの範囲を調べる。希望位置までの距離より外側は探索しない。手前の角を少し回れば着く位置は、中継点を1つ通る短い経路でも調べる。この追加探索の歩行距離は「元の指示距離＋最大24px」まで。画面端、個々の住民の表示枠、前景、地形と住民の接触を、終点と各区間で検査する。
3. 候補間の距離差が画面の0.75pxを超える場合は指に近い候補を優先し、ほぼ同じなら指の方向への前進量、歩く総距離、終点での他住民との間隔を比べる。水平・垂直の指示に逆変換の端数（1 CSS px未満）が付いても、別方向の前進条件を作らない。V5が認めていた方向の進みは、指から先に行き過ぎた分を除いて保つ。
4. 新しい補正で4pxより離れる場合には、2px以上の方向成分、3px以上の本人移動、指までの距離の減少などを確認する。以前から認めていたごく小さい安全な歩行は、新しい成功例に数えない。希望位置から24pxを超えて離れた途中停止は、元の距離を4分の1以上縮め、本人変位の75%以上が指の方向を向く場合に限る。実測では希望位置への到着と途中までの前進を分けて示す。

## 1体が道を譲れる条件

空いている住民を動かす前に、本人・候補の隣人双方の区間を現在の全員の足位置で調べる。正面にいる1体だけが通路をふさいでいて、その住民が3〜24 CSS pxの短い歩行をすれば本人が実際に希望位置へ近づける場合に限り、隣人が通常の歩行を始める。最初から重なっている楕円の中では間隔を狭めず、新しい楕円に入る区間は選ばない。歩行中も毎ステップ、その時点の住民・地形で再検査する。

一つの指示で頼める相手は1体までで、同時に道を譲る住民も1体まで。すでに歩行中、選択中、手動指示中の住民には頼まない。直前に譲った住民は3モデル秒休む。本人は相手の歩行を待ち、道が開いた時点で予定していた区間を改めて検査してから歩く。道が開かなければ既存の姿勢・表情で応じる。本人の退出、選び直し、キャンセル、一時停止で不要になった協力を終える。隣人を手で選び直した場合は、新しい手動指示を優先して、元の本人も空いた区間を改めて確認する。

足位置を一括更新したり、歩行可能領域や接触楕円を広げたりする処理はない。道譲り自体は会話の発生源にしない。通常の自動移動とキーボード等の既存APIは従来の経路選択を使う。

### 隣人だけが余分に歩いた例

もり・28体・幅390px・昼の同じ初期配置で、恋人のクマを体からつかみ、開始時の足元から左12 CSS pxで離した（`historical/1`）。V5は指から6.991px、V6の本人は4.695pxで止まった。続いて主人公が3.00 CSS pxだけ道を譲ったが、本人は追加で歩かなかった。実際に記録した座標でこの2区間を再生すると、譲った後には指から2.36pxまで近づける案ができる。水平のリリースを元の座標に戻す際に縦へ0.000004pxの端数が付き、横道へ0.24 CSS px入るこの案が、再試行時の縦方向の進みを保つ条件で除外された。次に見直す箇所は、初回に使う1 CSS px未満の端数処理を再試行・道譲りの判断にも適用すること。今回の4px以内の実績には含めていない。[実操作の再現用コード](input_probe.js)

## 長い指示での途中停止

最終モデルにV5と同じ初期配置・実際のリリース座標を与え、0.05秒ごとに通常の歩行を進めた例。前進と横移動は始点から終点の変位を、指示の方向とその直角方向に分けた。歩行距離は各ステップの長さの合計。すべて表示上のCSS px。

| 地域・指示 | 指示距離 | 前進 / 横移動 | 歩行距離 | 指から最終の足まで | 結果 |
|---|---:|---:|---:|---:|---|
| やま・恋人の斜め移動 | 68.0 | 0 / 0 | 0 | 68.0 | 条件を満たす前進がなく、その場で応答 |
| やま・別の住民がいる位置 | 40.7 | 15.9 / 0.2 | 15.86 | 24.85 | 途中まで前進 |
| ほしぞらのていりゅうじょ・恋人の斜め移動 | 68.0 | 20.0 / 16.7 | 26.05 | 50.88 | 指までの距離を25.2%縮めて途中停止 |
| ほしぞらのていりゅうじょ・別の住民がいる位置 | 40.2 | 22.3 / 0.0 | 22.26 | 17.94 | 空いている近傍に補正 |

ほしぞらのていりゅうじょの斜め移動は指から約51px離れたままなので、4px以内・24px以内の到達には含めない。とくに密集した地形では、長い指示がそのまま通らない例が残る。全地域での実タッチと、希望位置・端末幅・人数ごとの違いは操作実測に掲載した。[実操作の測定条件と内訳](INPUT.md)

## 再検査と負荷

同じポインター命令内の同一ナビゲーション・同一探索方式・同一終点・同一歩行枠・同一通過条件の経路は、失敗結果も含めて1回で済ませる。別の命令や再試行に結果を持ち越さない。分断した幅の狭い道で、足位置40から50への同じ指示について、通常経路の呼出しは7→1回、参照経路は4→1回。許す終点が異なる2種類の到達範囲探索はそれぞれ実行する。直接通れる場合はグラフ探索0回。譲った住民の先へ進むための区間も、再び安全なら大きなグラフを最初から探索しない。[経路と道譲りの回帰試験](model.test.mjs) ／ [実行性能](PERF.md)

実際の歩行で最終位置に着いた時点と、ゲームから通知された到着は別に数える。短い二段階の歩行では、2度目の到着が既存の650msの通知抑制時間に入る場合がある。終点で本人が停止していること、そこまで実際に足を運んだこと、指からの距離を確認し、途中で指の近くを通っただけの例と区別する。
