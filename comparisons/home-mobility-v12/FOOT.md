# 足元の保持・成長・再配置

森の成長は、320pxでパンダが1.00 CSS px歩くと、28体の最大画面変位が325.79pxから1.53pxに減った。390pxでは、全員が元の地面上の足位置を保ち、カメラ再投影分の最大0.58pxだけが残った。375pxと430pxでは元の退路をすべて残せる小さい変更が見つからず、従来の配置になった。本人限定試遊の「成長する住民の足位置を比べる」で各方式を操作できる。

## 森28体の実成長

表はLinux Chromium 156、DPR 2、高さ792 CSS pxでの実測。実ゲームの犬を25歳から45歳、成長段階5から6に進めた。同じ幅の全方式で28体の成長前の画面座標が一致している。表は成長前後の足の画面上の最大変位で、カメラの再投影も含む。全体の退路は、各住民について3・8・16 CSS px、各48方位、合計4,032本の候補を元の足から追跡した。元から通れた方位を1本でも失う保持案・局所補正案は採用しない。

| 森・28体 | 従来 | 元の足を保持 | 成長した本人が歩く | 周囲が譲る | 最小補正 | 安全な順に自動選択 | 自動選択後に失った以前の退路 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 320px | 325.79 | 325.79 | 325.79 | **1.53** | **1.53** | **1.53** | 0 / 248 |
| 375px | 207.49 | 207.49 | 207.49 | 207.49 | 207.49 | 207.49 | 103 / 542 |
| 390px | 231.11 | **0.58** | **0.58** | **0.58** | **0.58** | **0.58** | 0 / 398 |
| 430px | 325.21 | 325.21 | 325.21 | 325.21 | 325.21 | 325.21 | 70 / 432 |

- **320px**。元足のままでは再投影後にパンダの8pxの退路を1方位失う。自動選択はパンダを1.00px、既存の歩行更新2回で終点まで歩かせた。主人公の退路は36→40、恋人23→34、パンダ8→9。全28体の元の方位を維持した。個別の「最小補正」でもパンダだけを0.25px補正して同じ保持条件を満たす。「本人が歩く」では、犬の移動でこの経路を開けず、従来配置に戻る。
- **375px**。恋人の187.5°・3px先が再投影後に歩行地形から外れる。足を保つ案で失う方位は1本。ほかの住民が移動するだけではこの地形条件は変わらない。恋人が動くときの協力も調べた。0.25〜8px・16方位の候補で恋人の52終点に対し、条件を満たし得る助っ人の第一歩768本を既存判定に通したが、実行できる組み合わせは0。元足と従来の終点から選ぶ1〜2体の部分再配置も28通りで旧方位を最低1本失った。ほかの距離・方向・曲がり方まで不可能とは断定できない。
- **390px**。成長に伴う2回の再計算で全員の元の方位を保った。歩行・道譲り・補正を選んでも、保持で足りるため余分な動きは発生しない。
- **430px**。元足のままでは7方位を失う。羊と九尾狐の接触が3方位、コウモリと猫、柴犬とフクロウ、カメレオンとアザラシの接触が各1方位。ユニコーンは16px先が地形の外にある。4組の住民は互いに別で、地形から外れるユニコーン自身も動く必要がある。旧方位をすべて戻すには少なくとも5体の終点を変える必要があり、この場面の1〜2体の部分再配置では足りない。

375・430pxの表の103・70は、保持を断念して従来の配置を実行した**後**に失った方位数。保持案だけを評価した1・7と区別した。離散的な144本は短い直線の調査で、任意の長さや曲折経路の数学的な保証は含まない。役割ごとの全ビットと各住民の画面変位を保存した。[28体×4幅×6方式の個別結果](evidence/foot-growth.json)

## 通常の生育イベントでの照合

「通常の成長・時間制限付き保持」は、V12のゲーム自身の年齢更新と `onAgeChanged` を使用する。成長直前の退路を小分けに事前測定し、年齢・画像が変わるタイミングに現在の足位置、原画、装備、体格、投影、進行中の指示を再確認する。再利用には、ナビゲーションが同じ、表示境界と遮蔽ポリゴンが同じ、16px以内の経路に届く全住民の接触範囲・位置が同じ、という条件がある。一致を証明できない住民の方向は測り直す。専用の試遊入口に限った処理で、通常のV12比較ホームの自律移動に常時計算を追加していない。

統合版の森390pxを負荷の高い共有CPUのChromiumで測ると、事前測定ありでも、1段目が30msで通った後に2段目まで4秒の有効期間がもたず、最大231.11pxに戻る回があった。別の回は1段目で48msの照合枠に達した。12方位ごとに時間を確認する協調的な中断なので、最終表示版の別試行ではブラウザーが制御を返すまで118.3msかかった。事前測定なし、または幅変更で事前測定を失効させた対照も保持を適用しなかった。本人限定の比較画面では実際の最大変位と2段の採否を表示する。全4幅の別の照合では、キャッシュを使った13件・以前の137方位を改めて実地形と接触で計算し、判定差は0だった。この照合だけは期限を外しており、運用上の時間内採用率には含めていない。独立したLinux WebKit 26.5の計測（44993726285・028f）では、390pxの事前測定あり2回とも0.58px、事前測定なし2回とも231.11px。2段階の照合は各回5・7msで、成長呼び出し全体は準備あり116・118ms、なし180・178msだった。同じWebKitで375pxの通常配置の変位は360.03pxとなり、表のChromium値と差がある。試遊表示の「保持」は2回の照合がそろった場合に限定し、実際の最大変位を併記する。実機iPhoneのSafariでの時間内採用率・発熱は未検証。[ブラウザー実測、期限・再読込・対照](evidence/foot-events.json)

## 同じ投影での再配置と実歩行

| 320px・住民10体の元の記録 | パンダの従来変位 | V12変位 | 犬のV12実歩行 |
|---|---:|---:|---:|
| やま・180秒 | 55.66px | **0.00px** | 72.56pxで退路終点に到着 |
| もり・300秒 | 12.22px | 12.22px | 67.42pxで退路終点に到着 |

両方とも記録の住民・足・体格を復元し、本物のモデル同期を呼んだ。山では主人公の通路がすでに空いていた。森では元足のまま主人公の長い通路を確認できず、既存の配置を使った。Chromiumで山の実歩行中に足位置と描画した影の36姿勢を確認した。Linux WebKit 26.5でも、山で保持・森で従来配置となり、4つの操作すべてで犬が退路の終点まで歩いた。原画、装備、実測した表示範囲、投影を1種類ずつ変更した4対照と、歩行先が無効な対照では保持が働かず、安全なキーボード指示では同期後も同じ目標と操作種別が引き継がれた。

最初の13地域試験では、きおくのみずうみ320px・10体の180秒でもウサギが49.19px動いた。そのCIと同じ初期の全10体・乱数・候補バイトを復元した2回の試行では、自動的に同時刻のナビ交換が起こるところまでは再現できなかった。1回は元のウサギの足が全桁一致し、その場で同一投影のナビ交換を起こすと移動後の座標も全桁一致した。元足は地形・遮蔽・表示枠に収まり、先着者との接触0。本人の歩行目標はなく、主人公の予約通路が閉じていた。この再生での10体の配置は、元CIで各住民が次に歩き出した座標とも10体すべてで一致し、最大差は2.84×10⁻¹⁴モデル単位だった。元CI内の原因を直接記録したものと、この再生対照を区別している。

## 表示要素と保存の回帰

森320px・28体で、通知、会話、表情変更、時間帯変更、同じ画像のパンダ要素の差し替えによる足位置の変化は0px。進化は新しい猫の原画を再測定し、同じ条件の変位0px。装備の着脱では犬の範囲を再測定する。領域の変化を伴うこの試行は両方向で最大326.83pxの大きな再配置が残った。住民追加・削除、地域変更、幅・高さ変更も実行し、計14種類のイベントでブラウザー例外は0。真の画面変更で生じる画面変位にはカメラ分を含むため、同じ表示要素の差し替えによる飛びと別に記録した。

森390pxのゲーム保存データをV11足元版とV12に戻すと、両版で28体の結果が一致した。通常の初期状態の保存では差0px。主人公が歩行途中の保存では4.38px、別の足元まで歩いた後に保存した場合では29.00px、主人公が復元時の位置に戻った。現行のゲームセーブは一時的な歩行経路と足座標を永続化しない。320pxのイベント回帰は比較用にそろえた座席から保存しており、通常の座席へ再読込した最大画面変位は227.92pxだった。データ形式や復元仕様は変更していない。

## 再計測

生成済み本人限定版を `DIST` とし、そのルートをローカルHTTPで提供する。成長比較は `growth_verify.py URL OUT`、実操作は `growth_ui_verify.py URL OUT`、本体の生育は `live_growth_verify.py URL OUT`、2体の協力と部分再配置は `growth_pair_verify.py URL DIST OUT`。境界・経路の個別対照には `reflow_controls.py URL DIST OUT` を使う。通知・装備ほかの変化は `reflow_regression.py foot_transitions DIST OUT`、保存は `reflow_regression.py foot_save DIST OUT --native-opening`、同一原画差し替えは `reflow_regression.py foot_replacement DIST OUT --candidate --expect-stable` で元の操作を再生できる。
