# 森375pxの時計とハムスターの短い退路

時計が8 CSS px歩けたあと、隣のハムスターにどれだけ動く余地があるかを比較した。V12標準では、ハムスターが3px進める方向が384方位中17本から1本に減った。本人限定の追加案は、ハリネズミが別の地点で一度曲がることで4本を残し、時計も同じ距離を歩いた。[両案の全28体の結果、元の指示、折れ点、モデルのハッシュ](evidence/short-exit-margin.json)

## ハムスターの足から3px進めた方向

| 森375px・旧席・乱数937 | 助け手出発前 | ハリネズミの実歩行1歩目 → 2歩目 → 3歩目 | 時計が歩き終えた時 | 時計の実移動 |
|---|---:|---|---:|---:|
| V12標準 | 17 | 35 → 12 → 1 | 1 | 8.00 CSS px |
| 短い退路の幅を保つ比較 | 17 | 39 → 16 → 4 | 4 | 8.00 CSS px |

元からハムスターの8px・16pxの退路は0本だった。標準で最後に残った3pxの方位は146.25度。追加案では143.4375、144.375、145.3125、146.25度が通った。横軸の正方向を0度とし、384方位を0.9375度刻みで調べた。96方位だけで測ると最後は両案とも1本、48方位では両案とも0本となる。開始時と各実歩行の足を照合した。[足ごとの方位](evidence/short-exit-margin.json)

標準は、8pxの出口がない住民に初めからある3pxの退路を96方位で保護する。追加案では、元の足で96方位のどれかと、その左右いずれか0.9375度先の両方が通るとき、各折れ点・終点でもそのような2本が存在することを条件にした。元から1本しか確認できない足には標準の条件を使う。速度・接触・遮蔽は元の歩行処理を使い、探索上限は7,680回。時計の指示で調べた候補などの合計は2,355→2,548、助け手の出発は197.933→197.967ゲーム秒だった。2つの方位に対する検査であり、その間のすべての角度での通行まで保証するものではない。[比較用の差分](curve-short-margin.patch)

## 同じ初期状態からの300秒

通常の森で記録した178.2429秒時点の28体の足を、同じ旧席の開幕の個体・判断時刻・乱数状態に置いた。両案ともゲーム内時刻を0から1/30秒ずつ300秒まで進めた。通常歩行は、退避・道譲りを除く自律歩行で、本人が終点に到着し、開始時の足から8 CSS px以上離れ、元の目標へ0.75 CSS pxを超えて近づいた場合に数えた。比較用の時計はLinux Chromium 156.0.8078.79のシミュレーションで、実時間10分の公平性コホート、WPEのCPU・描画性能、実機iPhoneの測定は別に扱う。

|---|---:|---:|
| 時計の通常歩行、前半150秒 / 後半150秒 | 2 / 3 | 2 / 3 |
| ハムスター | 2 / 0 | 2 / 2 |
| ハリネズミ | 1 / 3 | 1 / 2 |
| 全28体の通常歩行 | 84 | 85 |
| 両方の半期に通常歩行があった住民 | 18 / 28 | 20 / 28 |

前半の回数は全員一致した。追加案でハムスターは268.667秒と294.967秒に通常歩行を完了し、リスとともに両方の半期で歩いた。後半の通常歩行は7体で増え、6体で減った。柴犬は3→1回、ハリネズミは3→2回。この1条件で家族全員の公平性が改善したとはいえない。同じ追加案を2回走らせ、全28体の終状態・各要求・選択・実移動が一致した。[28体の前後半、照合ハッシュ](evidence/short-exit-margin.json)

## 既知の成功例と採用判断

375pxのカワウソと390pxのみているなにかは両案とも8.00px、375pxの石像と430pxのキツネは8.01pxで終点に到着した。短い退路を失わせる390pxの石像の指示は両方とも見送った。別途試した「96方位で元々2本あるなら必ず2本残す」案では、390pxのみているなにかの歩行が8.00→0pxとなった。標準の助け手ハリネズミの退路は9→6→2→1→1本まで狭まる。[既知の入力と各指示への結果](evidence/short-exit-margin.json)

本人限定で比較し、標準への採用は保留する。採用を検討する段階では、同じ条件の10分コホートで6体の歩行減少が繰り返されるか、複数地域で指示と描画に追加の遅延が出るかを確認する。

## 元の記録から再現する

本人限定の原本ZIP `m12-margin-review.zip` に、両案の300秒の原本、追加案の独立反復、195〜201秒の28体の全181フレーム、照合した方向、ネイティブモデルと観測用ソースがある。アーカイブを展開し、ビルド済みV12試遊のルートを `DIST` として次のコマンドを実行する。PythonのPlaywright、Chromium、Node.js、GNU patchを使う。

```sh
python replay.py --dist "$DIST" --out ./replay-output
node named.mjs "$DIST" ./named-results.json
node audit-rays.mjs "$DIST" ./direction-audit.jsonl
```

再生スクリプトは比較専用のモデルを出力先に生成し、ループバックで配信した検証ページのモデルにだけ適用する。試遊の標準ビルドからこの差分を読み込む経路はない。本人向けの6秒再生は実際の足を記録したもので、画面上の操作によって同じ指示を新たに出す機能とは区別した。
