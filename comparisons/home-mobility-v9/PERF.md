## 変更した処理と画素

森のV8を25秒観察すると、住民・装備画像に前景ポリゴンを照合した10,672件のうち、矩形が交差したのは21件だった。V8はその判定前に、全住民に共通の前景頂点を住民ごとに再投影し、画像ごとに各多角形の外接矩形を作っていた。V9は位置に依存しない前景を、全住民の位置を書いた直後に1回投影する。スプライトと装備のアニメーション込みの矩形は毎回読み、前景と交差する場合は従来と同じアフィン変換でSVGを作る。

同じ調査で、V8では値が同じ `data-diorama-actor`、`role`、`tabindex` が各588回、`aria-label` が596回書き込まれた。V9では表示・向き・選択・ARIA属性の実値を確認してから書き込む。初期席の走査では、安全な矩形を同じ同期ループの内側で取り直す処理を省き、直前に取得した同じ矩形で座標を制限する。[V8調査の記録](evidence/paint-baseline.json)

同じ表示中の画面にV8→V9→V8を適用したところ、森の780×860画素は3枚ともRGBが一致した。みずべの横画面では、画面内の岸の輪郭に主人公のスプライトを重ね、3枚の画像に実際のマスクが付いた状態で、518×410画素すべてと各SVGマスク文字列が一致した。静止画の検証だけはアニメーションを固定した。[画素ハッシュ・遮蔽位置](https://github.com/Naoto214/naotocchi/actions/runs/44903860654/artifacts/14707855208)

Chromiumでも168コマの固定再生をV8→V9→V9→V8の順に計測した。実際のスタイル再計算は全試行376回、レイアウトは36・37・37・37回。V8で各99件発生した選択状態と `aria-pressed` の書き込みは、V9で各0件になった。DevToolsのPaintイベントは131・134・134・134回で、有限なクリップの面積の中央値はどれも390×792 CSS pxだった。大きいクリップは別計上した。LayerTreeの個別の再描画通知はこの環境で得られなかった。Paintクリップから住民一人ごとの実際のラスタライズ範囲までは特定できず、画面の再描画範囲が縮んだとは判定していない。[スタイル・DOM・クリップの記録](evidence/paint-work.json)

追加で、同じV9描画のまま全住民・装備を個別にレイヤー化するヒントと、背景コンテナだけをレイヤー化するヒントを試した。森・岸の画素は住民のヒントあり・なしで一致したが、住民のヒントは両順序で中央値が悪化し、背景のヒントもp95の改善が再現しなかった。どちらも試遊版への採用を見送った。[共有環境の対照実験](evidence/layer-control.json)

装備追従では、実際に装備中の主人公の `petAccessory` を全480コマで比較した。装備と本人の移動・拡大率、装備の変換原点・マスク・ブラウザー矩形はV8／V9間で全480件一致した。この記録で位置・大きさ・原点の組み合わせは2通りだった。[装備の検証](evidence/equipment-parity.json)

## 性能面の判断

今回のV9では、森28体の移動量を増やしながら通常再生のp95・p99が両順序で改善した。描画関数とマスクの平均処理時間も減った。一方、固定再生のp95は順序で優劣が変わり、p99は両順序で悪化した。同じ移動量で滑らかさが向上したという採用条件には届かず、正式採用の推奨は保留する。

## 再現手順

比較バンドルを `http://127.0.0.1:8377` で配信し、Python Playwright 1.62.0と同梱のLinux WebKitを使う。各プログラムの `--base` 引数でゲームの配信場所を指定できる。

```sh
python performance-fixed.py --out raw/fixed.json
python performance-native.py --order v7,v8,v9 --seconds 180 --out raw/forward.json
python performance-native.py --order v9,v8,v7 --seconds 180 --out raw/reverse.json
python performance-native.py --trace --seconds 25 --out raw/trace.json
python performance-touch.py --out raw/touch.json
python performance-pixels.py --out raw/pixels.json
CHROMIUM_PATH=/usr/bin/chromium python paint-work.py --out raw/paint-work.json
python paint-baseline.py --out raw/paint-baseline.json
python equipment-parity.py --poses raw/fixed-poses.json.gz --out raw/equipment-parity.json
python environment-cost.py --out raw/environment-cost.json
python seating-frame-cost.py --out raw/seating.json --raw /path/to/private-observations/seating-frame-cost.json.gz
MOBILITY_GAME=/path/to/private-bundle/game node route-cost.mjs raw/route-cost.json
python summarize-performance.py raw evidence --private /path/to/private-observations --run https://github.com/Naoto214/naotocchi/actions/runs/44903860654
```

Linuxのソフトウェアラスタライズ・合成スレッドのCPU時間、rAFコールバックの間隔、DOM上の足の応答を測っている。iPhone Safariの実画面の表示時刻、タッチパネルからの総遅延、GPU・熱・電池は実機での確認が残る。
