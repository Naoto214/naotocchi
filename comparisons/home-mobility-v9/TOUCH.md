# 森の28体を指で動かした結果

390 CSS px幅の森で、Linux Chromiumのタッチ入力を住民1体ずつに送った。画面に描かれた本人の画像を押し、その足元から横に12 CSS px離れた位置で指を離した。各入力の前に28体の足元・活動・モデル時計・乱数を復元した。

## V8とV9を同じ足元から比較

各行は28回。同じ開始状態の2版には、同じ押下座標と指を離す座標を送った。「押下時表示」は押した瞬間に画面の選択表示が本人になった件数、「解放後選択」は指を離した直後にモデルで本人が選択されていた件数。経路終点には、安全な補正先や途中までの経路の終点も含む。指先4px以内は、経路終点と指を離した座標との画面上の距離で判定した。

### 復元先の入力状態

各室で、画面の入力を受け付ける状態でネイティブのモデル時計が実際に進み、モデルの一時停止も解除されたことを確認してから、記録した足元・時計・乱数を戻した。一時停止の判定には復元先の画面と試遊設定を使った。168回すべてで、実際の指が触れた瞬間の画面・試遊設定・モデルの一時停止はいずれも解除されていた。

先に保存時の一時停止フラグまで複写した試験では、V8・937と配置案・214の両方で28回すべて本人に指示が届かなかった。元のV8では通知と住民の跳ねる反応、配置案では空腹反応が保存時に進行していた。独立した復元先にはその演出がなく、モデルだけが止まっていた。この2室で同じ元データ・画面レイアウト・指座標を使った対照試験では、いずれも指が画像上のいぬに当たり、現在のゲートを使うと各1回とも本人を選択して指示を発行できた。上表の168回は各室で改めて採った座標を使っている。元の演出中に直接操作したときの応答は、この復元試験の対象外である。
