# スマートフォン幅で見た秋の落ち葉

標準の B では、390 CSS px 幅のもりで手前の葉が **16.1 × 9.9 CSS px**、いなかの夕で **28.1 × 17.5 CSS px** になる。基準の E3+ は同じ比較画面でそれぞれ 6.5 × 2.6、10.6 × 4.1 CSS px。いずれも葉の面がこちらを向く間の中央値。

## 実際の画面での見え方

もりの手前の赤い葉は、1秒に尖った面と明るい折り目が見える。2.25秒には細い縁が斜めに伸び、3.5秒には裏側の落ち着いた面が広がる。A は小さく、林床や遠い葉になじむ。B は背景を見ながら一枚を追え、C は葉の切れ込みまで読み取りやすい。

いなかでは6枚のうち手前の1枚が、中央右の木の冠から舞う。3秒のえんじ色の裏、5秒の細い縁、7.5秒の明るい朱色の面が同じ葉に現れる。初期案では住民の耳と黄褐色の葉が重なったため、位置を約60 CSS px 上げ、裏面をえんじ色にした。分割時にも0秒、1.5秒、4.5秒、6秒、7.5秒、9秒に住民の上で確認した。3秒前後に中央を横切る瞬間は分割ラベルが一部を隠す。単体表示の切り出しではその瞬間も確認できる。

## 390 × 844 の奥行き別実測

## 測定方法

- Linux Chromium 156、DPR 2、縦844 CSS px。各条件で0〜24秒を0.5秒間隔で採取した。標準の粒子数・サイズ・速度・風、住民1体、晴れ、秋、候補色は混合。
- 通常の比較画面からホームの Canvas が cover に落ち着くのを待ち、実際に描く直前の背景、画像矩形、Canvas 変換行列、葉の描画関数を取得した。今回の絵は全幅で528 × 792 CSS px、元の #568 は531.33 × 797 CSS px。390幅での左端はそれぞれ −69、−70.67 CSS px。横長配置の contain はこの縦画面では選ばれない。
- 同じ座標・時刻・画素密度に葉を描き、アルファ0.10以上の画素の主軸・副軸への投影幅を DPR で CSS px に換算した。葉の直前・直後の同じ背景画素を sRGB から D65 の CIELAB に変換した。出現・消失のフェードを外すため飛行位相0.09〜0.88、元の不透明度0.2以上、全輪郭が画面内のものを採用。奥行きを3等分し、面は向きの絶対値0.70以上、縁は0.23以下として集計した。JSON に各中央値のサンプル数 n を記載した。
- 原寸画像はブラウザ画面を CSS px 解像度で撮影し、葉の周囲60 × 60 px を等倍で切り出した。落ち葉の時計を固定しても住民は動くため、同じ時刻の別案で歩く位置が変わることがある。iPhone 実機での見え方は未確認。

## Linux WebKit での照合

Linux WebKit 26.5（WPE）でも390 × 844 CSS px・DPR 2の比較画面で全4案と2場面を測定した。B の手前はもりで16.1 × 9.9 CSS px、いなかで28.1 × 17.5 CSS px。色差面積はそれぞれ87.5、260.3 CSS px²。WebKit でも暗い森と夕方の屋根の両方で面と縁の差が残る。同じ画像矩形と画素密度で Chromium と照合した。

[Linux WebKit の8条件の数値](evidence/visual-webkit.json)

## 再現

Playwright、Pillow、日本語フォント、各ブラウザが必要。2本のローカルサーバーで元の #568 と今回の比較画面をそれぞれ公開して、比較ディレクトリで実行する。

~~~sh
python verify_visual.py --url http://127.0.0.1:8196 --modes E3plus --out original.json
python verify_visual.py --url http://127.0.0.1:8197 --out current.json
python verify_visual.py --url http://127.0.0.1:8197 --engine webkit --dpr 2 --widths 390 --out webkit.json
python verify_visual_frames.py --url http://127.0.0.1:8197 --out screenshots
~~~
