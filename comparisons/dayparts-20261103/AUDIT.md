# 朝昼夕夜背景 — 既存仕様調査と統合設計 V1

調査日: 2026-11-03 JST。調査基準 main `81c044a9977dbd013f1632372a72785b540fb463`、PR490 `c0a05f8c4dd7f3ef335ed200f1459096bb05cc9e`、PR502 `5cb81cebd203514bebe68202df05e996352891ea`。このPRはmainから分岐し、PR490の実装コミットを取り込まない。追加は比較資料だけ。本編・正式画像・配信allowlist・保存形式を変更しない。

## 1. 時間

`world-environment.js:timeOfDay(mode,date)` は端末の `Date.getHours()` を読む。加速する世界時計や地域別タイムゾーンはない。`morning/day/evening/night` の手動指定は時計より優先。mainとPR490の同ファイルのblobは同じ `202fb21df94e25239ffb1b7aa637ec58342c8ccd`。

|時間帯|既存|今回決定した背景仕様|
|---|---|---|
|朝|05:00–10:59|05:00–09:59|
|昼|11:00–15:59|10:00–15:59|
|夕|16:00–18:59|16:00–18:59|
|夜|19:00–04:59|19:00–04:59|

`script.js:currentTimeOfDay()` → `currentEnvironment()` が共通の環境データを作る。環境は通常の描画や約3秒のループで再評価される。端末が日本なら日本時刻、海外や端末の設定変更時はそのローカル時刻。今回はJST固定への変更を行わない。

育成時計は別責務。`TICK_MS=3000`、`loop()/tick()` と `ageTicks` が育成を進める。メニュー・ゲーム・非表示タブ等では既存条件で停止するが、現実の時計は停止しない。`recoverSleepStepInner()` は `envModifiers().sleep` を使い回復量を計算する。したがって `timeOfDay` の10時台を直接変更すると、背景以外にも朝の空腹1.1倍・睡眠回復1.2倍、ミニゲーム抽選などが変わる。

保存は `saveState()` の `savedAt=Date.now()` と `lifetime.timeMode/weatherMode/seasonMode` を継承。自動の時間帯・季節は復帰時の現実日時から再計算する。`applyOfflineProgress()` は2分以上の留守から最大600tick=30分相当、ステータス下限・1回の低下上限を持つ。背景変更でこの計算に触れない。`travelToRegion()` 等の地域移動は同じ `currentTimeOfDay()` を使い、時計はリセットしない。睡眠中の移動制限も保持。

### 10時台の互換性判断

現在の共通判定からは「10時台の朝」と「9時台以前の朝」を区別できない。`env.time` だけで新仕様へ対応することはできない。

- **今回実装**: 比較ページ専用 `daypartAt(hour,minute)` のみ。ゲームコードから呼ばない。
- **背景だけの統合案（推奨・承認待ち）**: 既存手動 `timeMode` を尊重し、自動時だけ同じ端末 `Date` から背景用 `backgroundTime` を05/10/16/19で導出。既存 `env.time`・育成・睡眠・保存はそのまま。10時台のUIが「あさ」、絵が昼になる相違を本人に明示する必要がある。
- **共通判定を10時に揃える案（別承認が必要）**: `timeOfDay()` を変更しUI・イベント・育成補正まで一括変更。背景だけの作業範囲を超えるため今回は実施しない。

季節で日の出・日没を動かす処理、天文学的計算、新時計、セーブ移行は不要。

## 2. 天気

`world-environment.js` の `WEATHER_MODES` は `sunny/cloudy/rain/snow` の4種。`weatherDetails/weatherFromResponse` はOpen-Meteoのコードを4種へまとめ、観測2時間以内・未来15分以内を検査。`createTracker` がユーザーの位置情報要求から取得し、`script.js:maybeRefreshEnvironment()` は要求済み・可視状態等の条件で15分ごとの更新を行う。

`script.js:effectiveWeather()` の優先順位は手動設定 → おうちだけ2時間以内の現在地天気 → `simulatedWeather(region,season,date)`。予想天気は日付・端末ローカル3時間枠・地域のハッシュで安定し、同じ枠の再描画で乱数が変わらない。地域移動でその地域の予想を再計算。深海と星空は手動設定も適用せず `weather:null`、地上へ戻ると保存済み設定が再び有効。

地域の基礎比率（晴/曇/雨/雪）: home/city/countryside 45/30/20/5、forest/river 35/35/28/2、mountain 35/30/15/20、snow 22/30/8/40、sea 50/25/25/0、jungle 25/25/50/0、desert 78/15/7/0、memory 40/40/20/0。`climateFor()` は冬に雨の6割を雪へ（jungle/desert除外）、夏はsnow以外の雪を雨へ。雪国は夏も雪の一部を残す。

`script.js:ENV_EFFECTS/envModifiers()` は晴で機嫌減少を0.85倍、雨で1.15倍/出会い0.7倍、雪で空腹1.1倍/遊び疲労1.2倍/睡眠1.15倍などを合成し、最終0.7–1.5へ制限する。`environmentGameWeight()` は出題ジャンル等にも反映。これらは画像から逆算せず既存判定を維持。

## 3. 季節

`script.js:getCalendarSeason()` は3–5月春、6–8月夏、9–11月秋、12–2月冬。`getEffectiveSeason()` が手動設定を優先。自動時は月境界または復帰時の現在月から再評価。地域移動で季節設定は変わらない。

`render()/renderWorldNowCard()` の季節ラベル、世界画面の説明、`renderSeasonChoices()` の手動選択を保持。深海・星空は「地上は○○」として表示し、`hasSurfaceSeasons()` により地上季節の育成/抽選補正を適用しない。

`world-scene.js:resolveScene()` は地域の気候・植生・季節を使い、春の花びら、秋の落葉、冬の色調/霜、熱帯で積雪しない等を定義。旧背景には田舎冬の別画像、森秋冬・山冬・記憶冬の素材選択がある。`sceneMarkup()/createRenderer()` と `world-scene.css` が粒子・水面・植生・光量を表現する。これは既存旧背景向けの表現であり、2.5Dの各原画が季節別に描き直されているという意味ではない。

## 4. PR490の2.5D描画

- `script.js:updateHomeDiorama()` 周辺: `homeDiorama.update(currentEnvironment(),flags)` を呼ぶ。
- `home-production-diorama.js:createController()/sceneFor()/update()` が既存環境をシーンへ渡す。背景制作側から住民状態を操作しない。
- `home-production-manifest.mjs:ART_CANDIDATES/ART_SCENES/selectRecoveredScene()` が地域ごとに単一の原画・床・前景・席を選択。
- `home-production-world.mjs:createHomeWorld().setEnvironment()` は地域候補が同じで読込済みなら画像の再読込をしない。現在は時間帯別srcを選ぶ実装ではない。
- 同 `draw()` は絵をcanvasへ描き、夜は `rgba(21,30,73,.24)`、雨は `rgba(38,57,78,.15)` のレイヤーを重ねる。夜かつ雨は三項演算により夜色のみ（雨色との二重合成ではない）。雲/雪/季節をこの画像選択で扱っていない。7個の控えめな光粒子があり、reduced motion時は停止。
- `home-production-transform.mjs:artTransform()/paintBackdrop()/backdropComposition()` とナビゲーションは構図と接地の基準。今回コピーしたのは比較用の座標データだけで、これらの本編ファイルは変更しない。

旧 `world-scene` の地域制約・既存演出定義は再利用候補だが、旧植生や旧季節画像を2.5D原画へ無条件に重ねると構図不一致になる。今の2.5D描画で四季・雨雪すべての視覚演出が完成済みとは扱わない。

## 8. 制作方法と確認限界

画像生成のlighting-weather編集で原本の構図を参照し9枚を制作。おうち/都会の編集入力は正式原画から作られたPR490の配信用WebP、森はF3のPNGそのもの。入力と原画はそれぞれ保存して区別。画像の再採用はまだ行っていない。プロンプトの時間帯固有指示は `prompts.json`。共通指示は同一camera/crop/perspective、家具/木/岩/建物/床の位置維持、照明/影/空のみ変更、追加物/人/文字/滝なし。

生成編集には細部の描き直しがある。構図の大枠・主要床境界が似ていることと、全画素/全前景が一致することは別。比較ページの原本ワイプと床座標で本人確認できる。ピクセル完全一致や本編実機接地成功は主張しない。今回本編の地形・描画・住民には一切変更を加えていない。
