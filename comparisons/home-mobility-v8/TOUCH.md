## 測定方法

森・昼・390 CSS px・28体で、各住民の絵に触れ、足元から画面中央に向かって12 CSS px離れた地点までドラッグした。開始・終了座標は#576の保存値を使い、28体すべてを名簿順に1巡した。記録はブラウザーが送出した `pointerType=touch` と `isTrusted=true`、本人への指示、本人の最初の一歩、経路終点への到着、最後の足元から指先までの距離を区別する。画面のマーカーだけでは到着に数えない。[実行スクリプト](touch_trials.py) ／ [元の入力座標](../home-mobility-v7/evidence/forest-drag-touch.csv)

5分後の比較は2通り行った。各版を同じ初期状態・乱数でモデル時計300秒まで自律再生してから本人をドラッグする試験では、各版で自然に生じた混雑が反映される。もう一方ではV7の300秒時点の全住民・経路・行動・クールダウン・乱数・時計を復元し、同じ指の開始点・目標へ操作した。後者はV7に残った具体的な詰まりに対する検査で、V8の自律再生で同じ配置に至る頻度を表すものではない。いずれも実ブラウザーのタッチ入力に対して通常のモデルと歩行ステップを動かす。モデル時計を進める試験から端末のフレーム停止や入力遅延は推定できない。[5分後の基準配置](dual-drag-feet.json)

順次道譲りではハムスターと石像に実タッチを送り、0.30モデル秒後に同一の地域・住民による通常の表示同期を発生させた。同期前後の28体の足元と寸法が等しいことを確認し、道を譲った順序、各住民の実歩行、最後に本人の足が動くかを記録した。安全性は、各歩行区間の途中も含む住民間の侵入量、歩行可能な地形、足元の境界、遮蔽、毎ステップの速度上限で照合した。[処理の計測点](../home-mobility-v7/matrix_worker.py)

重なる絵は、保存済みの「手前が透明で奥の絵が見える点」「両方の絵が不透明な点」で試した。タップ、5pxの指ぶれ、10pxのドラッグを同じ座標から送り、入力時の原画アルファと奥行き順を独立して記録した。反応中の入力は、おうち4体・390pxで、通知・跳ねる反応の開始後と入力途中での発生、短いタップ、待ち時間切れ、モーダル、ポーズ、キャンセル、別操作への置き換えを個別のブラウザーコンテキストで試した。[選択画素の観測](../home-mobility-v7/selection-probe.js) ／ [通知などの操作手順](../home-drag-v6/reaction_input.py)

Linux ChromiumではCDPタッチ入力、Linux WebKitではWPEのタッチ入力を使った。iPhone Safari実機の指の接触範囲、操作中の応答、発熱は未検証。

## 再測定

本人用ビルドをローカル配信し、PythonのPlaywrightとブラウザーを用意する。各パネルで `touch_trials.py --origin <origin> --out <evidence-dir> --arm <v6|v7|v8> --suite <panel>` を実行する。`forest` は各住民12px、`resync` は表示同期を挟む道譲り、`aged` は300秒と保存状態復元、`extra` は8方向・通常ジェスチャー・反応中入力、`ink` は重なる絵のタッチである。`aged` はV7から、`extra` はV6から始める。`ink` は `--engine webkit` でも実行する。`CHROMIUM_PATH` と `WEBKIT_PATH` で実行ファイルを指定できる。各版で配信中のモデルのSHA-256を前後で照合する。反応試験では実際にゲームが中断状態を作れたかを検査し、準備段階で失敗した試行は別記する。

測定表には開始点・指示先・足元を含む。指定した住民と、押した画素で実際に一番手前に描かれた住民の両方を残した。ゲームが表示した通知や招待についても、生の入力履歴で確認できる。[個別タッチ結果](evidence/touch-inputs.csv) ／ [反応と操作の全件](evidence/touch-gates.csv) ／ [本人用の生データとSHA-256](https://naotocchi-cast-size.kerzion214.chatgpt.site/evidence/mobility-v8/touch/manifest.json)
