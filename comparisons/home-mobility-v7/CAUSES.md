# 森28体が歩き出せない条件

昼の森、390px幅、同じ28体・足位置・サイズで、自律移動の要求、経路の採否、足が動いた区間、到着を別々に数えた。乱数214での実時間連続再生では、V6で実時間379.94秒・モデル時間307.41秒の間に自律移動の要求446回、経路の採用72回、実際の歩き始め71回、到着70回を記録した。11体（タヌキ、ハムスター、ヒツジ、ユニコーン、カワウソ、パンダ、インコ、アザラシ、ハリネズミ、多尾のキツネ、箱）は一歩も動かなかった。全11体で15〜23回ずつ要求があり、開始時の足が他の住民と重なっている状態で失敗し続けた。通常の待機や睡眠だけではこの11体を説明できない。[個体別の連続再生](observe-forest.py)

## 同じ固定乱数で失敗を切り分けた結果

実際の森のナビゲーションを使い、別の固定乱数575で5分のモデル時間を0.05秒ずつ進めた。V6で全く歩かなかったのはネコ、タヌキ、コウモリ、ユニコーン、見守り、ウサギ、ニワトリ、ハリネズミ、多尾のキツネ、箱の10体。経路を得られなかった時点で、周囲の位置を変えず、地形・表示枠・前景・接触の区間全体を再検査した。

| V6で足が動かなかった住民 | 失敗した自律要求で見つかった区間 |
|---|---|
| コウモリ | 17回すべてで単独の安全な18 CSS pxがあった。 |
| ユニコーン | 18回すべてで単独の安全な18〜24pxがあった。 |
| ウサギ、ニワトリ | 安全な4pxが見つかった要求は17回中それぞれ17回、9回。これを行き詰まりからの復帰には数えない。 |
| ネコ、箱 | 全15回・17回で、既に重なった楕円から互いの間隔を縮めずに出る初期方向がなかった。 |
| タヌキ | 画面内の住民枠と接触の両方を満たす4px方向を19回の要求で見つけられなかった。 |
| 見守り、ハリネズミ、多尾のキツネ | 接触だけを調べると方向が残るが、地形・前景を含む区間検査を通らなかった。 |

V6の通常経路は、目的地側で全住民との接触楕円から完全に出られる地点を要求する。初めから重なった密集地では、近所に安全な8〜24pxの歩行区間があっても、終点でまだ重なっているため経路を返さない例があった。元の歩行要求が失敗した後、V7は混雑した16体以上の場面で、最後の移動計画から15モデル秒以上経っていれば、本人だけで8・12・18・24 CSS px歩ける区間を32方向で調べる。今の重なりを深めず、新しい重なりを作らず、地形と前景も通れる候補を使う。候補間では他の住民との距離が開く位置、元の要求へ近づく位置を優先する。直近45秒以内に同じ区間をすぐ引き返す回復歩行は抑える。通常の休息・会話の抽選や歩行枠数は変更していない。[実装](mobility-model.cjs) ／ [元のモデルで失敗する回帰試験](mobility-model.test.mjs)

最終版と同じ初期28座標で、300モデル秒を最後まで再生した。移動した住民は18→21体。コウモリ・ユニコーン・ハリネズミが新たに歩き、V6で動いた18体も全員歩いた。自律要求は418→386回、経路の採用60→106回、到着59→103回、歩行距離は合計679.12→940.19モデル座標単位だった。要求の総数を増やして得た結果ではない。この再生はゲーム内の昼の自律活動を対象とし、実時間300秒の表示性能には使っていない。[全住民の固定乱数結果](evidence/forest-fixed-575.csv) ／ [再実行用コード](replay-movement.py)

## 同じ足位置に残る相互閉塞

390px幅の初期状態を再構成し、28体全員で実画面の希望位置の地形・前景の可視性・境界判定・奥行きを照合した。希望する方角を限定せず、8〜24 CSS pxの本人変位、1回の折り返しを許す30px以内の経路を7.5度刻みで探索すると、単独で13体、1体が近くで24px以内を譲れば計16体に経路があった。次の7体にはこの範囲で単独・1体・2体の順次道譲りのいずれでも8pxを確保できなかった。300モデル秒後にも同じ7体で単独・1体の道譲りを再検査し、結果は同じだった。

| 住民 | 地形・前景だけなら通れた8px直線の方向数（144方向中） | 1体だけが直接ふさいでいた方向の相手 |
|---|---:|---|
| ネコ | 144 | ハリネズミ、多尾のキツネ |
| タヌキ | 144 | ニワトリ、ウサギ、箱 |
| 見守り | 73 | ニワトリ、箱 |
| ウサギ | 53 | タヌキ |
| ニワトリ | 80 | タヌキ、見守り |
| 多尾のキツネ | 74 | ネコ |
| 箱 | 144 | 見守り、タヌキ |

2モデル座標単位ごとの面積推定では、森ステージの歩ける地形は46,682 CSS px²。住民の表示枠と実際の前景を通る点は住民別に43,031〜44,845 CSS px²あるものの、他の27体の接触楕円から完全に離れた点は218〜994 CSS px²だった。この面積は空いた点の総量であり、本人の足元からつながっている面積はさらに経路を調べる必要がある。

例えばウサギが一方向へ出るにはタヌキが空ける必要があるが、タヌキがその方向を十分空ける位置まで移るための区間も別の住民がふさぐ。この表の人数は検査した角度・距離・経路長の範囲での結果。全ての連続曲線に解がないという数学的証明には使っていない。[再現用の地形探索](geometry-census.mjs) ／ [数値の記録](evidence/forest-geometry.json)

## 初期配置の比較

V5から使っている安全な座席候補の順位を変える案も、別の初期配置として試した。広く順位を変えた案では森の短いドラッグで16→18体が歩いたが、それまで動いたニワトリが動かなくなり、二乗した重なり量の合計も0.742→0.917に増えた。以前から通れた8px方向を全住民について残す案では、サルだけを7.09 CSS px動かし、方向候補は合計10増えた。実際に歩いた人数はドラッグ16→16、乱数214・300モデル秒の自律移動14→14、到着55→55だった。V7の比較にはこれまでの配置を使った。[初期配置の試験記録](evidence/forest-seating.json)

## ドラッグと順次道譲り

森28体の12px指示では、V6の1体の道譲りで動かない12体を先に検査した。ハムスターと石像では、地形・前景・接触を守った1体の短い道譲りでは足りず、2体が順番に歩く具体的な経路が見つかった。V7は元の経路・近傍・途中停止・1体の道譲りを先に使う。それでも本人に最初の経路がなく、16体以上かつ指示距離が6〜32 CSS pxの場合だけ、少しずつ2体分の候補を検査する。1人が24px以内を完全に歩き終えた後、2人目の経路と本人の区間を全員の現在の足位置で検査する。どちらかが手で選び直された、別の人が入った、指示が取り消された、または12モデル秒の期限に達した場合には、不成立の残り区間を実行しない。3人目の募集はない。

元の足位置を使ったネイティブ再生では、ハムスターは主人公・アザラシの順に譲った後に8.73px歩き、指から3.54pxで停止した。石像は柴犬・フクロウの後に9.28px歩き、指から7.31pxで停止した。クマでは水平ドラッグを逆変換した縦方向の端数0.000004pxが、道譲り後の縦0.24 CSS pxの差を後退扱いしていた。初回と同じ画面1px未満の軸判定を再試行にも適用すると、指から4.695pxだった足が2.36pxまで歩けた。全13地域と実際の入力の結果は比較表で個別に確認できる。[道譲りと入力の試験](mobility-model.test.mjs)

実画面の再同期も独立に検査した。森の28体の足がすべて同じ位置のまま、指示から0.30モデル秒後に通常の住民同期を通した。初期試作では、経路キャッシュの無効化を「人が動いた」と見なして1秒時点で2体探索を打ち切り、ハムスター・石像ともに指から12pxのままだった。最終版では2体探索を始めたときの足位置を保持して比較する。独立した実タッチでも、通常の昼夜表示の更新をその時点で再現し、28体全員の座標・サイズが更新前後で一致することを確認した。ハムスター・石像は各3.54px・7.31pxまで実際に歩いた。更新を挟まない実タッチでも同じ結果になった。全28体の短いドラッグでは本人の指示28/28、選んだ終点への到着18/28、指から4px以内に止まったのは9/28。V6は16/28、7/28。別の住民が実際に歩いた場合は予定どおり古い探索を打ち切る。[通常の住民同期を使った回帰試験](mobility-model.test.mjs)

## 移動中の接触と再探索

通常の自律歩行でも両端の足位置が改善しているのに区間の途中で接触が深まる例があった。森28体で、ウサギとカタツムリの正規化した距離は0.955470から0.955549に増えたが、その途中では0.955078まで縮んだ。V7では全住民の実際の一歩に同じ連続接触判定を通す。既に重なった楕円では距離の二乗が区間の始めから減らないこと、外側から出発する場合は区間中の最小距離が楕円の外であることを調べる。足が向いた先へ瞬間移動する処理はない。[途中でのみ接触する回帰試験](mobility-model.test.mjs)

元の経路キャッシュは1回の手動命令の中だけで共有され、次の命令と再試行では破棄される。今回の固定例では、V6に同じ足位置・同じ目標で新しく要求しても失敗が続き、古いキャッシュを前提にせず再現できた。近くの足が変わって通常の再試行時刻に達したら、未完の2体探索を打ち切って元の指示を再検査する。実機のiPhone Safariにおける長時間操作、居住者の見つけやすさ、停止時間については本人限定試遊での確認が残る。
