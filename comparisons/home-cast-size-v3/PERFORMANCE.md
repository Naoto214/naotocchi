# 生きている28体の処理時間

28体の重点試験では、最長の間隔はWPE WebKit・もり・+0%・固定の3.25秒だった。おうち430pxでは20体の+0%でも4.35秒止まり、経路計画2回でほぼすべてを説明できた。描画処理と経路探索の負荷は分けて判断する必要がある。

通常速度で28体全員を動かし、同じ名簿・装備・秋の晴れ・昼で倍率と初期配置を比較した。倍率の基準はV2の主人公120%・恋人120%・仲間105%。+0%はV2と同じ見た目と初期位置で、+5〜20%はこの実表示への追加拡大。固定と配置調整の両方を毎回、新しいゲーム画面で起動した。タイマーやフックは自動試験の配信応答にだけ挿入した。

Linux ChromiumはCPU 0、Linux WPE WebKitはCPU 1に固定し、DPR 2を使用した。もり320px・配置調整の+5%だけは配席の確定後にCPU 1でChromiumも再計測した。ホスト全体には4コア相当の上限がある。最初の森・固定の試行では別の配席テストが同じCPUを共有した。その後はほかの測定を別のCPUに移したが、ホスト全体の混雑は残る。専用ヘッダー52pxを除いたゲーム表示領域を実寸で開いている。rAFはブラウザーのコールバック頻度で、液晶への実表示FPSは未計測。過去に約2.53秒の停止を記録したV2比較はCPU 2コアで、実行環境も経路も異なる。[V2計測](../home-cast-size-v2/PERFORMANCE.md)

同期時間はブラウザー内で測った。住民は移動V5の更新、経路はその更新の内数、描画は住民・装備・影などのDOM反映、背景はCanvasと自然演出など。GPUの完了待ちは含めない。「歩いた秒」は1人以上の足座標が実際に進んだモデルステップの時間。会話・待機中や経路探索だけのステップは含めない。一部の初回試行は、直前と直後の2回の読み出しで歩行を集計したため、フレーム計測と歩行計測の終了に最大数ステップのずれがある。

## 全2,600条件の描画計測

13地域・4画面幅・5人数・5倍率・2配置の全組合せで、それぞれ別の実時間計測区間を設けた。1区間の目標は0.9秒。各CSV行で、表示中の住民数、フレーム間隔、住民更新、経路探索、住民描画、背景描画、実際に座標が進んだ時間をたどれる。画面の計測中は全住民の自律更新・会話を通常どおり進めた。

各地域・幅・人数で、全住民に対するV5の初期位置候補が完全一致する組合せだけが、同じ実ゲームの初期配置を共用した。候補が違う場合は、その倍率と配置のURLからゲームを起動し直した。候補が同じ場合も測定結果の転用はせず、倍率・配置の各行で0.9秒を別々に再生した。CSVには実測開始時点に至る世帯の初期姿勢ハッシュと、同じ世帯での測定順を記録した。
