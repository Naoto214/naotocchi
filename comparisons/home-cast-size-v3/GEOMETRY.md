# 住民の大きさと輪郭の重なり

## 測定条件

昼の正式なホームを縦画面320 × 568、375 × 812、390 × 844、430 × 932 CSS pxで動かした。DPRは2。試遊操作の52pxを引いた高さで実際のゲームを開いた。1・4・10・20・28体の同じ試験世帯を使い、主人公は成犬、恋人はもりのクマさんとした。1体時には恋人と仲間がいない。倍率は採用済みの主人公120%、恋人120%、仲間105%に、全員共通で1.00・1.05・1.10・1.15・1.20を掛けた値。

固定配置では各場面を開いたまま倍率を切り替え、全員のV5座標と当たり判定寸法が一致することを検査した。配置最適化では、各倍率の全住民について試遊版の初期座標関数を呼び出し、異なる開始位置を提案する組み合わせごとに新しい試遊を開く。同じ初期位置を使う候補は、同じ移動状態で倍率だけを変えて比較できる。[初期配置の比較方法](geometry_seat_modes.cjs)

初期配置のほか、V5モデルの通常の自律移動を0.1秒刻みで進めた8秒時点を調べた。28体は30秒でも調べ、他人数でも8秒の時点で累積移動距離が1未満だった場合と、375〜430pxの改善配置を採用した場面では30秒まで進めた。実時間の操作・フレーム計測は別試験に記録した。移動データにはモデル時間、初期位置から1以上離れた人数、累積距離、開始した移動、到着・会話イベントを記録した。接触回避単独の件数は元のモデルにカウンタがない。[移動の数値](evidence/geometry-motion.json) ／ [実時間の計測](PERFORMANCE.md)

390px幅・もり・4体・固定の最初の読み込みでは、初回の輪郭計測時に4体全員の影が生成されておらず、装備矩形のずれも最大40.768 CSS pxに達した。8秒後には全員の影を確認できた。別の2回の同じChromeビルドによる読み込みでは、初期・8秒・30秒すべてで、各住民の位置・画像枠・足元・影・5倍率のタップ結果が完全に一致した。表にはこちらの安定した表示を使い、最初の起動も生データごと保存した。初回だけ表示がそろわなかった原因と、実機での再現頻度は未確認。[初回表示と再測定の記録](evidence/geometry-startup-transient.json)

## 輪郭・影・装備の読み方

透明余白を除いた本体の高さをCSS pxで示す。表示中の原画、左右反転、奥行き、足元、画像枠、前景マスク、画面の切り取り範囲、住民の重なり順を正式ゲームから取得した。本体のアルファ値96/255以上を数え、輪郭が4 CSS画素以上重なる二人を1組とした。JSONには延べ隠れ面積（hiddenInkPx2）、同じ位置を一度だけ数える重なり面積（distinctOverlapPx2）、全員の本体面積の合計（totalInkPx2）をCSS px²で記録した。三人が同じ1画素に重なると、それぞれ2・1・3になる。「重なり面積%」は全員の輪郭面積の合計に対する隠れた延べ面積、「主人公・恋人の露出」はそれぞれの本体を手前の住民が覆わない割合。原画枠の端から1 CSS pxを超える本体のはみ出しを見切れとして数えた。装備と影は体高に含めず、足元基準のリボン・指輪の拡大位置誤差と各住民の影の有無を記録した。[全条件の測定](evidence/geometry-matrix.json)

全条件は実表示の画像枠と元原画から輪郭を再サンプリングした。投影とブラウザーの端画素の丸めの差を確かめるため、重点場面は実際のCSSと前景マスクを使い、同一時刻・同一座標の各住民だけを白で描いたスクリーンショットでも測った。輪郭が数画素しか重ならない組の数は、この差に敏感である。表情の読みやすさ・接地の印象・タップ操作は、輪郭の大きさや露出と合わせて本人限定の実画面で確認できる。[スクリーンショット校正](evidence/geometry-raster.json) ／ [同一座標の検証コード](geometry_collect.py)

WPE WebKit 26.5の320px幅・もり・28体では、固定の追加0%・5%・10%・20%で、恋人の見える面積が76.1%・70.2%・66.2%・59.0%だった。同じ画面で最適配置の追加20%では恋人57.1%、隠れる延べ面積21.1%。375px幅・おうち・4体でも、恋人の本体高は追加0%・5%・20%で73・77・88pxに増えながら、見える面積は26.6%・23.0%・15.8%に下がった。同じ375pxのおうちで採用候補の配置に切り替えると、追加5%・20%とも恋人の露出は100%になり、本体高は86・98pxだった。[Linux WebKitの実画面](evidence/geometry-raster-webkit.json)

## 見切れ・装備・測定精度

全2,600条件のうち、少なくとも一時点で1pxを超える見切れがあったのは1条件、住民の本体がすべて隠れたのは6条件だった。計測した住民の影の欠落は最大0体。足元・奥行きから求めた装備矩形の位置と大きさに対する最大誤差は0.009 CSS px。

初期位置が同じ候補をまとめると、自律移動の開始状態は340種類。最後の測定時点までの累積移動距離が1 native px未満だったのは0種類。会話や思考中に全員が必ず歩いているとは限らない。

Chromeの開始状態を157.0.8103.50で210種類、157.0.8103.78で130種類測定した。内訳はGitHub Actionsが271種類、同じ公式ビルドを使ったLinux上の追加測定が69種類。[開始状態ごとのブラウザーと測定元](evidence/geometry-motion.json)

各配置候補は同一バージョンのChromeで固定配置と比較した。

Chromiumのスクリーンショット17条件で校正した。本体高の最大誤差は1 CSS px。重なり面積の絶対差は中央値0.17、最大0.43ポイント。4画素以上が重なる組の数は最大2組の差があった。[Chromiumの実画面と投影の比較](evidence/geometry-raster.json)

WPE WebKitのスクリーンショット13条件で校正した。本体高の最大誤差は1 CSS px。重なり面積の絶対差は中央値0.19、最大0.70ポイント。4画素以上が重なる組の数は最大2組の差があった。[WPE WebKitの実画面と投影の比較](evidence/geometry-raster-webkit.json)

iPhone Safariの実機での体感、長時間動作後の熱、スクロールやアドレスバーによって表示領域が変わる状況は未検証。
