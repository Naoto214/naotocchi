### 375pxの1px調整も見送った理由

原画の通路、境界、既存接触を保ち、8pxの出口がない住民またはその進路を塞ぐ隣人を同じ規則で調べた。移動候補は24方向に1・2・3・4・6・8・12・16 CSS px。96方向・9距離で元の退出方向を一つも失わず、単独退出できる住民が増える案は、固定順の4画面幅では375pxでリスの初期席を右へ1pxずらす案だけだった。名前は探索に使っていない。

同じ1px案を0.25度刻みの1,440方向、1～24pxの各整数距離で再検査した。リスに36の方向と距離の組が増える一方で、時計の住民は最初の1pxを進めた0度・359.5度・359.75度を失った。近い角度と短い距離まで調べることで、粗い検査で見えなかった損失が判明した。V10ではこの1px案も採用しない。追加配置を除いたV10モデルと固定席モデルは、診断表示名を揃えると全バイトが一致するため、元の足位置と安全な退出方向を全方位で保つ。[高密度検査で変化した角度](evidence/forest-seat-375-candidate/direction-changes.csv) · [実装の同一性を検査するテスト](seats.test.mjs) · [本人限定・高密度検査の全方位](https://naotocchi-mobility-v8-evidence.kerzion214.chatgpt.site/evidence/mobility-v10/seats/375-one-pixel-directions.csv.gz) · [本人限定・候補探索の測定データ](https://naotocchi-mobility-v8-evidence.kerzion214.chatgpt.site/evidence/mobility-v10/seats/bounded-opening-search.zip)

### もう1席を動かした補償案

375pxのリス右1pxを固定し、時計・ハリネズミ・ハムスターのいずれかを0.25px格子の半径2 CSS px内でずらす588通りと、時計の左右位置をリスと揃える近傍54通りを調べた。既存の95,273本の測定済み経路を保ち、さらにリスに8pxの出口ができる接触条件を通ったのは、時計を右へ0.759126854px動かして両者の横座標を完全に揃える3案だけだった。

この3案を描画済みのネイティブ地形で再測定すると、時計を上へ0.1・0.01・0.001 CSS pxずらしたいずれの場合も、元からあった2pxの11方向（281.5～284度）がすべて失われた。リスの新たな8px退出は真右の1方向のみ。横座標を右へさらに0.01px動かすだけでもその退出は消えた。0度近傍を追加測定すると、元の時計には1pxの右下0.01～0.2度の退出があり、揃えた後は測定した右下方向がすべて失われた。[5案のネイティブ検査結果](evidence/forest-seat-375-candidate/two-seat-comparison.csv) · [個別角度の結果](evidence/forest-seat-375-candidate/two-seat-proof.json)

この制約はリスを右へ1px動かした場合について、2px以内の補償が難しい理由も示す。リスは下限ちょうどにいて、真左の同じ高さにハリネズミが接触しているため、単独で8px退出するには右へ進む必要がある。時計はリスの上にいて、2px以内の補正後も両者の楕円距離の上限は0.952（接触境界は1）。時計が元の右下0.05度を保つには時計がリスより右になければならず、その位置ではリスが許される右～右上の初動が時計に食い込む。時計以外を動かしても、時計とリスの間で既に失われた真右の条件は変わらない。この特定の1px案とその補償は比較用の検証資料に留めた。[本人限定・全候補と再検査の記録](https://naotocchi-mobility-v8-evidence.kerzion214.chatgpt.site/evidence/mobility-v10/seats/375-compensation-screen.zip)

## 入力と保存の測り方

10分間の通常再生は、乱数・画面幅・仲間順を記録し、ゲームの時計と実時計の両方が600秒以上になった時点で全員の足位置・体格・目標・待機・道譲り状態を保存した。タッチ検査では、1住民1回につきLinux Chromiumの新しいモバイル画面を開き、ブラウザーが `isTrusted` として処理するタッチ入力を送る。iPhone Safari実機はこの検査の対象外である。28体のキー・役割・寸法・足座標、ネイティブのモデルSHA、記録した時計を照合してから、原画の不透明部分を実際に押し、足元から左右12 CSS pxの位置へ指を離す。ほかの住民が手前にいてもその点を押し、実際に選択された相手、対象本人への要求、経路成立、安全な到着点、指から4px以内の到着を区別する。タッチ後は共通の12.35モデル秒の窓で、指示した歩行と必要な道譲りを観察する。自律移動はこの個別のタッチ窓では停止する。

新しい入力画面では現在のコントローラーが入力可能になったことを確認する。長時間観察時に実行途中だった探索ジェネレーターは別のJavaScript実行環境に移せないため、該当時は保留探索を外す。元の保存ファイルからの復帰は別途、比較用の再着席を無効にしてネイティブの読み込みを実行し、仲間の並び・恋人・地域・時計の再開を照合する。[実タッチ検査](forest_touch_v10.py) · [保存・読み込み試験](forest_live.py)
