### 動く雲（新規）

- 昼の原画から「開けた空」（青空と描かれた雲の白）を読み取り、その中だけに雲を描きます。山・木・建物・窓枠の手前には出ません。やま・ゆきぐには、雪山の白を空と間違えないよう青空だけを対象にしています。
- 雲の量：晴れ 8〜38%、曇り 62〜92%、雨 90〜100%、雪 84〜98%。約80秒ごとにゆっくり変わります。
- 色は時間帯と天気で変わります（朝夕は暖色、夜は暗い青、雨雲は暗い灰色、雪雲は明るい灰色）。雨・雪では雲が速く流れます。
- 夜の星と流れ星は、これまでどおり曇りで約3割、雨・雪で消えます。
- 天気連携：既存の問い合わせに雲量（`cloud_cover`）を追加しました。晴れ・曇りのときだけ使い、雨・雪は常に空を覆います。取得できなければゲーム内の変化を使います。
- 対象は空が見える10地域（もり・かわ・いなか・やま・とかい・ゆきぐに・うみ・さばく・きおくのみずうみ・おうちの窓）。ジャングル・しんかい・ほしぞらは対象外です。

**限界（静止画で確認）**

- 空を覆う雲は、ほぼ一様な灰色に見えます。雲の凹凸はあまり出ていません。
- うみの雨では、水平線の近くに原画の青が細く残り、原画の雲の縁が白い点として少し見えます。
- 葉の揺れで見える隙間には原画の空色が出るため、曇りの日は木の縁にわずかに青が見えることがあります。
- 低性能端末で草木・水面・光の層が止まると、雲も描かれません（色かぶせだけになります）。

## 遠景まで含めた季節の色と、適用範囲の見直し（VERSION 11）

### D案：遠景の山や奥の木まで

前回（C案）で遠くの山や奥の木が変わらなかったのは、青みのある緑を「針葉樹」とみなして色を変えない保護のためでした。同じ保護が川や池の水面も守っていたので、**水面より上の高さだけ**保護をゆるめる方式にしました。

- 各地域に「これより上は遠景」という高さを決め、そこでは、かすんだ青緑の植生も季節の色に変えます。空・雲・雪・灰色の岩は対象外です。
- 遠景は少しだけ淡く（約86%）、緑のまま残る木をやや多めにして、混交林の山らしくしています。
- 手前では、青みのある暗い緑は引き続き針葉樹として緑のままです。
- とかいは遠景の対象外です（ガラスのビルが緑がかって見え、誤って色づくため）。

### 実際の天気との連携

- 変更は `weather-link.cjs` に、本番2ファイル（`world-environment.js`・`script.js`）への置き換えとして書いてあります。試遊版にはこの置き換えを当てたものを入れています。**本番ファイルそのものはまだ変更していません。**
- 既存の1回の問い合わせに `precipitation, snowfall, wind_speed_10m, wind_gusts_10m, wind_direction_10m` を追加し、風速は m/s で受け取ります。問い合わせ回数と間隔（15分以上）は変わりません。
- 受け取った値の扱い：
  - 雨・雪は「報告間隔あたりの量」なので、間隔（`interval`）から1時間あたりに換算します。間隔がなければ1時間分とみなします。
  - 単位は応答の `current_units` を見て mm・cm・m/s に直します（inch、km/h、mph、kn に対応）。知らない単位の値は使いません。
  - 欠損・負の値・数値でないもの・あり得ない大きさ（雨200mm/h超、雪50cm/h超、風75m/s超）は、その項目だけ無効にします。平均風速より小さい突風も無効です。
  - 無効な項目・通信失敗・連携なしの場合は、その項目だけゲーム内の自然な変化を使います。
- 計測値が効くのは、いまの本番と同じく「天気：自動」かつ「おうち」のときです（ほかの地域の天気はゲーム内で決まるため）。**つまり実際の天気は、おうちの窓の外に反映されます。**
- 風は、新しい計測値が届いても数秒かけてなめらかに変わります。雨・雪の量は、降り始めの粒から順に変わります。
- 風向きは取得しますが、演出には使っていません（雨はまっすぐ落ちる承認済みの動きのため）。
- **未確認**：この作業環境からは天気サービスに接続できず、実際の応答では確認できていません。応答の形式は公開仕様に基づいており、テストは想定した応答で行っています。

### 植物の四季の色

- **方式**：B2で使っている「葉の判定」を原画全体にかけ、葉と判定された画素だけを季節の色に置き換えます。置き換える色は「季節の色相 × その画素の元の明るさ」なので、陰影・筆致・光の当たり方はそのまま残ります。
- **原画は上書きしません**。表示のたびにメモリ上で季節版を作ります（夏・強さ0は原画そのもの）。
- **木ごとの違い**：数本ぶんの大きさのゆるやかなむらで、黄・橙・朱・紅・遅れて緑のまま、に分かれます。
- **常緑樹**：青みのある暗い緑（針葉樹）は秋も冬も緑のままです。
- **草**：地面の高さより下の緑は草として、秋は金色、冬はわら色に寄せます。木との境目はなだらかに混ぜています。
- **時間帯**：夕方は8割、夜は5.5割に弱めて、原画の色調になじませます。
- **冬**：葉は消さず、色を落ち着かせるだけです（穴やぼやけを作らないため）。
- **揺れとの一致**：B2の揺れは季節版の絵から葉を切り出すので、紅葉した葉は紅葉した色のまま揺れます。
- **強さ**：A 現在の色／B 控えめ（45%）／C はっきり（100%）。

**限界**

- 葉かどうかは色で決めています。黄色く実った稲は「葉」と判定されにくく、あまり変わりません。花（赤・ピンク・青・黄）は変わりません。
- 木と草の区別は高さだけなので、背の高い草や低い枝は反対側の色になることがあります。
- 遠くの山の緑も、手前の木と同じ規則で色づきます（針葉樹らしい色のところは緑のまま）。
- 色の計算は原画の半分の解像度で行います。葉の縁は1〜2画素ぶん、なだらかに混ざります。
- 時間帯が切り替わるときに1回、季節版を作る計算が入ります。

**Claudeの推奨**：**C（はっきり）**。秋の紅葉が一目で分かり、春と夏、冬も原画の陰影を保ったまま季節が読み取れます。夕方・夜は自動で弱まるので、どぎつくはなりません。控えめが好みならBでも同じ仕組みです。

### ピンチズーム（最大10倍）との両立

- 環境演出は背景と同じCanvasに原画の座標で描いているので、ズームすると背景と一緒に拡大されます。波紋・植物の揺れ・粒子の位置は背景に対してずれません。
- 実ホーム・28体で確認：4倍・10倍とも、背景Canvasと住民の層の拡大率が一致（10.00倍と10.01倍）、描画用の画素数は変わらず（負荷は増えない）、1倍に戻すと元の位置に戻りました。
- 10倍では演出も背景と同じだけぼやけます（Canvasを拡大表示しているため。現行の本番の背景と同じ見え方です）。

### 風の強弱

- 無風に近い（0.22）・弱い（0.6）・普通（1.0＝承認済みの強さ）・強い（1.45）の4段階の間を、約30秒ごとに次の強さへ移ります。

### 実際の天気との連携

**現状**：`world-environment.js` が Open-Meteo から取得しているのは「天気コード（weather_code）」だけです。降水量・降雪量・風速は取得していません。問い合わせは位置情報の許可後に1回、その後は画面表示中に15分以上あけて更新されます。

**今回の比較版**：

- 計測値がない場合（現状の本番と同じ）は、上の「ゲーム内の変化」で強弱が決まります。
- 計測値（降水量 mm/h、降雪量 cm/h、風速 m/s、突風 m/s）が渡された場合は、それに合わせます。
  - 雨：1mm/h未満=小、1〜4mm/h=中、4mm/h超=大
  - 雪：1cm/h未満=小、3cm/h以上=大
  - 風：0m/s=無風、3m/s=弱い、6m/s=普通、10m/s以上=強い。突風との差が大きいほど強弱の幅が広がります
  - 渡されなかった項目は推測せず、その項目だけゲーム内の変化に任せます
- 試遊ページでは「実際の天気の例」で計測値を入れた場合の挙動を確認できます。本物のAPIへの接続は行っていません。

**本番で連携する場合に必要な変更（承認後）**：既存の1回の問い合わせに `precipitation,snowfall,wind_speed_10m,wind_gusts_10m` を追加するだけで、問い合わせ回数は増えません。`world-environment.js` と `script.js` の変更になるため、今回のDraftには含めていません。

### B2・B3：Bの動きのまま継ぎ目をなくす

- 揺れ幅はBの式と同じ（手前の葉先で最大約4.7、突風時はその約1.45倍）、速さもBと同じです。
- Bはタイルごとに無関係な位相で動かしていました。B2・B3は、同じ速さの波が木の中を風下へ流れる形にして、隣り合う場所がほぼ一緒に動くようにしています。これが四角い継ぎ目と隙間をなくす条件です。
- そのため「1枚1枚がバラバラに震える」感じはBより少し減り、「細かな波が葉を渡る」感じになります。

### B4：枝をしならせず、形を保って回す

- **小枝の分離**：葉に加えて、細い小枝だけを葉のレイヤーに入れます。樹皮の色の画素のうち、太さが約6画素以下のものだけを小枝と判定し、幹と太い枝は必ず原画側に残します。
- **回し方**：小枝と葉を、付け根を軸に1つの角度で回します。場所の中では厳密な回転なので、枝の長さ・太さ・曲がりは変わりません（C2は先端ほど角度が大きくなる「しなり」でした）。
- **角度**：手前で最大約1.6度、奥で約0.5度。木ごとに周期と向きが違います。
- **葉先**：その上にBの細かな揺れを重ねます。
- **無理に動かさない所**：夜は小枝を空と見分けにくいため小枝を分離せず、葉だけが回ります。場所の縁では動きがゼロになるので、縁をまたぐ枝は縁の近くでわずかに曲がります。

### Claudeの推奨

**B4を推奨します。** 「葉の動きが分かりやすい（Bの長所）」「継ぎ目がない（C2の対策）」「枝がぐにゃぐにゃしない（形を保った回転）」の3つを満たす仕組みだからです。B4で枝の付け根に切れ目やずれが見える場合は、枝を一切動かさない **B3** が安全な選択です。
