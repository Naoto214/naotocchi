# 森の28体で測ったフレーム間隔と指の応答

LinuxのWebKit（WPE 26.5）で森・昼・秋・晴れ・28体・サイズBを測った。幅320pxと390px、高さ792 CSS px、DPR 2。各ジョブ内ではV12、A、B、C、Dの順か、逆の順で各版を比較した。通常／逆は別々のGitHubランナー。乱数214、全版で同じ原画・住民設定と環境演出を使用した。A〜Dは直線の道譲り、V12は曲がる道譲りを含む基準。Dの初期席変更には375px専用の検証条件があり、320・390pxではCと同じ位置から始まる。曲がる道譲りの安全性・追加効果は10分間の公平性検証にある。

320pxの最長は逆順・Dの449ms。対応するサンプリング範囲のWebメイン／ラスター／合成は13.5／217.5／426.4 CPU ms（時刻対応の最大誤差±42.5ms）。 390pxの最長は逆順・Cの427ms。対応するサンプリング範囲のWebメイン／ラスター／合成は198.4／957／59.1 CPU ms（時刻対応の最大誤差±30.6ms）。 同じ姿勢と環境時刻を描く15,120間隔では、250／500／1,000ms超が0／0／0回。

## 再現と適用範囲

検証ソースは `3c6f94bfdf4246033ae0ff74402dc783704350a3`。公式ジョブのZIPを個別にSHA-256・バイト数と照合し、各版が実際に読んだHTML／モデル／描画／歩行領域のフィンガープリントを保存した。生ZIPがあるディレクトリと生成済みgameを performance-report.py へ渡すと機械可読の集計・CSVを再作成できる。320pxテープの再採取にはperformance-tape.py、390pxはV10で保存した2本の原本を使用する。 [計測CI](https://github.com/Naoto214/naotocchi/actions/runs/45011128770) ／ [集計・SHA-256](evidence/performance.json) ／ [フレーム統計CSV](evidence/performance-frames.csv)

iPhone実機のSafariでの描画・物理タッチ・GPU時間・発熱は未検証。Linux WPEのCPU集計からiPhoneのGPU負荷や発熱を推定していない。

障害物の全線分検査前にも3回のCIを保管した。最初の320px自然テープは採取した区間の移動密度が基準に届かず終了した。初版の320px高負荷テープは同じ足位置でも最初のネイティブアニメーションが2順で異なった。最終表には順序間でも姿勢・環境・位相が一致した再生を使った。 [初期3実行のソース・各ZIP・照合記録](evidence/performance-history.json)
