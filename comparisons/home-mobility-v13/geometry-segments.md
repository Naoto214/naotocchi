# 森の追加地形を通る線分の検査

初版のCでは、追加した草地へ向かう途中で旧床の判定が通ると、足が絵の立入禁止域を横切ることがあった。修正版は、足元が追加地形に依存する経路について、出発点から終点までの線分と背景の禁止域・前景の辺の交差を検査する。前景については、その家にいる各体格の9つの視認点の軌跡も検査する。体格や住人数が変わると地形グリッドを作り直す。元のAが許可した経路と接触判定は維持する。[実装](geometry.cjs)

元のAで通れた合計96,573線分は、すべて修正版でも通れた。この表は、各住人の実際の開幕足から、各自の移動可能枠内の6 CSS px格子を結んだ検査。禁止域の内部は、格子点や一定距離のサンプルと独立に、辺との交点に挟まれた区間で判定した。28体の開幕で見つけた禁止域横断はどれも他者との接触条件により実歩行前に棄却される。[座標・分母・各幅の例](evidence/terrain-segments-strict.json)

375 × 792・1体の実画面では、犬の開幕足から元のAだけを使って別の出発点に到達できる。そこから追加地形に向けた129.56 CSS pxの線分は、他者との接触がなく、視認点も通る。初版Cは絵の禁止域1番を横切る線分を受け入れ、修正版Cは棄却した。開幕から直接この禁止域を横切った実測ではなく、元のAで到達できる出発点から調べた経路検査である。1体・4体の別々の投影で、DOM上のステージ座標から再計算した足と絵の座標との差はいずれも0.000001 CSS px未満だった。[実画面の座標と投影](evidence/terrain-segment-sparse-camera.json)

狭い障害物の回帰検査には、足が通れるが視認点が前景の細い帯を横切る例、旧床と追加地形の境目の手前にある禁止域、禁止域の辺への接触、Aが以前から許可した線分、体格を受け取れないときの棄却を含めた。B/C/DとD＋曲線は同じ線分実装を使う。この表の数値はCの地形を対象にしている。[回帰検査](geometry-segments.test.mjs) · [カメラの採取手順](geometry-segment-camera.py)
