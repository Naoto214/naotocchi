# 足元保持だけの採用候補

本人限定試遊の `game/mobility-v13-foot.html` は既存のV11足元版に、同一投影で足元を保つ判定だけを追加した。曲がる道譲り、地形候補、接触変更、初期配置変更から独立している。山・森の記録は `v13/foot-corridor.html` で再生できる。Chromiumのタッチ操作で「配置を再計算」「主人公を歩かせる」を順に押し、山でパンダ0px・主人公72.56pxの結果表示まで確認した。[試遊画面の操作結果](evidence/foot-interface.json)

正式ホーム用には4ファイルの差分を別に用意した。#582の `bff63b9d` と照合に使用したmainの `526b326d` は、この4ファイルが同一。差分には原画・床形状・体格・セーブ形式・試験用APIや試遊UIの追加はない。足元の描画同期、同一投影の識別、モデル同期、キャッシュ更新用のファイル指紋を含む。V5以降の比較用移動機能を正式ホームに移植する必要はない。[独立して適用可能な差分](foot-only.patch)

V11の表示要素同期だけ、またはV12の同一投影保持だけを採用することもできる。次のコマンドは、上記4ファイルのGitオブジェクトを照合してから、任意の片方の正式ホーム用差分を標準出力へ出す。どちらも元の正式ホームに単独で適用できる。両方を採用する時は統合差分を使う。[分割処理](foot_parts.py) · [各差分のSHA-256と対象ファイル](evidence/foot-parts.json)

```sh
python comparisons/home-mobility-v13/foot_parts.py v11 > /tmp/foot-v11.patch
python comparisons/home-mobility-v13/foot_parts.py v12 > /tmp/foot-v12.patch
git apply --check /tmp/foot-v11.patch
git apply --check /tmp/foot-v12.patch
```

## 採否の条件

同じ画像でも、住民・体格・装備・算出済み表示範囲・投影・カメラ枠の一致を確認してから測定値を再利用する。ナビゲーションを作り直した場合は、同じ歩行床・遮蔽・実効投影、全員の構成と体格、足位置の有効性、接触、進行中の全経路を確認する。主人公用通路が必要な時は従来と同じ長さの連続した安全区間を追加確認する。条件不一致や検査上限では既存の配置に戻る。[組み立てと再生入口](foot.cjs)

山の元記録に対する10対照では、原画・装備・実測範囲・構成人数・投影の変更、住民の重なり、地形外の足、無効な指示経路をすべて棄却した。安全なキーボード指示の目標・操作種別は同期後も一致した。[条件別の採否](evidence/foot-controls.json)

正式ホームの複製に差分を適用し、既存の64テストと、実際のV18の `index.html` を使ったChromium試験を通した。旧育成セーブを読み込んだ森で、主人公とパンダの原画を表示し、パンダ要素の再作成と同一投影のナビゲーション交換を順に実行した。両者のモデル足座標は全桁一致した。正式ホームに一時的な確認APIを加えるのは試験中のブラウザー応答だけ。V5以降の移動を含む試遊用モデルでも既存の移動・会話・実セーブ84テストが通過した。[正式ホームの差分適用と64試験](evidence/foot-port.json) · [比較版の84試験](evidence/foot-legacy.json)

森320pxの同一記録で、通知、関係リアクション、空腹表情、時間帯変更の4操作はいずれも全員のモデル足・描画足が0pxだった。犬から猫への進化は新原画を再測定し、変位0px。成長時は13体に既存の再配置が生じ、最大325.79px。リボン着脱も各13体、最大326.83pxだった。窓幅・地域の実変更も含め10操作すべてで最終足が地形・表示枠内、ページ例外0件。成長や装備で生じる席替えには別途検討が必要。[育成・装備と表示同期](evidence/foot-care.json)

森390pxで開幕・歩行中・到着後の育成セーブを読み戻した。V11足元版と候補の復帰後の全28体・装備・仲間データは一致した。歩行中と到着後の主人公は通常開始地点へ戻り、保存時との差はそれぞれ4.38px、29.00pxだった。現行のセーブは歩行経路・足座標を保存しない。[保存内容の照合](evidence/foot-save.json)

## ブラウザーの範囲

この独立版で山の足保持と歩行を再現できたのはLinux Chromium 156。共有Linux上のWebKitでは、最初は試遊の準備完了を120秒で確認できず、別の試行は準備完了後に「配置を再計算」をタップしても120秒で再配置の完了を確認できなかった。320×516の直接入口では元座標の検査が1回棄却された。V12で得られた以前のWebKit結果と区別し、独立版のWebKit・実機iPhone Safariでの山の歩行は未確認とする。[WebKit各試行の到達点](evidence/foot-webkit-status.json)

## 再検証

V13の本人限定ビルドを `DIST`、一時的なJSONの出力先を `OUT` とする。正式ホームの独立試験は、4ファイルのSHA-256を照合してから一時ディレクトリにのみ差分を適用する。育成の合成データ、検査用の足位置・操作フックは公開用差分に含めない。

```sh
git apply --check comparisons/home-mobility-v13/foot-only.patch
python comparisons/home-mobility-v13/foot_port.py "$OUT/foot-port.json"
for suite in witnesses interface controls regions care save legacy; do
  python comparisons/home-mobility-v13/foot_verify.py "$suite" "$DIST" "$OUT/foot-$suite.json"
done
python comparisons/home-mobility-v13/foot_drag.py "$DIST" "$OUT/foot-drag.json"
python comparisons/home-mobility-v13/foot_drag.py "$DIST" "$OUT/foot-drag-repeat.json" --natural
```
