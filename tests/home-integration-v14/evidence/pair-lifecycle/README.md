森は28体、山は10体。試遊ランチャーのフォームから新規開始した。各地域で大人のいぬ、もりのクマ、通常の住民描画、昼の設定を使う。初期の天候、ゲーム内の時刻進行、自律行動は通常の試遊に従う。

`candidate1` は f5cfccbb の隣接配置と d1645af9 の地面構図。森の最初の地形同期で、パートナーは主人公から左に54.35、上下差0となった。Linux WebKit 26.5 ではカメラ計算後に旧構図を一時表示した。初回の足元の背景 y は .4956、次の描画で .7176。同じ画面座標のまま後者に変わる。山でも似た差が出た。この試行は暫定版として保存している。

## 記録の読み方

- 座標は主人公、パートナーの順。stage はゲーム内歩行座標、screen は画面上の足元（CSS px）、artwork は実描画した背景上の正規化座標。背景がまだ描画されていない瞬間の artwork は null。
- JSON の最初の3件は地形導入前の同期後、最初の地形同期直前・直後。ms はページ開始からの実時間、clock はゲーム内の秒数。モデル同期の前後で clock が変わらないジャンプは、その同期の中で起きている。
- 初回の地形同期・カメラ再計算は連続して実行される。同期点の正確な位置は JSON で確認できる。画像は、実際にブラウザが描画した画面を各チェックポイントで撮影したもの。同期点から次の描画までの自律移動が写る場合がある。
- 通常の描画同期、表情 happy、自律行動開始、390×630 → 375×615 → 390×630 の変更、別地域への移動、ページ再読み込みを記録。地域移動はゲーム本体の travelToRegion を通り、保存先の地域も照合した。再読み込み時にセーブを再投入していない。
- 試遊の既婚世帯は、記念日ムービーを始めることがある。表示された場合、試験は標準のスキップ・終了ボタンでホームに戻る。その操作履歴は coordinates.json の movieButtons、entryMovieEvents、reloadMovieEvents にある。表情試験は表示中の上段通知を片付け、ゲーム本体の表情処理を呼び、描画結果の happy を確認した。
- 画面の端末設定はポートレート、タッチ入力、DPR 2、日本語、東京タイムゾーン。Chromium と WebKit はともに Linux 上で動作させた。スクリーンショットは CSS ピクセルで保存している。WebKit の結果に実機 iPhone 計測は含まれない。

opening-photos.json は上表に対応する非丸め座標と画像の位置を収録する。coordinates.json は主要段階の座標・エンジンバージョン・ソース SHA-256 を収録する。同期段階の座標、カメラ倍率、投影リビジョン、実際の画像ファイル、表情確認、エラー件数は各記録内にある。完全な同期履歴と個別画像は下記コマンドで同じ形式に採取できる。地域移動とリロードでは、表題の地域からもう一方の地域へ移動した後の状態を記録している。

main-before-navigation.webp は main の地形モジュール応答だけを一時保留した別試行。通常の描画・自律タイマーが動いているため、最初の同期そのものの正確な座標は coordinates.json の最初の行を参照する。

*-opening.webp の3画面は左から main、修正前、修正後。写真だけを採る別試行で、地形導入後の自律移動の刻みを止めた。地形導入、座席決定、投影、背景、住民画像の読み込み、ブラウザの描画は通常の処理を通す。これにより、画像取得を待つ間に歩いた距離が比較に混ざらない。8列の画像と coordinates.json は自律移動を止めずに採取した。narrow-openings.webp は 320×516 の通常速度の初回表示で、上段が森、下段が山。

## 再現

各リビジョンからゲーム本体を取り出し、アセットを含む完全な Pages runtime を用意する。次のコマンドは既定の2地域を独立のブラウザーコンテキストで試す。

```bash
python tests/home-integration-v14/pair-lifecycle.py /path/to/revision /tmp/pair-opening \
  --assets /path/to/pages-runtime --browser chromium --executable /usr/bin/chromium
```

比較写真だけを撮るには `--hold-opening`、自律移動中の狭い初回画面は `--width 320 --height 516 --opening-only` を指定する。WebKit では `--browser webkit` と Playwright 対応の実行ファイルを指定する。実際のランチャーのキーだけを通常ゲームの読み込み先に置換しており、通常プレイのセーブと試遊セーブは独立している。
