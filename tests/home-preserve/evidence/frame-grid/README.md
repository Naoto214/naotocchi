# 13地域の実フレームと描画処理

本番 `384730f1` と候補 `93e9b8c2` の正式ホームを、13地域×1・4・10・20・28体×幅320・375・390・430 CSS pxの全260条件で比較した。高さは順に516・615・630・695 CSS px、DPR 2。各地域の専用Linux WPE WebKit 26.5ランナーで両版を順番に開き、実行順を地域・人数・幅で交互にした。本番先行・候補先行は各130条件。同じセーブ・ゲーム乱数214・住民乱数214・正午・秋・晴れを指定した。

画像読み込みとカメラ安定後、住民が移動中になるのを最長約4秒待ち、各版で3秒以上の実フレームを1回記録した。通常の会話やアニメーションも動作する。すべてのペアで実際の住民名と人数を確認し、カメラ座標・表示倍率・ステージ寸法は260/260組で一致した。測定開始時に移動目標があった条件は本番259件、候補260件、測定中に実際の歩行距離が増えた条件は本番254件、候補257件だった。

実際のフレーム間隔は本番14,274回、候補15,436回。260条件の各p95の中央値は本番83.5ms、候補84.0msで、候補のp95が短い条件152件、同じ条件15件、長い条件93件。1秒超の間隔は本番16回・計26.20秒、候補12回・計18.93秒だった。各条件1回・短時間の観測のため、単一条件のp95や希少な長い間隔には試行差が含まれる。

深海では地域内のp95中央値が144.5msから222.5msとなり、20条件の内訳は候補が長い10件・短い9件・同じ1件だった。1秒超の間隔は本番1回、候補0回だった。同じ人数・幅どうしで「候補p95 − 本番p95」を求めた20差の中央値は+0.5ms。

山の3秒測定では両版とも1秒超が0回だったが、別の60秒計測を各版2回行うと本番1回・候補3回となった。候補最長の1,498msのうち1,459msは経路計算に重なった。[60秒×2の実測と固定経路の照合](../navigation-cache-performance.md)

描画処理はホームのworld.drawと住民DOMのpaintが使ったJavaScript時間。経路計算は移動モデルの更新に、描画処理とモデル更新は住民更新に含まれる。GPUの描画完了、端末の発熱、実機の表示遅延は今回の計測範囲外。

ホーム・10体・390pxでは、本番の2,154msの間隔のうち経路計算2,102ms、候補の1,748msでは1,709msが経路計算と重なった。同じ地域・10体・430pxでも本番3,412ms、候補2,811msの間隔があり、この2件で住民更新が占めた時間はわずかだった。すべての長い間隔を同じ原因に帰すことはできない。
