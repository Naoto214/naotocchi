# なおぽよ。8×8 / 共通v2 / 発想型ステージ設計

## 今回の到達点と採用方針
8×8を新規制作の標準、共通v2を今後の基本ルールとする。今回の実装は独立7面Pilotで、正式統合はしない。1面は1盤面で完結し、物語は章を通してつながる。既存のv2 engine/input、WorldSession、描画、ポインタ処理を再利用。新エンジンを複製せず、共通mountへcatalog/key/ラベル/固定盤面/初回物語を注入する。旧呼出しの既定値は保持する。

検討した方式：①正式版を置換（保護条件に反するため不採用）、②別エンジンを複製（ルール乖離のため不採用）、③#430の子ブランチで設定とステージだけ拡張（採用）。本人が設計から公開まで一括承認した範囲で実施。

## 8×8画面
ドラッグBを継承。本体は実マス内に拡大、数字は頭上、保持中は数字拡大。Undo/Retry/任意Hint/面選択/一時停止。比較用8×6モードは新入口では非表示・起動不能。カメラ/スクロール不要。env(safe-area-inset-*)とsvh/dvhを継承。種族限定門/出口は犬・魚・カエル等の条件も表示し、隠れた条件にしない。重力面には重力↓、複数イベントは両方の予告秒数を表示。

## 正式移行と保存互換性
1. #428を新mainに整合し、v2 engineの仕様と保存不変条件を確認。
2. #430を#428へrebase/統合し、イベントと指保持の回帰を通す。
3. 今回の独立Pilotをその上に統合候補として載せ、共通mount設定を再検証。
4. 既存01–12、#422候補13–24を面ごとに再制作。#422をそのまま本番へ重ねて24面移行済みとは扱わない。物語上の役割と難易度に合わせて配置先を決定。
5. 正式ステージ選択/章解放/ヒント/進行レコードを実装。
6. 本人iPhone Safariで最終QA。その後に別途承認された場合だけmain統合→Pages本番公開。

安定IDと表示番号を分離：legacy-v1:01等の旧ID、v2-ch01-lesson01等の新ID、rulesVersion/layoutRevisionを持つmanifestを設ける。今回のI01–I07は恒久番号ではない。既クリアは旧IDのまま永久保持し、旧版クリアとして表示。新面のクリアへ自動転用せず、達成履歴を失わせない。将来の解放は旧実績への優遇を別migration関数で決め、マッピングに変更履歴を残す。

途中セーブは特に非互換。v1の実質質量2^(n−1)とv2の段階合計nは同じnでも意味が違い、分裂位置と重力タイミングも異なる。旧stateを新engineに自動読込み禁止。旧ランタイムで続ける選択肢と新面を最初から始める選択肢を提供し、原文saveを版付きbackupへコピーしてから新namespaceへ一度だけ移行。書込み失敗時は旧保存を残す。進行/途中state/Undo履歴は別schemaで検証。load/refresh/別tab/容量不足/中断復帰も移行回帰に含める。

今回の保存はnaopoyo.insight.pilot.20261023.v1のみ。既存正式/v2/worldのキーへ書かない。WorldSessionのsnapshot検証と80履歴上限をそのまま使用。将来の同ID盤面改訂はrevisionを含む識別と旧snapshot退避が必要（現validatorは地形変化を拒否するが、意味だけ変わる改訂を自動判別する機構ではない）。

## 品質ゲートと量産
各面に、実engineの全員脱出witness、段階合計/種族別合計、Undo/Retry/Save、8方向/必須門/水中/イベント決定性、正規画像、画面寸法、3段階ヒント、発見の仮説、短絡解検査を同梱。必須性は構造/数の不変条件/全探索のいずれかで説明し、上限到達を証明済みにしない。操作精度/待ち時間/反射神経で難易度を増やさない。今回イベントは3秒以上予告、周期再試行、時間制限/ゲームオーバーなし。

「解ける」は自動検証、「面白い」は本人QAで別判定。次は7面の実機評価→必要な盤面再配置→導入10面のv2版→各章3面ずつの試作→5～10面の小ロット制作。100面一括生成や人間評価なしの星付け固定を避ける。

## 追加の短絡解検証
I05は、照射を二回受けて5人の1にし、全員が1の星から脱出する合法の別解も実engineで確認（shortcut.test.mjs）。再合体は推奨解の発想であり、全解法で必須ではない。これは隠し条件や出口回数制限で禁止せず採用する。発見の評価は「少ない待ち時間で4+1を作る経路」と「光を繰り返し使う経路」を両方含む。ステージデータのmechanics配列は制作時のテーマ分類で、実ランタイムの勝利条件ではない（必須性の証明と誤認しない名前に整理）。必須と証明した項目はevidence.jsonのablationsに限る。I01/I04/I07は単独の必須門を塞いだ8近傍グラフで出口へ到達できず、分裂源/照射も門の先にあることをテストした。
