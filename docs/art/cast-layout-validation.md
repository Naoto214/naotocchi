## プレビューと再現方法

今回、正規のSites開発プレビューを起動し、Cloud Browserから接続できた。以前のURLポリシー拒否は再現せず、別ホスト・別ポート・トンネルへの迂回は行っていない。公開中のmainや既存の別タブを検証対象にしていない。

静的ゲームに最小のVite開発設定とlockfileを追加した。通常のローカル環境では次の手順で再現できる。

```sh
npm ci
npm run dev
```

表示された開発サーバーの `/__qa` を開く。Sites環境では `sites-preview start .` が発行する正規プレビューを使う。

`tests/visual-qa.cjs` は既存の会話テストハーネスを使って完全な検証用セーブを作る。ブラウザー内では、同じcheckoutの通常の `index.html`・`style.css`・`script.js`・WORLD_MASTER・画像をそのまま読み込む。ゲームのクロージャーへのテスト関数注入や時刻・乱数の置き換えは行わない。`/__qa` は開発サーバー専用のルートで、GitHub Pagesの本番入口には追加していない。

**Load sceneは、その開発プレビューoriginのセーブを検証用セーブで置換する。** Scene・Width・Heightを選択し、Measure layoutでDOMの境界・画像・内部スクロール幅を計測できる。Observe motionは4秒間requestAnimationFrameごとに計測する。計測中に通常のゲームボタンを押すと、その操作によるアニメーションも確認できる。初回に多数の画像を読むときは、pendingImagesが0になってから結果を採用する。
