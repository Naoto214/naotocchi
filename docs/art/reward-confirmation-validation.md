# デートのごほうび確認 — BU修正・BV実機確認（2026-09-10）

## 報告と切り分け

ユーザーのスマホ確認で「通常デートは問題なさそう」「ごほうびを1個使って、の確認が出ない」と報告された。「3番」は深海の場面番号ではなく、直前の操作案内の確認画面を指すと訂正した。通常デートの全条件や終了後復帰まで確認済みとは扱わない。

開始点は GitHub の BT `12257a5ea076a4639ca166f4dc201a4257102865`。専用確認ページのゲーム HTML/JS は BT と一致し、`special_date` / `deepsea_special_date` のごほうびは各1個、クールダウンは0。実際のロードとデートのハンドラーを Node で通すと、両セーブで確認処理へ到達した。

BT はブラウザーの `window.confirm()` が false を返すと、そのまま通常デートを開始する。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/confirm) にも、ブラウザーが確認ダイアログを抑止すると false を返すとある。ユーザー端末で抑止した具体的な理由、アプリ内表示の方式や設定までは確認できていない。

## 修正

- デートの行き先を選んだ後、ごほうび所持時は既存デート画面内に「ごほうびを1こ使う」「使わずにデートする」「行き先にもどる」を表示する。
- 選択前にはごほうび・デート回数・思い出・クールダウン・体調を変えず、既存のデート画面と同様に育成の時計を止める。
- 使用を選んだ時だけ1個消費して従来の7字幕を再生。不使用は消費せず従来の4字幕を再生する。戻る・Escape・キャンセル・連打・再訪で保留した選択を誤って実行しない。
- デートのブラウザー確認への依存を除いた。これはユーザーが報告した操作不能への製品修正であり、確認応答の自動承諾やテスト専用の回避処理ではない。旅の確認処理は今回の変更対象外。
- 承認済み301画像、WORLD_MASTER、台詞、再生時間、セーブ形式、旧キャスト・旧PERFECT・作者④⑤の互換性を保持する。

## 検証

修正前のコードに、ネイティブ確認が false を返してもゲーム内の確認を表示するテストを追加し、`reward confirmation must be visible even when native confirm returns false` で失敗することを確認した。

修正後の `npm test` は exit 0。DOM294 / ミニゲーム100 / variant collections91。ごほうびの使用・不使用・なし、深海、リング、連打、戻る・Escape・キャンセル、選択中の時計停止、消費と思い出の保存・再読込、最後の字幕と終了後復帰を確認した。全18恋人×10通常プラン、全18恋人×4記念日、深海30本文、既存のキャスト・旧セーブ互換の自動回帰も通過した。

これらは Node の DOM・時計・入力を用いる検証。BU保存時点で、こちらのブラウザーによる修正後の新しい実画面全編確認は0件だった。ブラウザーの初期設定は成功したが、タブ一覧の取得が15秒でタイムアウトし、実行環境リセットが通知された。プレビューは起動していない。その後のユーザー実機確認は次節に記録する。
