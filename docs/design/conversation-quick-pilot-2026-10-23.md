## 1. ねらい

クイックのあとにも、ときどき、なおとっちが短くて少しばかっぽい一言を言う。

- 例(まて!で失敗): 「まてって言われると」→「うごきたくなる」
- 例(いくつ?が 0 こ): 「ほし、数えてたら」→「数のほうがふえた」
- 例(まぜた 20 本をパーフェクト): 「20こぜんぶ」→「……いまの、だれがやったの?」
- 例(なかまが来ているとき・いくつ?): なかま「いくつだった?」→「いっぱい」→ なかま「数字で」

**クイックの軽さが最優先。** 会話のために「もういちど」や次の操作を待たせない。毎回は話さない。

## 2. クイックの結果として取れる情報(調査)

クイックは `quick.js` の 50 本の超短いゲーム。本体からは 2 つの「ゲーム」に見える。

| 遊び方 | id | 1 回 | 終わり方 |
|---|---|---|---|
| まぜた 20 本 | `quick-run` | 50 本から 20 本(同じものは 3 本以内にくり返さない) | 20 本 or 3 回失敗 |
| 1本ずつ | `quick-solo`(`quickGameId` = その 1 本) | 同じ 1 本を 10 回 | 10 回 or 3 回失敗 |

終わったとき、`quick.js` が本体の `onRunEnd(stats)` を呼ぶ(そのあと結果カード)。

| 情報 | どこにあるか | 今回 |
|---|---|---|
| ゲーム id | 1本ずつ: `stats.solo` / `game.quickGameId`。まぜた: 1 本ごとの `plays`・`clears` | そのまま使う |
| クリア数・全体の数 | `stats.cleared` / `stats.total` | そのまま |
| 点数・ランク | 結果カードの `record`(`cleared × 100 / total`) | 使わない(クリア数で足りる) |
| 最大コンボ | `stats.maxCombo` | そのまま |
| 残りライフ | `stats.lives`(0 なら 3 回失敗で終わった) | そのまま |
| 自己ベスト | 1本ずつ: `lifetime.quick.single[id].best`。まぜた: `lifetime.quick.bestCleared` | **この回を足す前**の値を、`recordQuickRun` の中で読む(セーブは変えない) |
| プレイ回数 | 同 `runs` | 同上 |
| どのゲームで失敗したか | **なかった** | **追加**: `stats.lastMiss`(最後に失敗したゲームの id) |
| 連勝・連敗 | クイックには記録がない | 使わない(足すならゲーム側の判断。§8) |

### 追加した読み取り専用の情報(1 つだけ)

`quick.js` の結果 `stats` に `lastMiss` を足した(失敗したときに、そのゲームの id を覚えるだけ)。
判定・クリア数・ライフ・レベル・点数・コイン・記録の形は変えていない。`recordQuickRun` は `plays`・`clears` 以外を保存しないので、セーブにも入らない。

## 5. いつ・どう出るか

1. クイックが終わり、結果カード(6 秒、「もういちど」付き)が出る。**カードが出ているあいだは何も言わない**
   - 本体の吹き出しは、出ると結果カードを閉じる作り(既存)。カードの上で話すと「もういちど」が消えてしまうため
2. カードが消えて 0.3 秒後に、1〜2 行(まれに 3 行)
3. 頻度
   - 話す確率: できごとがあれば 45%、ふつうの結果なら 30%
   - 話した次の回は休む(続けて話さない)
   - 同じ一言は Home の時間で 3 分あける(ゲーム中の時間は数えないので、クイックを続けて遊ぶ人にはおよそ 20 回分)
   - **実測(テスト・300 回): 68 / 300 = 約 4.4 回に 1 回。2 回続けて話したことは 0**
4. 来ている相手(なかま・こいびと)との掛け合い・気質の一言を少し優先(60%)。寡黙な相手は乗ってこない
5. 1 行目を出したときにはじめて「話した」と数える(すぐ次へ行った人のぶんは数えない)

## 6. 画面の移動と会話(最重要)

**会話はその場限り。画面をまたいで待つ会話(キュー)は作っていない。** 未表示の行は、その会話の持つタイマーだけにあり、やめるときに全部消す。

| 起きたこと | どうなるか | しくみ |
|---|---|---|
| カードの「もういちど」・別のクイック・通常ミニゲームを始める | その場でやめる。言いかけの吹き出しも消える | `startMinigame` → `clearConversationTimers`・`hideSpeechBubble`(既存) |
| メニュー・たび・ずかんなど | やめる | `openExclusiveMenu`(既存)+ 下の層の検知 |
| めぐる・人生イベントの 3 択・デート・アイテムの場面など、ホームの上に何かが開いた | やめる。言いかけの吹き出しも閉じる | **新規** `conv2LeaveScene`: `syncHistoryLayer`(画面の層が変わるたびに走る)で、ホーム以外の層が開いていたら呼ぶ |
| なおぽよ・CARD GAME へ移る(別ページ) | やめる | **新規** `pagehide` |
| 戻る(ブラウザの bfcache で前の画面がそのまま戻る) | 何も再開しない | **新規** `pageshow`(persisted) |
| アプリを裏に回す | やめる | `visibilitychange`(#419 からあり。吹き出しも閉じるように) |
| reload | 何も残らない | 会話は保存しない。Director の履歴(既存の別キー)は「いつ何を言ったか」だけ |
| 戻ってきた | 前の会話は出さない。新しいきっかけ(次のクイックなど)を待つ | やめた会話は二度と動かない |
| お世話の操作 | 操作が優先。会話はやめる | #419 から |

これは クイック・#421 のゲームのあと・#419 の掛け合い / 問いかけ のすべての会話に効く(同じ「単位」の仕組みのため)。

## 8. 他のゲームへの将来拡張(データの約束だけ)

なおぽよ・CARD GAME は今回変更していない。将来、結果に応じて話すなら、ゲーム側から次の形で**読み取り専用**で渡せば、同じ Director・同じ単位の仕組みにのせられる。

```
ResultContext = {
  source: 'minigame' | 'quick' | 'naopoyo' | 'card',   // どこから
  gameId: string,                                     // ゲーム・ステージ・デッキなど、台詞を引くための id
  mode?: string,                                       // 1本ずつ / まぜた、ひとり / ふたり など
  outcome: 'win' | 'lose' | 'clear' | 'fail' | 'draw' | null,
  score?: number, total?: number,                      // クリア数・点数(あれば)
  prev?: { runs: number, best: number },              // この回を足す前の記録(ゲーム側が数えたもの)
  extras?: { [key: string]: string | number }         // ゲーム固有の「話のきっかけ」(最後に失敗したもの、つかまえた数…)
}
```

- できごと(moments)は、会話側の純関数で ResultContext から読む(ゲームの判定はやり直さない)
- 会話はいつも**本体の Home**で、その場限り。別ページのゲーム(なおぽよ・CARD GAME)なら、戻ってきた直後の 1 回だけ、ゲーム側が `sessionStorage` などに置いた ResultContext を本体が読む形が候補(今回は作っていない。古い結果を出さないため、時刻と 1 回だけの消費が必要)
- ゲームごとに別の Director は作らない
