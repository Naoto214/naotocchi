## 0. 原因

`drawBackdrop` は流れる量として `px = plx('far')` を使っていました。`plx('far')` は `−yaw / 2π × 2.6W`(1 周で 2.6W)です。

| 描き方 | 模様の位置 | 右へ回ったとき | 速さ(方角固定の遠景 = 1) |
|---|---|---|---|
| `wave()`(波形の丘・砂丘・海の波) | `sin((x + px·phase)·freq + phase)` | **右へ**(逆向き) | `phase` 倍。海は `phase 5` で 2.2 倍 |
| `spikes()` / `blocks()` / 台地 / 樹冠 / 窓 | `x = … + px·m` | 左へ(正しい) | `m × 0.436` = 0.2〜0.6 倍 |

- `wave()` の `phase` は「形の位相」と「流れる速さ」を兼ねていて、しかも符号が逆でした
- `cam.yaw` は ±180° で折り返すので、そこで `px` が 2.6W 跳びます
  - 並べる形は、何番目の形か(`idx`)が入れ替わって高さが変わります
  - 波は位相が跳びます
  - つまり ±180° を通るたびに、帯の絵がパッと変わっていました

## 1. 直し方

```
turn  = (cam.yaw を 0〜2π に直したもの) / 2π
ring(r, period):
  k = round(r × 2πF / period)        // 1 周でちょうど k 回くりかえす(整数)
  s = −turn × k × period − lat × PLX.far[1] × (r / BD_R0) × (よいやすい設定なら 0.3)
波:      sin((x − s)·freq + phase)   // 符号を直し、phase は形の位相だけに戻す
並べる形: x = … + (s の端数)、何番目の形か = (i − floor(s / step)) mod k
```

- **向き**: `s` は右へ回ると減ります。どの層も左へ流れ、方角固定の遠景と同じ向きです
- **速さ**: `r` = 角度どおり(1° で F·π/180 = 5.60 px。遠景レイヤーの速さ)に対する割合です。層の意味の距離で決めます(§2)
- **継ぎ目なし**: 1 周の流れ量を模様の周期の整数倍に揃えました。0° / 360° と ±180° の前後で絵がつながります
- **使うもの**: カメラの向き・視野(F)・帯の種類(backdrop kind)だけです
  - 使わないもの: `mapX` / `mapY`・`REGION_FRAME`・world map 座標・実時刻
- 1 フレームの追加コストは、層ごとに掛け算が数回だけです。描画命令は 1 つも増えていません

## 2. kind ごとの係数(r = 角度どおりに対する速さ)

| 意味の距離 | r | 使う層 |
|---|---|---|
| 水平線 | 1.0 | 海の波・海の光のすじ・帆 ／ ほしぞらの霧の帯 |
| 手前 | 1.0 | 丘・湖の丘・田園・砂丘の手前の波 |
| 奥 | 0.8(台地の手前 0.9) | 丘・湖の丘・田園・砂丘の奥の波 ／ 台地(メサ) |
| とても遠い | 0.7 | 田園の奥の山並み |
| これまでの速さのまま | m × 0.436 | 街のビル・窓 / 森の木立 / 山並み・雪 / 樹冠 / 空の島 / 海底 / 霧 |

- C の 5 種(と、今は使われていない dunes)だけを角度どおりに近づけました
- B / A の種類は、向きがもともと正しいので **速さを変えていません**
  - 1 周でつながるよう整数に揃えた分だけ、数 % 変わります
  - 窓・看板・海底の光・空の島のように、1 周で 1〜2 回しかくりかえさないものは揃える幅が大きく、±30% 程度変わります。どれもゆっくり流れる小物です
- ほしぞら(skystops)の薄い霧の帯も逆向き(1.74 倍)だったので、水平線として 1.0 に揃えました
