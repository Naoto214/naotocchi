## 評価と検証の区別

[全100面8軸評価](STAGES.md) / [詳細JSON](evaluation.json) / [解法](solutions.json) / [検証](validation.json)。番号は目標難度であり、推論・分合計画・先読みを評価して並べました。手数や探索量を難易度点にしていません。解法を細分類し、導入前の素材が突然現れない順序と、近い難度での題材の切り替えを優先しました。

100/100面で合法解と最短手数を確認。最短の意味は離散的な1マス移動の回数であり、ドラッグのひと筆数・実時間ではありません。旧未確定97面は35,589状態の探索で18手、旧99面と100面は盤面を再設計して最短確認。旧盤面そのものの99・100面の最短は今回確定していません。

主素材のイベント／進入を禁止した探索を全対象へ実施。禁止対象は `primaryRequirement.label` に明記。旧20面の氷は「滑ったイベント」より「滑らない停止位置を作る」ことが主題なので、氷マス進入と蛙の先行配置を別検証しました。旧32面は水流を避ける問題なので、効果禁止を必須性の証明に使っていません。仕掛けを消す比較と、同じルールのまま使用を禁止する探索は別に扱っています。

旧97・100面の汎用主素材省略探索は12,000状態上限で未確定。100面は別途、左右それぞれのフクロウ・箱押しを個別に禁止した到達状態の全探索で必須性を確認（critical.json）。全ての補助素材・全ての抜け道を網羅的に排除したという意味ではありません。

[中盤の検証](MIDDLE-DESIGN.md) / [終盤の検証](LATE-DESIGN.md) / [重点必須条件](critical.json) / [CI原因切り分け](CI.md)。

## 実装済みと候補

分裂・合体・接触交換・余剰分離・落下・上方分裂・崩落・数値通路・氷・ワープ・水・水流・波・浮力・風・上昇気流・地下転送・時間差通路・重量板・保持板・記憶鍵・切替・順序装置・フクロウ協力を既存エンジンで使用。素材別の現在番号はvalidation.jsonのmaterialAppearancesと試遊版の設計資料にあります。

動く足場の独立した機構、乗り物、自由飛行、自由掘削は今回未実装・未採用。風や地下転送を自由飛行・自由掘削の実装と数えていません。「動く支え」は主人公の位置を足場として使う発想です。いぬ・かえる・さかな等の操作個体と、直接操作できないフクロウNPCは区別します。フクロウは旧73・81・100面に限定し、固有の協力条件と鍵に役割があります。

## 実機で改善判断する面

全100面の初見難度・独自性・楽しさは人の試遊で未確認です。特に、旧20（失敗する交換を停止に利用）、旧35（重くして風を避け再分裂）、旧54（短い時間差）、旧62（生成方向）、旧70（時計の役割交代）、旧78（崩落後の再利用）、旧99（転送先を塞ぐ）、100（合体を二度待つ）を重点確認してください。新番号は上表／全100面表で対応します。

90〜100面は複合の先読みを重視しましたが、旧92・94・95・97の分担や鍵の類似感は引き続き評価対象です。反復が多い／説明なしでは読めない面はメモへ残していただき、次の改訂に使います。最終100面が最も難しいという設計仮説は、実機試遊で確かめる必要があります。

## 再現

`node prototypes/naopoyo-100/v3/build.mjs` がV3を生成します。`node prototypes/naopoyo-100/v3/verify-critical.mjs` が重点省略探索を再実行します。旧build-stages.mjsはV1保存用です。V3では使いません。保護元のSHA-256はprotected-sha256.json、保存・全解法・並べ替えの回帰はv3-protection.test.mjsです。
