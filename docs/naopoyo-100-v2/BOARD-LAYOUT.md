# iPhone向け盤面幅の復元と固定（VERSION 2）

2026-11-10。比較元は PR #535 `20487bf6` の本人限定配信ビルド。修正は試作版のレイアウトのみ。

## 原因と修正

旧 `sizeBoard()` は `min(盤面欄の幅, 残り高さ−説明分)` からサイズを算出し、play画面を100dvh内に固定していた。絵本の文章・操作欄・クリア表示が同じ高さを取り合い、盤面が縮んだ。正式第1章の `.arena` とサイズ計算、共通canvas描画・TouchControllerの参照を調査した。正式版のサイズ関数自体も高さを考慮するため、そのまま絵本の固定高さ枠にコピーしても原因が残る。

今回、縦画面は利用可能な幅から盤面を決め、説明・ヒント・クリア欄は通常の縦の文書フローへ移した。左右はsafe-areaを考慮しつつ余白6px＋盤面枠2pxずつ。高さが足りない場合は盤面を縮めずページをスクロールする。操作ボタンは高さ44pxを維持。短い横画面は2列とし、盤面の上限を画面高さから決めるため、メッセージの増減には依存しない。

初回renderでもサイズを適用し、グリッドの最小幅を0に指定。375→320pxの変更で古い幅が残る問題も再現・修正した。縦スクロールの出現による幅の変化を避けるため、play時だけスクロールバーの幅を取らない（スクロールは有効）。

正式版から利用している描画・入力・物理の参照関係は変更していない。`TouchController.point()` はcanvasの現在の `getBoundingClientRect()` から座標変換し、拡大・縮小・スクロール後にも対応する。第1章／第2章保存版、100面・絵本8ページのデータ、キャラクター、ゴール、時の針、gate-art、280msアニメーション、通行判定のファイルは本修正で無変更。

## 検証結果と限界

- Chromeの実DOMで絵本8＋通常100×4幅＝432ケースを確認。盤面幅・ヒント／お手本表示前後の幅一致・横はみ出しなし・操作ボタン高44px、全件成功。初期表示だけでなく幅変更も含む。結果は `layout-browser-results.json`。
- 絵本1は320／375／390／430pxそれぞれで実際のポインタードラッグにより3手でクリア。クリア後も304／359／374／414pxを維持。前後の測定値は `layout-measurements.json`。
- 320×568ではヒントボタンまでスクロールして開けることを確認。568×320／844×390の横画面は盤面と操作ボタンが横にはみ出さない。
- 正式TouchControllerの座標変換を4幅×64マス×2サイズ×2スクロール位置で検証。既存204件＋追加4件、計208テスト成功。解法再生・正式物理回帰・採用素材保護テストを削除／無効化していない。
- Pages契約21件成功。公開対象への試作版混入なし。詳細は [PAGES-CONTRACT.md](PAGES-CONTRACT.md)。GitHub Pagesへのデプロイはしていない。
- ブラウザ比較はChromeでCSS幅を変えた検証。iPhone Safari実機で撮影したものではない。実機ではアドレスバー開閉、縦横回転、ノッチsafe-area、盤面外からのスクロール、拡大盤面上の長いドラッグ、クリア後の説明表示を最終確認する。
