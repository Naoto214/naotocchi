# 採用画像を使う1マス重力看板

基準: PR #504 `a475724e34ec033ca65850228e75a5e0e0e80314`。本人が提示画像を採用し、ゲーム組み込みを依頼。

承認画像を256×256 lossless WebPへ配信最適化（60,070 bytes）。構図・木の札・支柱・太い赤↓は同じ。A8（0,7）を丸々使い、床に接地する。重力06〜10だけ。看板は地形の後、キャラ・出口・トゲ・モーション効果の前に描画し、A8へ移動してもキャラを隠さない。入力透過・当たり判定なし。読み込み時も再描画する。DOM画像は描画元として透明化。

変更は看板画像と読み込み・描画・位置調整、配信ビルドへの画像追加、関連検証のみ。ステージ・物理・分裂・解答・操作・モーション・Undo・保存・おてほんのルールとデータはV10のまま。表示中のV10表記も維持。保護ハッシュ検証は許可した看板描画関連行のみ正規化。

検証:
- 全120テスト成功（既存119＋A8のキャラが看板より前に描画される検証1）。平面で画像を描画しないことも確認。
- DOM結合: 全10面おてほん、保存復元、Undo、A8タップ/ドラッグ、過去保存保護成功。
- 10面×7サイズ=70/70成功。画像デコード、A8全体との寸法一致、接地、入力透過、見切れ・スクロールを確認。
- clean buildは78ファイル（manifest含む）、77コンテンツのハッシュ一致。Site配信元とバイト一致。
- 初回ビルドは軽量作業コピーに既存キャラ画像がなく停止。既存Siteの同一素材を補い、再実行で成功。
- 差分レビューの画像配信漏れ・キャラ遮蔽の指摘は修正済み。再レビューで重要問題なし。
- iPhone Safari実機は未確認。
