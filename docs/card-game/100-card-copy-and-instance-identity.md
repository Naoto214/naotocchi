## 2. 2種類の識別子

| 識別子 | 例 | 寿命 | 用途 |
|---|---|---|---|
| `card_copy_id` | `A-001` | 1対戦中固定 | デッキへ入れた物理的なカード現物を追う |
| `instance_id` | `A-001#1` | その個体が有効な間 | 対象、支払い、連鎖、予約が参照したゲーム上の個体を追う |

開始時の山札では各現物に`initial_instance_id`を持たせ、必ず`card_copy_id + "#1"`とする。A/B各40枚なので、開始時はcard copy 80 IDとinitial instance 80 IDがそれぞれ全体で一意になる。

この分離は「領域移動して戻ったカードは新個体」という既存ルールを、再現記録上でも判別するためのもの。同じ現物であることと、同じゲーム上の個体であることを同一視しない。

## 3. 再登場の記録

eventの`instance_transitions`に、次の4項目を記録する。

```json
{
  "card_copy_id": "A-001",
  "from_instance_id": "A-001#1",
  "to_instance_id": "A-001#2",
  "reason": "zone_change"
}
```

validatorはeventを`seq`順に読み、次を検査する。

1. `from_instance_id`がその時点で有効な個体である。
2. from/toが同じ`card_copy_id`に属する。
3. 世代番号が1だけ増える。
4. `to_instance_id`が過去に一度も使われていない。
5. `reason`が現行語彙の`zone_change`である。

適正なtransitionの後は旧個体を無効、新個体を有効にする。後続eventが旧個体を発生源、対象、支払いとして直接参照すれば拒否する。不正なtransitionは状態を変更せず、後続検査を続ける。

## 4. 予約は移し替えない

予約の`source_instance_id`と`target_instance_ids`は、予約作成時に指定した個体を保持する。**予約は旧個体IDから新個体IDへ移し替えない。**

このため、`A-001#1`を対象に作った予約の後で同じ現物が`A-001#2`として戻っても、その予約は`A-001#2`を参照しない。履歴を再現するため、reservation欄は無効になった旧個体IDの参照を保持できる。一方、後続eventの直接参照には現在有効な個体だけを使う。

## 5. RED→GREEN

99の8テストを土台に、識別子分離と再登場のテストを先に追加した。旧validatorが`instance_id`だけを読むため6件失敗するREDを確認し、最小実装後に11件GREENとした。さらに不正な世代飛ばしと未知reasonが旧個体を誤って失効させるケースをREDで確認し、遷移成功時だけ個体状態を更新する実装へ直した。最終的な12テストは次を含む。

- 分離済み標準fixtureの受理。
- 正しい`#1`→`#2`再登場の受理。
- 別現物のIDへ移るtransitionの拒否。
- 再登場後の旧個体を直接参照するeventの拒否。
- 世代飛ばし・未知reasonの拒否と、不正transitionで旧個体を失効させないこと。
- 旧個体を参照した予約が新個体へ移らないこと。
