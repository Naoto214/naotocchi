# 454 — 全判断種別の別版評価方針・設計

## 1. 結論・承認範囲

balance評価へ進む判断根拠は、**完全な合法候補集合と許可情報に結び付いた、適用範囲内の既存の一意選択根拠**でなければならない。合法性だけ、選択が再現できることだけ、mode名だけでは足りない。全判断についてこの証拠が揃い、116の除外条件に該当せず、さらに標本設計と対戦記録が適切である場合に限り、算入の審査へ進める。

本設計は新しい比較器や戦略を定義しない。各判断の根拠と証明不足を同じ形式で監査する別版の評価方針である。114・A初版・116・505・過去結果を変更しない。新規則実装/採用、新対戦、新shadow比較、balance算入は0。fallback削減を目標値にしない。

## 2. 三つの審査を分ける

1. **合法性・入力の審査**：判断者、phase、現在の選択機会、完全合法集合、stable ID、情報制約、支払い/対象/期限等が整合するか。欠落・矛盾・禁止情報参照は比較不能ではなく証拠不備として扱う。
2. **選択根拠の審査**：なぜこの候補を一意に選べるか。唯一合法、適用可能な既存優先順位、限定安全配置、適用可能な同値tie-breakの根拠を確認する。根拠がない複数候補は116/119へ委譲する。
3. **対戦・実験の審査**：全判断種別のseeded/strategic unresolved、完走、記録整合/再生、固定policy版、入力生成・独立単位・鏡像・分析計画を確認する。判断単位の合格を独立標本の合格と呼ばない。

この三分割は審査設計上の整理であり、116のruntime schema/modeを増やさない。既存の初期順shuffleは戦略的fallbackとは別。初期順の乱数利用そのものを禁止しない。

既存優先順位を使うことは最適なプレイを証明することではない。将来のbalance評価でも固定された判断方式への依存と対象デッキ/局面の範囲を記録し、全戦略・全カードへ一般化しない。

|判断種別/責務|確認できる根拠|欠かせない情報と残存義務|現状の限界|
|---|---|---|---|

|mandatory：手札から戻す/支払う/捨てる等|正本で対象が唯一に固定される場合、完全候補が唯一の場合。複数候補の順位は当該正本に根拠がある時だけ|選ぶ現物、個体、移動元/先、枚数、順序の有無、残る手札、発生源、後続効果|異なる手札を同価値としない。たまご交換、終了時戻し、能力による戻しを発生契約で区別|
|mandatory：並べ替え/探索/複数対象|合法な組合せ・順列全体を列挙して一意性を証明できる場合|順序、選択数の上下限、対象現物、公開された範囲、残る山札/手札、継続義務|同名別現物や同数の組合せを潰さない。「最大枚数を取る」「ID順に戻す」を一般的最善としない|

|決定的な自動処理|正本により選択肢がない状態遷移|誘発の生成、予約/期限消費、chain解決、終了順序、state/hash|戦略判断に偽装しないが監査から消さない。途中で複数の合法選択が現れれば、その判断記録が必要|

開始時、通常行動後、chain追加/解決、終了時、最終比較に至るすべての機会を対象にする。画面やphaseの名前だけで数えず、その機会を発生させる契約で判断種別を特定する。未分類の選択機会は監査未完了であり、判断0件として通さない。

### 唯一候補と既存の記録方式

現行 `tools/proxy_continuation_choices.py::resolve` は選択肢集合が非空ならseed proofを生成し、1件でも `resolution_mode=seeded_fallback` / `strategic_unresolved=true` を記録する。これは実装を読んだ境界確認であり、保存12runにその1件経路が存在するという新たな実測ではない。

唯一候補であるという数学的性質と、その履歴の評価上の状態は別。今ある記録は116の除外条件に従う。fallback率の観測器が候補数を条件に数える場合でも、strategic_unresolved陽性を無視できない。将来この経路を非seededとして記録するなら、対象正本・caller・記録schema・再生の接続設計と承認を経て、将来生成する別成果物で検証する。過去のflagの付け替えや削除は行わない。本設計では修正しない。

## 5. 証拠束の設計（runtime schema変更ではない）

各判断を既存記録への参照で監査するsidecar案とする。以下は設計上の欄で、まだ実装・接続しない。

- **同定**：run、decision、actor、turn/round、phase、発生event、response機会またはmandatory発生源、前state/view hash。
- **根拠版**：カード/ゲーム/判断契約のpathとhash、policy ID、適用前提の検査。source参照があるだけで証明済みとはしない。
- **候補**：完全合法集合と列挙根拠、対象・現物/個体、組合せ/順序、除外理由。比較frontierと完全集合を分離。
- **情報境界**：許可viewと参照field、未知部分、禁止情報非使用の検査。監査用の全stateを選択器へ漏らさない。
- **選択証拠**：唯一性、既存比較の全前提、必要pair証拠、適用可能なtie-break、選択/次点、残差。未解決は0/equalにしない。
- **継続**：支払い、行動後の領域、残存効果、対象、期限、回数、予約、response/終了義務、後stateとevent/hash参照。
- **評価状態**：証拠充足/戦略的未解決/証拠不備を区別。元のmode・strategic flag・seed proofを保持し、分類名で上書きしない。

成分の同値証明と、候補全体を選ぶ根拠は別。通常passは終了・response処理を伴う。response-passもpriority/chain/戻り先を変える。両者を無操作として同値にしない。

## 6. 対戦から標本への判定手順

設計上の手順は次の順とする。これは新しい自動算入器ではない。

1. 正本/カード/デッキ/全判断policyの版と、事前実験計画が確定していることを確認。
2. event・snapshot・判断機会を突合。全判断の網羅性、各判断の証拠束、自動処理の保存整合を確認。
3. 116§4の除外を全phaseで適用。seededまたはstrategic unresolvedが1件以上なら独立balanceから除外する。二つの条件はORであり、一方の集計0だけでは通さない。
4. 証拠不備、真正停止、未完走、再生不一致は審査未完了/不適格として残す。勝者やスコアを補完しない。
5. 上記を満たした場合も「審査候補」に留め、独立入力・標本単位・鏡像の対応・対象母集団・事前の件数/精度・停止/除外分析を確認する。
6. 計画に基づく算入結果を記録。好都合な非fallback対戦だけを後から選んで一般化しない。根拠が揃わない標本設計は未承認として留保。

方針未確定、試行未実施、証拠不足の値は不明として保持する。0・false・成功に置換しない。A/414を実験に使うことの承認と、正本へのpromotionは分離する。本書はどちらも承認しない。

## 8. 期待境界と次の判断

本設計で一意になるのは、何を証拠として審査し、何を未解決/不適格として残すかである。未解決の手札保持価値、順序価値、反応/温存価値、450の通常行動残差を解決したわけではない。新規比較意味論なしにそれらがすべて一意になるとは主張しない。

将来の実装候補は、まずこの証拠分類と全判断の網羅性を記録する**読み取り専用の監査**。それでも選択・fallback数・balance標本数は変えない。唯一候補の記録接続を直す工程や、A証明の他判断種別への適用は、この設計だけで承認されたと扱わない。

実験目的・policy組合せ・対象デッキ・初期順/seed割付・標本数/精度・分析方法は453ひな形の未確定項目として残る。新しい比較意味論が必要なら別案として提示する。設計確認後にどの工程を行うかをユーザーが判断する。
