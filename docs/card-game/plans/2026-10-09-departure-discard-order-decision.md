# P07: 人物離脱時の捨て札到着順 — 未承認の裁定案

基準: ef20f712e62a90ae8f40975065d40fce5f422cfe。これは提案であり、実装済みルール、ユーザー承認、過去結果の追補証明ではない。今回の生成・本番固定・400戦実行は0。

## 決定が必要な理由

01「みにつける」は対象離脱時に装備も捨て札へ移すことを定め、01の満員交代は旧人物→新人物の配置と一続きの処理を定める。01/06/64/93から、複数装備と人物の捨て札内の厳密な到着順は一意に得られない。

449は明示的に「複数装着の同時退場順はJSON objectの列挙順から決めない。捨て札順の既存公開証明がない場合は生成器未対応を保持する」としている。番号付き476正本の「捨て札」と同時/順番/順序/好きな順/置く順/到着順の横断検索でも、この一般境界を確定する追補は確認できなかった。山札下へ戻す順序の個別指定はこの裁定ではない。

現行main_movement_effect/person_placement_effect/cat_activation_effectは、旧捨て札prefixと新規移動札のmembershipを照合するが、到着順の証明flagをfalseに保つ。runtimeのattachments辞書列挙順やeventのsorted IDを、そのままゲームルールに昇格しない。

## 案A: 固定順（提案する既定案）

カード本文に別の順序指定がなければ、人物1枚の離脱に伴う捨て札追加を以下に固定する。

1. 既存の捨て札の並びは保持する。
2. 離脱人物自身の行き先が捨て札なら、その人物を先に追加する。
3. 付属装備は、離脱処理直前のその所有者の準備枠配列の順で、その所有者の捨て札へ追加する。現在残っている配列やattachments辞書の登録順は使わない。
4. 人物自身が手札/山札等へ行く場合、人物を捨て札に加えず、付属装備だけを上記順に加える。
5. この内部移動中の新しい判断/反応機会は作らず、既存の一続きの処理と後続誘発の区分を維持する。

準備枠の並びも公開stateとして保存される。処理直前の並びを新たに好きな順へ変更する権利は与えない。この案は順序に意味がないという同値化ではなく、具体的なルール上の順序を新たに定める案である。現行実装と順序が異なる可能性があり、承認後に現行版の共通離脱処理と監査を一緒に直す。

利点: 新しい選択種別や乱数policyを追加せず、卓上でも準備枠の並びから再現できる。制約: 自分で捨て札順を選ぶ権利はない。

## 案B: 所有者が順序を選ぶ

当該離脱処理で同じ所有者の捨て札へ入る複数札の相対順を、その所有者が選ぶ。既存prefixは保持する。人物が別zoneへ移る場合は、捨て札へ行く装備だけを選択対象にする。

この場合は新たな指定外必須選択の機会・完全候補集合・選択記録・履歴への接続が必要。既存463の指定5種1/N policyを無断で広げない。順序選択を未知/未証明のまま扱う場合は、その事実と適格性への影響を保持する。

利点: 所有者が自由に相対順を決められる。制約: 新しい判断機会を増やすため、追加の選択契約が必要になる。

## 承認後の実装範囲

採用案を新しい追補正本に記録し、旧01/06/114/116/119/449や過去結果を遡及改変しない。現行版の共通離脱処理でmain移動、満員なかま交代、C-cat_friend本人支払を横断して接続する。付属0/1/複数、辞書登録順の反転、準備枠順の変化、人物の異なる行き先、prefix改変・欠落・重複のTDDを行う。順序の決定だけで全機会/情報利用/入力認証を完了へ上げない。
