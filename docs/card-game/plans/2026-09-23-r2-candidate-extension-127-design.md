126の4停止点をそれぞれ保存済みraw・game/continuation hashから独立して再開する。126の終了窓訂正と123の終了証明を巻き戻さず、121の6 family・12条件を現在stateで再計算する。PR #259はDraft/open/unmerged。過去のstate、112、121、125、126、カード本文・数値は読み取り専用。完了していない経路は勝者・独立balance標本に算入しない。

## 根拠と一般契約

1. 盤面枚数条件を持つ114の候補variantは、自分の3×3盤面上の現物（main、companions、partner、world、prepared）を各1枚として数える。`seven_or_eight_cards`は7〜8、`nine_or_more_cards`は9以上を満たす時だけ候補となる。不成立時は新しい証拠語彙`board_card_count_condition_not_met`と、現在の盤面現物ID、数、variantの範囲、114候補表と本文の参照を記録する。時不足など他の該当理由も失わない。カウントと証拠を再計算する。カードIDごとの例外は作らない。条件成立時の効果解決が未定義なら候補を隠さず真正停止する。
2. 既存117の人物配置・121のbirth・pass IDは維持する。114の単一対象行動で対象が現在stateから合法に一意の現物IDとして列挙され、ID衝突のない場合だけ、承認された`candidate-{action_type}-{source_instance_id}-target-{target_instance_id}`を付ける。対象なし／複数対象に拡張しない。単一対象の対象資格、時、本文条件が不明ならIDを付けず停止する。判定とIDの独立検証はsource/target現物、owner公開情報境界、対象の存在と一致を検査する。
3. order-01-b-firstで既に完全と証明された5候補は、107/114の上位優先順位を各候補の確定効果と支払時で対照する。無料なかま2件とpassは現在時2、有償birth2件は現在時1。確定そだち変化と100維持はこの機会にはない。birth2件が時収支で劣位、passは116の安全な時0人物配置条件が全て満たされる時だけ劣位と証明する。残るなかま2件の価値を恣意的に採点せず、既存順位で一意でなければ116のseeded fallbackを両配置候補だけに適用する。合法候補の全5件、候補比較、抽選部分集合、seed材料、次点、支払、公開証拠を保存する。
4. 候補の完全性より先に選択・支払・状態変更しない。選択後は117人物配置、119応答、122終了申出、123終了証明を各現在stateで再適用し、既存handlerの能力分類が証明できないときはそこで真正停止する。手札中の対象なしのセカイ通常配置など、今回承認していないID grammarが必要になれば`missing_candidate_id_grammar`のまま停止する。経路専用の解決器、先回りした全対戦エンジンを作らない。

01-Aの現在盤面1枚（こいびと）と時2は盤面枚数と時の両理由を記録する。01-Bの5候補は内容を再計算して比較する。02-A/02-Bの手札の装備は、盤面なかまを対象にする単一対象IDを付ける。02-Aのセカイ配置がその後に合法となる場合は対象なしIDの選択が未承認なので止める。さらに別の未定義predicateやカード効果が現れたら、現在state/hashを維持したまま停止して不足の根拠を記録する。
