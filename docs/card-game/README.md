## 読む順番と優先順位
設計を始める前に以下を順に確認する。

1. `01-core-rules.md` — 基本ルール
2. `02-main-system.md` — メイン、通常時コスト、たんじょう、ときとばし、へんしん、ちから／ちえ、ちょうせん、8属性
3. `03-design-principles.md` — 設計原則・未確定事項。中の古い「次の作業」は歴史的チェックポイントとして扱い、現在の進捗判断には使わない。
4. `04-representative-tests.md` — おとこのひと・いぬ・かえるの既存代表テスト。末尾の古い「次に再開する場所」は歴史的チェックポイント。
5. `representatives/README.md` — 属性別代表テスト索引
6. `representatives/*.md` — 属性別代表テスト（1属性1ファイル）
7. `05-horizontal-audit.md` — 横断監査の正本。末尾の再開地点は `06` 作成前のチェックポイント。
8. `06-action-chain-checkpoint.md` — **アクション／連鎖処理の最新確定事項・現在の再開地点**

基本ルールや確定事項は `01`・`02` を最優先する。8属性横断監査は `05-horizontal-audit.md`、その後に進んだアクション／連鎖処理の現在地・次の作業は `06-action-chain-checkpoint.md` を最優先する。

確定事項は、模擬対戦等で明確な破綻が確認されない限り理由なく変更しない。変更が必要な場合は、問題→原因→カード調整で直せないか→最小限の基本ルール変更、の順で検討する。
