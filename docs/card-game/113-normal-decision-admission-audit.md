# 113 通常意思決定反復の入場監査

更新日: 2026-09-18

## 結論

111で予定した独立初期順2組×先後鏡像4戦は、**fixture・completed記録を作る前に停止した**。107の判断protocolと既存materializerを照合したところ、次の3件を一意に解決できなかったためである。

1. 合法候補の列挙範囲が不足している。
2. 判断前状態のnested schemaが107と一致しない。
3. 107の優先順位どおりに有料行動とpassを比較する規則が不足している。

これは111の停止条件「既存正本だけでは一意に裁定できない」に該当する。113のfixture数、completed対戦数、独立balance標本数はすべて0とし、不完全な4戦から勝者、候補数、使用数、勝率、先後差、発動率、カード強度を保存しない。

## blocker 1: 合法候補の範囲

108由来の候補器は、メイン、なかま、こいびと、`G-hit-blow`、交際進行、通常ちょうせん、passだけを扱う。113候補デッキに含まれる次の種類は、通常使用できる局面でも全候補へ入らない。

- セカイ
- `G-hit-blow`以外のあそび
- アイテム
- できごと

具体例として、`W-deepsea`を手札に持ち、セカイ枠が空で時3の局面でも、時2のセカイ配置候補が作られない。この状態で「全合法候補」を称した記録は107の要件を満たさない。

対戦エンジン化や完全自動合法性判定は不要だが、少なくとも対象40枚について、正本文を照合した手動候補表を対戦前に固定する必要がある。

## blocker 2: 判断前状態schema

107の機械可読protocolは、判断前状態に次の5項目を要求する。

- `hand`
- `board`
- `time`
- `growth`
- `reservations`

既存判断記録器は`board`ではなく`field`を出す。従来validatorはtop-levelの判断欄だけを確認し、nested必須欄、公開情報policy、許可された公開情報keyを十分に検査していない。113の4戦より前に、schema名とvalidatorを一致させる必要がある。

## blocker 3: 優先順位比較

107は、上位に差がある時は下位を使わず、次の順に比較する。

1. 敗北・途中終了の回避
2. そだち100の維持／阻止
3. 確定そだち差
4. 時収支
5. 手札・盤面・予約価値

既存の固定判断は、有料の誕生・ときおくりを`board_value`でpassより先に選ぶ。しかし、確定そだち差が同じ局面で、時を支払わないpassと有料配置をどう比較するかの記録規則がない。この差を説明せず盤面価値を優先すると107の順位を置き換えてしまう。

再開前に、各候補の確定そだち差、時収支、手札・盤面・予約価値をどの単位で比較し、passとの上位差をどう記録するかを一意化する。
