## 1. 一意に実装できた範囲

[計画](plans/2026-10-04-record-integrity-457.md) / [監査器](tools/proxy_record_integrity_audit.py) / [専用テスト](tools/test_proxy_record_integrity_audit.py) / [保存集計](data/proxy-record-integrity-457/summary.json) / [再生成器](data/proxy-record-integrity-457/reproduce.py)。

`audit_record(run)`は次を直接検査する。policy、候補生成器、`run_route`、`bind_event`、共有moduleを書き換えるscopeは呼ばない。

- event数+1=snapshot数、連番、eventとsnapshotのseq一致、初期/最終envelopeと端点snapshotのcanonical一致、last_valid_event_seq。
- 全edgeのenvelope・continuation・gameの前後hash。game hashだけは既存規約に従いcards lookupを除く。continuation/envelopeはcardsやruntimeを含むため、それらを無視しない。
- 記録済み判断のトップレベルevent_seqがあれば、対応する直前snapshotと次eventが存在すること。pre_game/pre_continuation hashがあればその一致。
- 欠落、追加、順序違い、bool/int差、改変hash、契約版違い、不正配列は拒否する。欠落した判断アンカーは補わず、未確認として表示する。

`audit_record`単体は供給されたrunの内部結合を調べるだけ。固定447 manifest/gzip/12run集合への真正性は、再生成器が456の`load_saved_path`を呼んで確認する。自己整合する偽のrunを真の保存runと認証する機能ではない。

state schemaのゲーム上の意味、支払い/効果遷移の合法性、候補完全集合、許可情報の意味、戦略的妥当性は検証していない。`recorded_chain_integrity=verified`を、それらの合格に読み替えない。

## 4. 算入契約で決める具体的な分岐

現行116を維持するので、次の両案ともseeded/strategic unresolvedを含む対戦はbalance算入不可。新方式の採用、人間/別AI選択による解決扱い、過去結果の変更はどちらにも含めない。

### 案A：事前に指定した対戦集合全体を評価対象にする（推奨）

まず既存固定デッキの組合せに対象を限定し、全席の判断方式は既存114/116/119を起点に版固定する案。A/414を使う場合は別途実験利用の承認を求め、promotionとは分ける。初期順は将来の未観測入力から生成し、鏡像を含む対応群を独立単位として事前固定する。

全予定対戦の実施状況・停止・除外・未証明を保持する。適格な完走対戦だけを後から抜き出した勝率等を、予定集合全体のbalance推定値として発行しない。除外や未証明が残る場合、全体のbalance結論を保留する。除外対戦を敗北/0点・代替標本にせず、未実施や不足を埋めるための都合のよい追加生成もしない。

利点：評価したいデッキ組と実際に述べる結論がずれにくい。代償：現行方針では全体結論に到達できない可能性が高く、証拠整備だけで結論を保証できない。正確な入力分布と規模はなお未承認であり、この提案だけで実行しない。

### 案B：事前に定義した「全判断が既存根拠で解決する対戦」の条件付き評価

除外規則を事前に定義し、全予定入力の処理状況を残したうえで、全判断の証拠、完走、独立入力等を満たす対戦だけの条件付き結果を目的とする案。116陽性を算入する案ではない。鏡像の片側だけ通った場合の扱いも事前定義が必要。

利点：一部の適格対戦について限定された結果を述べる設計は可能。代償：到達局面やデッキに依存する選別が入り、通常の全対戦・全カードbalanceへ一般化できない。この条件付き母集団を独立balance評価の対象として認めるか自体が未承認である。保存12runは全除外なのでこの案でも算入0。

**確認したい選択はAかBか。** 推奨Aはカードbalanceという目的に対して結論の対象を保ちやすいため。どちらを選んでも、それは次の具体的な算入契約・事前標本計画を作るための方針承認であり、新対戦の実行許可ではない。
