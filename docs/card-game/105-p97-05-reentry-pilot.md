## 3. 共通の統制手順

1. 各ターン開始時に時をそのラウンド数へ更新し、山札の一番上を1枚引く。
2. A R1に`A-011#1`、R2に`A-012#1`、R3に`A-013#1`を通常配置し、なかま3枠を満たす。
3. A R4に`A-014#1`を通常配置する満員交代を宣言し、旧なかま`A-011#1`を捨て札へ置いてから、空いた枠へ`A-014#1`を置く。
4. 同じA R4に時2を払い、`A-001#1`のどうぶつしょうぎで捨て札の`A-011#1`を手札へ戻す。山札上の`A-010#1`を見て一番上へ戻す。
5. A R5に回収した現物`A-011`を通常配置する満員交代を行い、`A-012#1`を捨て札へ置く。この再登場時に`A-011#1 → A-011#2`を記録する。
6. そのほかの任意行動は行わず、R10終了時にそだちを比較する。

なかま／こいびとの通常配置は合計で自分ターン1人までである。R4の満員交代とどうぶつしょうぎはそれぞれ通常配置1回とアクション1回であり、人物を2人配置していない。R5の再配置は別ターンの通常配置機会を使う。

このmaterializerは固定した2本のtranscriptを生成するものであり、任意のカード効果や意思決定を解決する一般対戦エンジンではない。

## 5. 現物IDと個体ID

`card_copy_id=A-011`は対戦中ずっと同じ現物を示す。一方、ゲーム上の個体は次のように変わる。

1. 初手・最初の配置・満員交代による捨て札・どうぶつしょうぎによる手札回収までは`A-011#1`。
2. 手札へ戻っただけでは`#2`を作らない。
3. R5に場へ通常再配置するeventで、`A-011#1`をretired、`A-011#2`をactiveにする。
4. 再配置eventより後のeventは、発生源・対象・支払いとして旧`A-011#1`を直接参照しない。
5. 最終盤面は`A-013#1`、`A-014#1`、`A-011#2`。捨て札は焦点札`A-001#1`と交代した`A-012#1`を含む。

transitionは次の1件だけである。

```json
{
  "card_copy_id": "A-011",
  "from_instance_id": "A-011#1",
  "to_instance_id": "A-011#2",
  "reason": "zone_change"
}
```

## 6. 予約を作らない境界

このP97-05 `single`の合法手順には、`A-011#1`を対象とする実在の予約札が含まれない。そのため`reservations`は空とし、個体IDの非移行を示すためだけの架空予約は作らない。

100で固定した「旧個体を参照する予約は新個体へ移し替えない」というvalidator unit testは維持する。今回completed記録へ接続したのは、実際の`#1→#2` transition、旧個体のretired化、後続eventによる旧個体直接参照の禁止である。予約非移行を実対戦で確認済みとは数えない。
