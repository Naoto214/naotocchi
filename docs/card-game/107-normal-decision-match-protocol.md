## 3. 判断機会と記録項目

各自の通常行動機会ごとに、その時点で確認できる合法候補を列挙する。通常行動を行わない選択も`pass`として必ず候補へ含める。

各選択は次を記録する。

1. 判断前の手札、場、時、そだち、予約。
2. 合法候補の全列挙。
3. 選択した行動。
4. 次点候補。
5. 選択理由のreason code。
6. 支払い、対象、連鎖、判断に使った公開情報。

反応機会、開始／終了処理、連鎖、ちょうせん中は01・02・06の区切りを優先し、通常行動機会でない処理を通常候補へ混ぜない。合法性を完全自動判定する対戦エンジンは作らず、記録者が正本を照合し、検査器は形式・不変条件を確認する。

## 4. 判断優先順位

上から順に比較し、上位の差がある時は下位を使わない。

1. 敗北または勝負の途中終了を回避する。
2. 自分のそだち100を維持する、または相手の100維持を阻止する。
3. 確定するそだち差を最大化する。
4. 時収支を最大化する。
5. 手札・盤面・予約の価値を最大化する。

ここまで同点なら、次の順で決める。

1. 支払う時が少ない。
2. 消費するカード枚数が少ない。
3. 対象候補を含む行動を一意にできる最小のcard copy IDを選ぶ。

相手の手札や山札順など、実際に確認できない情報は参照しない。自分が正当に知る手札、公開されたカード、公開盤面、公開履歴、適用済み予約など、その判断時点で確認できる情報だけを使う。

## 5. 判断理由語彙

機械可読JSONでは次を固定語彙とする。

- 敗北回避／勝負途中終了回避
- 自分の100維持／相手の100維持阻止
- 確定そだち差
- 時収支
- 手札価値／盤面価値／予約価値
- 同点時の低い時支払い／少ない消費枚数／小さいcard copy ID
- より良い合法行動がないため何もしない
- 正本文だけでは判断不能

理由の自由記述は補足に使えるが、集計はこの固定語彙で行う。

## 6. 終了と停止条件

通常はR10の両ターンと終了処理を終え、最終比較までを1戦とする。既存ルールによる早期勝利、勝負参加メイン離脱による途中終了も、その発生条件と結果を記録する。

次のいずれかで対戦記録を終える、または保留する。

1. R10最終比較が完了した。
2. そだち100の維持条件を満たし、既存ルールによる早期勝利が成立した。
3. 正本文だけでは合法候補または優先順位を一意に判定できない。
4. 記録hash、個体ID、予約参照などの完全性が壊れた。

3または4では勝者やカード強度を推測せず、判断不能箇所として保存して修正後に再開する。

参加メイン離脱による勝負の途中終了は、対戦全体の停止条件ではない。比較・勝敗・報酬なし、宣言回数・支払済みコストは戻さない既存ルールを記録し、その対戦を続行できる場合は次の通常行動機会へ進む。
