## 1. 結論・承認範囲

全体適格の目的を維持し、既存正本・許可情報・判断契約だけで必須選択を非fallbackにできるかを設計検討した。**初回たまご交換の7現物について、非fallbackで1枚を選ぶ既存の根拠は確認できない。** 公開確定量の一致は証明できても、異なる手札・山札下の現物を同価値とは証明できず、必須選択に適用可能な優越規則・完全同値tie-breakもない。

一般の戦略的優越が数学的に存在しないという主張ではない。今回許可された正本・契約の範囲に、選択を正当化する証明規則がないという結論である。情報をもっと詳しく記録するだけでは優劣の規則は生まれない。460の現行実行器の不可避116除外は解除しない。

[別版の機械可読設計](data/proxy-mandatory-choice-design-461/design.json)と[既存115からの参照抜粋](data/proxy-mandatory-choice-design-461/historical-reference.json)を保存する。**選択器・validator・policy実装や現行方式の置換は行わない**。設計受入例は未実行。200組のseed・400戦の入力は未生成、独立balance標本0、新方式未採用。114・116・454〜460・A初版・505・過去結果を変更しない。

## 2. 7候補について確定できること

01の初手5枚＋初回通常1ドロー、02のたまご追加1ドローにより、最初の必須選択直前は7現物。02は手札の1枚を山札下へ戻すだけで、種類・段階・時・能力の条件による候補制限を設けていない。01は開始のこの区間への別発動の割込みを認めない。初期盤面・予約も空。7枚すべてが候補であり、今プレイできないカードを候補から落とす理由はない。

比較入力は107/114の`public_and_owner_known_only`境界を守る。本人が正当に知る手札・カード本文・公開stateは扱える。**自分の手札も相手にとって公開という意味ではない。** 記録者が保持する未公開山札の全順序、相手手札、将来のドロー・相手の反応は比較入力へ渡さない。461は新しい情報公開や情報記憶の規則を追加しない。

初期手札集合をH={c1,…,c7}、未公開の山札残部をUとする。ciを選ぶ場合、手札から現物ciを移し、山札残部の下へ置く。cjの場合と比較すると、i≠jなら次の差が残る。

|項目|証明できる事実|証明できないこと|
|---|---|---|
|合法候補|7つの異なる現物。ciとcjは別候補|同名だから代表1枚へ縮約してよい、とは言えない|
|手札|Hからciを除く場合とcjを除く場合では、残す現物が異なる|枚数6が同じでも保持価値の同値・優越は不明|
|山札|不透明なUの後ろへ、選んだ現物を戻す。33→34枚|Uの内容・将来の引き・底の札の将来価値は推定しない|
|公開量／本人既知の枚数事実|初回のこの移動自体では時1・そだち20・空盤面/予約を変えず、手札/山札枚数の増減は候補間で共通|公開量が同じだから選択全体が同値、とは言えない|
|分類・段階・系譜|本文・現物ID・現在の個体と系譜を識別できる|メインを残す、低段階を残す、今使えない札を戻す等の優先順位は導けない|
|継続|開始処理の残存義務と、その後の発動/反応/通常行動を保持する必要がある|異なる手札で可能な行動まで同じ、相手がpassする、とは言えない|

枚数計算は移動整合性の説明で、114の許可fieldを増やすものではない。比較入力への利用は既存viewの許可範囲に限定する。

Uは不透明領域を指す記号であり、その内容を比較に使う表現ではない。現物移動の説明も旧instanceの使い回しを認めるものではない。個体・領域移動・追跡は07/98の既存規則に従う別の整合性証拠を要する。過去engineの保存stateを461で修正・追認しない。

異なる候補の組は7×6÷2＝21組ある。どの組も戻す/残す現物の差を持つ。これは記号上の組数で、21回の比較器実行・シミュレーション・証明PASSではない。共通の5現物が両手札に残る場合も、差分との依存まで証明せず自動相殺しない。

## 4. 非fallback根拠の適用審査

|根拠候補|既存の適用条件|初回7現物への判定|
|---|---|---|
|唯一合法|完全列挙された集合が本当に1件（454）|7件なので不成立。縮約・恣意的除外で1件にしない|
|正本が特定対象を一意指定|発生元のカード/ルールが対象・枚数・順序を一意に定める|02は手札1枚を選ぶ指定で、どの1枚かは定めない|
|114優先順位/Pareto|通常行動の適用範囲と全比較証拠|mandatoryへ無条件移植不可。仮に共通の公開量だけを見ても手札差の順位は得られない|
|116限定安全配置|通常行動の人物配置対pass、6条件等|戻す必須選択は対象外。無料/安全という語だけでは適用不可|
|既存の完全同値tie-break|当該判断種別に適用可能な契約＋全比較項目の同値証明|どちらも未充足。小さいIDや昇順先頭を選ぶ根拠にならない|
|445Aの現物・依存同値|同じ現物/領域/対象/期限/依存と境界を保持|ci/cjの手札と山札下の差が残る。Aは未採用かつmandatory接続も未承認。証拠形式を参照しても選択許可にならない|
|116 seeded|完全合法集合、情報制約、継続/記録整合を満たす|既存の診断的継続根拠。非fallbackやbalance適格の根拠ではない|

全21組の価値関係を`equal`や0点として埋めない。「既存規則による順位を証明できない」という不足を保持する。候補順、ID大小、種類別優先、時の大小、手札の多様性、重複枚数を代わりの順位に使わない。

## 5. 再利用する別版契約案（証拠審査のみ、実装なし）

設計ID `mandatory_choice_basis_design_461.v1`。選択を必ず返す関数ではなく、**適用範囲を持つ根拠があるかを検査する契約**とする。runtimeの新resolution_modeは今回定義/登録しない。

### 入力と責務

1. **発生契約**：source/rule hash、発生eventまたは解決内位置、actor、phase、選択数、順序の意味、移動元/先、後続義務。通常行動とmandatoryを区別する。
2. **許可view**：本人既知/公開の区別、参照可能field、opaque領域。監査用全stateは別。hash一致だけで情報利用を正当化しない。
3. **完全候補証拠**：現物・個体・対象・組合せ/順列と除外理由。候補stable IDは識別であって順位ではない。欠落候補や合法性不明は証拠不備。
4. **確定遷移の記述**：選択後に正本から一意に言える移動/支払/公開結果と、途中で止まるべき未知・次の選択・response義務。将来のdrawやpassを補わない。
5. **選択根拠参照**：正本が対象を指定する根拠、完全singleton、または当該mandatoryに明示的に適用できる既存比較契約。単なるcallableやcallerのverified=trueを権威としない。

### 出力と処理順

|状態|返すもの|継続・評価|
|---|---|---|
|証拠不備|不足/矛盾/禁止情報の参照。selected=null|116にも送らず停止。合法性不明を抽選で隠さない|
|唯一合法/正本の一意指定を証明|候補IDと完全性・適用根拠の証明案|将来の非seeded記録経路の設計対象。現在の保存recordは変更しない|
|既存比較契約が適用可能で全候補に対して一意を証明|契約版・適用前提・必要比較・選択根拠|実装/記録接続の別承認が必要。今回は該当mandatory契約を新設しない|
|複数合法で一意根拠なし|selected=null、候補全件、未比較の差・残存義務・不足契約|戦略的未解決。116の継続条件を満たす場合の別途fallbackは可能だがbalance除外|

「既存比較契約」は拡張口の説明であり、空の登録欄へ新比較器を自由に差し込む許可ではない。461時点で初回egg_exchange_bottomに登録可能な優越/tie-break契約は0。非fallback選択0という新実測値ではなく、設計上の適用根拠がないという意味である。

0候補はsingletonではない。発生元が実行不能部分のスキップを定める場合はその自動処理として別途検証し、そうでなければ証拠/裁定不足として止める。任意の能力を発動するかという選択と、発動後に要求されるmandatoryも混ぜない。

選択根拠の証明と、合法な遷移、全機会網羅、対戦/鏡像群の適格、予定集合の算入は別層。将来singletonを正しく非seeded記録できても初回7候補はsingletonにならず、400戦の条件は解消しない。

## 7. 設計受入例（テスト未実行）

- 完全集合7件、公開枚数/時が等しい、手札現物が異なる → 複数合法・一意根拠なし。
- 同名別現物2件 → 未証明の同値縮約を拒否。
- 7件のうち今使えない札6件を落として1件 → 候補完全性違反。
- 完全集合1件、発生契約と情報境界が有効 → singleton根拠の証明案。過去seeded記録の除外は維持。
- 正本にない「低いID」「高コストを戻す」「メインを残す」 → 未承認比較意味論として拒否。
- 比較入力に保存山札全順序を追加 → 情報境界違反。
- hand_bottomの証拠に発動前stateを使用し、直前drawを脱落 → 対象stateの結合不足。
- 候補pairの共通公開量だけを一致させた証明 → 現物/継続残差を保持し全体同値を拒否。

## 8. 停止地点と選択肢

**現在の制約のまま、初回7候補を非fallbackで選んで全体適格へ進む設計は正当化できない。** 同じ監査や再生を繰り返してもこの選択根拠は増えない。ここで停止する。

|選択肢（未採用）|必要な変更・承認|限界|
|---|---|---|
|A 制約を維持して400戦を保留|現状を維持。必要なら残りの証拠基盤だけを別途進める|新しい価値意味論は不要だが、初回の非fallback選択は解決しない|
|B 必須選択の新しい比較意味論を、限定範囲で設計することを許可|比較の目的・適用範囲・許可情報・優越条件を新たに承認する必要。具体的な価値点/優先順位/同値化は未提案・未採用|選択根拠と将来policy版が変わる。400戦全体適格は保証しない。今回の「既存契約だけ」という制約の変更が必要|
|C 評価契約を別版として設計し直す|未解決を含む固定policy下の評価等へ目的/算入条件を変更する別承認が必要。116と過去評価は保持|現行458/459の全体適格とは別の問い。今回はユーザーが維持を選んだ目的なので実施しない|

未証明同値化・ID順・カード価値点・期待値等を「実装上の都合」で採用しない。現時点ではAの保留状態を維持し、B/Cへ進むなら明示的な範囲変更を確認する。カード追加の保守性改修・汎用エンジン化へも広げない。
