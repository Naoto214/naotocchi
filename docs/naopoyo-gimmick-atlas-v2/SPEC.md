# ひとマス共通仕様 VERSION 2（設計案・正式ゲーム未変更）

## 目的と保護境界

必要なものだけを、美しく、分かりやすく。現行の良い絵を残し、造形を増やす前に意味を整理する。PR532のV1は `afd94151222a4c30d2bebdfdb8240c95eec70d94` と既存v1ディレクトリにそのまま保存。PR523 V2も変更しない。今回作るのは資料・比較ページ・データ契約・検証用例だけで、本編図鑑、エディター、投稿機能、ステージは実装しない。

比較方式は「現行を描き直す」「画像だけを並べる」「現行描画関数を再利用し同条件で比較」を検討し、3番目を選ぶ。現行のまま使う項目まで新作に置換しない。A/B/Cは採否と別軸。推奨でも未実装ならCから技術検証が必要。

## 64候補と45素材＋2能力

`candidates.json` はV1の50候補を保持して51–64を追加。推奨41／保留16／不採用7。現行維持A8／見た目改善B11／仕組み再検討C45。Cには新規構想を含み、「45件を描き直す」という意味ではない。

`catalog.json` は45の意味単位。壁／固定ブロック／岩盤は壁へ統合、水面／水中は水へ統合。色・章・背景・濡れた見た目を別収集項目にしない。飛行と水中移動は「能力」2項目として別章に載せ、配置可能なタイルとして扱わない。45素材中の保留品は出荷パレット・発見総数に入れない。NPCもシナリオ専用で通常エディターパレットへ入れない。

全素材は固有ID、候補参照、名称、分類、表示renderer、現行対応、1マス寸法、接地アンカー、連結family、動作範囲、作動条件、状態、リンク、実装状況、発見条件、配置可否、初登場案を持つ。初登場案と現行使用面は別。例えば数値門の12面はV3での教材順で、V2の初登場を断言するものではない。

## 1マスとレイヤー

座標は整数x,y、原点左上、既定8×8。表示ローカル座標u,vは0–1、1マス＝1 footprint。各セルは `ground`（床）か `solid`（壁）のどちらか最大1。水等の`medium`、風等の`field`、`fixture`、押箱等の`object`、`decoration`は別層。NPCは専用`npc`占有。

- 主体輪郭はu/v 0.06–0.94に収める。接地はNPCのみ既存アンカーを維持。発光や泡の微粒子などは表示spillを別指定し、隣の条件札を覆わない。
- 移動足場は一つの足場部品が経路上を移動する。経路マス全部に足場本体を複製しない。レールは補助表示。
- 水・波の画は上下左右4ビットの接続マスク（N1/E2/S4/W8）。同family・同layerのみ連結。水面は上側非水の端、内部は水中。物理的な深さを勝手に追加しない。
- 波は位相groupと経路indexを持つ。隣接絵がつながることと、前線が届く手番は別データ。波前線は1マスずつ進む候補。数値や文字の代わりに泡縁と流線で方向を示す。
- 地中二層は保留。将来のlayerキーは予約しても本編の落下・接触へ混ぜない。
- 装飾はcollision=false / portsなし。草や灯りは通行・出生・出口条件に影響しない。木を置いて塞ぎたい時は壁＋装飾の合成を明示。
- `scenery.lamp`は常時照明、`fixture.signalLamp`は入力を表示する装置。信号灯は出力ポートを持たず解除条件の自己循環を作れない。

## 見た目

床プレートは既存の楕円・色・位置を保持する。記号の整理だけを別レイヤーで提案。扉は格子の開閉、記憶式は留め爪の固定、崩れる床は亀裂→欠損、大岩は不均一な稜線と少量の接地影。周囲に不要な石柱・枠は追加しない。

星は出口だけ。条件なし出口の数字・ALLは消す案、条件付きは単体の重さと明記。盤面内には短い数値、図鑑説明で体数との違いを示す。正式第1章へは今回適用しない。

色は対応関係、形は機能。1組は記号なし。複数組は同色＋溝数（1/2）か縁パターンで対応し、最多3組。可読性のため輪郭を1–1.5px相当、最小隙間2px相当確保。36px/48px実寸と8×8上で判定する。非選択の薄い装飾は仕掛けより低コントラスト。

## 能力と正式キャラクター設定

種族の画像や成長名と、パズルでの能力採用は別の承認。旧能力比較室の「ちょう06・セミ06・カブトムシ05・クワガタ05から飛行」は**候補実装**で、本編承認済みとはしない。飛行速度・浮力強度などの多段階能力は新設しない。条件が同じなら動作は同じ。分裂で飛行条件を失う場合は既存重力を同じ操作内で処理する。旧比較室のBFS分裂やトゲ支持は移植しない。

水族は旧Worldの魚限定が実装根拠。他のかめ・ペンギン・かえる等の範囲を画像から推測して採用しない。水面と水中は表示上の境界。潜水専用ボタンは追加しない。土中の適合種族は未決。乗物は運搬と積載が解法を変える場合だけ継続検討し、足場の見た目替えなら07へ統合する。

## ひとマス図鑑の発見

将来の本編では、通常プレイの盤面が正常ロードし、対象が初めて実際に表示された時に `visible-in-play` イベントを発行。壁・床も対象。隠し部屋内・未表示の土中・未解放面は未発見。失敗やUndoで発見を取り消さない（知識は消えない）。おてほん・編集・比較ページ・テストプレイは発見の対象外。クリア時だけ登録する仕様ではない。

表示は未発見「？？？」と抽象影。未発見の機能名・所属章・初登場番号でネタバレしない。発見済みは画像、名前、短い一般説明、初遭遇面、状態見本。解法や座標・順序は書かない。状態ボタン、任意再生、OSの動きを減らす設定に対応。色違い・接続端・状態変化はcatalogIdにまとめる。

## 保存契約（今回本編へ接続しない）

例は `save-example.json`。将来は既存セーブの既存キーを変更せず、任意の `extensions.naopoyoAtlas` を追加する案。実装前に現行保存形式の正式スキーマへ対応付ける必要がある。別namespace移行を選ぶ場合も既存キーへ上書きしない。

- schemaVersion=1 / catalogVersion / discoveries{catalogId:{firstStageId, firstSeenAt, source}}。
- 旧保存に拡張がない場合は空集合。クリア履歴だけから未遭遇品を一括発見にしない。初回再プレイで登録。
- 同じcatalogIdを再発見しても最初の面を維持。重複イベントは冪等。日時が不正ならnullにし面IDは残す。
- ID改名はalias→正準IDの写像で統合。廃止品はdeprecated一覧に保持し消さない。未知IDは隔離して保持、画面へHTMLとして展開しない。
- データ破損時は図鑑拡張だけを退避。ゲーム進捗を巻き戻さない。旧アプリが拡張を落とすリスクがあるため、実装時はnamespace別バックアップと二世代読み書き試験を必須にする。
- 端末間統合はID集合和。双方に同IDがある場合は有効な最古日時、日時なし同士なら既存ローカル値を維持。「最初の面」は端末間では参考値と明記する。

## 将来のエディター契約

`stage.schema.json`と`stage-example.json`は保存形式の提案、ゲームデータへの直接入力ではない。盤面8×8、registryVersion、rulesetVersion、instances、links、startActors、exits、metadataを持つ。instanceIdは面内一意、catalogIdは共通素材参照。startActorsは最大7、段階1–8。固定Dを指定し、ユーザーコード・任意式・外部URL・独自スクリプトを受け付けない。

編集のUndoは制作履歴、本編Undoは実行状態で分離。テスト開始時に編集データをcloneし、戻ったとき元配置を変えない。テストのクリア証明はステージ内容ハッシュ＋ルール版＋初期状態＋操作列。1マス移動単位と選択の扱いを固定する。変更したら証明を破棄して再テスト。

接続はタップで送信元→受信先を選ぶ将来案。ポート型boolean／event／phaseを検査し、合図灯は入力専用。ANDは明示ノードの宣言型パラメータ。自由なコードを書かせない。自分自身、型違い、無参照、即時循環、無限連鎖は公開前に拒否する。

公開前バリデーション：寸法／座標／上限／未知ID／保留品／合法レイヤー／開始位置／出口／ワープ対／足場経路の壁交差／NPCテンプレート／リンク型。静的検査合格だけではクリア保証ではない。作者の解法を同じエンジンで再実行し出口成立を確認する。難度は最短手数だけで採点しない。

オンラインは未実装。将来はサーバー採番stageId、immutable revision、作者、内容ハッシュ、ルール版、検証済み操作列を保存。公開後の編集は別revision。お気に入りはstageId、クリア・評価はrevision単位。サーバー再検証と投稿上限、通報・非公開化、著作権を侵害する外部画像の持込禁止を設計する。HTMLやコードを実行しない。本人の既存育成セーブ、恋人、連絡先等を投稿へ混ぜない。

発見状況は通常プレイ図鑑の表示権、エディター公開権とは分離する。未発見素材を作者が配置できるかは将来のUX決定。データ契約上は `editor.eligible` と `discovered` の別属性なので再制作不要。

水・水面・波前線・水中障害、風・上昇気流・失飛行、合図灯を教材順に再配置。土中と専用車船は保留し、無理に100面へ押し込まない。第1章を変更せず第2章V3は未実装。V3着手前に、保持式床の形維持、重量/記憶との識別、星出口の共通化、岩の無文字化、18協力前後の独立課題、19救出＋運搬＋後半課題、17/20の固定足場による上方出生を引き継ぐ。

## 契約レビューで確定した補足

- `board.gravity`を必須化。`routes`に経路マスとone-shot/ping-pong、`effectGroups`にmemberIds・routeId・位相offset・periodTurns、`logicNodes`にAND/OR/NOTを持つ。空配列も明示する。重力や足場経路を資料外の暗黙設定にしない。
- 各素材の`ports`はポートID／direction／typeの配列。床・重量床・記憶装置はboolean出力、扉・足場・合図灯はboolean入力、周期装置はbooleanとphase出力。NPCはready入力とhelped event出力。論理ノードの入力はin0…inN、出力はout、型boolean。linksはfrom/fromPort/to/toPort/typeを参照。
- 描画接続は`visualConnectionKey`が同じときだけ。水・波・泡のfamilyがwaterでも異なるID同士の線画を自動接続しない。作用groupは`effectGroupPolicy`で別に指定。水流・波・泡の基底には水が必要。
- 同一マスのfieldは1つまで。波＋水流の同時作用は禁止し、隣り合う別マスで組み合わせる。decorは最大1、fixtureとobjectは原則共存不可、NPCは他のfixture/object/solidと共存不可。groundとmediumの共存は水底を示し許容、solidとmediumは水中岩として許容するがactorの初期位置にはできない。
- 論理式は有限DAGだけ。遅延周期の状態を使う場合も通常リンクへ循環を書かず専用phase装置を参照する。移動足場のrouteは同じ物体を表し、routeセル数分のactorや足場を生成しない。
- 初期publicエディターschemaは主人公dogのみの安全なsubset。能力・土中・NPCは将来のschema/rulesetの明示更新で解放し、既存面を暗黙に読み替えない。保留機能の予約IDは出荷資格を意味しない。
