## 1. 結論

現行コードは、正本の最終仕様へ部分的にしか到達していない。主な差分は次の9群。

1. 通常装具カタログが旧14種のまま。
2. 使い切りカタログ・発動処理が旧V1/V2途中案のまま。
3. 通常ミニゲーム報酬が旧2コイン／大成功5〜11コインのまま。
4. スターバッジが通常成功2→4だけの旧効果。
5. Quickが通常ミニゲームの結果処理へ流れ、育成・通常報酬・スターバッジの影響を受ける。
6. 今日のチャレンジが旧ストリーク・直接コイン・成長2倍・シール報酬を残している。
7. 誕生日、段階変化、そだち節目、伝説、環境イベント、シールお題、留守のおみやげ等からコインが発生する。
8. 伝説遭遇がコイン・ごきげん100・せいちょう+8・おとろえ-25をまだ付与する。
9. テスト群が上記旧仕様を多数「正しい挙動」として固定している。

したがって、価格・文言だけを置換する実装では不十分。セーブ互換を守りながら、カタログ、挙動、経済、Quick、イベント、テストを順番に切り替える必要がある。

## 2. CIベースライン

監査HEADで確認したワークフロー:

- Home layout: SUCCESS
- Runtime smoke test: FAILURE

Runtime smoke testは571件中570件成功、1件失敗。失敗は `tests/quick-mode-test.cjs` の
`every quick game can be solved from its own target hint and each kind of input is covered`。

失敗例:

- `mole (Lv4) could not be solved from its target hint`

原因候補をコードまで追跡すると、`quick.js` の `mole` はLv4で必要成功回数が3回になり、ランダムなおとり（🌷）が出ている間は正解ターゲットを提示しない。レベル上昇で制限時間も短くなるため、おとりの引き次第で正解を3回出す前に時間切れとなる組み合わせがある。今回のdocs-only正本更新で生じた失敗ではない。

実装開始前に、この既存不安定要因を独立して再現・修正し、基準テストを緑にしてからItems V2差分へ入るのが安全。

大きな未実装:

- スターバッジ: 通常成功30→90、大成功60→180。現行は通常成功2→4だけ。

削除対象の旧効果:

- `energy1` げんき消費軽減
- `hat` 変身メーター増加

## 5. 装具イラスト／表示

現行 `ITEM_ILLUSTRATIONS` は旧商品に対応しており、`bowtie/ribbon/scarf/glasses` の見た目も旧商品そのもの。

そのため、名称だけを `おべんとうばこ / おもちゃばこ / きゅうきゅうばこ / ゲームパス` に変えると、商品名と絵が食い違う。

実装前に次の方針を固定する必要がある:

- 新4商品用の専用イラストを用意する（推奨）
- または既存の汎用ケアアイコンを暫定利用する

旧4商品の絵をそのまま新名称へ流用する案は採らない方が安全。

## 7. コイン経済

正本の通常コイン発生源は、通常ミニゲーム、Quick20/20、うそつきしょうぶ、ラッキーコインの4系統のみ。

現行コードで削除対象として確認できた発生源:

- 段階変化: +100
- 誕生日: `(3 + maxSodachi / 25) × coinMultiplier`
- そだち節目: `SODACHI_PERKS[].coins`
- 伝説: `LEGEND_COIN_GIFT × coinMultiplier`
- 中年／年齢ストーリーイベント: `ev.money`
- 環境イベント: `m.money`
- シールお題: `task.reward.coins`
- 留守のおみやげ: 5分につき1コイン、最大12
- 今日のチャレンジ: ストリーク報酬の直接コイン

これらのコインだけを除去し、イベント自体・記録・コイン以外の正本で残す要素は不用意に削除しない。

## 9. Quickモード

現行コメントとテストが明示する通り、`quick-run` / `quick-solo` は通常 `startMinigame/finishMinigame` を通る。

現行テストは以下まで旧仕様として固定している:

- Quick終了後に通常ゲームのげんき消費
- 通常ゲームのせいちょう
- 通常ミニゲームコイン
- StarによるQuickコイン増加

正本ではすべて不可。

必要な最終挙動:

- 育成パラメータ変化なし
- げんき消費なし
- 途中終了0コイン
- mixed Quick 20/20のみ100コイン
- Star対象外
- Quickの記録・実績は維持

`quick-solo` は正本の「20/20で100」の対象として明記されていないため、コイン報酬0として通常育成から切り離すのが正本と整合する。もしsoloにも別報酬を付けるなら追加設計が必要。

## 15. 実装計画へ進む前に必要な判断

### A. 通常装具の旧所有

販売終了4品 (`flower`, `energy1`, `hat`, `crown`) は旧購入価格で一度だけ返金する案が安全。

`glasses` は意味が別物になるため、旧サングラス所有者へ360コイン返金し、新ゲームパスは未所有から始める案を推奨する。

その他9系統は中核役割が同じなので、既存所有をそのまま新商品所有として維持する案を推奨する。価格上昇分を追加徴収しない。

### B. 新4装具のイラスト

`おべんとうばこ / おもちゃばこ / きゅうきゅうばこ / ゲームパス` は旧 `bowtie / ribbon / scarf / glasses` の絵をそのまま使わず、専用イラストへ置き換える案を推奨する。

### C. 旧使い切り在庫

基本方針は既存移行案を継承:

- 同じ意味に近い在庫だけ1:1維持
- 意味が大きく違う旧安価アイテムは旧購入価格で一度だけ返金
- 旧在庫を新しい高額チケットへ勝手に変換しない
- 旧Lucky Coin在庫は新Lucky Coinへ1:1維持し、発動待ちの旧2倍予約は在庫へ戻す
- 旧ゆめ在庫は対応するたまごへ維持
- 旧いのちのばんそうこう／へんしんのこかがみの扱いは、最終移行表で明示する

この3点を確定後、placeholderなしの実装計画へ落とし込む。
