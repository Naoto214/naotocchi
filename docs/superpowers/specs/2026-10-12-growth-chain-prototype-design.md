## 構成案の比較
A. 既存ミニゲームfactoryを拡張: UI再利用は容易だが本編依存と既存挙動への影響が大きい。
B. 独立ES modulesのengine + browser UI + Node runner: 推奨。試遊と統計が同じ裁定を使い、既存コードを変更しない。
C. 計算専用runner: 統計は早いが操作性・テンポの検証ができないため、今回の全目的は満たさない。

Bを提案する。新設 prototypes/growth-chain/ 以下に実装、テスト、再現盤面、測定結果を閉じ込める。
既存package.json・lockfile・Vite設定・本編HTML・既存ゲーム登録には変更不要。
外部ライブラリや画像資産は初版に追加せず、種類記号＋色＋01〜08で識別する。
既存本編のデータ型を共通化するためのリファクタリングも対象外。

## 固定するユーザー指定
- 基本盤面6×12、比較盤面7×12。
- 基本5種類。通常落下は01の2体セットで左右移動・回転可能。
- 基本バッグは20体、各種類4体。NEXTは3組。
- 同種・同段階の上下左右接続で進化。2/3/4/5体で+1/+2/+3/+4段階。
- 最高08。08を超える進化分は得点対象。08同士の接続は寿命消滅。
- 進化、重力、再進化で自動連鎖。同時成立した進化は同一連鎖段階。
- 普通/銀/金/プラチナ卵は01/02/03/04を任意種として配置。ストック上限なし。
- 08消滅時の連鎖数で卵ランク上昇。
- 通常へんしんは単体を同段階の別種へ、大は指定種全体を別種へ。
- 共通ゲージ。通常1本、大3本。

## 未決定ルールの比較候補
下記は実験候補であり、採用済みルールではない。各実行・リプレイに全設定を保存する。
未知の値を暗黙の既定値にしない。設定を列挙し、UIに「検証用仮設定」を表示する。

|論点|比較する案|測定前の仮説|
|---|---|---|
|進化位置|連結内の最下段→同段左優先 / 今回操作した軸個体優先→不在なら最下段|最下段は全操作に共通化でき、軸優先は狙いやすい可能性|
|2体セット内進化|ロック後に盤面とまとめて判定 / セット内を先に合成してから盤面判定|前者は例外が少ない。別設定として比較|
|候補競合|最大連結成分全体を一括 / 最大5体の互いに重ならない接続集合を決定的順序で採用|全体一括は単純だが6体以上の扱いと組み合わせる必要|
|6体以上接続|全体を消費して+4上限 / 5体まで消費し残りを次波へ|余剰消費の得失と予測可能性を比較|
|だいへんしんの位置|通常と共通の最下段 / 変更個体優先、複数なら最下段|種類の書換えは全体同時、後に進化判定。走査順依存を禁止|
|寿命消滅の種類条件|同種08のみ / 種類を問わず08接続|ユーザー指定の同種ルールを基準候補にしつつ曖昧さを明記|
|卵ランク境界|連鎖1/2/3/4以上 / 1/3/5/7以上で昇格|後者は上位報酬が希少。どちらも未確定|
|卵獲得個数|消滅グループごと1個 / 消滅個体2体ごと1個|大量08消滅時の資源増加を比較|
|ゲージ獲得|消費個体数ベース / 実際の成長段階差ベース|1本の必要量8/16/32を感度分析。開始0本、上限なしを実験条件として明記|
|得点|消費個体数+超過段階の線形評価 / 連鎖倍率付き|生スコアは異なる式の間で順位比較しない|
|ゲームオーバー|盤外ロックで終了 / 連鎖解決後のスポーン阻塞で終了|盤外個体の黙殺は禁止。後者は隠し行を明示的に管理|
|卵の配置|上から列へ落下 / 空きマス直接配置後に重力|配置自由度による戦略差を区別|
|アイテム使用タイミング|落下前の安定盤面で使用|初版の実験境界。連鎖途中割込みは別仕様が必要|
|4/6種類バッグ|各種類4体=16/24体 / 20体固定で不足・余剰枠の種類をバッグごと公平に巡回|主比較は各種4体。固定20体は感度分析として分離|

候補を無制限に組み合わせるのでなく、一変数ずつ比較し、その後に主要な相互作用を検証する。
軸個体等の優先判定に個体IDを利用し、重力移動後も一貫して追跡する。
進化後の個体ID継承と優先情報の寿命はルール設定で明示し、前の手の「操作個体」が次の手を優先しないようにする。

## エンジンの処理と監査
状態: 盤面、操作中セット、NEXT、バッグ位置、乱数状態、卵4種ストック、ゲージ、得点、手数、終了理由。
安定状態から操作を受け、ロック、設定に応じた重力、同一snapshotから候補発見、競合解決、同時適用、重力、次波の順で処理。
新しく成立した進化を同じ波へ混ぜない。独立した2グループの同時進化は1連鎖。
各波についてbefore、候補、採用/不採用理由、位置、成長差、超過、08消滅、報酬、afterを記録する。
連鎖解決中の操作を拒否し、UIの演出待ち時間と裁定を分離する。
変換で段階を変えない、ストック不足時は不変、盤外・不正種・不正段階・異なる設定のリプレイを検証する。
1波ごとに総個体数が減少する方式では盤面個体数による終了性を確認する。
競合方式を変えても、同じ個体を同一波で重複消費することを禁止する。

- 自動落下、一時停止、左右、回転、ソフト/ハードドロップ。スマホ用ボタンとキーボード。

## 再現性と比較実験
乱数はバッグ用と方策の同点選択用を分離する。描画・演出はルール乱数を消費しない。
同じ種類数の比較は同じバッグ列を利用。種類数が異なると同一ピース列にはできないため、対応seedの比較であって完全同一入力ではないと明示。
乱数方式/version、設定、seed集合、手数上限、方策version、操作列、開始盤面、終了hashを保存する。

主比較: 種類4/5/6 × 幅6/7、高さ12、各種4体バッグ。
方策は合法手から一様選択と、NEXT3の情報範囲内の固定先読み方策を分ける。隠れたバッグ内容を利用しない。
単純方策の低成績を人間のゲーム性の限界と解釈しない。
各条件200対応seed、通常落下500組までを初期計画とし、実行時間を記録する。
ゲームオーバー率は「500組以内」の率。生存打切りを終了扱いしない。
連鎖頻度は通常落下1組あたりに加え、全操作1回あたりも報告する。
08到達率は少なくとも1回08を生成したrunの割合とし、08消滅率と分ける。
2/3/5連鎖頻度、最大連鎖、08初到達手数、占有率、終了手数、報酬収支も報告。
比率の95%信頼区間と対応seedごとの差を保存。追加seedを選ぶ場合は結果を見て良いものだけ選ばない。

道具比較: 通常のみ / 卵のみ / へんしんのみ / 両方。
自然獲得による比較と、資源を同量付与する局面比較を分離する。初期資源付与実験を自然獲得成績に混ぜない。
同じ通常落下列を保持し、アイテム行動ではバッグを進めないという実験設定を明示する。
短期の自動方策だけで「長期戦略性が証明された」とは言わない。
温存/即使用、単体/全体、NEXTを待つ選択に異なる結果が生じる再現局面を用意する。
