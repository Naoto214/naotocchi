# PR #552: Home selected name 再開検証

基準HEAD: `8c7a000a96e7975ed971b73c7983ab4397279b03`。main: `105dba519890c2dc17e94a8c9d1b7679720fddf3`。

## 失敗の切り分け

最新HEADの [run 43585310048](https://github.com/Naoto214/naotocchi/actions/runs/43585310048) はChromium成功、WebKitの28住民ケースで `No visible grounded destination for pointer`。旧HEADのChromiumでも同じ種類の失敗を確認。ログと両エンジンの失敗画像を保存した。このテストはAudioContextを無効化するため、BGM出力の失敗ではない。

元の試験は壁時計を再開しながら入力座標を検索し、表示モデルにはcrypto由来の独立乱数があった。読み込み時間とプロトコル待ちに応じて住民の移動・重なりが変化する。失敗の再現では実ドラッグは受理されたが、後続の移動先が見つからない。別の再現を1ワールド単位で走査すると空き点51個のうちテストの12単位条件を満たす点は0個、実モデルで移動可能な3単位以上の点は37個だった。この結果は任意の密集配置の操作性を保証するものではないが、今回の失敗がゲームの移動処理の破損を示すという根拠にはならない。

## 修正範囲

`tests/home-selected-name-browser.cjs`のみ。使い捨てQA出力の表示モデルに既存のrandomオプションでseed 521を渡す。起動前から時計を固定し、画像・フォントを読み込んだ後に一定の実アニメーションフレームを進める。時計の停止先には起動前の空ページで1日の余裕を設け、1.5秒のプロトコル遅延でも両エンジンが停止できることを確認した。

実touch/mouse入力、住民数1/2/2/3/28、縦横切替、移動受付、通知との重なり、保存・再読込、既存16行のassertionは維持。座標選択ヘルパーの距離条件も変更していない。ゲームの配置・当たり判定・セーブ形式・音声経路・音源は変更していない。
