## 5. 今わかった不整合 — **歩けない線が地図に出ている**

見落としやすいが重要な点:

```
いまの 100% 世界地図 = 13 本の線
そのうち countryside|river_lake は gate が無い = **絶対に歩けない**
```

`worldLinksFrom()` は `mouths` の両端 spot を見つけたかどうかだけで判定し、
`gate` の有無を見ません。そのため `countryside.riverbank` と `river_lake.bank` を
見つけると、**歩けないのに世界地図に線が引かれ、探索率の分母にも入ります。**

Phase 3B-4 までは未実装が 3 本あったので「これから実装される線」と読めましたが、
**今や未実装はこの 1 本だけ**。放置すると「地図に線があるのに永久に歩けない」
唯一の例外として残ります。**保留継続がいちばん悪い**理由がここにあります。

## 7. 地理的必然性 — 阿智型の山村と天竜川型の大水系

- `countryside` は**阿智型の山村**。棚田と水車があり、水は山から下りてくる支流。
- `river_lake` は**天竜川型の大水系**。谷の大川とその源流の湖。

正本 `why` は「山里の 水車と たなだの 水は、やまから おりる 支流。それが たにの
おおかわへ 合流する」。**水系の理屈としては正しい。** 山村の水は確かに大川へ注ぐ。

**しかし「水が合流すること」と「人が直接歩いて行き来すること」は別です。**

- 支流が大川に合流する地点は、**谷の中**にある
- その谷は、地図上では `forest` の位置にある
- つまり「支流を下って大川に出る」体験は、**forest を通る体験そのもの**

現在の `countryside|forest`(2.02) と `home|forest`(2.20)、`home|river_lake`(1.76) が
すでにその道筋を短い 3 本で表現しています。直接線はこれを**飛び越して**しまう。

### 4 案の評価

| 案 | 評価 |
|---|---|
| **A. 直接 connection を残す** | ✗ forest を 42.9% 貫通したままでは不可。項目 7 の条件（forest と矛盾しない世界線）を満たすには、線を大きく南へ迂回させるか forest の楕円を縮めるしかなく、**どちらも「この 1 本のために世界地図の形を変える」ことになる** |
| **B. 削除する** | ◎ 連結性は維持。分母 13→12 は実データで確定。ゴースト線なし。`forest|snow` の前例あり。**未実装 0 本になり Phase 3B が閉じる** |
| **C. 将来 non-region geography として再設計** | △ 「支流 → 谷 → 河岸」は魅力的だが、それは**まさに今 `countryside|forest` + `home|forest` + `home|river_lake` が担っている**。別物として足す必然性が薄い |
| **D. 保留継続** | ✗ **いちばん悪い。** 5 章のとおり「地図に線があるのに永久に歩けない」唯一の例外が残り、global world 設計にその矛盾を持ち越す |

## 8. forest の意味（項目 10）

世界地図で 3 地域を並べると:

```
countryside (−1.30, −2.10)
        ↘
         forest (0.40, −1.00)      ← ちょうど 間に ある
              ↘
               river_lake (2.55, 2.10)
```

直接線は forest を **飛び越す・横切る・意味を弱める** の 3 つすべてに当たります。

- **飛び越す**: countryside → river_lake が forest を経ずに成立してしまう
- **横切る**: t 0.16–0.59 の 43% を forest の内側で過ごす
- **意味を弱める**: forest は「生活圏の中心にある森」で、
  `countryside|forest` `home|forest` `forest|mountain` の 3 本が集まるハブ。
  直接線はそのハブ性を削る

**forest は世界の交差点です。** そこを通らずに東西を抜ける近道を作るのは、
交差点を作っておいて脇にバイパスを通すようなものです。

## 12. global world への影響（項目 16）

これは regionOrigin / global world 設計前の**最後の connection 判断**です。

将来すべてを 1 つの座標系に載せたとき、各 connection は
「その座標にその道が実在する」と説明できなければなりません。

- 他 11 本: region と region のあいだの空白を通る。**説明できる。**
- `countryside|river_lake`: **forest の内部を 43% 通り抜ける。**
  1 つの座標世界では、これは「森の中を突っ切る道」になります。
  しかし正本の説明は「支流が大川へ合流する」であって、森を抜ける道ではない。
  **座標と説明文が矛盾したまま global world に持ち込むことになります。**

`forest|snow` を削除したのと同じ判断基準を、同じ理由で適用すべきです。

## 13. 推奨結論（項目 14）

> # **削除を推奨します。**

根拠を 5 点に絞ると:

1. **全 connection 中で唯一、他 region を貫通している**（forest 42.9% / home 7.1%）
2. **最長（5.70）で、平均+1.5σ（5.49）を超える唯一の値**
3. **削除しても連結性は変わらない。** 代替経路が 3 通りあり、
   中継 region をどれか 1 つ落としてもまだつながる（Phase 3B-4 の成果）
4. **保留継続は最悪。** 未実装がこの 1 本だけになった今、
   「地図に線があるのに永久に歩けない」唯一の例外として残る
5. **`forest|snow` に同じ判断を下した前例があり、削除の副作用は検証済み**
   （ゴースト線なし・旧セーブ無害・分母 13 → 12）

削除後の正式な **link 分母は 12** です。
**13 を維持するためだけに connection を残してはいけません。**

### 残す場合に必要になること（参考）

もし将来それでも直接の道が欲しくなったら、必要なのは anchor ではなく**世界線**です:

- 線が forest の楕円を避けて南へ回る形になるよう、
  `countryside` か `river_lake` の `mapX/mapY`、あるいは `forest` の楕円を見直す
- または non-region geography として「支流 → 谷 → 河岸」を持つ**別 id の connection**を
  新設し、その線が forest を貫かない位置に引けることを先に確認する

どちらも「この 1 本のために世界地図の形を変える」作業になります。
**Phase 3B の締めくくりとしては、削除が正しい。**
