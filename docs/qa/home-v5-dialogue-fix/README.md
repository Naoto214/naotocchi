# VERSION 5 自律会話回帰の修正（PR #561）

自律会話の既知の回帰は修正した。**本番統合は引き続き停止**する。会話テストは成功したが、後続の重要なブラウザーテストに失敗が残るため、mainへのマージ・GitHub Pages公開は行わない。

## 対象と修正

- main基準: `408c72e6ebef71da3eab33cfb268c7494117aaaa`
- V5採用元 #558: `02df2efc39cd18543b9c66df281872ed1751b02c`
- 統合準備・修正前: `7c6caf43f7c96633eefe7114633ffe276527c0d8`
- 会話修正コミット: `762971e65c2cc2f73efaf3ec1fb1edcdaed07eea`
- 保存先: [Draft PR #561](https://github.com/Naoto214/naotocchi/pull/561)

原因は、幅から計算する接近目標と、実際の会話開始条件の不整合。既知のいぬ＋しばいぬでは横間隔だけで `105.5894375 native px` になる一方、到着時のsocial判定は距離 `<100` を要求していた。V5で目的地へ正確に到達するようになり、従来の境界補正によって偶然100以内へ寄る挙動に依存できなくなった。旧ログでは180秒にmove/arrive各20回、social 0回。会話UIの生成や表示条件を緩める問題ではない。

`home-production-model.js` のapproach/togetherの目的地選択だけに `socialDestination` を追加した。元の候補が安全で会話範囲内なら維持する。それ以外は元の方向を優先して最大16方向を調べ、既存の楕円接触判定・個体境界・地形・遮蔽を満たし、相手から99px以内にある地点を選ぶ。接触境界にも1pxの余裕を設ける。大型個体で横から近づけなければ斜め・縦方向を検討し、安全な場所がなければ接近を見送る。

普通の経路探索・歩行・到着時の距離判定をそのまま使用する。相手が移動中、手動操作中、保持中なら会話を強制しない。相手を動かす処理や道譲りは追加していない。乱数の消費回数、行動の抽選、会話内容・発言者・肖像・UI・セーブ形式は変更していない。経路補正後も実際に100px以内へ到着しなければsocialは発生しない。

本番ファイルはモデルとindexのキャッシュ識別子だけを更新し、配信allowlistのハッシュも更新した。追加のテストはnpm testと既存CIに登録した。前工程のQA画像17枚は内容ハッシュ付き保管例外に登録し、生成物チェック自体は維持した。

## 残る失敗・公開停止理由

1. GitHub CI `fixed-controls (webkit)` の後続孵化テストが失敗。320×568で成長時の足元深度zが `0.4469006933704403 → 0.8427524495470821` へ変化した。reduce/no-preference双方で発生し、誤差と扱えない。同じ320px/reduceケースを分離した比較でもmainは位置維持に成功し、会話修正前V5は同じ位置ずれで失敗した（`birth-main/`、`birth-v5/`。再現用 `tools/home-v5-production/birth-regression-probe.cjs` は元テストの条件を1ケースに絞るだけで、操作順・待ち時間・アサーションは維持）。自律会話修正より前からあるV5統合上の問題。両点は地形上valid、JSエラー0だが、位置維持の重要アサーションを満たさない。`ci-birth-webkit.json` に全10条件を保存した。
2. GitHub CI `home-layout` はWebKit/forest/320px/1体のmovementチェックに失敗した。会話テストの成功でこの失敗を相殺しない。現時点で原因未確定。
3. ローカルWebKitの現行UI全行列は430×932/28体でpane下端が約0.01691 CSS px変化し、既存1/64px許容値を超えて2回失敗した。GitHub CIの同じステップは成功。対象条件はreduced motionで、新接近関数の呼出し0を別途確認した。単一条件ではmain/修正前V5/修正版とも成功。別途走らせた全行列では修正前V5は18条件成功、mainは横画面568×320/1体のink laneで失敗した。ローカル環境・描画タイミングの影響が疑われるが、同一の微小誤差が旧版でも再現したとは断定しない。閾値は変更していない。

孵化とhome-layoutの重要検証が未解決のため、本番統合条件を満たさない。会話修正に便乗して位置保持・移動範囲やUIを変更しない。PRをDraftのまま保存する。

## 実行環境・限界

Playwright 1.62.1のChromium/WebKitで検証。ローカルLinux WebKitは不足ライブラリを別ディレクトリから供給した環境で、GitHub CIのWebKitでも会話テスト成功を確認した。**実機iPhone Safariでは未検証**。追加人数行列はChromium/390×844/120秒の代表条件であり、全住民種・全進化・全装備・全地域×乱数の総当たりではない。

接近候補は有限探索で、混雑や地形により安全な会話地点が見つからない場合がある。相手が途中で歩き始めた場合は会話を強制しない。social発生とUI発話は別で、通知・会話中など既存の表示抑制があり、全socialが直ちに会話表示になる保証はない。安全性を優先した従来仕様を維持する。

独立コードレビューでも接触・経路・手動保護条件に変更なしを確認し、会話修正そのものへのblocking指摘はなかった。ただし、これは失敗したCIの代替にはしない。
