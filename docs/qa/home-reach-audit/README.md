前回の左右拡張量は、他の個体を障害物として含めない幾何学的領域の数値でした。実ドラッグの到達範囲を示す数値として受け取れる報告になっていました。今回の同一配置からの実入力では左側の拡張は約2.6pxで、前回の約23pxとは一致しません。

## 同じ左ドラッグで後退する原因

入力先を画面 `(1, 530)` に固定した例：

| 項目 | A | B |
|---|---:|---:|
| 入力から変換したnative x | −126.88618 | −126.88618 |
| 境界による補正後native x | 80.78094 | 44.86454 |
| 選び直された目的地native x | 152.78094 | 156.86454 |
| 実停止した画面の足元 x | 178.66991 | 180.95500 |
| 実停止した画面の足元 y | 474.60978 | 483.35436 |

Bは約2.29px右に止まります。しかしAの実停止位置を画面座標でBに直接ドラッグ指定すると、Bも `(178.66991, 474.60977)` に到達しました。Aの位置がBの移動領域から削られたわけではありません。

`home-production-model.js` の `destination()` はまず `limit()` で入力座標を補正し、その位置に対して `navigation.nearest()` を呼びます。背景や他個体と干渉する場合、`home-route-navigation.mjs` は境界の `left/top` を起点にした8 native pxの格子から目的地を選びます。VERSION 1で境界が変わると、距離計算の基準となる補正後入力も格子の位相も変化します。結果として、画面の同じ位置へドラッグしても、別の近傍点を選びます。右側が広がっても左操作が期待どおり改善しない具体的な仕組みです。

アザラシでは上側の背景境界に加え、同じ格子のずれと接触回避で最端の補正位置が変わり、代表条件で約5.45px下に止まりました。「背景ポリゴンが上限だから実到達位置も変わらない」とは言えませんでした。

## 制約を分離した結果

調査用に生成したファイルだけで、制約を一つずつ無効化しました。解除した画面を改善版として提案・公開したものではありません。比較サイトは測定画像とデータのみです。

- **左:** 通常の到達位置はA約178.5/B約175.9px。接触回避だけを外すとA132.7/B109.9pxまで移動。背景歩行ポリゴンだけを外しても同程度まで移動。座標境界だけを外しても左は約178.4pxにとどまります。下側の背景制限と上側の他個体の配置が、利用できる左側の通路を狭めています。
- **右:** 代表条件の最端から2px先では座標境界に当たります。座標境界だけを外すと両方約295pxへ進みます。今回の右拡張は実入力でも確認できます。
- **ヤドカリ上:** 通常の4体ではA433.7/B422.0px。接触回避だけを外すとA331.2/B309.1pxまで上がります。単体の座標上限を広げても、この仲間配置で先に効くのは接触回避です。3体条件では上側の到達位置が大きく変わりました。
- **ヤドカリ下:** 最端から2px先で座標境界に当たり、通常の拡張は約3px。境界だけを外す診断では約545pxまで進みますが、これは本体・揺れ余裕を無視した結果で安全な改善候補ではありません。76pxセリフ領域を保持する条件は変えていません。
- **アザラシ上:** 背景ポリゴンを外すと大きく上へ進むため、背景上辺が主な制約。接触回避だけを外した場合も位置が変化します。最終停止位置は背景・接触・格子による補正の組合せです。
- **遮蔽:** このとかいの配置では遮蔽だけを外しても実測最端に大きな変化なし。他地域まで一般化しません。
- **座標変換:** 同じポインター入力から得たnative座標のA/B差は全1430候補試行で最大0。カメラ倍率も一致。画面座標変換そのものの左右への平行移動は確認されず、変換後の補正が差を生んでいます。

無効化比較は同じ48px間隔の候補群で実施。通常の最端探索にはさらに8px間隔の追加候補を使うため、解除表と通常表にサブピクセル程度の探索・停止誤差が含まれます。近傍の2px判定だけで原因を決めず、移動先・経路・実停止と制約解除の結果を合わせて判断しました。

## 方法と検証範囲

- 6条件：390×844/4体/装着あり、390×790/4体/装着あり、390×844/3体/装着あり、390×844/4体/装着なし、375×812/4体/ごうかな貝、430×932/4体/大きな貝。背景はすべてとかい・夜。
- ヤドカリ上下左右と、存在する条件でアザラシ上を測定。29組の最端A/B、計1430候補試行＋制約解除試行＋同一入力の再現・再到達検証。
- Playwrightの実ポインター入力で既存のpointerdown/move/upハンドラーを通過。目的地への直接 `model.move()` 呼出しで測定したものではありません。両方で同じ初期native座標を復元したこと、正しい個体を選んだこと、最端に採用したドラッグが受付成功したことを検証。
- 入力後は自律移動を止めた同じモデルの30秒分を進めて到達・停止を確認。移動の到着判定は既存の約0.5 native px。画像読込、同一倍率、同一初期配置を確認。
- 計測器はビルド出力のみを書き換えます。PR #554のゲームJS・CSS・画像は変更なし。無効化フラグなしで既存の実ドラッグ回帰検証と境界6テストも成功。
- **実機iPhone/Safariの検証ではありません。** Chromiumモバイル設定で再現。添付画像の種類・人数を参考にしましたが、正確な実機viewport・保存配置を画像から確定していません。動き続ける仲間や操作履歴によって到達範囲は変化します。

## 次の改善で必要なこと

座標境界だけの拡張を繰り返しても、左右両方の実到達範囲は保証できません。まず境界変更で目的地の補正格子がずれない方式を検証し、同じ入力で既存の到達位置を失わないことを回帰条件にする必要があります。その後、他個体が塞ぐ通路と背景の歩行設計を別々に検討する必要があります。接触回避や背景制約の一律解除は提案しません。今回の段階では原因調査に留めています。
