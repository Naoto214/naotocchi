# 自然な道譲り VERSION 1

基準は移動VERSION 5のPR #558（`02df2efc`）と、現行仕様調査PR #559（`7eccb1e5`）。独立ブランチ `codex/home-yield-v1`、Draft [PR #560](https://github.com/Naoto214/naotocchi/pull/560)で比較する。既存PR #554〜#559・main・ゲーム本番への統合は行わない。

## 比較の意味

- **A：現状維持**。凍結したV5の実装をそのまま使用する。
- **B：手動操作のみ道譲り**。どの役割のキャラクターでも操作要求を優先する。
- **C：手動＋自律移動**。Bと同じ退避処理を、自律移動が実際に停止してから2秒待った場合にも使用する。

この試作に「主人公＞恋人＞仲間」の通過・描画順位はない。最終的な推奨は実操作測定と安全性・処理負荷の結果で判断する。

## 仕組みと保護条件

既存のV5目的地補正・迂回を先に実行する。要求した方向へまだ安全に進める余地があるのに止まった場合、1体だけを仮に除いたときに通路が開くかを調べる。その個体の短い退避線分と、退避後の操作対象の経路が両方安全な場合に限って道譲りを始める。2体以上を順番に退かせる連鎖処理は行わない。

退避は通常の歩行速度・歩行アニメーションで行い、毎ステップで既存の接触・描画・地形保護を確認する。退避先へ到着した後も通過経路を再確認する。道を譲った個体は8秒観察し、元の場所へ戻す要求は出さない。明示的に選んだ休息・座り、移動中、つかまれている個体、直近の手動操作対象は退避させない。初期配置の未選択 `rest` は実際に休息を選んだ状態とは区別し、退避可能とする。

退避後の通過点は、元の目的地との距離を8 CSS px以上縮め、要求方向の各成分について現在位置と既に受理したV5到達点を後退させないものに限定する。退避完了と目的地到達は別の出来事であり、カウンター上の `passages` も元のドラッグ目的地への到達率ではない。

接触式は変更しない。

```text
hypot((p.x-b.x)/((a.w+b.w)*0.5+10),
      (p.y-b.y)/((a.h+b.h)*0.38+10)) >= 1
```

本体・装備の画像、サイズ、主人公の追加110%、深度倍率、足元yによる描画順、背景52枚、V5歩行領域・カメラ・76pxセリフ保護・保存形式は変更しない。本体側の変更ファイルは `home-production-model.js` のみ。道譲り状態はモデル内の一時情報で保存しない。

## 試作から採用した制限

|項目|今回の値・動作|目的|
|---|---|---|
|同時退避|全体で1体|道譲りの連鎖を作らない|
|自律移動予算|5体以下5、6〜15体3、16体以上2。退避も消費|従来の画面の落ち着きを守る|
|手動の待機|既存経路の停止後、要求から最低0.25秒|通常の迂回を先に利用|
|自律の待機|実際の停止から2秒|一時的な接近ですぐ退避しない|
|退避候補|8/16/24/32/40/48 CSS px、横・斜め6方向|近い安全な場所を順に探す|
|要求者と相手の候補|近い退避可能個体4体まで|全員に対する重い探索を避ける|
|探索上限|最大48プローブ、モデル時間3秒、正の1ステップにつき1プローブ|候補を一度に総当たりしない|
|全体クールダウン|6秒|連続発動を抑制|
|同一ペア|役割・方向を問わず24秒|交互に譲り続けない|
|当事者の保護|14秒|直後の別の退避要求を抑制|
|退避＋通過の期限|24秒|未完了要求を残し続けない|

数値は安全性と計測結果を見ながら限定した試作値で、全環境での最適値と断定しない。最初は「元の目的地まで完全に通れる場合のみ」を試したが、28体で進行率78/112は改善しなかった。部分的に有用な通過を認めた次の試作は改善例があった一方、1ステップ約1.9秒の探索が発生したため、その探索方式は採用しなかった。現在は最初の有用な安全候補で探索を終え、小分けに進める。各ナビゲーション問い合わせ自体は既存の同期処理のため、1フレームの処理時間を厳密に保証する方式ではない。

探索中に他個体の位置や行動が変わった場合は古い予測を捨てる。この場合に自動で全探索を繰り返すことはせず、新しい操作が必要になる場合がある。安全側の制限だが、周囲が自律移動していると有効性が低下し得る。

## 処理負荷の残る理由

既存の `navigation.reachable` は細かい候補格子の接続と到達可能成分を調べ、候補ごとに地形・描画・最大28体の接触を確認する。`route` も経路探索と線分サンプル検査を行う。今回の段階実行は多数の候補を1回にまとめる負荷を減らすが、これら1問い合わせの内部までは分割しない。負荷を根本的に抑える次の候補は、この既存探索自体の段階実行・再利用であり、接触判定を省略することではない。

## 検証方法と読み方

#559の保存済み初期配置、カメラ、個体・装備、つかみ位置、ポインター終点を再使用する。人数1/4/10/20/28の全252方向について、実際のポインター処理を通した最終足元・描画端を比較する。Aの28体78/112を再現できたことを基準とする。

「要求方向へ0.5 CSS px超進む」と「同じ入力のV5単独配置で到達した安全な目的地から2px以内」は別集計。最初から目的地にいる条件は後者の分母から除く。ポインターの画面端そのものは描画・UI保護により届かないことがあり、それを接触による失敗とは呼ばない。

静止配置の手動比較は、通常の自律移動を止め、操作対象と退避だけを動かす。各操作で道譲りの履歴もリセットするため、連続プレイより発動しやすい。通常の自律移動が動いている中での手動操作は補助測定として分離する。

自律移動はseed521、同じ開始配置から600モデル秒進める。停止時間には休む・座る・観察・移動予算の待ちが含まれる。A/B/Cで経路が変わると行動履歴も分岐し、平均距離だけで自然さを断定できない。#559の自律移動とは開始状態の復元条件が異なるため、今回のAを対照にし、過去の平均492.31pxと混ぜない。

## 検証の限界

実機iPhone Safariの検証ではない。Chromiumのモバイル画面幅と実ポインター入力、独立したモデルシミュレーションを使う。実際の指でのつかみやすさ、Safari固有の負荷・CSSアニメーション、長時間の自然さは本人限定試遊で確認する必要がある。

代表条件はとかい・夜、ヤドカリ段階5と紙の装備、恋人ゴリラ、固定の仲間集合。全種類・段階・装備・13地域×4時間帯・全乱数の総当たりではない。接触は既存のサンプル検査であり、連続時間の厳密な衝突証明ではない。退避先がない場合、意図的な休息しか周囲にいない場合、複数体を退かせなければ通れない場合は停止を維持する。
