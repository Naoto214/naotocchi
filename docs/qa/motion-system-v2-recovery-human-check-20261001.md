# Motion System v2 — 回復pilotの実画面確認

対象branch: `design/motion-system-v2-20261001`。mainへは未統合。
設計正本: `motion-system-v2-design-20261001.md`。

## 起動

このbranchの作業コピーで実行する。

```sh
npm ci
npm run dev -- --host 0.0.0.0 --port 5178 --strictPort
```

PCでは `http://localhost:5178/__qa` を開く。iPhoneでは同じWi-Fiに接続し、
Safariで `http://<起動したPCのLAN内IP>:5178/__qa` を開く。
この資料はローカル確認手順であり、公開済みの確認URLではない。

`/__qa` は開発サーバー限定。実際のHome HTML/CSS/JSと承認済み画像を読み込む。
**Load sceneはこの確認用originのセーブを置き換える。専用のport 5178を使い、
ここで通常プレイを継続しない。公開ゲームのセーブをインポートしない。**
再生用の別アニメーションやゲーム内部関数へのQA用置換は使用しない。

## 1回の確認手順

1. 読み込み後、画像が表示され病気になっていることを確認。
2. Homeの **くすり** を1回押す。病気が治り、実際の `medicine_cure` 経路が動く。
3. 「少し沈む → 大きく1回跳ぶ → 柔らかく着地 → 小さな余韻 → 原点」を見る。
   基本レシピは1450ms、主な上昇は14px、専用の移動上限は16px。
4. 主役とリボンが同じ軌跡を通り、26体が一緒に大きく跳ばないことを確認。
   恋人・なかまの返答が続いても、集団ジャンプが追加されないかを見る。
5. 数秒待つ。回復後のうれしい表情は残すが、遅れて2回目のbounceを出さない。
6. 同じ場面を再生するには **Load scene**。そのまま2回目のくすりを押すと
   健康な状態への投薬なので `medicine_wrong` のshakeになる。

「まずい」「苦い」を含む成功台詞でもrecoverになる意味判定は自動テストで確認する。
特定の台詞が出るまで実機で繰り返す必要はない。

## 頂点と割り込み

- `recovery_dense26` / `recovery_pair` は特に、上昇中の顔と恋人・指輪の関係を見る。
  静止時の矩形は保たれても、主役だけが上がる瞬間の余白は別途目視が必要。
  独立コードレビューでwoman/06＋クマの指輪との矩形交差リスクを指摘済み。
  これは可視ピクセルの衝突が確認されたという意味ではない。
- 気になる場合は画面収録し、一時停止して頂点・着地を比較する。
  PCではDevToolsのAnimationsパネルで**実際のアニメーション**を停止・スロー再生してよい。
- 回復中にメニューを開く／別のケアを押す／タブを離れて戻る。
  原点からずれたままにならず、古い遅延ジャンプが再発しないかを見る。
- iPhoneの「設定 → アクセシビリティ → 動作 → 視差効果を減らす」をONにして
  再読み込みし再確認する。大きな移動を止めても、治癒・台詞・表情は残る。

## 記録と停止点

記録: 端末/OS/ブラウザ、表示サイズ、Scene、通常/reduced-motion、
大きさ（小さい/適切/大きい）、可愛さ、顔・指輪の隠れ、着地ずれ、再現手順。
必要なら画面収録を添付する。

自動回帰のGREENは美観の承認ではない。このチェックポイントでは人間目視は未実施。
実ブラウザ自動検証も未実施（この実行環境ではブラウザ本体の取得に失敗）。
人間承認までは回復pilotに留め、他ケア・マイルストーンへの横展開、main mergeを行わない。
