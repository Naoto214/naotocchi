## 原因と変更

過去の V18 調整（`4478b25f`, `caca2f97`, `6243acf3`）と現行コードを調査しました。従来はネイティブ座標上で左右に「本体／装着物の幅＋12」、上に「高さ＋18」、下に「領域高−12」を確保し、その後に画面変換・本体独立スケール・深度スケール・背景歩行ポリゴン・遮蔽判定が重なっていました。移動座標の1pxと実際の描画の1pxは同じではなく、CSSの見える余白だけでは限界を判断できませんでした。

V18縦画面の個体別境界を、既存の描画エンベロープと実画面の `.screen-frame` から逆算する方式に変更しました。左右の装着物余白は別々に扱い、上下は既存の深度変化とアニメーション余裕を含めます。画像内の透明余白は既存 CastBounds と足元補正を利用します。装着物は透明部分を切り詰めず、保守的な全体枠と既存の揺れ余裕を保持します。「毎フレームの見えている絵だけ」に合わせて限界が揺れる実装ではありません。

カメラを決めるエンベロープは旧境界を参照し続け、移動範囲の拡張で本体が縮む循環を防ぎました。装着変更直後も、描画前に新しい境界で位置を補正します。無効・未測定の形状は旧境界に戻します。自律移動とドラッグは同じ `actorBounds` を使い、モデル・経路探索・接触回避は変更していません。

背景52枚、本体・装着物画像、サイズ・進化、最大28体、セーブ形式、通知・セリフ・プロフィール・操作UI・背景フェードは変更していません。下部76pxセリフ領域は非表示中も保持します。既存の横画面境界の仕組みも維持します。

## 検証結果と範囲

- Chromiumのモバイル設定で29条件×A/B＝58画面。幅320/375/390/430、代表高さ568/667/790/932、短い568・長い844の追加条件。大きな貝／ごうかな貝、装着あり／なし、通知・セリフ両方なし／両方あり／各片方、1/2/4/6/28体を組み合わせました。全組合せの総当たりではありません。
- 58画面すべて画像読込・エラーなし、指定人数、76pxセリフ領域、A/B同一の本体寸法・カメラ倍率を確認。
- 1体の実ポインター入力で上下左右の到達、歩行中と到達後の本体・アイテム枠の非見切れを検証。4体でも実ポインターのドラッグ受付を検証。混雑下で全個体が任意の端に到達する保証はしません。
- 自律移動の共通経路に加え、固定乱数の待機行動を1,200秒シミュレーションし、明示的な移動命令なしで拡張範囲を利用することを確認。
- 装着変更の最初の描画で再補正、画像遅延読込、320→844横画面→430→375→390のリサイズ、Safe Area下余白0/21/34px、もり／おうち／とかい切替を検証。
- 今回の境界テスト6件、V15/V17/V18・アセットハッシュを含む重点テスト24件、Pages整合性20件が成功。
- 既存 `npm test` の主要3293件は最初3284成功・9失敗。古いハッシュ実行時点と部分取得に伴う画像／CSV不足が原因で、修正・取得後の該当再実行は成功（アセット版、rollout 6件、画像256件、監査1件）。先行101件と後続の会話159件・ホーム238件も成功。全体を単一のコマンドで再度全件成功させたという意味ではありません。
- 独立コードレビューの指摘を受け、装着直後の再補正、地域／投影更新キャッシュ、入力・ライフサイクルの追加検証を実施。

## 比較ページの使い方

Aが現行版、Bが改善版です。幅・高さ・進化・装着物・人数・地域・通知・セリフを同じ条件にして切り替えます。「境界表示」で個体の座標枠と描画保護範囲、「現在の数値を測定」でヤドカリ／アザラシの数値を表示します。矩形デバッグ枠全体が歩けるわけではなく、背景ポリゴン・遮蔽・他個体との接触がさらに制約します。

「ゲームだけ開く」でiframe外に出せます。比較はホーム専用で、専用セーブ領域を使用し、本編のセーブは読み書きしません。本人以外の許可ユーザー・グループ・外部訪問者は設定していません。

代表画面: [A](a-390.png) / [B](b-390.png)。単体Bの到達例: [下](b-limit-bottom.png) / [上](b-limit-top.png) / [左](b-limit-left.png) / [右](b-limit-right.png)。
