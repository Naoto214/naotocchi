### 0-3. いちばん大きな構造的発見 — **13 地域はすべて「廊下」である**

`WORLDS` は例外なく **x が狭く z が長い細長い world** です。`world.entry` は z ≈ 0、奥地は z ≈ `len`。
つまり **どの地域も「入口から奥へ向かう一本の廊下」** であり、地域アイコンのような「面」ではありません。

| region | 口（entry, z≈0） | 奥（deep, z≈len） | 廊下の意味 |
|---|---|---|---|
| home | いえのまえ | おおきなき | 家 → 裏の大きな木 |
| city | えきまえ | とけいとうのおか | 駅 → 高台の時計塔 |
| countryside | むらのいりぐち | むらのはずれ／ちんじゅのもり | 村 → 森のへり |
| forest | もりのいりぐち | もりのおくのおく | 明るい森 → 奥 |
| mountain | ふもと | ちょうじょう | **登る**（標高が上がる） |
| snow | ゆきのいりぐち | ゆきやま | **登る**（雪原 → 峰） |
| sea | すなはま | はてのはま（とうだい・かいしょくどうくつ） | 浜 → 岬・果て（**海は −x 側**） |
| deepsea | あさせのたな | ふかいやみ | **下る**（棚 → 深淵） |
| river_lake | かわぎし（**下流**） | なかのしま／みずうみ（**上流**） | **遡る** |
| jungle | ジャングルのいりぐち | ふかいジャングル | 入口 → 奥 |
| desert | さばくのいりぐち | さばくのはて | 入口 → 果て |
| star_stop | ていりゅうじょ | そらのはて | 停留所 → 空の果て |
| memory_lake | みずうみのほとり | みずうみのそこ | **沈む** |

**ここから自動的に決まる地理がある:**

1. **`river_lake` の口は下流で、奥が湖。** 水は**口から流れ出す**。したがって **river_lake の口の側には必ず海（または海へ続く低地）があり、奥の側には必ず高地がある**。これは 3 案すべてが従うべき固い制約で、監査 N-2 の「川が山頂から出てしまう」問題を構造的に解きます
2. **`mountain` の口は麓、`snow` の口は雪原の入口、どちらも奥が峰。** ふたつの廊下は**奥どうしで接続できる**。つまり「登って、尾根を越えて、向こう側へ下りる」という接続が、既存データの形のまま成立します（#6 の「山脈の向こう側だから雪国」への直接的な答え）
3. **`deepsea` と `memory_lake` は「下る」廊下、`star_stop` は「外へ出る」廊下。** 3 つとも地上の平面に置くと廊下の意味が死にます（監査 N-1 / N-6）
4. **`sea` の歩ける陸は海岸線の +x 側の帯。** 世界地図では **sea は「面」ではなく「海岸線に沿った細長い帯」** として描くのが正しい

### 0-4. 接続点は、すでにコードが決めている

`enterRegion()` はプレイヤーを必ず `world.entry` に置きます。つまり **どの地域にも「世界から入ってくる場所」がすでに 1 つ定義されている**。
そこで本設計では接続点の語彙を 3 つに固定します。

- **口（くち）** = `world.entry`。**その地域の正式な世界側の玄関。必ず 1 本はリンクを持つ**（既存の `travelToRegion` の到着点と一致するので、互換が自動的に取れる）
- **奥（おく）** = z ≈ `len` の終端。原則クライマックス。**リンクを持たせるのは、越えること自体が演出になるときだけ**（峠・潜行・河口）
- **脇（わき）** = x = minX / maxX の側面。`edge` kind の spot（実測 **41 個**）がちょうどそこに並んでいる（`たなだのてんぼう` `いわばのみはらし` `かぜのきれめ` `すなおかのうえ` など）。**脇のリンクは「見晴らしから向こうが見える」に使える**

### 0-5. `HABITAT` は、すでに「どの地域が近いか」を語っている

31 系統の生息地（実測）を「複数地域にまたがる系統 = その地域どうしが生態的に近い」と読み替えると、**コードはすでに世界の地理を部分的に決めています**。

3. **`unknown: deepsea, star_stop`** — 深海と空は同じ「知らないもの」として書かれている。**「同じ一点の真下と真上」という配置（C 案）に、コード側の裏づけがある**

## 2. A 案 — **「ひとつの山から、すべての水が落ちる」**

### 2-1. 構造思想

> **世界の中心は陸の高さである。** まんなかに白い山塊がひとつあり、そこから三方へ水が落ち、外へ行くほど低く、暖かくなる。地図は同心円。

気候も接続も**中心からの距離と高さ**で決まります。横断すると気候は同心円状に変わります。

### 4-5. 山系・水系・海岸線・気候帯

- **山系**: 輪の北側に 1 つ（やま）、その外にゆきぐに。輪の西側は山ではなく**乾いた高原**
- **水系**: **すべての水が内側へ落ちる（内向きの流域）。** ゆきぐにの氷河 → かわ・みずうみ → 内海。やまの水 → 同じ湖へ。内海には出口がなく、**海面は蒸発で釣り合っている**（内陸海）。ジャングルの雨だけは外洋側へ落ちる
- **海岸線**: 2 本ある。**内海の岸**（輪の内側、全地域が面している）と**外洋の岸**（輪の外側、南西のジャングルと南のうみの外側）。世界地図で海岸線が二重になるのは C だけ
- **気候帯（円周に沿って一周する）**: 北＝高山 → 北東＝冷温帯林 → 東＝田園 → 南東＝暖温帯 → 南＝内海の暖かい岸 → 南西＝熱帯（外洋の雨）→ 西＝乾燥内陸（外洋からも内海からも遠い）→ 北西＝冷涼な湖沼 → 北へ戻る。**世界を一周すると、気候も一周する**
- **生活圏**: 輪の東側に固まる（とかい・おうち・いなか）。内海に面した「表側」
- **世界の外周**: 外洋（南・南西）／乾いた高原の果て（西）／氷原（北）／風上の断崖（東）。**内側の限界は壁ではなく「沖へ出ると足がつかなくなる」**——既存の `shoreX` クランプがそのまま「これ以上は泳げない」として読める。その先へ行く道は**下（しんかい）か上（ほしぞら）しかない**
- **初期地点**: おうちは輪の東、内海が見える丘の集落。最初の 2 方向は村と街
- **発見の流れ**: おうち → 村か街 → どちらへ進んでも輪をたどれる → 輪を半周すると反対側から戻ってこられる → 山から輪の外の雪国 → 海の沖で下へ（しんかい）、灯台の夜に上へ（ほしぞら）

### 4-6. 世界地図のシルエット

> **まんなかに大きな内海をかかえた、ひとつづきの輪の陸。北にひとつだけ、輪の外へはみ出した白い地方。そして中心の一点に、上下 3 枚が重なっている。**

シルエットの記憶しやすさは **4 案で C が最も強い**（「まんなかに海がある輪の世界」の一言で済む）。

### 4-7. C 案の弱点

1. **うみが実質 5 本**（環 2 ＋ わたし舟 ＋ しんかい ＋ ほしぞら）。**#16 に真正面から触れる。**海が世界のハブになる
2. **さばくの理由づけが 4 案でいちばん弱い。** 「外洋からも内海からも遠い内陸」という距離だけで説明しており、山脈の雨陰という強い理由が使えない
3. **輪は行き止まりがない代わりに、「その先はもうない」という特別さが作りにくい。** 外に出られるのはゆきぐにだけ
4. **地図の中心へ歩いて行けない。** 中心が内海なので、達成感の置き場所を しんかい／ほしぞら に全面的に頼ることになる
5. **面積差が円周上で極端に不均等になる。** さばく 59.8 Mu² と おうち 6.9 Mu² を同じ輪に並べると円が歪む（§7 の図上サイズ規則が必須）
6. **Three.js のとき「対岸問題」が出る。** 内海ごしに反対側の地域が見えるはずで、出さないと嘘っぽく、出すと遠景 LOD が 13 地域ぶん要る。**4 案でいちばん重い描画リスク**
7. **シームレス化したとき、輪の一周が 9 地域ぶんの長大な帯になり、ストリーミングの順序が一次元に伸びきる**

- **外周**: 北＝氷原／北西＝砂の果て／西・南西＝外洋／南＝湾の口の先の大洋／東＝風上の断崖

### 5-6. D 案の弱点

1. **やま・いなか・とかいが 3 つとも 4 本**。ハブが 3 つに分散するのは健全だが、**「この地域が世界の交差点」という主役が立たない**
2. **キャラバンの街道（とかい↔さばく）は地図上で長い線を 1 本引くことになり、シルエットを横切る。** 弓のかたちを壊さない描き方が要る
3. **A の「同心円のうつくしさ」も C の「まんなかに海」も、部分的にしか継いでいない。** 3 案の良いとこ取りゆえに、**シルエットの一言が 4 案でいちばん長い**（「弓なりの大陸と、そのふところの湾」）
4. **湾は内海ほど閉じていないので、C のような「中心へ行けない」という緊張が薄い**
5. 接続 17 本（層込み）は 4 案で最多で、**Phase 2 の `REGION_LINKS` 定義と発見演出のコストが最も高い**

### 7-2. 世界地図と地域地図の役割分担（#19）

### 7-5. 世界探索率の案（#20 / #42 / #43）

**秘密 107 個を 1 つも要求しません。**分母はすべて公開情報の定数です。

```
せかい ％ ＝ 0.40 × （到達した通常 region ／ 11）
           ＋ 0.25 × （見つけた幹線リンク ／ L）      L は案ごと（A 15 / B 15 / C 14 / D 16。層リンク込み・記憶を除く）
           ＋ 0.20 × （見つけた tier1 landmark ／ 17）
           ＋ 0.15 × （訪れた通常 zone ／ 103）
```

| 分母 | 値 | 既存セーブで足りるか |
|---|---|---|
| 通常 region | **11**（`REGIONS.length`。しんかい込み） | ✅ `lifetime.regionsVisited` |
| 幹線リンク | 案ごとの定数（14〜16） | ❌ **新規 1 つ**: `lifetime.meguru.links = ['forest|mountain', …]` の id 集合 |
| tier1 landmark | **17**（18 − ほしぞらの 1） | ✅ `lifetime.meguru.marks[regionId]` に `lm:` 接頭辞で既にある |
| 通常 zone | **103**（通常 11 地域の zone 合計、実測） | ✅ `lifetime.meguru.zones[regionId]` |

**秘密を逆算できないこと**: 4 つの分母はすべて定数で、秘密 spot・秘密 path・秘密だけで通じる zone を 1 つも含みません（通常 11 地域の 103 zone はすべて非秘密 spot を持つことを実測済み。秘密だけの zone は memory_lake に 1 つあるだけで、分母の外）。つまり **せかい 100％ は、秘密を 1 つも見つけなくても、特別 2 地域へ行かなくても達成できます。**

**特別地域の扱い**（#43）:

| | ％ に含めるか | 表示 |
|---|---|---|
| **しんかい** | **含める**（`REGIONS` の通常地域なので、外すと既存の「せかいいっしゅう」実績と数が食い違う） | 通常どおり |
| **ほしぞら** | **含めない** | ％ の横に **★** を 1 つ灯す（「そのさきへ」） |
| **きおくのみずうみ** | **含めない。★ にも入れない** | **地図の余白に、ナオトに会った記録として 1 行だけ**。地理の発見と同列にしない |
| **ひみつ 107** | **含めない** | 別軸「ひみつ」。既存の地域地図と同じく残数を逆算させない表示 |

これで **「ずかんを埋める」≠「世界を歩いて地図を埋める」≠「ひみつを見つける」** の 3 本が独立します（#44）。既存のずかん 168 などの達成条件は変更しません。

## 8. 4 案すべてに残る、正直な弱点

1. **もり と ジャングル が、どの案でも地理的に遠い。**`beetle, stagbeetle` が両方に住んでいるのに、地図上では離れます。
   **対処の提案（実装しない）**: 隣接させて解決するのではなく、**「同じ系統が、温帯の森と熱帯の森の両方にいる」**という緯度のペアとして読む。現実のクワガタ・カブトムシもそうなっており、`HABITAT` の書き方（系統に 2 地域）はこの読み方と矛盾しません
2. **ゆきぐに（38 Mu²）を「山の向こう」だけで説明すると、広さが余ります**（監査 N-5）。4 案とも「峠を越えた先の、広い盆地または高緯度の平原」という二重の理由を与えていますが、**B / D の「背骨の北端＝高緯度かつ高標高」が最も説明が効きます**
3. **とかい（30.4 Mu²）の孤立感**（監査 N-4）。生活圏 3 地域が `HABITAT` で強く結ばれている以上、都会を遠くへ置くことはできません。**「近いが、街に入ると別世界」**を地形ではなく景観の遷移（§7-7）で作るしかありません
4. **さばく（59.8 Mu²、最大）がどの案でもシルエットを歪めます。**A は円を、B は大河の重心を、C は円周を、D は弓を、それぞれ西へ引っぱります。図上サイズ規則（§7-1）で 1.77 倍に圧縮しても、**最大地域であることは変えられません**
5. **ほしぞらの入口が二重になる。**そだち70 の特別なたび（既存仕様）と、地図上の「地上のこの一点の真上」。どちらかを「見えるだけで、行くのはたび」にする整理が必要です
6. **`sea` の歩ける陸は海岸線の片側の帯**（実 box 幅 3205、うち海が食う）。世界地図で「うみ」を面として塗ると実態より広く見えます。**帯として描くのが正しい**
