実際に28体を同時に置いた [密集配置の一覧](dense-residents.md) も別に測定した。V5では112方向操作のうち74件が移動し、38件は安全に留まった。旧版の逆向き移動を抑止した差を除いて、23方向で実際の外側到達が改善した。例はしばいぬ左151.49px・上40.81px、カワウソ下12.01px、アザラシ上7.38px。通路が完全に塞がる配置をすり抜けさせる変更はしていない。

V4で問題となったゴリラの斜め下入力 `(2,545)` と `(50,545)` は、従来版の足元y=294.951、V4=269.573に対しV5=302.164となった。**V4より32.591px下へ到達**し、従来版からの25.378px後退を解消した。純粋な左入力 `(17,293)` の到達位置はV4と同じで、左上入力 `(17,242)` ではさらに2.393px左へ進む。

ゴリラの左下入力3種類については、旧版が左上へ戻るため左成分だけで比べるとV5が劣る記録がある。これらは操作ベクトルとの内積が旧版では負、V5では正になる意図修正として、生の回帰記録を残して区別する。すべての入力・全条件が無条件に旧版と同じになるという報告ではない。

## 変更の理由と方法

V4で分離した問題は、背景の実際の `cover` 投影と歩行判定の仮想投影が異なることだった。背景と同じ投影へ全体を置き換えると既存の足元・カメラ・安全な到達点を失うため、V5では旧領域を残し、実背景に描かれた地面だけを追加する。追加にも地域ごとの `ground` / `exclude`、前景遮蔽、個体別の本体・装着物・アニメーションの描画保護、従来の接触条件を適用する。

カメラの包絡計算は `layoutNavigation` に保存したV4の地形を使い続ける。深度関数、カメラ倍率、キャラクター・アイテムの画像と表示サイズを変更しない。背景52枚、通知・セリフ・操作UI、セーブ形式も変更しない。

目的地探索は背景固定の8 native px格子とV3の半間隔探索を維持し、最後の安全な点からポインターへ向かう線分を検証して格子間の余裕を使う。完全なV4の計画結果と比較し、安全な要求方向の到達成分を失う候補へ交換しない。操作方向の評価は画面上のベクトル内積を使う。45度付近で軸を切り替える試作はアザラシを後退させたため不採用。

他個体で一時的に経路が塞がった場合は、同じ手動要求を最大4回・12秒間だけ再探索する。新たな接触を許さず、受け付け済み目的地の方向成分を後退させない。キャンセル・再選択で保留要求を破棄する。

28体の実操作検証では、3 native pxごとの線分チェックが2つの地面投影の間の細い隙間を飛ばし、移動途中で停止する条件も見つかった。V5では両投影のポリゴン辺との交点で線分を分割し、各区間の連続した安全性を検査する。旧経路を再利用する場合も同じ検査を通し、目的地を保持した安全な迂回へ置き換える。装備・画面変化後には、新しい表示投影で歩行判定を更新する。

## 測定の読み方

- 成果は本番と同じポインター処理に `pointerdown / move / up` を入力し、移動後の足元とPNG alpha描画端を測った値。理論境界の広さを到達成果にしない。
- [全28体の一覧](all-residents.md) は390×844、とかい・夜、28体表示時のカメラを固定して接触だけ分離した各1体の測定。通常の1体表示のカメラとは異なる。
- [CSV](limits.csv) に版別足元・描画端・入力・局所制約を保存する。`matrix-evidence.json.gz` は全試行、`summary.json` は条件と件数、`regressions.json` は同じ入力で方向成分が減った記録を含む。
- 4体の代表配置と最大28体の密集配置は別に測る。密集時に本体を直接選べない個体は比較用の選択操作後、既存の地面ドラッグ処理へ実ポインターを入力し、その入力方式を記録する。
- 最端値は同じ有限の入力群から選んだ最良値。版間で最良値を出す入力が異なる場合がある。同一操作の回帰は別集計する。
- 後退検出の許容差は0.8 CSS px。既存の到着判定と浮動小数点の差を含むため、数学的な全点包含・全入力一致を実機で証明したという意味ではない。
- 到達後の局所プローブは、その位置から直進した場合の制約を説明する補助資料であり、実行中の停止イベントや全経路の不可能性の証明ではない。

比較ハーネスにも修正を行った。通常のフレームだけでなく、操作や装備更新による同期処理にも自律移動OFFを適用する。初期の複数体試行は一部の同期処理で他個体が歩き始めることがあったため、最終比較から除外して取り直した。最終試行では開始配置・ポインター始点と終点の一致に加え、他個体が動かず、余計な自律経路が生成されていないことも確認する。

## 背景ごとの扱い

[地形監査](terrain-review.md) に13地域×4時間帯の画像確認と採用条件を記載。全地域へ同じ矩形を適用しない。森の追加候補は元画像の `z >= 0.55`、ジャングルは `z >= 0.58` に限り、樹根・植栽・水際に見える遠景を追加しない。他11地域も既存groundの輪郭と除外を守る。

和集合方式は既存2.5D表示を保持するため、以前から建物の前に浮いて見える足元をすべて地面へ移すものではない。アザラシ上方向の改善を「背景の地面と全面的に一致した」とは評価しない。

## 総合検証

- 11条件セット、289個体・方向行。5,752予定試行中、実ポインター入力は5,672件。直接選べなかった320pxアザラシの80件は成功に数えず、選択後の地面ドラッグ80件を別途検証。
- 全28体主表は3,792操作。同一ポインター始点・終点の差は最終データで0件。記録した21例外はすべて旧版の逆方向応答の抑止で、その他の未解決後退は0件。
- 13地域×4時間帯の52条件、4画面幅×16装備状態の64条件で、画像alpha端と恋人の指輪・ハートDOM矩形を確認。描画枠からのはみ出し0。今回測った通知下端との最小間隔23.03px、セリフ上端との最小間隔12.89px。
- 地域別の同一ポインター比較は別途52組・104操作。方向後退0、他個体の位置・経路・自律要求が変わらないことを全操作で確認。
- 自律移動は4体・28体を各1,200シミュレーション秒確認し、追加領域への訪問を検出。新規接触・接触悪化0。すべての個体が同じ時間内に追加領域を訪れる保証ではない。

## 制約と未検証範囲

下端には76pxのセリフ領域と本体・装着物・揺れの描画余裕を常に予約する。セリフが消えている間だけ下限を広げると表示時に隠れるか急に戻るため、予約を維持する。見える空白すべてを使用可能とは扱わない。

主人公の横方向には、現在の静止PNGだけでなく表情・動きを含む既存の最大包絡（`max(bodyWidth/2, frameHeight*0.55)` など）が残る。したがって左端の静止画に隙間が見えても、その隙間をすべて安全に削れると確認したわけではない。表情SVGの横方向や全アニメーションを段階別に厳密計測すれば再検討できるが、今回その余裕を未検証のまま削減してはいない。

例として海の地面は実背景上で約561pxから始まるが、今回の390px幅・4体ヤドカリの描画保護下限は約535pxである。水面へ地面判定を広げるか、UI側の予約を削らない限り、この配置で海の追加領域は利用できない。[地域別比較](regions-compare.md) ではこのような改善0の条件も記録する。

実機iPhone Safariはこの環境から操作できない。ブラウザ自動検証はモバイル設定のChromiumとCSS幅320・375・390・430pxによるもので、Safari固有のアドレスバー・Safe Area・タッチ挙動を完全に代替しない。本人限定試遊版で最終的な実機確認が必要。

全28体は主人公1・仲間26・恋人1の代表構成。主人公31種×全進化段階×装着物×恋人種×52背景×画面幅×全配置の総当たりではない。代表進化・装備・画面幅・地域の検証範囲を別の結果ファイルに明記する。
