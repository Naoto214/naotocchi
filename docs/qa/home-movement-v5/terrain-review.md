# VERSION 5: 背景に描かれた地面の追加候補

基準: VERSION 4 / PR #557、`48d062aa55681061e72b593e5ec4012ed305270e`。

## 結論

既存 `ART_SCENES.ground` を背景画像と同じ `cover` 投影で評価する追加候補は、13 地域中 11 地域では元の地面形状を保って試作できる。森とジャングルの遠景側には、元の ground に含まれていても画像上では樹根・植栽・水面に見える部分がある。この 2 地域は**追加候補だけ**奥側を制限する。旧 VERSION 4 の判定を置き換えるのではなく、安全な既存経路との和集合として扱う。

これは背景の目視監査と試作の採用条件であり、実到達改善の計測結果ではない。実際のポインター操作・接触回避・描画端・76 px セリフ領域の検証を通過した領域だけを成果に数える。

## 再利用した証拠と今回の確認範囲

- [VERSION 3 の地形調査](../home-movement-v3/investigation.md) と、同フォルダーの地域別 4 時間帯シート（下表のリンク）を再利用した。
- 13 シートの朝・昼・夕・夜、計 52 背景について、シアンの元 ground と背景の地面・水際・建物・植栽の位置関係を目視確認した。元画像を変更したり、時間帯別に別の地形を発明したりしていない。
- シートは元画像座標上の ground を示す。VERSION 4 の実画面に表示されていた「古い投影の歩行領域」が、そのまま地面に一致していた証拠ではない。
- [VERSION 4 の座標分析](../home-movement-v4/coordinates.md) と [検証報告](../home-movement-v4/README.md) にある投影差を引き継ぐ。画像の cover、カメラ、深度スケールを一律に変更する案は採らない。
- 全 52 枚の高解像度での画素単位の地面抽出ではなく、既存の 4 時間帯一覧画像を使った構造の目視監査である。境界付近の安全性は runtime の描画・遮蔽判定でも確認する必要がある。

森の `0.55` とジャングルの `0.58` は、全地域共通の固定余白ではない。今回の画像監査で明瞭に地面と判断できる手前側へ追加候補を限定する地域固有の保守的な境界である。境界上をさらに奥へ増やせるとする定量的な証拠はなく、その範囲を成果として数えない。

## 実装時に必要な条件

1. 背景が DOM 上で実際に描かれる cover 変換を使って、候補足元を元画像座標へ戻す。旧ナビ用の仮想画像寸法から cover を推定しない。
2. 追加候補にも元 `ground`、`exclude`、地域別制限を適用する。前景遮蔽も実背景に対する既存の判定を維持する。
3. 旧ナビ側で安全な足元と経路を保持し、追加領域との接続を接触判定付きで検証する。背景の地面があることだけを理由に他個体をすり抜けない。
4. UI・本体・装着物・揺れ・向きの描画保護は、背景上の歩行判定よりさらに内側の制約として残す。画像の下端まで地面がある地域でも、セリフやステータスの位置まで歩かせない。
5. カメラ倍率・深度スケール・画像サイズ・背景画像は変更しない。描画保護に収まらない位置を、縮小によって有効にしない。

## 残る制約

- 旧ナビと cover 投影の和集合は「旧版の到達性を保ちながら、画像上の地面を追加する」方式である。旧版の全足元を背景の地面へ再配置する方式ではない。旧版の投影差そのものが全域で消えるわけではない。
- 背景上の安全な地面でも、画面幅・UI・体格・装着物・接触・到達可能な経路により使えない場合がある。本報告はその部分の拡張量を約束しない。
- 森・ジャングルの奥の追加を保留する判断と、他地域の元 ground 外への拡張を保留する判断は、未検証範囲を安全とみなさないためである。元画像への手描きの細密な地面マスク、各種体格を使った実機確認があれば再検討できる。
- iPhone Safari の実機操作検証はこの画像監査には含まれない。V5 の実ポインター測定・比較ページ・端末別検証は総合報告を参照する。

## stage 3 の実ポインター到達画像の確認

`v5-smoke390-stage3` の `matrix.json` と、代表 3 体×4 方向の V5 PNG 12 枚を照合した。条件は 390×844 CSS px、Safe Area 下 34 px、とかい・夜、4 体、ヤドカリ段階 5、`poop1` 装着、通知・セリフ非表示。iPhone 実機の撮影ではない。

| 確認対象 | V4 → V5 の到達足元（CSS px） | 画像上の判断 |
| --- | --- | --- |
| ヤドカリ左 | `(175.340, 438.643)` → `(109.924, 530.000)` | 新しい左下の足元は明瞭な舗装上。本体・貝・装着物は画面内に収まり、UI と重ならない。既存のカメラ・深度に従う見た目で、背景の建物・植栽へ新しく侵入していない |
| ヤドカリ下 | `(210.000, 535.123)` → `(109.924, 535.123)` | 下方向の限界は同じ。V5 の左下の到達点も舗装上で、本体の実測最下端は `535.115`。描画保護枠下端 `545.984` まで約 `10.869` px を残す。横へ移動したことを下方向の改善とは数えない |
| アザラシ上 | `(231.149, 279.746)` → `(230.806, 275.014)` | 約 `4.732` px 上へ到達。本体は画面内で上部プロフィール・UI に干渉しない。ただし背景の手前の舗装ではなく、建物・手すりの前に浮いて見える既存の 2.5D 表示帯。この結果を「地面と足元の投影が一致した」とは説明できない |

この表は方向ごとの到達候補のうち最端の結果であり、左右・上下の最端を得たポインター終点は必ずしも同じではない。同一ポインター操作の後退有無は、総合検証の対応する操作ペアで別に評価する。

残る 9 枚でも、今回の静止状態では新しい画面端の見切れや操作 UI への重なりは見られない。ゴリラのハート・指輪も画面内にある。既存の上方の表示帯では、キャラクターが背景の建物・木の前に浮く投影差が引き続き残る。既存到達性を保持する和集合方式の制約であり、この 12 枚だけで全経路の自然さ・接触安全性・通知/セリフ表示時の安全を証明したとは扱わない。

中間 PNG ではデバッグ十字と足元ラベルが初期配置に残り、移動後のスプライトと一致していなかった。この確認には JSON の `actor.foot` と実描画端を使用した。公開用の比較画像では、ラベルを移動後へ更新するか非表示にして、初期座標を実到達位置と誤認させない必要がある。
