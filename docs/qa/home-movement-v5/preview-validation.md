# VERSION 5 試遊ページの検証

Chromium のモバイル画面・タッチ対応エミュレーションで、実際の比較ページと iframe を操作した。実機 iPhone Safari の検証ではない。生データは `preview-validation.json`、画面例は `preview-390.png`。

最終ログは `passed: true`。ページ例外 0 件、画面に必要なアセットの読み込み失敗 0 件（favicon は検査対象外）。59 件の記録を保存した。これは比較ページの動作確認であり、移動限界の改善量を測る試験とは分けている。

|外側の画面幅|iframe の実幅|外側 scrollWidth|iframe scrollWidth|
|---:|---:|---:|---:|
|320|320|320|320|
|375|375|375|375|
|390|390|390|390|
|430|430|430|430|

430px を指定しても画面が狭い場合は実際に収まる幅を使い、キャラクターへの CSS 縮小は行わない。28体・歩行領域・描画保護境界・描画枠を表示した状態でも横方向のはみ出しはなかった。

確認内容：

- 従来版・VERSION 2・VERSION 4・VERSION 5 の切替。各版の model/world が該当する版のディレクトリから読み込まれることを Resource Timing でも確認した。
- 28体すべてを個体選択メニューから選択できること。
- 主人公（イヌ・ヤドカリ）、進化段階（0・5・7）、地域（もり・とかい）、時間帯（昼・夜）の切替と実際のゲーム状態の一致。
- 装着なしと10種すべての装着アイテムの切替。達成アイテムの表示と装着操作。
- 自律移動 ON/OFF、セリフ・通知 ON/OFF。セリフと通知の切替前後でキャラクター座標が変わらないこと。
- 21回の実際の pointerdown → pointermove → pointerup によるドラッグがゲームの入力処理へ到達し、すべて受理され、移動後の足元座標が変わったこと。移動前に入力ログを消して、過去の操作ログを誤検出しないようにした。
- 人数1を指定した場合は主人公を選択し、1体表示になること。

比較用キーは `naotocchi-movement-v5-{a,c,d,e}`。本編キーを読み込まない。通常の画像、表示サイズ、ゲーム本編の保存処理は変更していない。

## 配信形式

`V5_SHARED_ASSETS=1 V5_INCLUDE_AUDIO=1` で構築した静的ファイルを検証した。画像・背景・音源・CSS は共有ディレクトリに置き、各版の JS/module は固定したディレクトリに置く。`vendor` と `character-3d` はモジュールからの相対 import に必要な小さな実ディレクトリとして各版へコピーする。配信にシンボリックリンクは必要ない。

検証中に見つかった欠落（背景フォールバック、空腹マーク、音源、Three.js）を補い、修正後の全検証で失敗 HTTP 応答がないことを確認した。

## 描画診断の追加確認

`preview-cue-validation.json` は4版すべてで、恋人の指輪とハートが `withItems` に含まれることを確認している。絵文字・SVGのハートは `kind: dom-cue` のDOM矩形であり、本体画像のアルファ境界とは区別する。時計を止めた検証でも `MovementQA.step()` の直後にデバッグ表示を描き直し、全個体の足元ラベルが現在の足元座標と一致することを確認した。

## 再実行

```sh
V5_SHARED_ASSETS=1 V5_INCLUDE_AUDIO=1 node tools/home-movement-v5/build.cjs /tmp/v5-runtime
V5_PREVIEW_DIST=/tmp/v5-runtime node tools/home-movement-v5/preview-check.cjs
```

既存の出力ディレクトリを上書きしない。別のパスを指定する場合は両方のコマンドを同じパスにする。

## 検証範囲の限界

この UI 試験は全種・全進化段階・全地域・全時間帯の直積を実施していない。地域別の描画安全性、28体の限界到達、接触・経路の安全性は別の測定資料を参照する。実機 Safari のブラウザバー、Safe Area、ソフトウェアキーボード、OS の絵文字描画との差はこの試験では確定できない。
