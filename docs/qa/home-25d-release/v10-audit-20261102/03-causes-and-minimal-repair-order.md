## なぜ再発するか

**分類、状態管理、DOM配置、CSS、検証が別々の単位で作られ、同じ「一件の通知」を共有していない。**

1. 同じ行動が結果N/A・掛け合いB・描写Tを並行発火する。Tは上部通知と下部コメントを同じキュー・DOMで運用する。
2. V7/V8/V9/V10のCSSと複数の配置controllerが併存。DOMを移すと祖先依存の背景色・画像・幅・優先度が変わる。
3. 一件表示をCSSで実現する一方、非表示側のタイマー／speechActive／conversationBusyUntilは進む。表示時間や入力可否と画面が一致しない。
4. 380px以上の世界を小さいスクロール窓で見せている。固定UIを増やすほど窓が縮み、消失に見えるクリップや追従の問題が表面化する。
5. 既存テストは固定寸法やDOMの可視数に強く、背景色、中央揃え、意味分類、実際の読める時間、自然会話との競合を十分に検査しない。旧版の固定fixtureの成功も混在する。
