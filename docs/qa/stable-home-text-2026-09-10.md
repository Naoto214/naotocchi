# ナレーションの有無でホームを動かさない（2026-09-10）

## 基準と依頼

最新main `3cf2903bcc02d667e86c3e68e9c173549e44e52f`、PR #216本文、Runtime・Pages成功をGitHubから再取得して再開。仲間最大26人＋恋人＋装備の見本と、ナレーションが出たときに画面の大きさが変わる問題の修正を依頼された。

## 原因と修正

- `.message:empty` が `display:none` になり、ナレーションの出入りで高さが増減していた。吹き出しも非表示時には欄ごと縮み、余り高さを使うキャラ欄を再配置させていた。
- ナレーションは3行分、セリフは2行分＋吹き出しの内側余白・枠・先端の余白を常に確保。空でも領域は保持する。文字サイズ「大」では領域も文字に合わせて拡大する。
- 長文は全文をDOMに保持し、文章欄内でスクロールして読める。通常の文章のためにホーム全体を伸縮させない。文章欄はキーボードからも到達できる。
- 新しい文章は先頭から表示する。通常のrenderでは同じナレーションを入れ直さず、読んでいる位置を維持する。通知4.2秒・発話2.5秒の表示時間、話者・動きとの連動を維持。
- キャスト配置計算・元画像・保存・ゲーム・ゲージの区分・操作ボタンは変更しない。仲間は26人なら左右13人ずつ、内外の半楕円の弧に並ぶ。恋人と装備は主役の身体に重ならない位置を維持。

## 検証と限界

- 長文から次の文章へ切り替えたときのスクロール位置の残留を、実ランタイムのテストで再現して修正。全文保持・読み位置維持・消去タイマーも確認。
- 既存のリサイズ中の発話テストは、文章量でDOMの偽高さを変える代わりに、可視領域の変化を明示して検証するようにした。実際の端末回転等で高さが変わったときの再配置と反応の維持を引き続き検証する。
- ローカル `npm test` 全80件成功、fail/skip 0。起動・会話・QA fixtureも成功。既存の0〜28人の全身・動作余白・左右の弧のテストを含む。
- NodeのDOM代替にはCSSのレイアウトエンジンがない。上記テストでSafari上の高さ不変・折返し・スクロール操作を実測したとは扱わない。CSSは固定枠と非表示時の寸法保持をレビューし、最大人数の見本には実装のCSS・配置関数・元PNGを使う。
- 公式ブラウザーへの接続を再試行したが、タブ取得が20秒でタイムアウトした。別経路への切り替えは行っていない。修正後のiPhone実画面・実際のスクロール量・タッチ・滑らかさは未確認。極端な拡大や追加操作で高さが足りない場合に、ホーム全体の内容を切らず到達できる方針は維持する。
