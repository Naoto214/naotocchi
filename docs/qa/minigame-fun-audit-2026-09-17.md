# 変更した21ゲームの「遊んで楽しいか」監査（2026-09-17）

難易度の総点検（`minigame-difficulty-audit-2026-09-17.md`）で調整した21IDを、
数字ではなく「触っていて楽しいか」の観点で見なおした記録。

## 0. 10個のものさし

| # | 見るところ |
|---|---|
| A | 自然な操作で成功できるか |
| B | 適当に操作しただけでは高得点になりすぎないか |
| C | 上手く操作すると明確に結果が良くなるか |
| D | 成功／失敗の理由が画面を見て理解できるか |
| E | ガイドが答えそのものになっていないか |
| F | 逆にガイドを見ても理不尽に失敗しないか |
| G | 成功したときに「自分で上手くやった」感覚があるか |
| H | 失敗しても、次はこうすればよいと分かるか |
| I | iPhone 390px で対象物や文字が小さすぎないか |
| J | 短時間の育成ゲームとしてテンポが悪くないか |

測り方は3つ。①**無操作**（画面に触らない）②**でたらめ**（ランダムなタップ/スワイプ）
③**ちゃんと操作**（実機と同じ操作をスクリプト化、またはコードどおりの数値シミュレーション）。
B は①②が高すぎないか、C は③が①②より明確に上かで判定した。

## 1. この監査で見つけて直したもの

### ひこうき着陸 — 「何もしなくても68点」を、3段階の上達に組みなおした

前回の調整で**着陸そのもの**はやさしくなったが、点のつけ方が
`滑走路に着いた=40点 + ゾーン内=30点 + 沈下の速さ=30点` のままだったので、
**ぼーっと飛んでいても68点**取れてしまっていた。

風や突風を強くして難しくするのは避け（ご指摘のとおり理不尽になる）、
**着陸の成否ではなく「どう飛んだか」に点を移した**。

| 項目 | 配点 | 何を見ているか |
|---|---|---|
| 着陸できた | 15 | 滑走路に着けば必ずもらえる（初心者の土台） |
| ちゅうしん | 0〜15 | ◎(x=345)からのずれ。±25mは満点、±41mで0 |
| ふわっと | 0〜35 | 接地の瞬間の沈下速度（3.2m/s→0で満点） |
| ライン | 0〜35 | 進入中、緑の線から平均どれだけ外れたか（4m外れると0） |

そのうえで**上達の段が3つになるよう**、緑の線(▲)を◎より**30m手前**に向けた。

1. **何もしない** → 線のとおりに▲へ降りる。滑走路には必ず着く（＝初心者でも遊べる）。
   でも「ふわっと」も「ライン」もほとんど取れない。
2. **線にのせ直す** → 風で流されるぶんを直す。ライン点が伸びる。
3. **接地の直前に機首を上げる（フレア）** → ふわっと浮いて◎まで届き、
   「ふわっと」と「ちゅうしん」が同時に伸びる。

配点を「ちゅうしん15／ふわっと35／ライン35」にしたのが肝で、
**着地位置の点を小さくした**ので、フレアで多少浮きすぎても損をしない。

#### この過程で潰した4つの理不尽

- **機首のききが強すぎた**（`pitch*6`）。直そうとした人ほど行き過ぎて接地が5m/sを超え、
  「強く着陸=12点」に落ちていた。実測すると**へたに操縦する人（11点）が、
  何もしない人（50点）より低い**という逆転が起きていた。
  ききを `pitch*3.8` に落とし、**「強く着陸」の崖をなくした**
  （硬い着陸は「ふわっと」が0点になるだけ。たたきつけ判定は8m/s超のみ）。
- **緑の線が、採点している線と別の場所で高度0になっていた**。
  `glide()` は AIM を狙うのに、描画は `RUN0+6` で接地する線を引いていた（2.7mのずれ）。
  線を `glide()` そのものに合わせ、▲と◎を描いた。
- **フレアで飛び去れた**。機首上げで上昇できたため、早めに引くと滑走路を越えて
  **0点**になった（実測で3回中3回)。`alt<8m` では上昇できず、
  沈下の下げどまりを `max(1.2, alt*0.5)` m/s にした。高い位置で引いても効かず、
  1〜3mで引くと1.2〜1.5m/sになって20〜50m伸びる。**浮き続けることは構造的に不可能**。
  まっすぐ降りているぶんには2.8m/sのほうが速いので、この縛りはかからない。
- **進入の最初の1.2秒はラインを数えない**。わざと線より1.5m上から始める仕様なので、
  手をつける前のずれで減点するのは理不尽だった。飛行中のラインバーも、
  データが貯まるまでは灰色にして「いきなり赤」に見えないようにした。

#### 結果（age 40・ふつう、実機同等の390×844。カッコ内は画面に出る内訳）

| | 前 | 後 |
|---|---|---|
| でたらめ（ランダム操作） | **68点** | **27点** |
| 無操作（画面に触らない） | — | **45〜52点**（ちゅうしん+15／ふわっと+3〜7／ライン+5〜19） |
| フレアだけ | — | **68〜72点**（ふわっと+20〜27に跳ねる） |
| ライン補正だけ | — | 66点（数値シミュレーション） |
| ライン＋フレア | — | **90点**（数値シミュレーション。理想進入で95点超） |
| へたな操縦（反応0.45秒＋行き過ぎ） | 11点 | **47点**（＝無操作と同等。触って損をしない） |

数値シミュレーションは `update()` の式をそのまま写したもので、
無操作の予測値46点に対し実機45〜52点と一致したので、操縦時の値も同じ精度で見ている。

### カーリング — ガイドが「まっすぐ」で、実際は曲がっていた

止まる位置の●は出していたが、**ガイドは直線、石は `curl` で曲がる**ので、
ななめに投げると見た場所と違うところへ行っていた（F に反する）。
ガイドを `step()` と同じ式でなぞる方式に変え、**曲がりもそのまま描く**ようにした。
検算すると予測と実際の停止点の差は**1px未満**（石の半径は9px）。
シートから出る投げ方のときは●を赤にして✕印を出す。

ほかの石との衝突はわざと計算に入れていない。そこは自分で読むところ＝E を満たす。

### ぴょんぴょんジャンプ — 1回踏み外すと2秒で終わっていた

変更した21本ではないが、全体点検で見つけた**明らかに楽しさを損なうもの**。
落下＝即終了だったため、ランダム操作の計測では **2秒・5操作でゲームオーバー**していた。
25秒のゲームが2秒で終わると「どうすればよかったか」が分からないまま終わる（H に反する）。
**1回だけ助ける**ようにした（下の台に戻して「あと1回!」と表示）。
ランダム操作のスコアは 10点 → **36点**。

## 3. 変更しなかった79IDの最終確認

「テストが通るから触らない」ではなく、**明らかに楽しさを損なうもの**が無いかだけを見た。
結果、1本だけ見つかった（ぴょんぴょんジャンプ＝上記）。ほかは次の理由で現状維持とした。

- **ボード／パズル系24本**: 制限時間60〜90秒、操作精度を要求しない、部分点がある。
  失敗の理由も盤面を見れば分かる。運要素が強いのはブラックジャック・ヨット・すごろくだが、
  いずれも1プレイが短く、チップ／役の選択／コイン点で挽回できる。
- **アクション系**: ライフ制（ブロックくずし3・タンク3・ボンバー2・フルーツ3・
  アステロイド3・ジャンプクエスト3・かたむき迷路3・フロッガー3）か、
  進捗に応じた部分点（じんとり・ドットイーター・ボクセル・せんなぞり）があり、
  1回のミスで0点にはならない。
- **スポーツ系**: ボウリングは強さの幅が狭くどう投げてもレーンに届く。
  ダーツ・ビリヤード・ミニゴルフ・カタパルトは狙いを固定してから離せるので
  片手でも精度が出る。
- **一人称系**: ミニマップとコンパスがあり、迷って終わることがない。

現状維持のものを無理に触ると、既に成立している手ざわりを壊すリスクのほうが大きいと判断した。
