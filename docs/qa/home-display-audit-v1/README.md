## 1. 表示サイズ：110％の意味

**主人公の最終表示サイズが仲間・恋人の一律110％という仕様ではない。** `index.html` の `data-home-hero-percent="110"` を `script.js` がレイアウト引数へ渡し、`layoutTerrainCast()` が主人公の既存基準サイズに **1.10倍を追加**する。

5体以下では、`size=min(220,幅×0.62)×0.8` が基準。主人公の正方形画像枠は `size×0.85×1.10`、恋人は `size×0.50`、仲間は `size×0.55`（overview時は共通0.84倍）。同じ奥行きなら画像枠比は主人公/恋人 **1.87倍**、主人公/仲間 **1.70倍**。これは透明余白を含む枠の比で、見えている体の幅・高さ比ではない。

6体以上では列数・行数からセル幅 `cw` と高さ `ch` を決め、`min(cw−10,ch−7)×役割係数×(0.94+0.06×配置段の深度)` を画像のalpha外接矩形の長辺に合わせる。役割係数は主人公1、仲間・恋人0.80。主人公にはさらに1.10倍が掛かる。同じサイズ段ならalpha長辺比は **1.375倍**だが、段ごとの係数や奥行きが違うので全員に対する実比率は一定でない。

さらに現在の `home-population-profile="v1"` は以下の身体表示倍率を持つ。これは今回の変更ではなく、V5以前からの人数対応である。

|人数|1〜2|3〜5|6〜10|11〜18|19〜28|
|---|---:|---:|---:|---:|---:|
|身体表示倍率の上限|1.00|1.00|0.90|0.80|0.70|

縦画面では装着物を含む全体包絡が収まる倍率 `sizeLimit` と比較し、小さい方を採る。座標投影の `scaleX` と `scaleY` も画面・人数・包絡に応じて変化する。したがって「人数によってカメラもサイズも変わらない」は正しくない。個体の描画側で逆倍率を掛け、最終的な画像は `レイアウトサイズ×bodyScale×depthScale` となるため、座標投影が非等方でも画像を縦横に引き伸ばさない。

進化段階・種によってPNGのalpha外接矩形が違う。少人数は同じ画像枠でも体の大きさが違い、大人数は長辺合わせになる。卵・死亡・別れは通常の地形キャスト分岐から除かれるため、歩く全28体の測定とは別扱い。仲間・恋人は専用の画像を使い、主人公の進化段階を共有しない。

装着物は主人公のレイアウト変化に追従し、本体と同じ足元を中心として同じ深度・身体倍率で表示される。恋人のハート・指輪も恋人の子要素として同じ倍率を受ける。指輪には既存の局所1.2倍表示が別途ある。画像と動きの安全余裕は描画保護に入り、後述の身体接触の幅・高さには装着物を加算しない。

**評価（主観）:** 少人数では主人公が明瞭で、遠い個体を少し小さくする表現も読み取りやすい。大人数では既存の縮小が混雑を抑える一方、小さい個体の識別・直接つかむ操作が難しくなり得る。サイズをさらに変更すべき根拠にはしない。

## 2. 奥行きと描画順

深度倍率は背景座標へ逆変換した `z` に対し、`clamp(min+(z−far)/(near−far)×(max−min),min,max)`。

|地域|far〜near|min〜max|最奥比で最前は何％大きいか|
|---|---|---|---:|
|おうち|0.36〜0.96|0.80〜1.00|25.0%|
|もり|0.38〜0.96|0.74〜1.00|35.1%|
|かわ・みずうみ|0.38〜0.96|0.78〜1.00|28.2%|
|とかい|0.53〜0.96|0.80〜1.00|25.0%|
|いなか|0.34〜0.96|0.76〜1.00|31.6%|
|やま|0.43〜0.96|0.76〜1.00|31.6%|
|ゆき|0.50〜0.96|0.80〜1.00|25.0%|
|うみ|0.665〜0.955|0.78〜1.00|28.2%|
|ジャングル|0.46〜0.89|0.78〜1.00|28.2%|
|さばく|0.47〜0.96|0.78〜1.00|28.2%|
|しんかい|0.40〜0.96|0.78〜1.00|28.2%|
|ほしのていりゅうじょ|0.48〜0.92|0.76〜1.00|31.6%|
|おもいでのみずうみ|0.49〜0.95|0.78〜1.00|28.2%|

これらは関数の上下限。個々のキャラクターが装備やUI制約のため両端へ行けない場合、実際に経験する変化はこれより小さい。例えば0.8→1.0は「20ポイント増」「手前から見て奥は20％小さい」「奥から見て手前は25％大きい」を区別する。

本体の描画順は `zIndex=Math.round(a.y)`。足元が画面で下にある個体ほど上に描画する。主人公・恋人・仲間の固定優先順位はない。同じ丸めyではDOM順が効くため、1 native px程度の境界で順序が切り替わる。画像上端・頭の位置では決めない。

恋人の指輪・ハートは恋人のスタッキングコンテキスト内で描画される。一方、主人公の装備 `petAccessory` は兄弟要素で、本体と同じ移動・倍率を受けるが、本体の足元z-indexを明示的には共有せず、今回のDOM検査では `z-index:auto`。他の本体と交差すると装備だけ先に隠れる可能性がある。これはコード上の潜在的不整合で、今回の画像だけから不具合頻度は確定しない。

背景前景は画像へのマスクで遮蔽する。本体の足元順、装備の独立積層、前景遮蔽は別の機構。V5は背景と同じ投影の安全領域を追加したが、旧歩行領域と旧深度投影を保護しているため、全位置が背景写真の厳密な接地点と一致する仕様ではない。画面例には奥の個体が植栽・建物付近に浮いて見える配置があり、これは主観的な自然さの限界として残る。

**固定の「主人公＞恋人＞仲間」描画順は推奨しない。** 奥の主人公が手前の仲間を覆い、足元位置・深度縮小と前後関係が矛盾する。操作優先度を変える場合も、描画順は足元順のままが適切。

## 3. 接触と画像の重なり

足元座標を `a,b` とすると、移動候補 `p` は次の値が1以上なら分離している。

```
sqrt(((p.x-b.x)/((a.w+b.w)*0.5+10))²
   + ((p.y-b.y)/((a.h+b.h)*0.38+10))²) >= 1
```

`w,h` は各画像のalpha外接矩形をレイアウトサイズへ換算した値。足元はalpha矩形の下中央で、画像枠の中央ではない。横長の貝を含むヤドカリは横の必要間隔が大きい。進化・種・人数によるレイアウトの変化が接触サイズにも反映される。装着物・ハート・指輪は身体接触の寸法に入らない。

これは各個体を単純な矩形として判定する処理ではなく、2体の組合せに対する足元間の楕円距離。画面上の身体をピクセル単位で判定していない。前後方向では身体画像が重なっても足元が十分離れれば許容される。「何％まで重ねられる」という固定値はない。深度倍率・bodyScaleもこの式に直接は掛からないので、画面の実画像と接触の占有範囲は一致せず、特に小さく描かれる奥では相対的に保守的になり得る。

経路計画は他個体を障害物として扱い、実行中も毎ステップで再確認する。初期配置が非常に混雑して完全分離できない場合は、全員を地形内に残し、主人公の初期出口を保った上で重なりを小さくする代替配置を選ぶ。既存の接触重なりからの脱出は、すべての該当距離が改善する場合だけ認める。無条件のすり抜けはない。

ただし、接触の線分検査は3 native pxのサンプリング、実行時はステップ終点検査であり、接触楕円との厳密な連続衝突判定ではない。通常速度と0.1秒の上限で1ステップは最大4.2 native px（夜3.15px）。今回の軌跡で新規・悪化接触がないことと、あらゆる接線近傍で一切の瞬間的重なりが不可能という証明は別である。

**評価:** 画像の多少の重なりはすでに許容しており、D案を採用する前提として「画像が重なるから緩和が必要」とは言えない。一方、人数別の対照測定で他個体による到達制限は確認できる。どの接触係数が最小限なのかは現状のままの調査では決められない。

28体時の主人公と恋人を同じy・深度0.92558へ置く仮定で式だけを比較すると、横方向の接触が要求する足元間隔は **46.33 CSS px**、見える身体の半幅合計は **24.95px**。身体画像間に約21.38pxの空白があっても接触境界になり得る。これは同じyを仮定した計算で、その配置への実到達結果ではない。ただし、密集時の見た目に対して接触が保守的である理由を具体的に示す。Dを試すなら一律の割合変更より、表示倍率との関係を先に検証する必要がある。

## 4. 移動優先度・経路・自律行動

- 動的な通過優先権は全役割にない。主人公も恋人も同じ接触述語で仲間に止められる。明示的な手動操作は、その個体の自律移動を12秒抑えるが、他の個体を退かせない。
- 新規・再配置時は主人公のために8方向から短い出口 `max(40,主人公幅×1.2)` を検査する。通常の同期では既存個体を動かして出口を作り直さない。恋人の出口は同等には予約しない。
- 更新は配列順。先に処理された位置を後の個体が見るため同時移動に順序差はあり得るが、「主人公優先通過」の規則ではない。
- 地形は固定8px格子、細かい補助探索、直線検査、到達可能成分の検索を使う。V5は安全な旧経路・目的地を比較し、描画境界・遮蔽・接触の条件を維持する。歩ける空間でも探索の有限解像度や接続候補数による取りこぼしは理論上残る。
- 手動要求は一時閉塞時に最大4回、12秒まで再探索する。自律移動は実行中に安全でなければ停止し、1〜3秒後から次の行動選択へ戻る。常時全員で協調する経路予約や道譲りはない。
- 自律移動の同時実行上限は5体以下で5、6〜15体で3、16体以上で2。大人数で停止が長くなるのは一部が意図した仕様。
- 行動候補は歩く、向きを変える、見る、座る、休む、観察、単独行動、他個体へ近づく・一緒にいる。直前2種類の選択を避ける。気質の大胆さ・好奇心・社交性・持続性が重みに効くが、現在の橋渡しでは個別気質を持つのは主人公で、仲間・恋人は既定3。
- 種別の専用歩行速度はなく、通常42 native px/秒、夜31.5。縮小・座標投影が違うためCSS px/秒は個体が置かれたシーンの投影にも依存する。
- 休息等の選択時間は少人数の夜で `6+乱数×5+持続性×0.35` 秒、6〜15体で `5+乱数×5+…`、16体以上で `9+乱数×12+…`。到着後は3〜8秒。18/35/70秒歩かなければ歩行を選びやすくするが、同時移動上限や経路失敗で実際には歩けないことがある。
- 恋人が主人公から `max(110,(両者幅の和)×0.8+40)` より離れると、近づく・一緒にいる重みが増す。恋人が主人公へ寄る傾向は仕様。画面全体を均等に訪れる設計ではない。
- メニュー等のブロック状態では停止する。reduced motionでは自律移動を無効にする。今回はメニュー閉・ブロックなし・reduced motionなしで測定した。

## 5. 人数別評価と推奨

人数別の実測・結論は [測定一覧](measurements.md) と本節末尾の最終評価にまとめる。通常の人数比較は既存のサイズ・カメラ変更を含む。別の固定カメラ対照では28体の配置から個体を除くだけにして、人数による接触制限を分離した。計画拒否、画面端の安全停止、操作で要求方向に進まないこと、自律的な休息を同じ「失敗率」にまとめない。

|人数|要求方向に実際に進んだ操作|他個体を除くと進める操作失敗の割合|自律移動の平均距離/個体（600秒）|評価|
|---:|---:|---:|---:|---|
|1|4/4（100%）|0%|5207.19px|今回の4方向はすべて進行|
|4|16/16（100%）|0%|3202.94px|身体矩形の重なりが生じても移動・前後関係を維持|
|10|39/40（97.5%）|2.5%|2315.65px|接触で塞がる方向が現れる|
|20|74/80（92.5%）|7.5%|662.79px|主人公右が停止。恋人の自律停止が長い|
|28|78/112（69.6%）|28.6%|492.31px|主人公右、恋人右・上などが制限。混雑の問題が明確|

全252操作は本体の見える部分から入力でき、選択済み地面ドラッグへの代替は0件。操作後30秒モデルを進めて足元・描画端を記録した。これは端への到達率ではなく、要求方向へ0.5px超進めた割合である。

28体時の失敗34件のうち32件は同じサイズ・同じカメラ・同じ開始位置の単独対照で進行する。残り2件（ぷにゅ・ハリネズミの下）は下端近くで `below_minimum_distance`、目的地まで3 native px未満として拒否される。接触の問題と混同しない。

固定カメラ対照では、主人公の左移動は1体187.46px→28体91.63px、右は95.55px→0px。恋人は4体時に右126.56px・下311.46px進めるが、28体では右0px・下1.91px。単に表示倍率が変わっただけでなく、他個体が経路を制限している。

自律移動600秒では全人数で全員が一度以上移動し、接触距離1未満への新規侵入・悪化はサンプル上0件。**今回の条件で主人公・恋人が600秒間まったく動けない状態はなかった。** ただし、28体の主人公は1135.23px、恋人は456.16pxで、最長連続停止はそれぞれ140.3秒・97.2秒。20体の恋人では229.8秒、28体のリスでは430.2秒の停止がある。停止には休息・同時移動数2体の予算・失敗が混在し、これをすべて接触による閉じ込めとは呼べない。

30秒ごとの短距離8方向検査では28体の主人公4/20回、恋人10/20回が全方向不可。20体の恋人では17/20回。これは12px直進の局所的な代理指標で、長い迂回の不可能性や一般的な発生頻度を証明しない。恋人の主人公へ近づく行動と既存の座席配置も影響するため、人数に対して単調な悪化になるとは限らない。

描画を10秒ごとに採取すると、4体では本体alpha外接矩形が平均1.88組重なり、小さい方の矩形面積に対する最大交差率は約45.5%。10体は平均0.05組、20・28体は0組だった。**画像重なりを避ける余裕が見えていても、密集時の足元接触で止まる**という構造と整合する。不透明画素の重なり・隠れた割合とは異なる。

**最終評価:** 少人数について、今回の結果からサイズ・描画順・接触を変える必要は認めない。まずAを維持する。一方、20〜28体の操作自由度についてAが最適と断定するのは適切でない。次の開発を行うなら、**足元順の描画・現在の接触・サイズを維持し、手動操作が塞がれた場合だけ道を譲るCの限定試作**を第一候補とする。Cの改善量は未実測であり、採用決定ではない。Bのすり抜けや固定描画優先は勧めず、Dは表示倍率と接触寸法の関係を別途検証してから判断する。

この調査の結論は「すぐに仕様変更すべき」ではない。**現行V5は維持したまま、混雑時の課題と次の検証対象を明確にする**。無条件の描画優先や衝突緩和を導入する理由は得られていない。

|C 道を譲る|接触を保ちつつ、存在する通路を空けられる可能性。役割優先を描画順へ持ち込まない|退避場所がない密集では解決しない。連鎖的な退避、往復振動、仲間の落ち着きのなさに注意|中〜高。経路再計算増。対象限定・回数制限が必要|今回観測した他個体由来の制限に直接働く可能性。改善量は未測定|
|D 接触を軽く緩和|狭い通路の可用性を増やせる可能性|既に画像重なりは許容。全種・全深度の接触感、既存の安全経路に影響。囲まれた配置が必ず解消するわけではない|係数編集自体は低いが、検証は高い。探索負荷が減る保証もない|未測定。閾値の最適値・効果を断言しない|

固定役割順の描画はA〜Dのいずれにも必要ない。B＋固定役割描画は避ける。CとDを最初から組み合わせると何が効いたか分からず、今回は推奨しない。

将来の最小変更候補は、**手動操作が他個体で拒否されたときだけ**、邪魔している仲間1体に短い安全退避を依頼するCの限定試作。通常の接触・描画・地形を守り、退避先がない場合は現状の停止を維持する。最大回数・クールダウン・手動操作中の個体を退避対象にしない条件を設ける。描画順やサイズを変える必要はない。装備の積層は別の視覚回帰課題として、実際の交差例を再現できた場合にだけ検討する。

## 7. 未検証と再現方法

今回の動的測定は390×844、とかい・夜、ヤドカリ段階5、紙の装備、恋人ゴリラ、固定の仲間集合、乱数seed521の代表条件。全31主人公種×全段階×全装備×13地域×4時間帯の総当たりではない。1・4・10・20・28体ごとに仲間集合、自然な初期配置、カメラが変わるので、人数だけの因果比較は固定カメラ対照を参照する。

600秒の自律シミュレーションは実時間600秒の動画ではない。モデルを進め、10秒ごとに描画を採取した。CSSアニメーションの全位相、Safariのタッチ／フレーム落ち、実機性能、実際の不透明画素の遮蔽率、数時間の閉塞頻度は測っていない。Playwright Chromiumのmobile viewportと実ポインターイベントであり、**実機iPhone Safari検証ではない**。成功率は決めた4方向入力に対するもので、一般ユーザーの操作成功率とは異なる。

