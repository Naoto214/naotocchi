## 2. 通常 spot が画面に持つもの（描画コードから）

`buildWorld()` が spot ごとに作るのは次だけです。

| 条件 | 生成物 | 地図marker |
|---|---|---|
| `s.landmark` | `size 560` の巨大prop（`emoji` 省略時 🌳） | `lm:<id>` tier1/2 |
| `s.prop` が `SPOT_PROP_STRUCT` に有る | `size 210` の struct | `mk:<id>` tier3 |
| `s.prop` がその他の絵文字 | `size 175〜230` の絵文字 | **なし** |
| 上のどれでもない | **何も作られない** | なし |

これに描画側の要素が加わります。

- `kind:'water'` … 半径いっぱいの**青い水面＋濡れ縁**を描く（＝見える特徴）
- `kind:'edge'` / `cam:'wide'` … カメラが引く（430 → 560 / 600）＝「ながめ」が体験になる
- `degree>=3` の path/plaza/grove … **どの分岐にも同じ 🪧**（size 84）が立つ
- `s.secret` … 周囲に遮蔽物4つの輪（＝「奥に隠れている」体験の素）
- それ以外 … 道色の円い地面（alpha 0.28、plaza は 0.5）**だけ**

## 7. §15 内部 navigation spot との分離

`degree`（道の本数）で見ると L0 の多くは 2〜5 本の分岐点で、**path graph の節点として必要**です。
spot 自体は消さず、**通知の可否だけを分ける**のが正しい設計です。

## 8. §16 探索率・§17 セーブ互換

- `recordSpot()` / `recordMapBits()` は**全 spot でこれまで通り呼ぶ**（記録は減らさない）
- 変えるのは「トーストを出すか」だけ。分母（region 11 / link 13 / tier1 17 / zone 103）も式も不変
- レベルは spot データ（landmark / secret / kind / prop / crowd）から**その場で計算**するので、
  セーブに新しい項目を足す必要がなく、旧セーブもそのまま動く
