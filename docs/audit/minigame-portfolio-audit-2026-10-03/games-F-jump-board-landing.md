### doodle-jump（ぴょんぴょんジャンプ）
1. **基本情報**: id `doodle-jump` / 表示名「ぴょんぴょんジャンプ」🐰 / category `doodleJump`（genre action）/ `makeDoodleJumpGame` / 7510-7595 / 通常版のみで、派生版はない。
2. **ルール**: キャラは自動で跳ね続ける。左右に動かして台に着地し、上へ登っていく。台は4種で、緑=普通、青=横に動く、茶=1回で壊れる、🔴バネ=大ジャンプ。⭐コインもある。左右の端はつながっている。落ちても1回だけは救済される（7550-7558）。
3. **入力**: 下のパッドの横デルタ（mgPad delta, x軸, 7524）か、キャンバスの横ドラッグ（7529-7531）。ドラッグ中は p.x を指の位置に直結させる（係数1.4）。スマホでの懸念: キャンバスをドラッグすると指がキャラに重なって見えにくい。係数1.4のため細かい位置合わせが難しい可能性がある（要実機確認）。
4. **長さ**: `mgDuration(25000)` = 25秒（7514）。2回落ちるとその時点で終了。
5. **スコア**: `clamp(round(10 + 到達m/3.8 + coins*3), 10, 100)`（7586）。最低は10点。上限には約342mで届く（コイン0の場合）。
6. **難易度**: 台の間隔 `lerp(48,62)`、動く台の速度 `lerp(40,80)`、普通台の比率 `lerp(0.6,0.45)` が difficulty で変わる（7533, 7535）。高く登るほど間隔が最大+30px まで広がる（7545）。
7. **ランダム性**: 台の種類・位置・バネ・コインがすべて乱数。運の比重は**低〜中**。壊れる台が続いたり台の間隔が広がったりする不運はあるが、救済が1回ある。
8. **技量**: 落下中の横位置合わせ、動く台の先読み、端のワープ利用、バネとコインの取捨。
9. **繰り返し**: 毎回ステージが違うだけで、新しい要素は出てこない。記録は本体のベストスコアだけ（ゲーム内には無い）。5回目くらいで操作感は分かり、以降は距離の更新だけが動機になる。
10. **タグ**: 精密操作 / 空間認識 / 予測 / タイミング。毎秒「次に降りる台を選び、落下中に横位置を合わせる」。
11. **類似**: jump-quest（ジャンプクエスト）や stack 系と「縦方向への着地」が近い。ただしジャンプボタンが無い（自動）ので、判断は「横位置だけ」に絞られている。
12. **固有の核**: 自動ジャンプの軽快さと、画面端のワープ。背景が高度に応じて夜空へ変わっていく（7564-7566）。
13. **キャラ接続**: `currentSprite()` で育成キャラ本人が跳ねる。上昇中と落下中で伸び縮みする演出あり（7570）。台詞は「🔴バネ!びよーん」「💦おっこちた…あと1回!」など状況の説明のみで、キャラらしい台詞は無い。
14. **懸念**: CONTROLS の説明文は **93文字**で、25秒のゲームに対して長い。台の色分け3種とバネの説明を全部読ませている。救済の仕様（1回まで）も説明文に入っている。
15. **改善判断**: 小改善でかなり良くなる。土台はしっかりしている。説明文が長いことと、繰り返しで変化が無いことが弱い。高度に応じた出来事（例: 何mで何かが起こる）を足すと再訪の動機になる。
16. **差し込み候補**: ①救済が発動したとき、キャラが一言（「いまのはノーカン!」など。回数でセリフを変える）。②一定高度ごとに「雲の上のおやつ」など、なおとっち世界の物を置く。③自己ベストm を超えた瞬間にキャラが叫ぶ。

### curling-ice（カーリング）／ curling-winter（ふゆのカーリング大会）
1. **基本情報**: id `curling-ice`（MINIGAMES, category `curling`, genre sports）/ `makeCurlingGame` / 7604-7707。
   **季節版** `curling-winter`（SEASONAL_MINIGAMES 冬, 10212）は**同じ生成関数の派生**で、パラメータの差は `stoneCount: 4`（通常版は未指定→3, 7608）とタイトルだけ。制限時間は両方とも `mgDuration(45000)` で同じ（7608）。CONTROLS の説明文は完全に同一（script.js 15034 / 15068）。天候が雪のときは両方とも出現が2倍に加重される（script.js 13744 `/snow|ski|curling/`）。
2. **ルール**: 自分とAIが交互にストーンを投げる。全部投げ終わった時点で、ハウス（半径62）の中で中心に最も近い石を持つ側が得点する。得点は、相手の最も近い石より内側にある自分の石の数（7668）。ホッグラインを越えなかった石は除外される（7663）。
3. **入力**: 🔴から上方向へスワイプ。スワイプの長さで飛距離（×2.4）、横ずれでカールが決まる（7630-7633）。スワイプ中は予測線と停止位置●が出る（7678-7681）。投げた後はキャンバスを連打してスイープ（7622）。懸念: スワイプ方向の dx が「角度」と「カール」の両方に効くため、斜めに投げると曲がりが二重にかかる。ただし予測線がそれを含めて描くので、実害は小さい。
4. **長さ**: 制限時間45秒（7608）だが、**HUD に残り時間の表示が無い**（ヘッダーは残り石数だけ, 7612）。投げる回数は通常版が6投、冬版が8投。
   - 推定: 石が止まるまで約4〜5秒（初速 √(76×距離)、減速38px/s²）。AIの手番待ちが0.9秒（7666）。
   - 通常版6投で約35〜40秒、**冬版8投だと約45〜50秒になり、45秒の打ち切りに最後の1〜2投が間に合わない可能性が高い**（要実機確認）。
   - 「みじかめ」設定では制限が31.5秒になり、通常版でも途中で打ち切られる見込み。打ち切られると、その時点の盤面で判定される（7692）。
5. **スコア**: 勝ち `clamp(70 + n*10, 70, 100)`（n≥1なので80〜100）、ハウスに石が無い（引き分け）は45、負けは `clamp(40 - n*6, 15, 40)`（7698）。
6. **難易度**: AIの初速精度 `lerp(0.90, 0.99)`、角度誤差 `lerp(0.20, 0.10)`（7652）。AIは50%の確率で、こちらの最も近い石を狙ってはじく（7653）。
7. **ランダム性**: AIの誤差と狙い先の選択。運の比重は**中**。石の数が少ないので、AIのブレ1つで勝敗が反転する。
8. **技量**: 予測線を見ながらの力加減、相手の石をはじく／ガードするといった石の配置読み、スイープの連打量。
9. **繰り返し**: 物理なので毎回の展開は変わる。ただしAIの戦術は2択だけで、5回目くらいで「予測線どおりにボタンに置くだけ」になりがち。冬版は石が1個多いので、配置の読み合いが少し深くなる。
10. **タグ**: 物理エイム / 予測 / 対AI読み合い / 連打。毎投「予測線の●をハウスのどこに置くか（置く／はじく／ガードする）」を決めてスワイプする。
11. **類似**: mini-golf-physics、billiards-6、bowling-3d とは「狙って離す」の点が同じ。異なる点は交互の陣取りと、最後の1投の価値。
12. **固有の核**: 停止位置を完全に予測できる線を見せたうえで、他の石との衝突だけは読ませる設計（7634-7635 のコメント）。相手（AI）の石もスイープで伸ばせる（moving 中のタップは手番に関係なく効く, 7622）。
13. **キャラ接続**: 無し。currentSprite は使っておらず、台詞もシステムメッセージだけ。冬版も見た目は同一で、季節要素はタイトルだけ。
14. **懸念**:
    - 制限時間が見えないまま打ち切られる。冬版は4投ずつと名乗っているのに投げきれない恐れがある（推定、上記4）。
    - 冬版は通常版との体験差がほぼ無い（石+1だけ）。
    - CONTROLS の説明文は **65文字**。
15. **改善判断**: 仕様確認が必要。冬版8投が45秒に収まるかの確認と、残り時間表示の有無は、実機で確かめるべき不具合候補。そのうえで、冬版に見た目か仕様の差（雪、なおとっちの応援など）を付けるかどうかを整理する必要がある。
16. **差し込み候補**: ①スイープ中にキャラ（currentSprite）が氷上をほうきで走る。連打数に応じて「ぜぇぜぇ」。②最後の1投の前に、キャラが相手の石を見て一言。③冬版では仲間が観客席から応援する。

### jenga-tower（ジェンガ）
1. **基本情報**: id `jenga-tower` / 表示名「ジェンガ」🪵 / category `jenga`（genre action）/ `makeJengaGame` / 7711-7786 / 派生版なし。
2. **ルール**: 3本×10段の塔からブロックをタップで抜く。抜いたブロックは最上段に積み直される。安定度（各段について、上に載る重さの重心が支えの範囲内にあるか, 7731-7735）が下がると、確率的に崩れる。
3. **入力**: タップのみ（7738）。ブロックは34×16pxと小さいので、スマホでは誤タップの懸念がある。
4. **長さ**: 45秒（7715）。HUD に時間の表示は無い。20本抜くと終了（7744）。抜ける場所が無くなっても終了（7772-7774）。
5. **スコア**: `clamp(10 + 抜いた数*8 + (崩れていなければ12), 10, 100)`（7777）。崩さずに11本抜けば100点に届く。
6. **難易度**: 崩れる確率 `max(0, (1-安定度) - 0.55) * lerp(0.6, 1.0)`（7750）。安定度が0なら確実に崩れる。
7. **ランダム性**: 崩落の判定だけが乱数。運の比重は**低**。**安定度が45%以上なら崩れる確率は0**（7750）。
8. **技量**: どの段からどれを抜くかの選択。実質的な正解は「各段の両端を抜いて中央を残す」（中央1本の段は安定度100%、端1本だと0%）。
9. **繰り返し**: 盤面は固定で毎回同じ。最適解が分かると毎回同じ手順で100点になり、2〜3回目で枯れる。
10. **タグ**: 選択 / パズル / リスク選択。毎手「この段の端を抜いて安定度がどう変わるか」を確認してタップする。
11. **類似**: stack 系とは逆向きの塔もの。lights-out のような決定論パズルに近い。
12. **固有の核**: 安定度メーターを見ながら、ぐらつく塔をスリルとして味わうこと。積み直しのアニメーション。
13. **キャラ接続**: `currentSprite()` が塔の横に小さく立っている（7767）が、反応は無い。台詞は「😱ぐらぐら…!」など状況の説明のみ。
14. **懸念**: 簡単すぎ。安定度が45%以上なら無リスクなので、運もスリルもほぼ無い。CONTROLS の説明文（**61文字**）が攻略法（真ん中を残す）をそのまま書いている。崩した場合は自分の落ち度ではなく判定の結果に見えにくい。20本で終了するが、得点は11本で頭打ちになるため、その後の9本は無意味。
15. **改善判断**: 大きな改善余地がある。決定論的な最適解があって挑戦が成立していない。ブロックごとの摩擦や重さを乱数にする、抜く操作をドラッグ（引き抜き量）にする、などが必要。
16. **差し込み候補**: ①安定度が低いとき、横のキャラが目を覆う／逃げ腰になる。②崩れたらキャラが下敷きになるギャグ。③15本以上抜くと「もうやめよ…?」と弱気になる。

### line-trace（せんなぞり）
1. **基本情報**: id `line-trace` / 表示名「せんなぞり」✏️ / category `lineTrace`（genre puzzle）/ `makeLineTraceGame`（図形 TRACE_SHAPES 7789-7796）/ 7797-7858 / 派生版なし。
2. **ルール**: 6種類の図形（まる・ほし・なみ・ハート・うずまき・むげん）から3つを乱択（7802）。●から一筆でなぞり、指を離すと判定される。3問。
3. **入力**: ドラッグ（7815-7818）。開始点から30px以内で押し始める必要がある。懸念: なぞっている指で線が隠れる。うずまきは線同士の間隔が狭い。
4. **長さ**: 32秒（7801）。HUD に時間の表示は無い。判定後に1.7秒の間がある（7829）。
5. **スコア**: 1問 = `精度(線への近さ平均)*55 + 被覆率*45`（7826）。最終 = `clamp(10 + 平均*0.9, 10, 100)`（7849）。時間切れで解けなかった問題は平均に含まれない（0点扱いにならない）。
6. **難易度**: 許容幅 TOL を `lerp(16, 11)` で変える（7812）。
7. **ランダム性**: 図形の選択と順番だけ。運の比重は**低**。
8. **技量**: 指先の精度。速さは得点に影響しない。
9. **繰り返し**: 図形は6種で組み合わせは20通り。5回目くらいで全図形を見終わり、「同じ図形をもっと正確に」以外の動機が無くなる。
10. **タグ**: 精密操作 / 観察。毎秒「指を線の中心に保ったまま進む」。
11. **類似**: 担当外の dragDecorate 系やお絵かき系と同じ指操作。判断要素はほぼ無い。
12. **固有の核**: 線の近さに応じて軌跡がリアルタイムで緑〜赤に色付く（7831）。
13. **キャラ接続**: 無し。
14. **懸念**: 時間切れでも解けた問題だけの平均で採点されるので、1問だけ丁寧にやると高得点になる（7848-7849）。指で線が隠れる。CONTROLS の説明文は **43文字**で適切。
15. **改善判断**: 小改善でかなり良くなる。操作そのものは明快。図形をなおとっち由来のもの（キャラの輪郭、食べ物）にすると、意味と再訪の動機が生まれる。
16. **差し込み候補**: ①お手本の図形を「なおとっちの顔」「好物」の輪郭にする。②精度が低いとキャラが「…それなに?」と首をかしげる。③90%以上のとき、なぞった絵がキャラの持ち物になる演出。

### checkers-6（チェッカー）
1. **基本情報**: id `checkers-6` / 表示名「チェッカー」🔘 / category `checkers`（genre board）/ `makeCheckersGame` / 7866-7936 / 派生版なし。
2. **ルール**: 6×6盤で、駒は各6個。斜め前に1マス進み、相手の駒を飛び越すと取れる。取れる手があるときは取らなければならない（強制取り, 7893）。連続ジャンプあり。最奥に着くとキング（後ろにも動ける）。全部取るか、相手を動けなくすれば勝ち。
3. **入力**: 駒をタップし、光ったマスをタップ（7906-7911）。セルは盤幅/6で十分大きい。
4. **長さ**: 60秒（7870）。HUD に残り時間の表示は無い（7876）。時間切れは駒数で判定し、同数なら引き分け（7924）。
5. **スコア**: 勝ち `clamp(78 + 自駒数*4, 78, 100)`、負け `clamp(15 + 自駒数*5, 15, 45)`、引き分け50（7927）。
6. **難易度**: AIの探索深さは difficulty<0.35 なら2、それ以外は4（7897）。評価値に `lerp(1.2, 0.1)` の乱数ノイズが加わる。
7. **ランダム性**: AIのノイズだけ。運の比重は**低**。
8. **技量**: 強制取りを使った誘い込みと連続取り。
9. **繰り返し**: 初期配置が固定で、AIもほぼ決定的。何回か遊ぶと定石化しやすい。深さ4のAIは60秒で全滅させるのが難しく、駒数判定になりがち（推定）。
10. **タグ**: 対AI読み合い / 短期戦略 / 予測。毎手「取らせて取り返す」交換の損得を数手先まで読む。
11. **類似**: reversi-6、animal-shogi、connect-four、gomoku-9 と同じ対AI盤面ゲーム群。チェッカーに固有なのは強制取り。
12. **固有の核**: 強制取りのルールで相手を罠に誘い込めること。
13. **キャラ接続**: 無し。
14. **懸念**: 残り時間が見えないので、時間切れの駒数判定に気づけない。60秒（みじかめ設定だと42秒）は1局には短い（推定）。CONTROLS の説明文は **73文字**。
15. **改善判断**: 他ゲームとの役割整理が必要。対AIボードゲームが多数あるので、短時間の1局で何を味わわせるかを決めたい（例: 詰めチェッカー化）。
16. **差し込み候補**: ①キングになったとき、キャラが王冠をかぶる。②連続取りに成功するとキャラが「いっきに!」と調子に乗る（連続の段数で台詞を変える）。③AI側を仲間キャラにして、負けたときに悔しがらせる。

### memory-cards（しんけいすいじゃく）
1. **基本情報**: id `memory-cards` / 表示名「しんけいすいじゃく」🃏 / category `memoryCards`（genre puzzle）/ `makeMemoryCardsGame` / 7939-7992 / 派生版なし。
2. **ルール**: 4×4の16枚（8ペア）。2枚めくり、同じ絵ならそろう。8ペアすべてそろえれば完了。
3. **入力**: タップのみ。カードが大きいので操作の懸念は無い。
4. **長さ**: 45秒（7943）。HUD に残り時間の表示は無い（ペア数とめくり回数だけ, 7958）。全部そろえると即終了。

9. **繰り返し**: 絵柄は固定の8種（7944）で、配置だけが変わる。何度遊んでも同じ体験。
10. **タグ**: 記憶 / 観察 / 運。毎手「既知のペアがあるか確認し、無ければ未知のカードを開ける」。

13. **キャラ接続**: 無し。絵柄も汎用の絵文字（🍎🐶🚗…）。

## 担当範囲全体の気づき
- **残り時間が表示されないゲームが多い**。curling、jenga、line-trace、checkers、memory、domino、sudoku、mancala の8本は、内部に制限時間があるのに HUD に表示が無い。時間切れで判定されて終わる（特に curling-winter、checkers、mancala は時間内に完走できない恐れがある）。
- **ageDifficulty を取得しているのに使っていないもの**: memory-cards と halfpipe-skate。また閾値が 0.5 / 0.55 の分岐（sudoku の6×6、area-claim の✨2体）は「ふつう」設定では到達しない。
- **決定論的な最適解で枯れるもの**: jenga（安定度45%以上なら無リスク）、domino（点線をタップするだけ）、halfpipe（ポンプ押しっぱなし＋1回転で100点に届く）。「簡単すぎ」の3本で、どれも得点の上限に早く届く。
- **説明とコードの不一致**: domino の「余った手持ちはボーナス」が未実装。sudoku の「まちがうと赤く光る」は重複時のみ。plane-landing のコメント「3かい」に対して定数は2回。dot-eater の「全部食べよう」は時間的にほぼ不可能（推定）。
- **重複群**: 対AI盤面ゲーム（checkers / mancala と、reversi / animal-shogi / connect-four / gomoku）。着陸もの（plane-landing と lunar-lander）。迷路もの（dot-eater と snake / bomber）。
- **季節版の差が薄い**: curling-winter は石が+1されるだけで、見た目・台詞・季節の演出はタイトル以外まったく同じ。
- **キャラ接続**: currentSprite を使っているのは doodle、jenga（飾りのみ）、halfpipe、plane（11pxでほぼ見えない）の4本だけ。キャラらしい台詞や回数に応じた反応はどのゲームにも無く、台詞はすべてシステムの説明。
- **良い実装パターン**: curling の予測線（物理と同じ式で描く）、plane-landing の採点内訳表示と「何もしない／直す／フレア」の3段階設計、doodle の1回救済、area-claim の「囲むと絵が見える」報酬。
- **繰り返しへの備え**: 乱数生成のステージがある dot-eater、area-claim、doodle、domino、sudoku はある程度もつ。盤面固定の jenga、checkers、mancala、memory（絵柄固定）は早く枯れる。
- **手軽な改善策**: 汎用の絵文字（memory の絵柄、area-claim の背景、dot-eater の自機、missile の町）を、なおとっちの仲間・食べ物・家に置き換える。それだけで世界観との接続が大きく改善できる。
