## 4. 最優先の5件

1. **判定の抜け道をふさぐ（stack の開始位相、count の真ん中の数、catch のデコイ、rhythm の空打ち、flames の左端）** — S。「成功・失敗が明確」の前提が崩れている。stack は cue と同時に押せば必ず成功し、count は⭐を見ずに当たる（F6, F7）。どれも数行で、他への影響は記録の分布だけ（性格なし）。
2. **結果演出フック＋○/✕ を小さく（R1, R2）** — S〜M。台詞を足さずにゲーム固有の成功・失敗の絵を出せる唯一の土台で、F4 により cliff の落下・shutter の写真など既存の絵が今は見えていない。個別のゲームの絵の追加（holdlid の 🤡 など）はこの上に S で積める。
3. **入力の持ち越し遮断と開始猶予（R3, R4）** — S。こする系→スワイプ系で「触っていないのに失敗」がコード上起きうる（F9）。クイックは連続性が売りなので、iPhone の誤操作に直結する。
4. **画面高さの正規化（R5、特に umbrella と feather）** — S〜M。低い画面の Lv5 umbrella は約0.28秒、feather は羽が画面外に消える（F11）。端末による不公平の解消。G-QI-05 の実機測定と同時に進める。
5. **重複群の差別化（stop の複数たこやき、fish のニセあたり、pushbox の止めどころ、pull の戻り、flee の2体）** — 主に S（stop だけ M）。50本を維持したまま「繰り返しても単調になりにくい」を大きく改善する。暗記化している color / season / weather の答えプール化（S）も、この次に続ける。

（T9 の判断が必要な R8 レベル曲線・R12 振り返り・partner/doors の仲間0人は、判断が出しだい S で実装できる。）

## 5. 気づき（5行）

1. クイックは `individualGameResult` より前に抜けるので、どの改善も性格の C/B 到達率に影響しない（individuality-runtime-test:56-61 が保証）。ただし avgSkill（れんくん）は点数で動くので、成功率を変える案は G-QI-10（T9）とあわせて見る必要がある。
2. いちばん大きい問題は「つまらない本」ではなく、結果表示中に update が止まるため、すでに書かれている成功・失敗の絵（cliff の落下、shutter の写真、charge のジャンプ）が見えていないこと（F4）。
3. 判定の抜け道が2件ある（stack は t=0 で真上、count は正解がいつも真ん中の数）。テストは target() の理想操作だけなので、こうした抜け道は見つからない。
4. iPhone での事故の主な原因は、ゲームをまたぐポインタの持ち越し（F9）と画面高さの差（約220〜510px、F10）。どちらもランナー側の1か所で直せる。
5. 重複群は、本数を減らさなくても「判断を1つだけ変える」（複数・ニセ・戻り・止めどころ・空いている方）で分けられる。どれも通常ゲーム並みのルールにはならない。
