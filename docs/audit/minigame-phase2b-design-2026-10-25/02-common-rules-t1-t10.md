## 1. T1 対戦・終局の点数尺度

### 現行仕様（main f16e0f37 で確認）

| ゲーム | 勝ち | 時間切れ・引き分け | 負けの上限 | 根拠 |
|---|---|---|---|---|
| reversi-6 | 60〜100 | **50**（石の数が同じ） | 45 | g:4618 |
| animal-shogi | 70〜100 | **50** | 45 | g:4907 |
| connect-four | 72〜100 | **55** | 45 | g:5665 |
| gomoku-9 | 72〜100 | **55** | 45 | g:6294 |
| checkers-6 | 78〜100 | **50**（駒の数が同じ） | 45 | g:7972 |
| mancala-kalah | 70〜100 | **50** | 45 | g:8323 |
| air-hockey | 70〜100 | **50** | 48 | g:6030 |
| tennis-rally | 70〜100 | **50** | 48 | g:6485 |
| curling-ice / winter | 70〜100 | **45**（ハウスに石がない） | 40 | g:7741 |
| pingpong-3d | 62〜 | 同点は負け扱い（20〜） | — | g:3397 |
| fp-dungeon | 脱出: 40〜100（宝0個でも約52〜68） | 時間切れ: 15〜45（宝3個でも45） | — | g:1329-1330 |
| tower-defense | 時間切れでも「守りきった」＝勝ち（60〜100） | — | 55 | g:3966, 3971 |
| roguelike-dungeon | 60〜100 | 時間切れは負けの帯（最大58＝B） | 58 | g:4092 |
| bubble-shooter | 100 | 時間切れ: 20〜**92** | 55 | g:5442 |
| line-trace | — | 終わった問題だけで平均する（1問満点で時間切れ→100） | — | g:7891-7892 |

- **実測（無操作）**: 盤上6本は、何もしないと必ず時間切れの引き分けになる。点は 50〜55。
  - connect-four と gomoku は **55＝B**。reversi / animal-shogi / checkers / mancala は **50＝C**。
  - air-hockey は 0-0 で 50（C）。curling は 45（C）。
  - 出典: `agg.tsv`（3シード、ふつう・みじかめとも同じ値）。
- まだ共通の関数はない（`mgVersusOutcome` は grep で0件）。

### 問題点
- **負けそうなとき、時間切れまで粘る方が得**になる。引き分け（50〜55）が負けの上限（45）より高いため。
- 「みじかめ」では盤上の制限時間が 60秒→42秒 になる（実測。T3）。そのため時間切れの引き分けがさらに起きやすい。
- 結果として、性格の C（35以上）・B（55以上）、コイン30（30以上）が、勝負の内容と関係なく出る。
- fp-dungeon は「宝0個で脱出」が「宝3個で時間切れ」より高い。脱出ゲームとしては筋が通るが、宝の価値が小さすぎる。

### 選択肢
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A | 現状維持。説明文に「時間切れは引き分け」と書く | 変更なし | 粘り得が残る。C/B が勝負と無関係に出る |
| B | 時間切れの引き分けを、負けの上限以下（40〜45）に下げるだけ | 数行×6本 | 優勢のまま時間切れになっても報われない |
| **C（推奨）** | 共通の点数帯（下表）を `mgVersusOutcome(kind, quality)` にまとめる。時間切れは盤面の優劣で「判定勝ち／互角／判定負け」に分ける | 1つの表で全部そろう。粘り得が消える。説明しやすい | 約14本を触る。C/B の到達率が変わる |
| D | 時間切れを廃止する。手番の区切りまで延長して決着させる | いちばん公平 | プレイ時間が読めなくなる。T3・T4 とぶつかる |

### 第一推奨: 案C の点数帯

| 終わり方 | 点数帯 | ランク | 例 |
|---|---|---|---|
| 決着勝ち・クリア | 70〜100（内容で加点。余裕勝ちで S） | A〜S | 4つそろえた、全部とった、宝3個で脱出 |
| 時間切れ・優勢（判定勝ち） | 55〜69 | B | 時間切れで石・駒・点が多い |
| 本当の引き分け（盤が埋まった、同点で終局） | 45〜50 | C | connect-four の盤が満杯 |
| 時間切れ・互角 | 35〜45 | C の下限 | 時間切れで同数 |
| 時間切れ・劣勢（判定負け）／決着負け | 10〜45（進み具合で） | D〜C | |
| 入力0回 | 25以下 | D | T7 の共通処理 |

- 原則は1行: **「時間切れで取れる点は、同じ局面で決着したときの点を超えない」**。
- 個別の扱い:
  - fp-dungeon: 脱出は 40＋宝×15＋残り時間（最大10）。時間切れは 15＋宝×10（最大45）。
  - tower-defense: **生存型なので「時間まで守りきった＝勝ち」を正とする**（現状維持）。説明に「○秒守りきれば勝ち」と書く。
  - line-trace: 平均の分母を問題数（3）にする。手をつけていない問題は0点。
  - bubble-shooter: 時間切れの上限を 69（勝ちの帯の下）にする。

### 推奨理由
- **公平性**: 粘り得が消える。勝った人が必ず上になる。
- **楽しさ**: 「優勢なら時間切れでも B」で、最後まで攻める理由ができる。
- **直感性**: 結果の文言（勝ち／判定勝ち／引き分け／負け）と点の帯が1対1になる。
- **保守性**: 1つの関数と1つの表。新しい対戦ゲームを足すときも、これを呼ぶだけで済む。

### 影響
| 項目 | 内容 |
|---|---|
| 影響するゲーム | reversi-6、animal-shogi、connect-four、gomoku-9、checkers-6、mancala-kalah、air-hockey、tennis-rally、pingpong-3d、curling-ice、curling-winter、fp-dungeon、line-trace、bubble-shooter（TD・roguelike は説明文だけ） |
| 性格（C/B） | 時間切れで出ていた C/B が減る。ただし性格の各欄は**1人生で最大6件**（individuality.js `experience`: `a.length>=6` で打ち切り）。なので**総量は変わらず、たまる速さと「どのゲームで付くか」が変わる**だけ（推定） |
| コイン・そだち | 時間切れの 50〜55 は「成功」帯（30以上）のまま。コイン30・そだち+7 は変わらない。B→C の変化はコインに影響しない（境目は 30 と 70。s:17140-17141） |
| 実績 | 条件は変えない。過去の自己ベストは巻き戻さない（推奨） |
| セーブ | 形は変わらない |
| 会話 | `reactionInput.score` / `band` は新しい点で正しく渡る（s:17252-17260）。会話のコードは変えない |
| 実装規模 | M（関数1つ＋14本の呼び出し差し替え＋全本のテスト） |

### 人間の判断が必要な部分
- 点数帯の表そのもの（とくに「判定勝ち＝B」「時間切れの互角＝C の下限」）。
- tower-defense の「時間切れ＝勝ち」を正とするか。

### 選択肢
| 案 | 内容 |

| C | 現状維持。届かないゲームを王冠の対象から外す（実績の表示の変更） |

- beach-volley: 勝ったときの加点を 22→30 にする（最高96）。または「3点差以上の勝ち＝+10」。
- puzzle-2048: 段を1つずらす（256→75、512→90、1024→100）。

### 推奨理由
- 100点を全部にそろえると、満点の価値が下がる。手間も大きい。
- S は実績・王冠・成長ブースト（s:17196-17198 `BOOST_TICKS_S_RANK`）につながる「本当の目標」。そこに届かないことだけが、遊ぶ人に不公平。

## 3. T3 「みじかめ」設定の原則

### 現行仕様
- `mgDuration(ms)`（s:2945-2951）:
  - 「みじかめ」は、**20秒以上のゲームを一律×0.7**にする。
  - 「やさしい」は×1.2。
- 測定（`agg.tsv`）: 通常100本のうち **71本**で、終わる時刻が「みじかめ」で縮んだ（無操作）。
  - 盤上6本: 60.6秒 → 42.6秒。
  - sugoroku: 50.6秒 → 35.6秒。
  - curling: 45.6秒 → 32.1秒。
  - solitaire / sudoku: 90.6秒 → 63.6秒。
- 前回資料で数値が確定しているもの（今回は測り直していない）:
  - grand-prix: みじかめでは、ブーストなしの2周完走が0%（G-AC-33）。
  - sky-shooter: みじかめではボス戦が3.9秒（G-AC-34）。
  - curling-winter: 8投が必ず打ち切られる（G-FG-10）。
  - sugoroku: みじかめでは84%が時間切れ（G-FG-14）。
- **時間で終わらないゲーム**（無操作だと 240秒たっても終わらない。実測）: pinball-physics、ski-jump、darts-board、blackjack-21、track-field、yacht-dice。どれも「入力しないと進まない」型。

### 問題点
- 「回数で区切るゲーム」（周回・ボス・投数・手番）は、時間だけ縮むと、**最後まで遊べないゲーム**になる。
- 盤上ゲームは、時間切れの引き分けが増える（T1 の粘り得を強める）。

### 選択肢
| 案 | 内容 |
|---|---|
| A | 現状維持（全部×0.7） |
| **B（推奨）** | **手番で進むゲームは「みじかめ」の対象外**にする（`mgDuration(ms, {turn: true})`）。回数で区切るアクションは、回数・周回・ボスの出現を比例で縮める（`mgScale`） |
| C | 全部 `mgScale` で比例させる（手番も減らす） |
| D | 手番の区切りで終わる（時間が来たら、その手番が終わるまで待つ） |

### 第一推奨: 案B
- 対象外（手番型、約15本）: reversi-6、animal-shogi、connect-four、gomoku-9、checkers-6、mancala-kalah、curling-ice、curling-winter、sugoroku-race、solitaire-klondike、hit-blow、slide-puzzle、sudoku-mini、picross-5、push-puzzle。
- 比例で縮める（回数型のアクション）: grand-prix-3d（周回）、sky-shooter（ボスの出現）、tower-defense（ウェーブ）、missile-command。

### 推奨理由
- 「みじかめ」を選ぶ人の目的は「1回を短く」。手番型は、**1手の重さを変えずに時間だけ削ると、ただ時間切れが増えるだけ**になる。
- 対象外にするのは、フラグ1つで済む。手番の時計を作る案（D）より小さく、壊れにくい。
- 設定画面の文言は今の「20秒以上を70%」のままでよい。「考えるゲームは そのまま」を1行足す。

### 影響
| 項目 | 内容 |
|---|---|
| 影響するゲーム | 上の約15本（対象外）＋4本（比例） |
| 性格・コイン | 「みじかめ」の人だけ、時間切れの引き分け（C）が減る。勝ち・クリアは増える（推定） |
| 実績・セーブ・会話 | 影響なし（設定の値 `minigameLength` は変えない） |
| 実装規模 | S（mgDuration にオプション1つ＋15か所）＋ M（mgScale を4本） |

### 人間の判断が必要な部分
- 「みじかめ」を選んだのに、盤上ゲームが短くならないことを許すか。

## 4. T4 残り時間の表示

### 現行仕様
- 時間制限があるのに、画面に残り時間を出していないゲームを静的に調べた（`timer.cjs`。canvas 上の描画は目視していないので**推定**）。
  - breakout、cake、bento、crane、rhythm、mini-golf、pingpong、roguelike、grand-prix、push-puzzle、reversi、animal-shogi、connect-four、gomoku、picross、pipe-connect、lights-out、jenga、line-trace、checkers、memory、domino、sudoku、mancala（24本）
  - ＋ tower-defense（制限は g:3965 の `mgDuration(90000)` で、表示なし）
  - 計 **約25本**。前回資料の「約16本」より多い。
- 共通の部品 `mgTimerHud` はまだない（grep 0件）。
- Phase 1 の W03 で、4本のヘッダー初期値を実際の制限時間から作るようにした（解決済み）。

### 問題点
- 「時間切れ」で点の帯が決まる（T1）のに、残り時間が見えない。
- 時間切れが**不意打ち**になる。

### 選択肢
| 案 | 内容 |
|---|---|
| **A（推奨）** | すべての時間制ゲームに、共通の残り時間（`mgTimerHud`）を出す。残り5秒で色を変える |
| B | 盤上・パズルだけ細いバーで出す（数字は出さない） |
| C | 現状維持 |

### 第一推奨: 案A
- 理由:
  - **直感性**: 「あと何秒」が分かると、時間切れの点（T1）に納得できる。
  - **保守性**: ゲームごとに作っている `残り：○秒` を1つにまとめられる。
- 盤上ゲームは、ヘッダーの右側（「○の番」の横）に小さく出す。

### 影響
| 項目 | 内容 |
|---|---|
| 影響するゲーム | 上の約25本 |
| 性格・コイン・実績・セーブ・会話 | 影響なし（表示だけ） |
| 実装規模 | M（部品1つ＋差し込み25か所） |

## 9. T9 Quick と avgSkill

### 現行仕様（grep で全部たどった結果）

| 対象 | 場所 | Quick で動くか |
|---|---|---|
| `state.minigameScoreSum += rawScore` | s:17143（**isQuick の判定 s:17146 より前**） | **動く** |
| `state.minigameCount += 1` | s:17144（同上） | **動く** |
| `state.lifetime.minigamesPlayed += 1` | s:17145 | 動く（実績 `minigame-50/300/1000` s:2224, 2257, 2309） |
| `actionCounts.play`、`envPlays` | `notePlayStarted` s:17910-17913（tryStartPlay s:17936） | 動く（実績 `play-100`、`rain-play`、`snow-play`、`night-play-10`） |
| 記録 `minigameRecords['quick-run'/'quick-solo']` | s:17136 | 動く。S の実績は通常100本だけを数えるので関係ない（s:2344-2348） |
| コイン | 混合ランの 20/20 だけ 100（s:17148） | — |
| 性格・そだち・勧誘・ストーリー | s:17146-17161 の return で通らない | 動かない（`individuality-runtime-test.cjs:56-62` が保証） |

- **avgSkill の使い道は1か所だけ**:
  - `pickTransformCandidates`（s:960）で `avgSkill = minigameScoreSum / minigameCount` を計算する。
  - それを、隠しキャラ「れんくん」の候補条件 `minigameCount >= 5 && avgSkill >= 85`（そだち80 では 78）に使う（s:989-990）。
  - ほかのファイル（会話・個性・Director など）には参照がない（リポジトリ全体を grep）。
- 値は1人生ごと（`freshState` s:1473-1474。新しい人生で `lifetime` 以外はリセット）。
- Quick の点: 混合は「クリア数×5」（q:914, 981）。1本ずつ（solo）は「クリア数×10」。
- テストの前提:
  - `quick-mode-test.cjs:196`: `s.minigameCount === 1`（solo 1回で1）。
  - `individuality-runtime-test.cjs:59,61`: 50本＋混合で `minigameCount` が 50 → 51。
  - どちらも「結果処理が最後まで動いた」ことの目印として使っている。

### 問題点（推定の計算）
- **Quick solo で「れんくん」の条件を満たせる**。
  - 例: ふつうのゲームを20回、平均75点で遊んだとする。
  - そこへ、やさしい1本を solo で10/10（100点）を20回足すと、avgSkill =（1500＋2000）÷40 ＝ **87.5**。85 を超える。
- 逆に、Quick を気軽に遊んで40〜60点が続く人は、avgSkill が下がる。
  - 「Quick は育成に影響しない」（spec / README）に反する。
- Quick の役割（短時間・直感）と、avgSkill の意味（育成の腕前）が混ざっている。

### 選択肢
| 案 | 内容 |
|---|---|
| **A（推奨）** | **Quick は `minigameScoreSum` / `minigameCount` に足さない**（2行を isQuick の後ろに移す）。`minigamesPlayed`・`actionCounts.play`・`envPlays`・記録・100コインは今のまま |
| B | 混合ランだけ足す。solo は足さない |
| C | 現状維持。spec を「Quick も腕前に入る」と書き直す |
| D | Quick の点を別の値にため、どこにも使わない |

### 推奨理由
- **役割分担**: 通常＝育成・性格・腕前、Quick＝短時間の手応え。avgSkill は育成側の値なので、Quick は入れない。これで spec と実装が一致する。
- **公平性**: solo で稼ぐ抜け道が消える。Quick を気軽に遊んでも損をしない。
- **禁止事項**: Quick に育成効果を足さない（むしろ減らして、元の約束に戻す）。実績の数え方（`minigamesPlayed`）は変えない。
- **保守性**: 2行の移動。

### 影響
| 項目 | 内容 |
|---|---|
| 影響するゲーム | quick-run、quick-solo（Quick 50本すべて） |
| 性格 | 影響なし（もともと通らない） |
| 育成（れんくん） | 条件が「通常のゲームだけの腕前」になる。Quick で底上げしていた人は、出にくくなる |
| 既存セーブ | 形は変わらない。今の人生にたまった Quick の分は残る。**次の人生で自然に消える**（1人生の値のため）。移行処理は要らない |
| 実績 | 変わらない |
| 会話 | `conv2Quick`（s:6800）は quickRun の統計を使い、avgSkill を使わない。影響なし |
| テスト | 3か所（上記）の目印を `lifetime.minigamesPlayed` に変える必要がある。**テストの意図を変えることになる** |
| 実装規模 | S |

### 1本ずつの方針
1. **sugoroku-race（中改善）**
   - ① 同点の時間切れを最下位にする（T7）。
   - ② 目を 1→6 の順に回す。速さは難易度で変える（T8）。これで「止めたい目」を狙えて、S にも届く（T2）。
   - ③ 「みじかめ」の対象外にする（T3）。
   - ボードとマス目の仕組みはそのまま使えるので、全面の作り直しは要らない。
2. **blackjack-21（中改善）**
   - ① 各ハンドで賭けを選ぶ（20 / 40）。判断を1つ足す。
   - ② 点の式は「チップの増減」の帯を T1 にそろえる。勝ち越し＝B〜、イーブン＝C の下限。
   - ③ 難易度でディーラーの止まり方を変える（T5）。
   - 基礎点50 を下げると C の割合が下がる＝**人間判断**。
3. **jenga-tower（中改善）**
   - ① ブロックごとに見える「きつさ」を乱数で付ける。
   - ② 満点を「18本」に伸ばし、文言の「20こ」と合わせる。
   - ③ 安定度の閾値を難易度で変える。
   - 安定度の計算（g:7774-7777）は使い回せる。
4. **halfpipe-skate（中改善）**
   - ① 下り坂の後半だけポンプが効く（タイミング判定）。上り坂で押すと減速。
   - ② 同じ回転を続けると加点が減る（いろいろな技の価値）。
   - ③ 着地の許容角を難易度で変える。
5. **domino-run（中改善・全面に近い）**
   - ① 手持ちを「すき間ちょうど」にする。
   - ② 置く場所を点線の上だけでなく自由にする。間隔が広すぎると倒れない（倒れの伝わり方 g:8152 は既存）。
   - 遊びの中心が変わるので、設計の承認が要る。ただし倒れの仕組みは残せる。
6. **solitaire-klondike（小改善）**
   - ① 目標を「台に○枚」にし、点の帯を枚数で決める（T1・T2）。例: 12枚＝C、24枚＝B、完成＝S。
   - ② 「みじかめ」の対象外（T3）。
   - ③ めくる枚数を難易度で変える（T5）。
   - 解ける配りの保証（ソルバー）は後回しでよい。
7. **push-puzzle（小改善）**
   - ① 手作りの面を4→12に増やす（各面の最短手数をテストで確かめる）。
   - ② 難易度で面の段を選ぶ（T5）。
   - ③ 残り時間を出す（T4）。
   - 逆再生での自動生成は、品質（つまらない面が出る）のリスクがあるので後回し。
8. **dragDecorate-cake（中改善）**
   - ① 注文カード（ランダムな順番と場所）を出す。
   - ② 置いた位置の正確さで点を付ける（中心からの距離）。
   - ③ トッピングを3→5にする。
   - ④ 完成の絵を見せてから終わる（T8）。
   - 「初めてのドラッグ」という役割は残す。

### 結論
- **全面の作り直しが本当に必要なものはない**。8本とも、今のゲームの骨組みを残したまま直せる。
  - 中改善: 6本。domino-run はその中で全面に最も近い。
  - 小改善: 2本（solitaire、push-puzzle）。
- 共通ルールが先に決まると、8本のうち7本で改善の設計が簡単になる。
  - T7（共通の無操作ガード）と T1（点の帯）: sugoroku、blackjack、push-puzzle。
  - T3（手番型は対象外）: sugoroku、solitaire。
  - T5（難易度ノブ）: 7本。
- 性格への影響: jenga / halfpipe / domino / cake は今「ほぼ全員が B」。改善すると B の割合が下がる。ただし欄の上限が6件なので、1人生の総量は変わらない（推定）。
