| 項目 | 内容 |

### 1-4. 第一推奨: B案「とりやま」

- 唯一の完全な複製を解消できる。
- 釣りに足りない「どこへ投げるか」の判断が入る。ためゲージの「遠くへ投げる」という表示にも、ようやく意味が出る。
- **群れだけでは効かない**。試作では、群れを足しても近投げが一番有利なままだった（近投げ82.9点、群れを読む人69.2点）。巻き取りの距離の損（g:3066）を sea だけで軽くして、初めて「群れを読む人」が一番になった。この2つは**1組で入れる**こと。
- 会話の台詞（「大物を逃した」など）とも矛盾しない。

### 1-5. 実装時の注意

- 群れの移動先は update の中で乱数を引く。**描画（render）では乱数を引かない**。鳥の羽ばたきは `now` から計算する。
- 新しいオプション（例: `hotspot: {kind:'flock'}`）で、sea だけに効かせる。real-fishing の挙動は変えない（real-fishing を含む会話テスト tests/conversation-postgame-test.cjs:30,104,172 があるため）。
- tests/minigame-phase1-core-test.cjs:135-140 は `category:fishing` と `game:fishing-river` の台詞の範囲を見ている。ID とカテゴリを変えなければ影響はない。
- 依存する T判断はない。

### 1-6. iPhone 実機で確かめること

- 鳥の群れが、小さい画面でも水面の上に見分けられるか。
- ためゲージの「群れまでの距離」の印と、実際に落ちる位置が合っているか（幅が実機とハーネスで違う）。
- 群れが動いた直後に投げ直したくなるか。いまは待っている間に回収できない（normal-games-1 の real-fishing A案 (a)）。投げ直しの手段がないと、群れを追う判断が成り立たない。**共通の「回収」と同時に入れるのが望ましい**。

| 会話との整合 | **「流れを読んだ」（cp:593）と食い違ったまま残る**。会話は今回触らないため、A案だけでは不整合が解消しない | 台詞とそのまま合う | 合う |

### 2-4. 第一推奨: B案「ながれとよどみ」

- 説明（タイトル・desc）と会話の台詞の両方が、すでに「流れを読む」ことを約束している。これに挙動を合わせるのが、いちばん変更が少ない整合のとり方になる。
- 岸まで流れたら自動で回収されるので、「待つしかない」という釣り全体の弱点も、river では解消する。
- sea の「とりやま」と同じ部品（寄りやすい場所 = hotspot）を使い、場所が動く（sea）か、固定で流れが運ぶ（river）かで違いを出す。
- **T8（G-AC-25）の判断が要る**。T8 で「文言を直す」が選ばれた場合は A案になる。ただし、その場合は会話の台詞との食い違いが残ることを、判断の材料として示す。

### 2-5. 実装時の注意

- 流れの線は `now` で動かす。よどみの位置は、投げるとき（cast, g:3002-3008）か開始時に update 側で乱数を引く。描画では引かない。
- 自動回収は「逃げた」に数えない（得点式の −4 に入れない）。
- 雨の日に流れを速くする案もありうる。ただし、天気で難易度が変わると、同じ記録 ID で条件が揃わなくなる。入れるなら見た目だけにする。

### 2-6. iPhone 実機で確かめること

- 流れの速さと画面の幅の釣り合い（よどみを通る前に岸に着いてしまわないか）。
- 渦の印が、水の色（#5fc0b0 → #1c5a5a）の上で見えるか。
- 「上流に投げる」ことに、説明なしで気づけるか。気づけない場合は、最初の1投だけヒントを出す。

### 7-4. 第一推奨: B案「はるかぜ」（ただし7本の中で最も低優先）

- タイトルの「そっと」と、会話の「くしゃみ、がまんできなかった」に、体験として応える。春の間だけ出やすい限定版らしさが出る。
- C/B の到達率を変えず、上の段（A/S）だけに判断を足せる。育成への影響が最も小さい。
- **現状維持でもよい理由**: stack の6本は、地域・季節の「出会い」の見た目として役割が成り立っている。点数も簡単に頭打ちになる。直す必要性は、釣りやカーリングよりはっきり低い。ほかの6本を先に進め、余裕があれば入れる。
- leaves（秋）には同じ風を入れない。重複になるため。

### 7-5. 実装時の注意

- **花びらを fillText('🌸') で描かない**。tests/minigame-illustrations-test.cjs:77-90 は、画像が読み込めた後に 🌸 の fillText が0になることを確かめている。花びらは小さなピンクの楕円で描く。
- 同じテストの 99-111 行は、Math.random を0.5に固定して、絵の有無で描画の命令（署名）と結果が同じことを確かめている。0.5なら風は0になる（`(0.5×2−1)×40 = 0`）ので、このテストはそのまま通る見込み。花びらの位置は `now` と風の値から計算し、描画で乱数を引かない。
- tests/minigame-phase2-randomization-test.cjs:89-118（開始位置の乱数・直後に押してもパーフェクトにならない）は、風が4段目からなので影響しない。
- 描画のゆれ（g:297 の `Math.random`）は、終わった後（over）にしか起きないので、遊んでいる間の結果には影響しない。

- 風で流されたとき、「自分のせい」ではなく「風のせい」と感じられるか（不公平に感じないか）。
