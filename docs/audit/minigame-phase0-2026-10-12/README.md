## 数字（再検証した結果）

前回監査とその付録にあった指摘を**全件、コードで再検証**し、次のように分類した。

| 区分 | 件数 | 内容 |

| 確定不具合（挙動を直す） | **19** | 正本だけで正しい挙動が一意に決まるもの。うち8件は再現スクリプトの再実行かコードで直接確認済み（✔） |
| 確定不具合（文言・コメント側を直す） | **15** | 実装は正しく、説明・コメント・README が古いもの |

| 改善工程送り | 多数 | 面白さ・役割の話で、不具合ではないもの |

**主な確定不具合**（詳細は 01）
- push-puzzle: 1問解いただけで100点になる（再現済み）
- shanghai: 12〜19%の配りで全部取りきれない
- sudoku: 正しい別解がミス扱いになる
- bubble-shooter: 降下のたびに泡が消える、ずれる
- mini-golf: ホールが飛ばされる、6打の上限を抜けられる
- クイック: 質問が命令口調で読まれる。「1本ずつ」の自己ベストが偽りになる。「なかまは？」で正解が2つになる
- なかまの誘いから遊んだ回は、雨・雪・回数の実績に数えられない
- 30〜69点の帯で、そだちが上がった瞬間に結果トーストが消える

修正は、13個の**再利用できる修正単位（U1〜U13）**に集約した。たとえば入力ロック、検証つき生成、アクション時計と HUD、対戦の終局理由、正誤マーク、開始時の共通記録など。

## 停止点: 人間の判断が必要なこと

ユーザーの指示に従い、**新しい意味論・性格の獲得方法・育成効果に関わる判断はここで止めている**。

1. **T0 性格（traitCounts）の扱い**
   - 現行コードには性格を増やす処理が1つもない。せいかくクイズは 2026-09-06 の PR #132 と #133 で消え、廃止の記録はない。
   - そのため新規セーブでは、**実績3つ・ゴール⑤（とレインボーのテーマ・♾️のせかい・⑤のあいさつ）・れんくんの恋愛ルート**に到達できない。
   - 案 A（クイズを復元）／ B（既存の行動で加算）／ C（実績から外す）／ D（文言だけ直す）から選ぶ必要がある。比較は 03 を参照。
2. **T1〜T10**（02 を参照）
   - 対戦の点数尺度、100点に届くべきか、「みじかめ」の原則、残り時間の表示、難易度の配線の原則、ゲームごとの判定の意図、無操作のときの点数、説明と実装のどちらを正とするか、クイックの仕様（特にクイックが avgSkill を動かす件）、本体とのつながり。
3. **反応基盤について確認が要ること**（04 を参照）
   - pet-expression の REACTIONS に minigame の表情を足してよいか。
   - クイックの後にキャラの吹き出しを出してよいか。
   - 本当の天気や恋人の名前をクイックの出題に使ってよいか。

**判断を待たずに進められるもの**
- 01 の確定不具合19件と文言15件（W15 を除く）。
- 反応基盤の v0（挙動は変えない。トーストの保護 B05 だけ含む）。

## その後の改善工程案

| 工程 | 内容 | 前提 | 規模の目安 |
|---|---|---|---|
| **Phase 1 確定不具合の修正** | 01 の P1-a〜P1-e（5本の小さな PR）。各 PR に回帰テストを付ける。B10・B09 の過去の記録は巻き戻さない（推奨） | なし（すぐ着手できる） | 小×5 |
| **Phase 2 仕様判断の反映** | T0〜T10 で決まったものから順に実装する。共通単位（U3 HUD、U4/mgScale、U5 mgVersusOutcome）を使い、テーマ単位で一括して入れる | 人間の判断 | テーマごとに小〜中 |
| **Phase 3 反応基盤 v0→v2** | `minigame-reactions.js`（純関数とデータ）と script.js の薄いアダプタ。v0 は挙動を変えずに導入し、既存テストが全部通ることを条件にする。v1 でジャンル単位の台詞を少しずつ足す（テキストのレビュー付き）。v2 で30〜69点帯の静かな反応と表情 | v0 はなし。v1・v2 は台詞のレビューと表情の確認 | 中 |
| **Phase 4 付加情報とクイックへの適用** | `onComplete(score, msg, detail)` の口を開ける。対戦と釣りから始める。クイックの最終画面の一言と、判定表示の一言 | Phase 3 v0 | 中 |
| **Phase 5 派生ゲームの差別化** | road / stack / fishing / ring / curling の各派生に、小さな判断差・地域差・季節差を付ける（構成と本数は変えない）。まず反応のスコープで差を付け、ゲームの判断差は1本ずつ承認を受けてから | 人間の承認 | 1本ずつ小 |
| **Phase 6 小改善の一括対応** | 前回監査 F の44本を、パターン単位でまとめて直す（時間と目標、乱数化、絵柄をなおとっちに寄せる、など） | Phase 2 の原則 | 中 |
| **Phase 7 大改善の9本** | 前回監査 G（すごろく、ブラックジャック、ジェンガ、ドミノ、ハーフパイプ、ソリティア、そうこばん、カタパルト、ケーキ） | 1本ずつ設計の承認 | 1本ずつ中〜大 |

**この順番にした理由**
- 点数と判定が信用できない状態（Phase 1）のまま反応や改善を足すと、「自己ベスト」「惜敗」などの反応が誤った記録の上に乗ってしまう。
- 反応基盤は、v0 で挙動を変えずに入れられる。そのため、仕様判断を待つ間も並行して進められる。
- 派生ゲームの差別化と個別の改善は、反応基盤のスコープ（gameId / home）ができていると、ゲームを作り直さずに一部を実現できる。
