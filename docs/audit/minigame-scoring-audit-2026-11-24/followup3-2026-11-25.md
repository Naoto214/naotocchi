## 0. 時間の めやす【コード】

- 1 tick = 3秒、1さい = 20 tick = 60秒。**一生(100さい)= 約100分**の プレイです(ページを開いている間だけ時間が進む)。
- 「100日間の育成」は、このゲームでは「一生(100さい)」に あたるので、**一生を 1回 = 1サンプル**として シミュレーションしました(1人物像 × 1案 につき 20〜40回)。

## 2. 一生シミュレーション【シミュ】

- 本物の script.js を ハーネスで動かし、tick・ごはん・そうじ・ねる・くすり の ボタン・ミニゲームの 結果処理(finishMinigame / 途中でやめる)を 実際に 通します。A/B/C は しっぱい時の 2行だけを 差しかえました。

- 限界: ボットの お世話は 単純(なでる・おでかけ・アイテムは 使わない)。絶対値より **A/B/C の差**を 見てください。

※ メーターが まだない ゲームでは、1回の 操作で 記録されます(Phase 5 で 全100本に 広げる予定)。記録されれば「挑戦して 29点以下」と 同じ扱いです。

放置・途中終了が 得に ならないか:
- **どの案でも、まじめに遊ぶ ほうが 放置・途中終了より 得**です。しっぱい でも きげん +5〜10(放置 +2)・へんしん +25(放置 0)で、30点以上なら コイン・そだち・おとろえ回復が 加わります。シミュでも「途中でやめるだけ」は 一生で そだち 44・コイン 0・寿命 46さい で、しっぱいの 多い 初心者(そだち 69・寿命 97)より ずっと 不利でした。
- 途中終了の げんき −6 は 挑戦(−12)の 半分なので、げんき だけ を 見ると 途中終了が 軽いです。ただし げんきは ねれば 数秒で もどる 量で、育成上の 差には なりません。
- C案で「わざと しっぱい する(意味のない入力で 記録だけ させる)」ことの 得は、きげん +5 と へんしん +25 だけで、これは A案でも 同じ(A案は おとろえ・いのちが 加わる だけ)です。コイン・そだちの 差は 残るので、わざと しっぱい が まじめな プレイより 得に なることは ありません。

## 5. 推奨

**C案(実際に挑戦して 29点以下なら、おとろえ・いのち ともに 加算しない)を おすすめします。** B案でも 結果は ほぼ 同じです。

理由:
1. シミュレーションで、寿命・そだち・へんしん・コインへの 影響は A/B/C で ほとんど 変わらず、ペナルティの 効果は「おとろえ・まえぶれ の 出やすさ」に 限られる。ゲームバランスを 支えているのは、ご指摘のとおり **コイン(0 / 30 / 60)と そだち(0 / 7 / 14)の 差と、げんき の 消費**。
2. A案には「高齢期は 挑戦するより 途中でやめる ほうが 安全」という 逆転があり、運のゲームの 負けが 寿命を 削る。B・C案は どちらも これを なくせる。
3. B案と C案の 差は おとろえ平均で 0.1〜0.7 程度で、育成上の 意味は ほとんど ない。C案は「ミニゲームで しっぱい しても いのちも おとろえも 変わらない」と 子どもにも 説明でき、なおとっちの「安心して 挑戦できる」方針と いちばん 合う。
4. C案でも、放置・途中終了・わざと しっぱい が まじめな プレイより 得に ならない(3章)。

B案を 選ぶ 場合: 「しっぱい にも 少しだけ 重みを 残したい」ときの 案です。数値は おとろえ +2〜+4、いのち 0。

## 6. Phase 2 の 最終確認(初心者が 不利に なりすぎていないか)

### 6-1. 30点以上に なる 割合(自動プレイの でたらめ操作、16本)【自動】

- 変更前: 記録された回の 60%(61/102)が 30点以上 → 変更後: 35%(31/89)。記録されない回(放置・スタートだけ など): 6 → 19。
- でたらめ操作は「何も 達成していない」初心者の 下限の めやすで、ここが 30点未満に なるのは 方針どおり です。ただし **A案のまま Phase 2 だけを 公開すると、初心者の 記録された しっぱいが 約1.6倍(40% → 65%)に なり、おとろえ・いのちの ペナルティを 受ける回数が ふえます**。

## 7. 同時公開 と 別々の 公開

| | 同時(同じ日に 両方) | ペナルティ変更を 先 → Phase 2 | Phase 2 を 先 → ペナルティ変更 |
|---|---|---|---|
| 初心者への 影響 | しっぱい が ふえる と 同時に ペナルティが なくなるので、きびしい 期間が ない | きびしい 期間が ない | **しっぱい が ふえて、ペナルティも 残る 期間が できる**(おすすめしない) |
| 原因の 切り分け | 2つの 変更が 重なり、問題が 出た ときに 切り分けにくい | 1つずつ 確認できる | 1つずつ 確認できる |
| 公開の 手間 | 公開ゲート(script.js と games.js の 承認差分)を 1回で | 2回 | 2回 |
| 説明 | 「採点を 見直し、しっぱい しても 寿命が 減らなく なりました」と 1回で 伝えられる | 2回に 分けて 伝える | 2回 |

**おすすめ: ペナルティ変更を 独立した PR で 用意し、Phase 2 と 同じ日(ペナルティ変更 → Phase 2 の 順)に 公開する**。PR を 分けるので 切り分けは でき、初心者に きびしい 期間も できません。Phase 2 だけを 先に 公開するのは 避けてください。
