# 3Dホーム version 8 — iPhone QA追加改善

対象: Draft PR #426、version 7の継続。採用は本人iPhone Safari試遊後。mainマージ・本番Pages更新なし。

## 正式な来訪人数

| 区分 | コード上の仕様 |
|---|---|
| 仲間の登録 | 通常18種＋レア8種＝現行有効ID26種。個別IDを重複獲得しない。独立した人数制限の定数はなく、現行マスターの集合が範囲。過去の互換IDはcanonical化される |
| 現在の仲間 | `state.companions`。絆が0になればその人生で離れる。登録履歴とは別 |
| 現在の恋人／配偶者 | `state.partner`の単一オブジェクト、最大1人。NPC／通信相手のいずれでも同じ枠 |
| 恋人図鑑 | 正式NPC18種の履歴。18人を同時所有・来訪できる意味ではない |
| ホーム来訪 | **仲間または恋人1人、主役込み最大2体** |
| 来訪者選択 | 絆60以上の現仲間＋現恋人を候補化。双方いればカテゴリは各50%、仲間カテゴリ内は抽選。単一visitorスロットを使用 |
| 時間 | 共有セッションの予算に従い、最初の訪問はactive-time300秒以降。滞在60〜180秒、訪問間隔の制限300〜600秒と共有イベント制限あり |
| 非表示 | 睡眠、育成中以外、ミニゲーム、めぐる、メニュー、hidden時に来訪を終了。候補離脱／期限で帰る。関係や登録は消さない |

根拠: `character-world-master.v1.js`のcompanions/partners、`script.js`の獲得処理・homePresentCompanions/homePresentPartner/updateHomeVisits/renderCompanionRow、`relationship-life.js`のcreateSession/createVisits。既存`docs/qa`やrelationship-free-life系テストとも整合。`POLICY.partyMax=2`はめぐるの同行人数で、ホームの来訪人数ではない。version7の6体画像は負荷用fixtureであり正式同時来訪ではなかった。比較ページも最大2体を初期値として明記した。

## サイズ・操作

390px時の画像枠198px(90%)／176px(80%)／154px(70%)を主役＋仲間／主役＋恋人で切り替えられる操作見本を用意。**176px維持**。正式最大人数が2体であり、人数依存の縮小を必要とする根拠がないため。Cloud Chromeの操作見本で70/80/90%を比較し、正式最大2体の表情・分散を確認した。サイズの最終評価は本人実機QAに委ねる。相対体格と仲間0.55／恋人0.5の既存比率、人数に依存しない幅基準、カメラ・分散移動は維持。

タップは正式PNGのbody boundsを先に調べ、手前の透明余白が奥の来訪者の見える部分を奪うケースを改善。44px以上の補助タップ域は残す。輪郭ピクセル単位の判定ではなく既存cast-boundsの矩形。完全に重なった箇所では手前が優先される。静止横一列へ変更せず、既存の離隔・移動・自律行動を維持。

## 都会

灰色台形の原因はHome専用の縦道路 `x=-100,z=-300..1150,half=240` と都会の全面アスファルト配色。縦道路を削除し、同じめぐるsegment meshで以下を構成した。

- 中央: z1400、幅220の車道。車の既存経路そのまま、中央線追加。
- 手前: z1150の歩道。通行人の既存z1150経路は全区間でsolidに接触しない。
- 道路両側: z1280/1520に縁石。ホームの既存車道侵入禁止を維持。
- 奥: z1650の歩道。既存shopfrontの部品を回転し入口を通り側へ向け、入口への接続路を追加。colliderも同角度に回転。
- 前景: 芝生と細い散策路の小公園。中央道路とは舗装色を分離。街路樹を歩道から離し、共通bushを端に追加。

新レンダラーなし。共通rendererにHome cityのsegment色/薄い高さとHome用地面配色を渡すだけ。通常のめぐる・他地域は既存配色/形状を使う。森・水辺のオブジェクト配置、川幅、魚群/魚影/波紋、共通地形・衝突・経路探索を変更しない。

## 初回案内

`タップで選択・ドラッグでおさんぽ`は初回のみ。キャラタップの既存足元リングで選択を表示。成功した**キャラからのドラッグ**で習得を記録し、その散歩終了／中止後に行を折りたたむ。すぐ折りたたむと再レイアウトが最初の移動先を消すため、再現テストで保護した。失敗／キャンセル／地面からのドラッグは習得にならない。

「とじる」でも終了可能。「メニュー → あそびかた」でいつでも読め、「ホームで案内を見る」で再表示。再表示は一時的で既に習得済みの永続記録は戻さない。

保存は`${SAVE_KEY}:home-guide-v1`という端末UI設定のみ。育成セーブJSON／schema／性格／関係値を書き換えない。storage拒否でもセッション内で動作。試遊版は既存の別originと`naotocchi-home-diorama-preview-v1`キーから派生し、本番と分離。

## UI・検証

年齢/そだち/お金 → 環境 → 名前/成長 → 初回案内 → イベント通知のv7構造を維持。通常は案内高さ0、390pxで約27pxを活動領域へ戻す。通知キュー／内容／報酬／優先度／Conversation v2を変更しない。

管理プレビューは当初容量不足で起動できなかったが、既存成果を保持したまま復旧した。同一公開sourceでCloud Chromeの320/375/390/430px相当の画面を確認。都市の道路・歩道・公園、2体配置、70/80/90%比較、案内再表示/非表示、通知＋会話の配置見本、森・水辺を確認した。撮影画像はブラウザー側に保存できたが、共有先への同期が失敗し、GitHubへ保存・添付できなかった。画像7種類の納品は未達。v7の既存画像は docs/home-free-terrain-20261023/screenshots/ にある。

幅320/375/390/430相当のレイアウト数値、人数変化時の主役サイズ不変、正式最大来訪2体、都市歩行経路と地形、案内保存・再表示・ドラッグ成功判定は自動テストで検証。スマホの実際の見た目・表情の見やすさ・タップ/ドラッグ・WebGLの画質・safe-area・長時間の滑らかさは本人iPhone Safariで要確認。

再開時にタップ判定修正によるキーボード選択の回帰を発見し、失敗する再現テスト→修正→12/12成功。独立レビューでも都市の3つの入口と奥側歩道の接続・扉の向き・保存分離を検証し、重要指摘なし（レビュー担当の焦点テスト16/16）。

最新main 76f32494を作業ブランチへ統合。index/package/allowlistの競合は双方の必要な変更を保持し解消。mainへのマージ・Pages公開は行わない。

検証結果はVALIDATION.md、公開の正確なSHA/アクセスはPUBLICATION.md。比較画像7種類の保存と本人実機QAは未達。CIのHome layoutで旧来の全document canvas数検査が失敗したため、めぐる画面内の数へ修正。再実行の結果はVALIDATION.mdを参照。
