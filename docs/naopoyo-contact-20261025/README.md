## 実装と適用範囲

- 同種族の合体・余剰分離が優先。8+8と異種族は双方の通行・上昇・門条件を交換前に確認する。合体が地形条件で拒否された場合を交換で回避しない。
- 交換は2体の位置を原子的に変え、操作キャラ→相手の順で実進入の地形効果、重力の順。自然落下では交換しない。8+8は落下時には足場として残る。
- 両側が岩／壁の斜め移動と分裂体の配置経路を禁止。片側だけは可。キャラと魔法門は角の岩に数えないが、門への実進入は各キャラ・合体結果・余剰ごとに判定する。
- 出口は条件不一致でも通行・停止・保存できる。停止には通常の支持が必要。条件一致時だけ救出し、合体結果・余剰・交換相手にも同じ判定を適用する。出口そのものは支持を与えない。
- 交換の表示は180msの小さな弧、落下を伴う場合は交換180ms＋落下240ms。表示待ちで入力をロックしない。再タッチは表示中の生存キャラを選び、表示を確定して新しいジェスチャーへ移る。reduced-motionは演出のみ省略。
- 新キー `naopoyo.komorebi.contact.20261025.v1`（QAは `.qa`）。旧pilot/supportedキーは読取専用で進捗・ヒント等のみ移行。旧盤面とUndoは解釈し直さず旧キーへ書かない。

## 18・20の最小再設計と採否

18: 岩(3,6)→(3,7)、8門(3,7)→(3,6)。岩数・門条件・トゲ・出口・初期数字を維持。門の先への閉じた斜め角を、岩に登って門を横に渡る経路へ変更。単純な岩除去案は門を回避できるため採用しなかった。[比較](evidence/candidates-18.json) / [門を上げた案](evidence/gate-step-18.json)。

20: 岩(4,7),(4,5),(5,4)を除去し、岩(5,3)を追加。出口・門・トゲ・初期数字は維持。門の先の岩支持をなくしたため、別の8を下へ運んで足場にしないとトゲへ上がれない。上部では閉じた岩角を開き、7が左上の岩を回って星へ届く経路を残す。出口を近づけたり、初期数字を簡単にしたりしていない。

単一岩除去3案では20は解答不能。3か所を開けるだけの案、上下の門を移す案等も比較し、解答を実行確認でき、既存の門条件・出口条件・トゲ配置を維持できる案を採用。[単一変更比較](evidence/candidates-20.json) / [複合変更比較](evidence/workshop-20.json) / [追加比較・探索上限](evidence/final20.json)。探索上限に達した案を解答不能とは呼ばない。

20の機構を一つずつ禁止した全探索では、分裂なし80状態、合体なし1状態、余剰なし1状態、下8門なし25状態で解なし。このため位置交換だけで突破できない。[アブレーション](evidence/ablation-20.json)。確認済み85手では下8門と上3門を使用し、右4門を使わない合法別解となっている。上3門の必須性は探索上限で未証明。位置交換そのものは確認済み解答では必須ではなく、操作の自由度として追加した。
