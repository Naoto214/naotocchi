## 波の調査と修正
旧B初期状態の実engine検証でt=2000msに魚x1→2、x3→4の1歩移動は成立。2000〜2800msの発光中は追加移動しない。水中はy3..6だが波はy3..5で、水中全域に波が当たるわけではなかった。移動の瞬間と余韻の見た目が同じで、個体の移動アニメーション・停止理由がなかった。Safari固有の原因を断定しない。
新表示: 常時点線で波の通る列、予告時は金色の帯と方向・秒数、発動時は帯全体を明るくし泡の余韻、実際に移動したキャラだけ220ms補間。足元輪と黄色枠は即時更新した論理マス。入力を受けたら補間を終了し操作を優先。発動時刻と個体別from/to/結果をlastWaveに記録し、押した数・合体/分裂・停止を表示。装飾だけで動いたと扱わない。
波の判定は既存どおり周期の発動瞬間、前方から順に1体ずつ。泡の移動は発動後の余韻で二度目の衝突ではない。途中で帯に入ったら次周期が対象。岩・門・非適性水中は停止、合体/分裂/出口/重力は既存v2 APIを使用。

新たに、指を通れない門へ進めたまま波を待つと、過去に拒否された指のマスが波の後に再実行され、次の指の1マス移動で2歩進む問題を再現。失敗テストでx6（期待x5）確認後、マスへの入力意図は拒否時も消費する修正。波後もactive IDを保持し、指の次の1マスで1歩だけ移動。
時刻管理・停止/復帰・保存の方式は変更なし。整数ms、背景時停止、復帰時catchupなし。視覚receiptは非保存、Undo/Retry/Restoreで消去。
