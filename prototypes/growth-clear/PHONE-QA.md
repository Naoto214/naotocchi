# なおぽよ・ドロップ 新ルール iPhone試遊

標準は新ルール2／6・残存位置A。`player.html`が新しい試遊画面です。`index.html`は従来の比較ラボのままです。既存の560試行・エンジン・バッグは変更していません。正式採用・mainマージ・公開版更新はしていません。

## iPhone Safariで開く

### 非公開のCodespaces（HTTPS）

1. GitHubのNaoto214/naotocchiで、PR385のhead branch `feat/naopoyo-growth-clear-20261015`を選び、そのブランチのCodespaceを開きます。
2. リポジトリ直下で `python3 -m http.server 8765 --bind 0.0.0.0` を実行します。既存サーバーが使うポートは避けてください。
3. Portsで8765を転送し、Visibilityは **Private** のままにします。表示されたHTTPS URLをコピーします。
4. iPhone Safariで同じGitHubアカウントにログインし、そのURL末尾に `/prototypes/growth-clear/player.html` を付けて開きます。
5. 「保存して戻る」で開始。比較費用や種族を変える場合は「新しく開始」。コードのmainマージ・GitHub Pages変更は不要です。

Codespaceはこの作業では作成していません。既存の契約・利用枠の範囲で利用してください。接続URLは実際のCodespaceが発行するものを使い、上記の説明から推測して作らないでください。
GitHub公式説明: https://docs.github.com/en/codespaces/developing-in-a-codespace/forwarding-ports-in-your-codespace

### PCと同じWi-Fiで開く（外部公開なし）

1. PCにこのブランチを取得し、リポジトリ直下で上記Pythonコマンドを実行。
2. PCのWi-FiのIPv4アドレスを確認（例:192.168.1.20）。ファイアウォールは家庭内ネットワークからの8765接続を許可。
3. iPhone Safariで `http://PCのIPv4:8765/prototypes/growth-clear/player.html` を開く。`localhost`はiPhone自身なので使いません。
4. 同じURL・同じSafariで保存と再開を確認。HTTPではWeb Locksを使えないため、**1タブで試遊**してください。保存時には更新番号を照合し、別画面の更新を検出したら上書きを停止します。HTTPSのWeb Locksと同等の排他保証ではありません。
5. 終了後にサーバーをCtrl-Cで止める。ルーターのポート公開は不要です。

### 単体HTML

既存ビルダーと同じesbuild方式で、全31種族×8段階の画像・4再生記録・CSS・コードを1ファイルへ内包できます。

```sh
# esbuildを利用できる環境で、リポジトリ直下から実行
node prototypes/growth-clear/build-phone.cjs
```

出力: `prototypes/growth-clear/phone-standalone.html`（生成物・git対象外）。配信URLの末尾をこのファイルへ置き換えても遊べます。ランタイム外部依存はありません。iPhoneの「ファイル」アプリ内HTMLプレビューはSafari実行と異なるため、実機QAは上記HTTP/HTTPS経由で行ってください。

Workの実行環境からiPhoneへ到達する一時プレビューURLは取得できませんでした。Sitesの利用可能なデプロイAPIはproductionとして扱われるため、今回は利用していません。公開URLを新設する場合は別途承認が必要です。

## 操作と演出

- 左右ボタン長押し／左右スワイプで移動。盤面タップで右回転。回転・逆回転ボタン、下ボタン、下スワイプ／一気に落とすボタン。
- 卵: 卵在庫→種族画像→列（3タップ）。へんしん: 道具→盤面キャラ→変更後画像（3タップ）。だいへんしん: 道具→元画像→変更後画像（3タップ）。同じ種族への変更は無効。選択取消は無料。
- 変更前画像と変更後候補は横並び。対象を金色の輪郭、次の着地で接続する候補を緑色の輪郭で表示。番号は常時表示。
- 通常操作／道具選択中も落下。着地で選択を解消し、別キャラへの誤使用を防止。落下中ペアに衝突する道具は資源を消費せず拒否。
- 同種進化: 膨らむ→金色の光→段階変化→弾む。異種: 水色の光→柔らかな光の粒→空きマス→重力。
- 2連鎖から数値、3連鎖から星と複音、5以上は大きな金色表示と3音。音は明示的にONにしたときだけ。1波420ms、4連鎖以降350ms（描画フレームにより多少変動）。10連鎖は約3.7秒。
- 卵: 落下→殻のひび→孵化→通常の連鎖（追加480ms）。08寿命: 温かな光と「おめでとう！ いのちが めぐった！」。
- 設定／背景移行は明示的休止。進化演出中は状態更新を直列化し二重入力を防止。これは道具選択中の時間停止とは別です。
- 保存キーは `naopoyo-growth-clear-phone-v1` のみ。旧ゲーム／図鑑のデータを読んで登録状態を変更したり、書き換えたりしません。記録は試遊専用。保存禁止環境は警告付きで保存なし試遊。
- 演出中の中断では、直前に保存済みの安定した状態から再開します。演出途中そのものの再開は行いません。クリア後は終了表示（エンドレス続行UIは今回の範囲外）。

## 自動検証と限界

専用モデル／DOM／mutation・既存ルール・全体回帰の実行結果は`phone-qa-results.json`を参照。単体HTMLも実行可能なDOM環境で検証。

実ブラウザの操作API（control-browser）がこの環境では利用できず、管理環境のSites規則に従いブラウザ導入／代替操作を行っていません。**WebKit・Safariの実画面レイアウト、音、ジェスチャー体感は未検証**。DOM試験を実機QA合格として扱いません。

320×568、375×667、390×844、430×932を対象に、下記の実ブラウザ試験を用意しました。44pxの主要ボタン・横はみ出し・操作領域の下端・画像読み込み・10連鎖を検査してスクリーンショットを保存します。

```sh
# PlaywrightとWebKit導入済みの端末、試遊サーバー起動後
BROWSER=webkit node prototypes/growth-clear/tests/phone-browser.cjs
# 必要ならPLAYWRIGHT_PATHでパッケージを指定、TRIAL_URLで試遊URLを指定
```

盤面セルは狭い画面では44px未満です。列タップやキャラ選択の正確さはHuman QA必須。極端に低い画面（高さ500px未満）は縦スクロールを許し、操作を切り落としません。
