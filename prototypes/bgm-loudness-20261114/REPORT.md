# V7 全32曲 最終ラウドネス最適化

音楽は完成済みとして保護。個別補正は全32曲0dB。変更は別ページBGM共通ゲイン0.9→0.36（−7.9588dB）と、そのJSキャッシュ参照3件のみ。主旋律・編曲・音色・余韻・圧縮・原盤に変更なし。PR549を基準とする独立Draftで、本番main/本番サイトは更新しない。

## 実際のゲイン経路

本体: source → 曲フェード → duckGain1 → playerOut1 → fileBus(0.4/0.28) → bgmBus0.28 → master0.9 → destination。定常積0.36。別ページ: source → 曲フェード → duckGain1 → playerOut0.9 → destination。両方とも同じAudioGainの線形振幅係数で、BGM経路に追加EQ/コンプレッサー/ユーザー音量係数はない。明示level0.36で積を整合。汎用forPage既定値0.9やcreateのlevel指定機能は変更しない。

別ページの効果音・操作音は別系統。なおころのofficialAudioはsoundBgm:falseで、ミニゲームiframeの音/声は親へ委譲する既存構成。BGM音源の二重再生を避ける既存構成を保持。ゲームのBGMオン/オフ、効果音設定、声設定は変更しない。端末音量やOS処理はこの線形ゲイン計算の外。

実際のホーム/なおぽよ/なおころ/CARDのHTML文書をChromium/WebKitで読み、AudioNode接続を観測して定常BGM1本・実効ゲイン0.36を検証。制御状態を渡した既存audio.jsの実ブラウザ試験では4時間帯、ゲーム、クイック、睡眠、イベント、孵化、音声ダッキング、BGMオフ/再開を検証。OSの声出力だけはスタブであり、声の実際の発声を確認したものではない。

## 測定条件と限界

AAC全32曲とFLAC全32曲のSHA256一致を先に確認。前回の同一ファイルのEBU128全時系列を継承し、今回AACをデコードしてゲームと同じ正確な曲尺へ末尾paddingを除いた解析も実施。解析結果のI差はAAC/FLACで最大0.1LU。小数0.1表示による丸めと解析器差を補正対象にしない。既存PRのloudnormによるIとは特に短いジングルのゲーティングに差がある。

- FFmpeg7.1.5 ebur128、BS.1770のK重み付け・ステレオエネルギー和。Integratedは400msブロック/100ms更新、絶対−70LUFSと相対−10LUゲート。
- Momentary400ms、Short-term3秒、100ms記録。M/S表示自体はラウドネスゲートをかけない。STの分位点は完全な3秒窓かつmax(−70,I−20)以上を選ぶ記述統計で、Integratedのゲートとは別。
- LRAは3秒窓、絶対−70/相対−20LUゲート、10〜95百分位。短いジングルでは参考値。
- True Peakはebur128 peak=trueのオーバーサンプリング。アナログ出力や端末内DSP後の実測値ではない。
- 帯域エネルギーはWelch/Hann8192点・44.1kHz・50%重複、20Hz–20kHz全電力に対する割合。聴感ラウドネスの割合ではない。
- モノラルは(L+R)/2を左右に複製してチャンネル数を揃え、元のステレオと比較。単一チャンネル計測の3dB差を位相損失として誤算しない。
- 導入/終止はmin(8秒,曲尺/3)、通常部はその間、クライマックスはST最大3秒窓という測定上の定義。作曲上の感情的な頂点とは限らない。各区間の境界時刻とM/S中央値・最大値はdetailed32.json。窓の終了時刻が区間内にある値を集計するため、区間冒頭のM/S窓には直前の区間の音も含まれる。

規格/実装資料: [ITU-R BS.1770](https://www.itu.int/rec/R-REC-BS.1770) / [EBU R128](https://tech.ebu.ch/publications/r128) / [FFmpeg ebur128](https://ffmpeg.org/ffmpeg-filters.html#ebur128-1)。

## 音色・マスキングと小型スピーカー感度分析

機種固有の実測資料は使用していない。以下はiPhone測定曲線ではなく、低域再生能力の異なる仮定の感度分析。共通条件はモノラル合成、2次Butterworth HPとLPの直列、因果フィルター、中域基準、正規化/音量補償/歪みなし。生成物は解析用メモリだけで、原盤・配信音源へ適用しない。

| 仮定 | HP | LP | 全32曲のI変化範囲（mono損失込み） |
|---|---:|---:|---|
| wide_120_12k | 120Hz | 12000Hz | -1.6〜-0.4 LU |
| small_250_8k | 250Hz | 8000Hz | -2.2〜-0.8 LU |
| limited_400_6k | 400Hz | 6000Hz | -2.8〜-1.4 LU |

低域の多い録音は仮定のHPで影響が増え、同じLUFSでも中域主体の旋律が相対的に残りやすい。ピアノの短いアタックと弦/木管の持続はM最大・crest・S最大の差へ現れるが、楽器別の快適さを決定する指標ではない。元の混合マスターからは楽器ごとのマスキングを一意に分離できないため、帯域電力と声部構成を記録し、推定値だけの補正を行わない。音色差/楽器の重なりによる局所変動は既存の曲内表現として保護。

モノラルI損失は次表/CSVに記録。帯域別mono損失とL/R相関も収録。電力の損失があることを自動的に位相不良とはしない。典型的なステレオ幅による差を補正すれば、ステレオで音量を上げてしまうため、個別補正しない。モデルを変えても0.9→0.36の線形スケール差は常に−7.9588dBなので、この修正には機種モデルの不確実性がない。

## 自動検証と未測定項目

- 全64原盤/32配信用AAC/ホームlock16のSHA256、32ID/曲名・3158旋律音・配置50行を保護。原盤完全一致なので曲内ダイナミクスも完全一致。
- 修正前は実AudioContextで0.9対0.36の不一致を検出、修正後は3ページ一致。効果音・音声・save・選曲・fade・出力方式コードは元と同一。
- 実HTML4文書のBGM出力経路、同じ曲の反復選択、定常BGM1本をChromium/WebKitで確認。制御入力のruntime試験で日内/ゲーム/睡眠/イベント/孵化/音声duck/オンオフ/急な切替を確認。意図的なクロスフェード/ジングルoverlayの重なりは許容。
- 既存比較ページの出力中断/再接続/HTMLAudioElement切替は既存試験で確認。実機のスピーカー振動やBluetooth/イヤホン抜去のOS経路を自動試験で証明したものではない。
- 技術的に確定できないもの: 楽器別の知覚的マスキング、端末DSP/音量段階/置き方/周囲騒音による絶対音圧、音色の好み。原盤ゲインを変更する客観的根拠なし。
- 実機でのみ判定できるもの: 特定iPhone本体の音圧・音質・音割れ、出力先切替後の実際の可聴性。今回の共通ゲイン整合はこれらの追加試聴を条件にせず、線形経路の自動検証で完了させる。
