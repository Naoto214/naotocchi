# 正式統合の手順案（VERSION 5 を採用する場合・未承認）

この文書は、試遊版のパッチ（`lib/v5-patches.mjs`）を**そのまま本番へ写さず**、正式のコードへ書き直して入れるための手順です。統合は、本人の承認後に**別のPR**で行います。PR #517 はマージしません。

## 0. 前提と守ること

- 変更は `prototypes/card-game/` の CARD GAME の実行ファイル、その文書（`docs/card-game/`）、テスト、配信リスト（`tools/pages/allowlist.json` の CARD GAME の行）に限ります。
- 他のゲーム、本番の2.5Dホーム（`index.html` などリポジトリ直下の画面）、共通の画像は変えません。
- 共通ルール（こいびと±0・結婚前の別れ−5・結婚+10・結婚後の別れ−10、#515）は変えません。
- **保存は「操作の記録を再生する」方式です**（`engine.mjs` の `restore`）。そのため、新しい能力は新しい版でだけ働くようにします。そうしないと、今ある対戦の保存（`hotseat-7` 以前）を再生した時に、結果が変わってしまいます。

## 1. 版

| 項目 | 現在 | 統合後 |
|---|---|---|
| 対戦の版 `VERSION` | `hotseat-7` | `hotseat-8`（`RULE_VERSIONS` に追加。旧版は残す） |
| CPU 判断の版 `POLICY_VERSION` | `heuristic-2` | `heuristic-3`（中級だけ結婚の能力を評価。初級は変えない） |

- 結婚の能力の条件 `married`（試遊版の `v4Married`）は、「`s.version` が `hotseat-8` 以上、かつ結婚中、かつメインがいる」とします。
- こうすると、`hotseat-7` 以前の保存は今の能力のまま再生されます。
- タコ・ゆきだるまの読みやすい本文は、表示だけの変更なので版に関係しません。ただし文書74の手順（#476 と同じ）に従います。

## 3. テスト（正式の `prototypes/card-game/tests/` に追加）

1. `tests/v5-abilities.test.mjs` の30件を、正式のモジュールを直接読む形に移します（写しの組み立ては不要になります）。
2. **旧保存の互換**：`hotseat-7` で記録した対戦（恋人デッキのCPU対戦など数件）を `hotseat-8` のエンジンで復帰し、保存の文字列と結果が一致することを確かめます。
3. CPU の golden テストは、記録した時の版（`hotseat-6`／`heuristic-2`）に固定したままにします（#515 と同じやり方）。`heuristic-3` の golden を新しく追加します。
4. 既存の CARD GAME のテストをすべて通します。ホーム・他ゲームのテストは、変更がないことの確認として通します。
5. ブラウザ確認：試遊版の `trial/qa-trial.cjs` を、正式版の画面に合わせて移します。確認するのは、縦・横、18種類の詳細表示が切れないこと、通知、保存→復帰、CPU対戦です。
