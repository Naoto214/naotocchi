# 改善案の小規模比較実験の計画（設計のみ・未実施、2026-10-27）

本人が改善案の検証を承認した場合に実施する計画です。**今回は実施していません。** 正式カード・正式ルール・CPU判断は変更せず、PR #447 と同じく隔離コピー（未コミット・Pages梱包外・runtime非接続）で試す前提です。

## 対象

- 第1：ぴょんぴょんジャンプ（G-doodle-jump）の改善案「次のときおくりで1枚引く。1段階だけ上がった場合、さらにそだち+5」。
- 第2（第1が不十分な場合のみ）：ジャンプクエスト（G-jump-quest）の「ときおくり2回以上」→「ときおくりを行っている」。
- 2枚を同時には試さない（効果が混ざるため）。

## 実験の前に固定すること

- エンジン：その時点のmain。隔離コピーで、該当カードの効果定義1か所だけを置き換える（PR #447 の `make-variant.mjs` と同じ方式、置換箇所は完全一致1回を確認）。
- デッキ：
  - **検証デッキ**：旧試験デッキ「メイン成長重視」（`balance-verification-20261020/decks.mjs` の D1_main_growth。ぴょんぴょんジャンプ2・ジャンプクエスト1を含む既存の40枚）。カード構成は変えない。
  - **相手**：正式CPU 7デッキ。
- seed：`EARLYBIRTH:<相手デッキ>:<群番号>` から既存の導出（`deriveSeed`）で作り、現行版と改善版で同じ配札・policy seedを使う。
- manifest・計画書は実行前にコミットする。

## 実験1：効果の強さ（カード単体）

| 項目 | 内容 |
|---|---|
| 組み合わせ | 検証デッキ × 相手7デッキ × 20群 × 先後2 × 版2（現行・改善）＝**560戦** |
| CPU | 正式CPU中級（無変更） |
| 追加の比較 | CPUの予約効果の評価が弱い影響を分けるため、検証デッキ側だけ「ときおくりできるターンにこのカードを先に使う」強制policyの条件も同数（560戦）行う。正式CPUは変えない |
| 主要指標 | ①検証デッキの得点率の対応差（版間、群単位bootstrap 95%）、②このカードの使用率（使用／ドロー）、③+5が実際に成立した回数（1試合・1枚あたり）、④1試合でこのカードから得たそだちの最大値・分布 |

## 実験2：待機の選択肢が残るか

| 項目 | 内容 |
|---|---|
| 組み合わせ | 検証デッキ鏡像 × 20群 × 先後2 × 戦略2（A 早期、C R7で高段階）× 版2＝**160戦** |
| 方法 | PR #447 の `strategies.mjs` をそのまま使う |
| 主要指標 | A−Cの得点率差が、現行版と改善版でどれだけ変わるか |

## 停止基準・判定（事前固定）

| 判定 | 条件 |
|---|---|
| 強すぎる | 実験1で検証デッキの得点率差の95%区間の下限が +0.10 を超える、またはこのカードだけで1試合+15を超える試合が5%以上 |
| 効果なし | 強制policyでも+5の成立が1枚あたり0.2回未満 |
| 待機を消しすぎる | 実験2で A−C の差が +0.15 を超えて広がる（早期以外が選べなくなる） |
| 停止 | 異常終了・保存再生不一致が1件でもあれば中断して原因を報告 |
| 採用を検討できる | 上のいずれにも当たらず、+5の成立が1枚あたり0.3回以上で、得点率差の区間が0〜+0.10の範囲 |

## 規模・時間の目安

- 合計 1,280戦（560＋560＋160）。PR #447 の実行速度（4並列で約0.5戦／秒）で約45分。
- 固定400戦は再実行しない。正式CPU 7デッキの採用構成も変えない。
