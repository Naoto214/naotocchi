# 調査計画：「時」の使い方・相手ターンの反応・すぐつかう／しかける（2026-10-30）

実行前に固定した計画です。基準は remote main `851cf09a`（tree `5517352b`）。

## 目的

現行ルール（01 正式ルールの「時」「すぐつかう」「しかける」）を変えずに、正式CPU（`heuristic-1`、初級・中級）がその駆け引きを使えているかを客観的に測る。CPUの正式実装は変更しない。

## 守るもの

正式452枚の本文・効果・数値、正式ルール、時の管理方式、発動・連鎖の共通処理、CPU初級・中級の正式実装、保存形式、戦績、カード画像、固定400戦の証拠、他の未マージPR。分析コードは正式モジュールを読み込むだけで書き換えない。

## 手順

1. **既存記録の再利用**（再実行しない）
   - `balance-verification-20261022-variety/runs/V1`（中級×中級1,680戦）、`V2`（同デッキ初級×中級840戦）、`deck-balance-20261025/runs/X`（480戦）の集計項目 `responseDecisions`・`responsesUsed`・`timeLeft`・`unaffordable`・`cards`。
   - 既存記録には「どの窓で何を持っていたか」がないため、窓ごとの内訳はここからは出せない。
2. **計測付きの再生**（`lib/run.mjs`）
   - 正式の対戦ループ（`balance-verification-20261020/run.mjs`）と同じ判断・同じ自動進行。計測は状態の複製だけを読む。
   - 正式ランナーと同じ終局保存hashになることを事前に5戦で確認済み。全試合で、CPUの選んだ手の評価値が計測側の順位付けの最大値と一致することも記録する（`policyCheck`）。
   - 対象：
     - **X再生**：`deck-balance-20261025/runs/X-manifest.json`（480戦、同じseed・同じデッキ。こいびと・交際デッキ対6デッキの中級×中級360戦＋同デッキ初級×中級120戦）。既存記録とラウンド別そだち・revision・結果を照合する。
     - **TR（追加・小規模）**：`runs/TR-manifest.json`（sha256 `779e6b52…`）。7デッキの同デッキ鏡像×10群×先後2×難易度4通り（中×中・初×中・中×初・初×初）＝560戦。デッキの強さを相殺し、難易度・先後・デッキ別に比べる。
3. **固定局面**（`scenarios/`）：自然対戦で出現の少ない局面（しかける札・相手ターンの本当の反応・準備枠満杯・同名カードの重複）を正式エンジン上に組み、正式CPUの選択を記録する。自然対戦の結果とは分けて報告する。

## 記録する指標

- 反応機会：応答窓ごとに、席・ラウンド・自分／相手ターン・自動パスか・時・手札の「すぐつかう」を「今使える／時だけが足りない／条件・時機が合わない」に分類（時を10にした複製で合法手を再計算して判定）、選んだ手と評価値、最良の「すぐつかう」候補の評価値。
- 時の台帳：自分ターンごとに、開始時の時、自分ターン中の支払い、終了時の残り、相手ターン中の支払い、次の開始時に失われた残り（再設定直前の値）、時の増加。終了時に時だけが足りなかった行動。
- しかける：しかけた札、発動・見送り・発動せず場を離れた・伏せたまま終局。準備枠満杯で持っていた「しかける／みにつける」。準備枠満杯のときに「すぐつかう」が合法だった回数。
- 反実仮想（記録のみ）：`lib/counterfactual.mjs`。時の機会費用で「同名カードの別の写し」を失う候補として数えなかった場合に、選択が変わる決定を数える。正式CPUの手は変えない。

## 判断の原則

- 見送り・使い残しそのものを誤りとしない。相手ターンへの備え、他カードのための温存、価値の低さを区別する。
- カード固有の強さと使用方式（すぐつかう／しかける）の価値を混同しない。CPUデッキの「しかける」は3種（スキージャンプ・ミサイルコマンド・たこやきやさん）に限られるため、方式の比較は固定局面で補う。
- 推測だけでCPU判断を変更しない。改善案は A（現行維持）／B（軽微）／C（大きな変更）で比較のみ。
