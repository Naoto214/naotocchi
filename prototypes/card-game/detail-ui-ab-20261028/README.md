## 本人限定試遊版

https://claude.ai/artifact/N3Juwrd6rxe2W1KT6m3ZXn

- claude.ai のアカウント（本人）だけが開ける非公開ページです。共有メニューで共有しない限り、他の人は開けません。
- 正式版（https://naoto214.github.io/naotocchi/prototypes/card-game/）とは別のURL・別の保存領域です。試遊版の保存はすべて `naotocchi-detail-ab-trial:` で始まる鍵に入り、正式版の対戦・戦績・マイデッキは読みも書きもしません。
- ゲーム本体（エンジン・CPU・カード・ルール）は正式版と同じコードをそのまま使っています。違いは詳細パネルの見た目と、比較用の案内だけです。

### 使い方

1. 開始画面の一番上「詳細表示 A/B 比較試遊版」で、**改善A／旧A／B案／現行**を選びます（既定は改善A）。
2. 「比較用の場面から始める」で場面を選びます（各場面に「ひとり（CPU）」「ふたり」）。
   - **必須選択中（たまごの交換）**: 手札に長文カード（とかい・まねっこサル）と短文カード（ヒトデ①）。
   - **通常手番**: 同じデッキの2ターン目。長文カードに行動ボタンがあります。
   - **応答中（相手の手番）**: ラッキーコインで応答できる場面。
   - **対象を選ぶ行動（交代先などを選ぶ）**: サングラスのカメレオンの交代先が3択。
3. 手札のカードを押して詳細を開きます。詳細の右上（「盤面へ ×」の左）のボタンで、開いたまま 改善A → 旧A → B案 → 現行 の順に切り替えられます。
4. ふつうの「新しい対戦を開始」から通常の対戦もできます（CPU・2人対戦とも）。

注意: 試遊版の中では「保存ファイルを書き出す」（ファイルのダウンロード）は動きません（公開先の制限）。読み込み・途中保存・復帰・戦績は動きます。

## 改善A案（2026-10-29、第一候補）

旧A案の骨格（本文の内側スクロールなし・詳細全体を1本でスクロール・操作ボタンは下端の帯）を保ったまま、

- 縦向き: カード画像（同じ大きさ）を左に寄せ、右側にカード名・種類・コスト・レアリティ・関連ルール。本文は画像の下から全幅。
- 操作帯: ボタンの余白と行間を詰め、配置先をラベルの後ろに続ける。ボタン間隔8px。高さ44px以上・文字13pxは維持。
- 横向き: 選択肢を横並び（1つ170px以上）。種類・コスト・レアリティは1行、関連ルールは見出しの右。
- 操作帯の高さの上限: 固定40%をやめ、縦は「画面高さ−セーフエリア−カード画像−150px（最低132px）」、横は55%。

## 初回の2つの案（2026-10-28）

| | A案：全文を自然に展開 | B案：既存構造のまま読みやすく |
|---|---|---|
| 本文 | 内側スクロール枠をやめ、全文をそのまま表示 | 内側スクロール枠は残す。枠を内容の高さまで広げ、最低約3行を確保。行間 1.6→1.65 |
| スクロール | 縦向きはカード画像も含めて詳細全体が1本でスクロール。横向きは右の列だけが1本でスクロール | 本文枠の中をスクロール（従来どおり） |
| 操作ボタン | 下端に固定（影付きの帯）。帯は画面の高さの40%まで、超える時だけ帯の中でスクロール | 本文の下に置く。狭い画面で全体が溢れた時だけ下端に留まる（安全策）。選択肢が多い時はボタン欄を約2個ぶんに収める |
| 見出し | 種類・コスト・レアリティを1行の流れにまとめる（共通） | 同左。「関連ルールを読む」を見出しの右へ |
| 続きの手がかり | 帯の上の影 | 本文枠の下端をぼかし「続き ↓」を表示（続きがある時だけ） |
| 文字サイズ | 14px（現行と同じ） | 14px（現行と同じ） |
| カード画像 | 現行と同じ大きさ | 現行と同じ大きさ |

## 再現手順

```sh
# 1) 比較用シナリオ（任意。scenarios.json は保存済み）
node prototypes/card-game/detail-ui-ab-20261028/make-scenarios.mjs > prototypes/card-game/detail-ui-ab-20261028/scenarios.json
# 2) 試遊版を組み立てて配信（esbuild が必要: 作業用ディレクトリで npm i esbuild@0.25.10）
ESBUILD=<esbuildの実行ファイル> node prototypes/card-game/detail-ui-ab-20261028/build-trial.mjs ../trial --large-only
(cd .. && python3 -m http.server 8766)
# 3) QA
QA_BASE=http://127.0.0.1:8766/trial/index.html node prototypes/card-game/detail-ui-ab-20261028/qa/run-ab-qa.mjs
QA_BASE=http://127.0.0.1:8766/trial/index.html node prototypes/card-game/detail-ui-ab-20261028/qa/run-ops-qa.mjs
node prototypes/card-game/detail-ui-ab-20261028/qa/summarize.mjs
```

公開用（claude.ai Artifact）は `--artifact` を付けると CSS/JS を HTML に埋め込みます。公開先のファイル数上限のため `--large-only` で盤面用の小さい画像も大きい画像で代用しています（詳細パネルは元々大きい画像なので、比較対象の見た目は変わりません）。

## 正式採用する場合（本人判断の後）

1. 採用した案のルール（改善A案なら `:root[data-detail-variant=a2]` と、A・B共通の見出し部分）を `variants.css` から `style.css` の詳細パネル部分へ移し、`:root[data-detail-variant=…]` の条件を外す。
2. 改善A案は CSS のみで JS 不要。B案を採用する場合は、`trial.mjs` の「続き ↓」の処理（`updateMore` と `decorate` の後半）を `app.mjs` の `inspect()` に移す。
3. `tools/pages/allowlist.json` の `reviewed_runtime_sources` のハッシュ（`style.css`、B案なら `app.mjs` も）を更新。
4. 既存のブラウザ試験（`ui-iphone`・`ui-layout`・`ui-final-layout.browser` 系）と本フォルダの QA を再実行し、実機 iPhone で確認。
