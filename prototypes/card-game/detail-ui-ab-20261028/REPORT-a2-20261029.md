- 測定は Chromium（Playwright、タッチ・モバイル表示）。実機 iPhone Safari では未確認です。

## 1. 改善A案の具体的な変更

`variants.css` の `:root[data-detail-variant=a2]` だけに効く CSS です（JS なし）。旧A案の骨格（本文の内側スクロールなし・詳細全体を1本でスクロール・操作ボタンは下端の帯）はそのままです。

1. **縦向き：カード画像の右側を使う。** 画像は同じ大きさのまま左に寄せ、空いていた右側にカード名・種類・コスト・レアリティ・「関連ルールを読む」を置きました。本文は画像の下から全幅で始まります。320×568 では本文の開始位置が約40px上がりました（カード名・種類などの段がなくなったため）。
2. **下部操作帯の詰め方。** ボタンの文字（13px）と高さ44px以上は保ったまま、上下の余白と行間を少し詰め、「配置先：なかま①」をラベルと同じ行の後ろに続けました。ボタン同士の間隔は 5〜6px → 8px に広げました（誤タップ対策）。
3. **横向き：選択肢を横に並べる。** 操作帯のボタンを「1つ170px以上」の横並び（入りきらなければ折り返し）にしました。3択が1段に収まります。種類・コスト・レアリティは1行、「関連ルールを読む」は見出しの右です。
4. **操作帯の高さの上限を固定40%から可変に。** 縦は「画面の高さ − セーフエリア − カード画像の高さ − 150px（ツールバーと本文冒頭ぶん）」、ただし最低132px。横は画面の高さの55%。実際の帯の高さは中身で決まり、上限は小さい画面の安全策として働きます。

## 4. 下部操作帯40%上限の再評価

- 旧A案で帯が40%に達したのは3択の時だけで、その時は帯の中にスクロールができ、本文も初期表示で見えませんでした。原因は上限の値よりも、**帯の中身（ボタンの余白・配置先の行・縦積み）が大きいこと**でした。
- 改善A案では中身を詰めたため、帯の高さは縦で最大34%（320×568の3択）、通常は8〜28%、横で18〜37%でした。上限に当たったのはアドレスバー表示の320×474だけで、その時もボタンは欠けません。
- 結論: 40%の固定値はやめ、上の可変式を推奨します。上限は「本文の冒頭を必ず残す」ための安全策として残します。
