# 実験計画（実行前に固定、2026-10-31）— 12ラウンド・そだち120・120維持勝利の比較

**目的：** 現行（10ラウンド・100歳・そだち100・100維持）と、時計統一案（12ラウンド・120歳・そだち上限120・120維持）のどちらがゲームとして優れているかを確かめる。ラウンド延長とそだち120化の効果を分けて測る。
**正式ルール・カード452枚・CPU・保存形式・本番Pages・固定400戦・既存のPR #495の結果は変更しない。** 隔離したコピーだけで行う。

## 1. 基準
- main `7c1f18c7`（PR #493 統合後。作業開始時の最新 remote main）。CPU は正式の **heuristic-2**（中級対中級）。全条件で同一。
- PR #495 の既存結果（heuristic-1、main `851cf09a`）は再実行しない。既存の A・B（MAIN の R10・R12）は、同じ seed で heuristic-2 版と並べ、**CPU 方針の違いによる影響の確認**に再利用する。
- 隔離ビルド：`lib/build-g120.mjs`（出力 `build/G-*`、`build/g120-manifest.json`）。

## 2. 条件（そだち上限と維持勝利の値は別設定）
| 条件 | ラウンド | そだち上限（cap） | 維持勝利（hold） | CPU のそだち上限定数 |
|---|---:|---:|---:|---:|
| A：現行 | 10 | 100 | 100維持 | 100 |
| B：ラウンド延長のみ | 12 | 100 | 100維持 | 100 |
| C：そだち拡張のみ | 10 | 120 | 120維持 | 120 |
| D：時計統一案 | 12 | 120 | 120維持 | 120 |
| D0（感度分析） | 12 | 120 | 120維持 | 100（正式のまま） |
| G-OFF（等価性） | main 7c1f18c7 の無改変の写し | | | |

変更箇所（`engine.mjs`、正確な文字列一致のパッチ）：
- ラウンド（B・D）：早期勝利の判定を R1〜R11 へ、最終比較を R12 後攻の終了へ、保存の検証を round≤12・時≤12 へ（PR #495 の R12 と同じ4か所）。
- **そだち上限（cap）**：`grow()` の上限 `Math.min(100,…)`、`validate()` の `growth>100`。
- **維持勝利（hold）**：`grow()` の維持の起点 `growth<100 → reached=null／old<100 → reached=…`、`endTurn()` の勝利判定 `growth===100`（`>=hold` に。cap＝hold のときは `===` と同じ意味）、勝利理由の表示 `'100維持'`。
- CPU（C・D）：`cpu-policy.mjs` の「そだちの残り幅」の計算に使われる上限100（5か所）を120に。CPU の判断方法は変えず、ルール上の上限値だけを合わせる。D0 はこの書き換えをしない感度分析。
- カード本文に「100」を参照するものはない（全452枚を検索）。

## 4. 評価指標（`analyze_g120.py`）
- 勝率・得点率、先後差、デッキ別・相性、そだち獲得・アイテム・こいびとデッキの強さ、デッキ間の幅（最大−最小）
- 到達：そだち100・110・120に届いた席の割合、120（上限）に初めて届いたラウンド、最高そだち
- 維持勝利：発生率、維持の開始（上限・維持値への到達）回数、阻止（維持値未満へ戻された）割合、維持値に届かず終局した割合、通常のそだち比較による決着の割合
- 早期決着率、最後の2ラウンドで結果が動いた割合、決着ラウンド、接戦（点差10以内）
- 手札枚数、時の消費・失効、決定数・推定プレイ時間（PR #495 と同じ仮定）、R11・R12の行動
- ⑧：到達率、到達後の手番、⑧そのものの効果（main+8lite − main+dup）、A と D の違い
- 差：B−A（ラウンド延長）、C−A（120化）、D−B（12R下での120化）、D−C（120下での延長）、交互作用（D−C−B+A）。seed グループ単位のブートストラップ（2,000回、seed 固定）
- CPU 方針の影響：A・B の heuristic-2 と、MAIN の heuristic-1（同じ seed、001〜020）

## 5. 判断の枠組み
PR #495 の PLAN §6 と同じ。そだちが増えたこと自体は改善と数えない。特殊勝利（維持勝利）は「ほとんど起きない」も「起きすぎる」も問題として扱う。時計の美しさは、ゲームバランスを悪くする理由にしない。
