# 100維持勝利の仕様分析と、120維持の仕様候補（正式変更はしない）

出典：`engine.mjs`（main `7c1f18c7`）の `grow()`・`endTurn()`・`validate()`、`docs/card-game/01-core-rules.md` §「そだち」「勝利」（:121-134）。

## 1. 現行の100維持勝利（コードと正本の照合）
```js
// grow()：そだちの増減
p.growth = Math.max(0, Math.min(100, old + n));          // 0〜100に収める
if (p.growth < 100) p.reached = null;                      // 100未満になったら維持は途切れる
else if (old < 100) p.reached = s.serial + (a === s.turn ? 1 : 2);  // 100に届いた時点で「期限」を記録
// endTurn()：各ターンの終了処理の後
if (s.round < 10) { winner = A,B の順に「growth===100 かつ reached!==null かつ reached<=serial かつ 今のターンの持ち主でない」; }
if (s.round === 10 && s.turn === 'B') 最終比較;
```
| 論点 | 現行の扱い |
|---|---|
| 何ターン維持すると勝つか | **到達した後に始まる、最初の相手ターンの終了まで**100を保つと勝ち。自分のターン中に届いたら直後の相手ターン（1ターン）。相手のターン中に届いたら、そのターンは数えず、自分のターンをはさんで次の相手ターンの終了まで（`reached = serial+1` または `serial+2`） |
| いつ判定するか | **相手ターンの終了処理（終了時の予約・誘発・反応・期限切れ）をすべて終えた後**。連鎖の途中で100に届いても、その場では勝たない（01-core-rules :131） |
| 判定できるラウンド | 判定時点が **R1〜R9** のときだけ。判定時点が R10 なら早期勝利せず、R10後攻の終了後に最終比較（:129・:133-134。例：後攻が先攻R9中に届いた場合、次の先攻ターンはR10なので早期勝利なし） |
| 100を超える場合 | 上限100で切り捨て。超えた分は失われる。100のままなら維持は続く |
| そだちが減った場合 | **実際に100未満になった時点で維持は途切れる。** 同じ連鎖・終了処理中に100へ戻しても、以前の維持は復元せず、新しい到達として数え直す。減少を全部防いで100のままなら途切れない（:132） |
| 相手による妨害 | 相手のそだちを減らす効果（基本−5中心）、すれちがい（恋人を手札へ戻す → 持ち主に別れ−10）など。ちょうせんの負けにはペナルティなし |
| 先攻・後攻の判定順 | 判定はターン終了ごとで、勝てるのは「そのターンの持ち主ではない側」だけ。同時に両者が勝つことはない。コード上の確認順（A→B）は結果に影響しない |
| 通常の終局判定との優先 | 同じ `endTurn()` の中で、早期勝利の判定が最終比較より先。ただし R10 では早期勝利の判定自体を行わないので、R10後攻の終了では最終比較だけになる |

## 2. 120維持を「100→120の置き換え」で作れるか
**作れます（数値の置き換えで処理できます）。** 実験（PLAN-G120.md）では、次のように**そだち上限（cap）と維持勝利の値（hold）を別の設定**として、エンジンの5か所を書き換えました。

| 箇所 | 現行 | 実験（C・D） | 区分 |
|---|---|---|---|
| `grow()` の上限 | `Math.min(100,…)` | `Math.min(120,…)` | cap |
| `validate()` | `growth>100` で不正 | `growth>120` で不正 | cap |
| `grow()` の維持の起点・途切れ | `growth<100`・`old<100` | `growth<120`・`old<120` | hold |
| `endTurn()` の勝利判定 | `growth===100` | `growth>=120`（cap＝hold なら `===` と同じ） | hold |
| 勝利理由の表示 | `'100維持'` | `'120維持'` | hold |

- 判定のタイミング・必要なターン数・途切れの扱い・R10（12Rでは R12）で早期勝利しない点は、**現行と同じ**です（12Rでは判定できるラウンドが R1〜R11 になります）。
- **単純な置き換えだけでは足りない点（理由つき）：**
  1. **CPU の評価**（`cpu-policy.mjs` の5か所）が、「あといくつそだちを増やせるか」を `100−そだち` で計算しています。そのままでは、CPU は100を超えるそだちに価値を感じません。実験では、判断方法は変えずに、この上限値だけを120にしました。そのまま100にした版（D0）は、感度分析として別に比べています。
  2. **保存の検証**（`validate()`）と**戦績の検証**（`records.mjs`。そだちの範囲）も、上限の値に依存しています。
  3. **ルールブック・チュートリアル・学習画面**の「100」「R1〜R9」「R10」の文言。
  4. カード本文には「100」を参照するものはありません（全452枚を検索。そだちの値を名指しするのは「おもちゃばこ：そだち20以下」だけ）。
- 初期値（20）・5刻み・最低0は、変更不要です。

## 3. 別案（独立した提案。正式変更はしない）
実験結果（REPORT-G120.md）によっては、次の別案も考えられます。どれも今回は実装・比較していません。
- **維持ターン数の短縮**：120に届いたら、直後の相手ターンの終了で勝ち（自分のターン中に届いた場合と同じ扱いに統一）。到達しにくい場合の救済。
- **維持値と上限を分ける**：上限120・維持勝利は110。到達のしやすさと、終盤の伸びしろを両立する。
- **維持勝利の廃止**：上限まで届いても、早期勝利はなく最終比較だけにする。
