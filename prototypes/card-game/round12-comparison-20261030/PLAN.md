# 実験計画（実行前に固定）— 10ラウンド／12ラウンド比較（2026-10-30）

この計画は、本実験（MAIN・SENS・EQ）の実行前にコミットします。パイロット（pilot）の結果を見てから変更した点は §8 に書きます。

## 1. 目的
現行の10ラウンド制（R10）と、ラウンド数と時の設定値だけを12へ延ばした12ラウンド制（R12）の比較。
戦略性・試合テンポ・育成・恋愛・逆転の面白さを、**同じデッキ・seed・先後・CPU方針**で測ります。
「12ラウンドの方がそだちが高い」こと自体は、面白さの証拠として扱いません（§6）。

## 2. 基準
- main `851cf09a80c7ed41ba7293888084272917e4582c`（#484 統合後。2026-10-30 時点の最新 remote main）。
- エンジン版 `hotseat-6`、CPU方針 `heuristic-1`（main の正式CPU）。
- **PR #493（中級CPUの B1・`heuristic-2`）は Draft・未マージのため使いません。** 10R・12R ともに `heuristic-1`。
- デッキ：正式CPU 7デッキ（`cpu-decks.mjs`：main・companion・partner・challenge・growth・item・balance）。

## 3. 変種（`lib/build-variants.mjs`）
| 変種 | 内容 |
|---|---|
| R10 | 正式モジュールの写し＋状態に影響しない記録フック（時のリセット時の残り・恋人の退場）だけ |
| R12 | R10＋ラウンド数12（エンジン3か所：早期勝利の判定を R1〜R11 へ、最終比較を R12 後攻の終了へ、保存の検証を round≤12 へ）。時の設定値は「時＝ラウンドの値」のままなので R11＝11・R12＝12 |
| R12h | **感度分析専用。** R12＋CPU評価の中のラウンド定数3種を最終ラウンド基準へ（`min(10,…)→min(12,…)`、`round>=8→>=10`、`round===10→===12`）。10ラウンドの試合では同じ書き換えが恒等なので、「R12の結果が10R向けに調整されたCPUのせいか」を確かめる |

- `VERSION` は `hotseat-6` のまま（カード規則が版名で分岐するため。例：かえるのみちわたり `onlyVersions:['hotseat-6']`）。
- カード本文で固定ラウンドを名指しする3枚（さいごのじかん「R10」、50さいのお祝い「R5」、なおとのおまもり「第7ラウンド以降」）は**本文どおり**のまま（＝R12でもR10・R5・R7）。使用回数とラウンドを記録し、裁定候補として別に洗い出します。
- 正式ファイルは読むだけ。ビルド前後で作業ツリーの正式 `.mjs` の sha256 を照合します。

## 5. 測定（`analyze.py`）
勝率・得点率（勝1・分0.5）、先後、デッキ相性（7×7）、最終そだちと分布、メイン到達段階（⑧到達率）、たまご待機（初めてのたんじょうのラウンド）、ときおくり・へんしん、恋人の配置・交際進行・結婚・別れ・離婚、ちょうせん回数、逆転（下記）、時の付与・使用（自分のターン／相手のターン）・失効、手数（CPUの決定数・非パス行動数）、R11・R12の行動内容、R8以降の手札・山札、⑧到達後の行動、しかけ（伏せ・発動）、なかま・恋人の能力使用、パスだけのターン。

逆転の定義（事前固定）：
- **終盤逆転**：勝敗が付いた試合で、勝者が R8 終了時点で負けていた（そだちが相手より低い）割合。あわせて「最終ラウンドの2つ前（R10ならR8、R12ならR10）終了時点で負けていた」割合も出す。
- **決着ラウンド**：最終結果のリード側が、それ以降ずっとリード（同点を含まない）を保った最初のラウンド。早いほど「早く決まっている」。
- **リード交代回数**：ラウンド終了ごとのリード側（同点は前のリードを維持）の入れ替わり回数。R8以降のみも別に数える。

推定プレイ時間：人が操作する手数＝CPUの決定数（自動パスを含めない）。人のプレイ時間の換算は「非パス行動 1回 12秒・パス／確認 3秒・ターン切替 5秒」の**仮定**で示し、主には 10R 比の相対値で比べます。

信頼区間：グループ（同じ seed の先後2試合）単位のブートストラップ（2,000回、seed 固定）。R10 と R12 は同じ seed なので、差は対応のある差として求めます。

## 6. 判断の枠組み（事前固定）
「追加2ラウンドの価値」と「時間の増加」を分けて評価します。
- 価値として数えるもの：R11・R12 に**選択肢があり実際に行動している**か、逆転の余地（終盤逆転率・決着ラウンドの遅さ）、⑧到達後・結婚後にも行動の意味があるか、デッキ間の偏りが縮むか。
- 代価として数えるもの：手数・推定時間の増加、パスだけのターンの増加、早期勝利（100維持）による試合短縮の偏り、手札・山札の枯渇、時の失効。
- そだちの上昇・⑧到達率の上昇は「到達しやすくなった」という事実として報告し、それ自体を面白さとは見なしません（100上限への張り付きは、むしろ差が付きにくくなる兆候として扱う）。

## 7. 物理版の時カウンター
対戦データとは独立した机上評価（`COUNTER.md`）。時計の目盛りを12にすることと、ゲームを12ラウンドにすることは別の判断として扱います。

## 8. パイロット後の変更（MAIN 実行前）
パイロット1回目（`runs/pilot-v1/`、168試合）で見つかったこと：
1. **12ラウンド化の漏れ（実験環境だけで修正）。** `engine.validate()` が各席の時を `p.time>10` で不正扱いするため、R11 の開始（時11）で12R の全試合が異常終了した（R12・R12h の 28/56 と 28/56 が abnormal、残りは R10 までに100維持で決着）。`validate-time` パッチ（`p.time>12`）を追加。正式エンジンは変更しない。
2. 記録の修正：失効した時を正しいラウンドへ記録（後攻の添字ずれ）、ラウンド終了時のそだちを「ターン切替の直前」に記録（開始時の効果を含めない）、支払い回数（`payEvents`）を追加。いずれも状態に影響しない記録だけ。

パイロット2回目（`runs/pilot-shard*.jsonl.gz`、168試合）：R10・R12・R12h とも 56/56 正常終了、保存の復元一致 56/56。12R の最終比較は R12 後攻終了で行われ、100維持の早期勝利は R11 まで有効。
MAIN・SENS・EQ の試合数・seed は §4 のまま変更なし。
