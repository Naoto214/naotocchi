## 0. 開始時に見つけた問題と修正

【事実】PR #444 の CI のうち、Pages の梱包（`Pages runtime package / build`）だけが失敗していた。原因は「runtime source changed; review dependency contract: prototypes/card-game/cpu-decks.mjs」。公開対象の `cpu-decks.mjs`・`cpu-session.mjs` を変えたのに、`tools/pages/allowlist.json` の依存確認済みハッシュ（`reviewed_runtime_sources`）を更新していなかった。

- 依存の確認：`cpu-decks.mjs` は `./engine.mjs` だけを読み込み、変更なし。`cpu-session.mjs` は既に公開している `./cpu-decks.mjs` から読み込む名前が1つ増えただけ。新しいファイル参照はない。
- 修正：2ファイルのハッシュだけを更新した（`ddbba098`）。手元で `tests/pages`（16件）、`package.py`、`verify.py` がすべて成功（4,053ファイル、missing 0・hash 不一致 0）。
- 【推論】この2ファイルは公開されるランタイムなので、PR #444 を main に入れると、本番の CARD GAME の CPU「こいびと・交際」デッキが新しい40枚に変わる。これは今回の公開の目的どおりだが、本番の配信内容が変わる点は明記しておく（PR #408 のような配信物不変のマージではない）。

## 5. 恋人デッキ6枚構成の中身

【事実】X1（別seed、360戦）と PR #444（PD seed、360戦）。

| 指標 | X1 | PR #444 |
|---|---|---|
| 配置率 | 100% | 99.7% |
| 結婚率 | 99.4% | 97.5% |
| 終局時に手札に残った恋人 | 2.53 | 2.39 |
| 恋人能力の記録（1試合） | 2.67 | 2.69 |
| コネクトフォーの使用（1試合） | 0.59 | 約0.6 |

旧10枚（PR #444、同じ PD seed）では、手札に残った恋人 3.57、恋人能力 1.86、結婚率 100% だった。

【事実】難易度差（X2）：新6枚同士で、中級の得点は 0.517（120戦）。第4段階 V2 の旧構成同士は 0.500。

【推論】恋人デッキの個性（交際を進めて結婚し、シカ・ワシの能力を使う）は保たれ、余る恋人は減ったまま。初級と中級の差が小さいのは、旧構成からの性質（恋人の配置と交際はどちらの難易度でも同じ評価）で、今回の変更による後退ではない。

## 6. 判断：微調整なし

- 【推論】新6枚構成に、明らかに強すぎる・弱すぎる問題は見つからなかった。得点率 0.56 は7デッキの範囲（0.39〜0.57）の上端付近で、他の上位2デッキと同水準。偏った組（恋人対バランス）は旧構成からのもの。
- 【推論】これ以上の構成変更（たとえばコネクトフォーを1枚にする）は、数値を少し動かすための調整になるため行わない。
- そだち獲得の弱さ、アイテムの対なかま・対そだち獲得の強さは、他の6デッキを変えない今回の範囲外の課題として残す。
