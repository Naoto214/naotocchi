# hotseat-1 旧保存の「続きから」復帰（2026-10-27）

- 基準: main `2a961f8a`（#449 公開後）。その後 main に入った #452（ぴょんぴょんジャンプ、新規対戦は `hotseat-4`）を取り込み済み（`983c7db0`）。
- カード452種類・本文・効果・数値・正式ルール・CPU 判断方式・保存形式の意味は変えていない。固定400戦の証拠も変えていない。

## 1. 根本原因（2段階）

hotseat-1 の保存は `{version, seed, commands}` だけで、デッキ情報（`decks`）も対戦履歴（`history`）も持たない（hotseat-1 は固定15種類のデッキだけで遊ぶ形式。デッキ編集は hotseat-2 から）。

1. **戦績への接続（`records-match.mjs` の `decodeMatch`）。** 戦績機能（#411）より前の保存に「デッキ不明の旧セーブ」用の戦績情報を作る処理が、hotseat-2 の `decks` があることを前提に `g.decks[s]` を読んでいた。hotseat-1 では `g.decks` がないため `Cannot read properties of undefined (reading 'A')` で止まり、ゲームの復元は成功していても「続きから」全体が失敗していた。
2. **盤面の表示（`engine.mjs` の `view`）。** 1 を直すと、次に盤面の描画で止まった（`Unknown card classification`）。hotseat-1 の表示は旧15種類の表（`cards.mjs`）を使うが、現行のカード面は色分けのためにメインの `attribute`（属性）と `form`（姿）を必要とする。旧表にはこの2項目がない。

## 2. 修正

| ファイル | 内容 |
|---|---|
| `records-match.mjs` | hotseat-1 はゲームだけを復元し、戦績情報は `null`（戦績の対象外）にする。デッキ・使用カード・日時は作らない。hotseat-1 に戦績情報が付いている保存、CPU 保存の中の hotseat-1 は拒否する |
| `engine.mjs` | hotseat-1 の表示だけ、同じカードIDの `attribute`・`form` を現行カタログから補う（表示専用。ルール・本文・状態は変えない） |
| `app.mjs` | hotseat-1 を復帰した時の表示を「保存を検証して復帰しました（旧形式のため戦績には記録しません）」にする |
| `tools/pages/allowlist.json` | 上の3ファイルのハッシュ更新（新しい読み込み先なし。`legacy-engine.mjs` は既に公開対象） |

戦績の対象外にした理由: 戦績の1行には、開始時の40枚（順番つき）とカードごとの使用回数が必要。hotseat-1 の保存にはどちらもなく、使用回数は旧エンジンの状態にも残っていない。推測で埋めると、デッキ構成やカード使用統計を誤って集計することになる。

## 3. 互換性

| 形式 | 結果 |
|---|---|
| hotseat-1 | 途中・決着済みとも復帰。復帰後に合法な操作ができ、再保存・再復帰しても hotseat-1 のまま。戦績には記録しない（何度復帰しても0件） |
| hotseat-2 | 従来どおり（デッキ不明の旧セーブとして戦績に接続、同じ保存は同じID） |
| hotseat-3・hotseat-4（現行） | 従来どおり。決着済みは1件だけ記録し、再復帰しても増えない。A/B 席別に集計 |
| CPU（初級・中級） | 保存・復帰で設定・戦績情報を保つ |
| 破損・改変 | 操作列の改ざん、不正 seed、hotseat-1 への `decks` 追加、hotseat-1 への戦績情報の付加、CPU 保存の中の hotseat-1 を拒否 |
