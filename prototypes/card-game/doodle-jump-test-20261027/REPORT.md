# ぴょんぴょんジャンプ 効果改善案の1,280戦比較（2026-10-27）

PR #448 の改善案「ぴょんぴょんジャンプ」を、たまごの共通ルールを変えずに検証しました。
**正式カード本文・効果・数値・ゲーム処理・CPU判断・正式ルールは変更していません。** 改善案Bは、正式ソースを読み取って2か所だけ置き換えた隔離コピー（未コミット・Pages梱包外・runtime非接続）で動かしました。
固定400戦（PR #408）の凍結ソース・manifest・seed・mandatory choice policy・承認履歴・記録・結果専用ブランチ・checkpointには触れていません。今回の1,280戦は、それとは独立した比較実験です。

- 事前固定条件：[PLAN.md](PLAN.md)（manifest・コードとともに全実行前にコミット `70f7495d`）
- 集計表：[results/tables.md](results/tables.md)、全指標：[results/summary.json](results/summary.json)、再現性：[results/reproduction.json](results/reproduction.json)

## 0. 結論（先に）

1. **改善案Bはカード効果として妥当で、強すぎません。**
   - 使用機会を揃えた比較（E1F）で、そだち+5の成立は使用1回あたり A 0.04 → **B 0.48**。名前どおり「1段階ずつ育てた時」に報われるカードになりました。
   - 得点率の差は **+0.018（95%区間 +0.009〜+0.029）** と小さく、事前に決めた「強すぎる」基準（下限+0.10）から十分離れています。
   - このカードから1試合で得たそだちは最大+10（2枚とも成立）でした。
2. **ただし現行のCPUは、改善案Bをうまく使えません。**
   - 通常CPU（E1）では、Bの使用は215回ありました。そのうち186回は、ときおくりできない場面（相手ターンや応答中を含む）での使用で、ドローも+5も1回も発動しませんでした。
   - 現行Aは、CPUが一度も使いません（247枚引いて0回）。
   - 得点率の差は +0.007（−0.002〜+0.018）で、差を確認できません。
   - この空振りはカードの強さではなく、CPUの予約効果の評価（PR #406・#407の報告で既知）によるものです。
3. **早期たんじょう・長期待機のバランスは変わりません。** E2で、早期たんじょうとR7待機の差は A版・B版とも +0.087 で、変化は 0.000（−0.163〜+0.163）でした。ただし通常CPUでは+5が一度も成立していないため、この結果は「効果が働いた時の影響」を測れていません（§5）。
4. **第一推奨：改善案Bを採用候補とします。ただし正式採用は、CPUの使用判断の修正、旧保存の版管理と同時に行うことを条件とします。** これらを用意しないまま本文だけ変えると、人間にとっては良いカードになる一方で、CPUがこのカードを持った時（マイデッキのCPU使用など）は空振りが増えます。条件をそろえられない間は、現行維持が無難です。

## 3. 結果

### 3.1 使用機会を揃えた比較（E1F、カード効果そのものの価値）

| 指標 | A 現行 | B 改善案 |
|---|---|---|
| 得点率 | 0.386 | 0.404 |
| 得点率差 B−A（同じ配札、群単位bootstrap 95%） | — | **+0.018 [+0.009, +0.029]** |
| 検証デッキの最終そだち | 61.04 | 61.82 |
| 使用（＝使用機会） | 100 | 100 |
| うち1段階だけ上がるときおくりが可能だった機会 | 54 | 54 |
| ドロー発動 | 100 | 100 |
| **そだち+5の発動** | 4（使用あたり0.04） | **48（使用あたり0.48）** |
| このカードからのそだち（1試合） | 0：276試合、+5：4試合 | 0：234試合、+5：44試合、+10：2試合 |

- 使用とドローは同数で、違いは+5の成立だけです。純粋な効果の差を測れています。
- Bで+5が成立した48回は、1段階だけ上がれる機会54回のほとんどです。CPUが2段階以上を選んだ時は成立していません（+5の条件どおり）。
- 相手別の差（各n=40、目安）：なかま +0.037、そだち獲得 +0.037、バランス +0.025、こいびと・アイテム +0.013、メイン成長・ちょうせん 0.000。

### 3.2 通常CPU（E1、実際の使われ方）

| 指標 | A 現行 | B 改善案 |
|---|---|---|
| 得点率 | 0.380 | 0.388 |
| 得点率差 B−A | — | +0.007 [−0.002, +0.018] |
| 引いた枚数／使用 | 247／**0** | 251／**215**（0.86） |
| 使用機会があったターン | 127 | 52 |
| 機会があって使った | 0 | 29 |
| **機会がないのに使った** | 0 | **186** |
| 機会があったのに使わなかった | 127 | 23 |
| ドロー発動／+5発動 | 0／0 | **0／0** |
| 発動しないまま期限切れ | 0 | 211 |

- 現行Aは、CPUが一度も使いません。予約効果の中身が空（ドローも+5も2段目以降にある）と評価されるためです。
- Bは、ドロー＋条件付き+5を予約効果として評価し、使う価値があると判断します。ただし、使った後にときおくりをするかどうかは考慮しないため、多くが空振りします。
- 「使用率が上がった」こと自体は改善を意味しません。通常CPUでのBは、結果としてカード1枚と時1を失う場面が多くなっています。
- それでも得点率が下がらなかったのは、空振りの損（時1）が小さいためと考えられます。

### 3.3 早期たんじょう・長期待機への影響（E2、通常CPU、検証デッキ鏡像）

| 戦略 | A版 得点率 | B版 得点率 | 差（同じ配札） |

| A_early（序盤からたんじょう） | 0.688 | 0.637 | −0.050 [−0.150, 0.000] |

- 両戦略ともB版で0.05下がっていますが、両席ともB版のカードを持ち、CPUが空振りする条件です（両席の+5は0回）。カード効果の影響ではありません。区間も0を含みます。

| 観点 | 評価 |

## 5. CPU判断による影響

- 現行CPUは、予約型の「次にときおくりした時」効果を、その後に実際にときおくりできるかどうかと結び付けて評価しません。
- そのため現行Aは「価値ほぼ0」として使われず、Bは「価値あり」として、ときおくりできない場面でも使われます。
- 現行の正式CPU 7デッキには、このカードは入っていません。ただし、マイデッキをCPUに使わせる場合などは影響します。
- 正式採用するなら、CPUの評価に「このターン中に払えるときおくりがある時だけ価値を認める」を加える修正（今回のE1Fの使用条件と同じ考え方）を、別承認で同時に行うことを推奨します。

## 6. 第一推奨と根拠

**改善案Bを採用候補とします。正式採用は、次の3点をそろえてから行うことを推奨します。**

1. CPUの使用判断の修正（ときおくりできる時だけ使う）と、その検証。
2. 旧保存の再生互換の保護（§7）。
3. 人間の試遊での確認（PR #447の課題①「早期たんじょうの魅力」と合わせて）。

根拠：
- 効果は小さく（+0.018）、強すぎない。
- 「1段階ずつ育てると報われる」というカード名どおりの体験が生まれる（+5成立 0.04 → 0.48）。
- 待機や直接高段階の価値は下げない。
- 現行は、CPUにも人間にもほぼ機能しない（条件成立4%）。

条件をそろえられない場合は、**現行維持**とします。本文だけを先に変えると、CPUがこのカードを持った時の空振りが目立ちます。

## 8. 限界・未確認事項

- 検証デッキは1種類（メイン成長重視）です。ほかのデッキでの価値は確かめていません。
- カブトムシ④・ハンググライダー3Dとの組み合わせは、計算だけで確かめています（検証デッキに入っていないため）。
- E2（早期／待機）は通常CPUの条件で、+5が働いた場合の影響は推定です。
- 強制policyが選ぶのは「いつ使うか」だけで、どのときおくりを選ぶかは正式CPUです。人間なら、1段階だけのときおくりを意図して選ぶため、+5の成立はもっと高くなり得ます（上限は1段階可能な機会の54%）。
- 人間の試遊での楽しさは未確認です。
