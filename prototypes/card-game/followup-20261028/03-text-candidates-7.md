## 各カード
### G-lunar-lander ルナランダー（時1・すぐつかう）
1. 現行本文（29字）: 自分の残り時がちょうど2なら、1枚引き、自分のそだち+5。
2. 分かりにくい点: 残り時をいつ見るか（使う前か、支払い・反応の後か）が本文にない。
3. 案A（最小・推奨, 33字）: 解決時、自分の残り時がちょうど2なら、1枚引き、自分のそだち+5。
4. 案B（別案, 49字）: このカードの支払いと反応を終えた解決時、自分の残り時がちょうど2なら、1枚引き、自分のそだち+5。
5. 裁定との一致: doc 85「残り時は支払いと反応を経た解決時に見る。発動条件ではないので不一致でも発動できるが、効果は得られない。時0軽減時も印刷時から逆算しない」。A・Bとも一致（Bは裁定の言い回しに近いが冗長）。
6. 実装との一致: `iff('time2',…)` は解決時の `p.time===2` を評価。A・Bとも一致。
7. 表示: +4字／+20字。どちらも短く、面の表示に影響なし。

### G-submarine-3d サブマリン3D（時2・すぐつかう）
1. 現行本文（92字）: 発動時に0・1・2から数を1つ選び、時コストをその数だけ増やす。山札の上から、3に選んだ数の2倍を足した枚数を見る。その中から1枚までを手札に加え、残りを好きな順で山札の一番下に置く。
2. 分かりにくい点: 「3に選んだ数の2倍を足した枚数」の読み解き。
3. 案A（最小, 92字）: …山札の上から、選んだ数の2倍に3を足した枚数を見る。…（語順のみ）
4. 案B（推奨, 99字）: …山札の上から、選んだ数が0なら3枚、1なら5枚、2なら7枚を見る。…
5. 裁定: doc 83「選んだ数0／1／2に対して探索は3／5／7枚。実際の支払額から探索数を逆算しない」。A・Bとも一致。
6. 実装: `n:'submarine'` は `3+Number(variant)*2`（0→3, 1→5, 2→7）、`extraTime:'variant'`。一致。
7. 表示: B は+7字（99字、140字未満）。

### M-venus_flytrap-03 ハエトリグサ③（段階3・メイン）
1. 現行本文（55字）: 相手のターン中、このターンに自分がしかけていたカードの効果が1度でも適用されていた場合、このメインのちえ+1。
2. 分かりにくい点: 「しかけていた」の過去形と「適用されていた」。ただし語は正確で、doc 474（効果の適用）にも一致。
3. 別案（**除外**）: 「…効果が1度でも適用された、自分がしかけていたカードがある場合…」。しかけたカードは解決後に捨て札へ移るため、「しかけていたカードがある」と読むと**意味が変わる**可能性があり、採用候補から除外。
4. 裁定・実装: doc 57、`ownTrapEffectAppliedThisTurn`（相手ターン限定のパッシブ）と一致。
5. 第一推奨: **現行維持**。

### M-venus_flytrap-08 ハエトリグサ⑧（段階8・メイン）

### M-sakura-06 サクラ⑥（段階6・メイン、144字）
1. 現行本文: このメインがこの段階になった時、発動できる。自分の準備枠のカード1枚を選ぶ。このターン、選んだ後にそのカードまたはそのカードの能力が発動し、その効果の一部が解決時に適用された時に1回だけ、自分のそだち+5。選んだカードが発動のために準備枠から発動領域へ移動した場合も、その発動を参照する。
2. 分かりにくい点: 条件が三重（選んだ後／効果の一部が解決時に適用／準備枠→発動領域の移動）。ただし効果そのものが「準備→発動→適用」を追う設計で、条件は省けない。
3. 案A（最小, 145字）: 「その効果の一部が解決時に適用された時に1回だけ」→「その効果の一部でも解決時に適用された時、1回だけ」。

5. 裁定: doc 67「一部でも解決時に効果が適用されれば予約の+5を1回処理」、doc 474。案Aは一致。
6. 実装: 予約 `reserve(effectApplied)` ＋ 条件 `targetSelectedApplied`。一致。
7. 表示: 実画面QAで全幅とも本文は欠けない（`04`）。
8. 第一推奨: **現行維持**（採用するなら案Aのみ）。
