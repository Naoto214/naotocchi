## B1 の効果（既存の比較結果を再利用。新たな大量対戦はなし）
正式実装は実験版と試合単位で同一なので、PR #491 の E1 の結果がそのまま当てはまります。
- 中級の能力値一致率：50% → 100%
- 単独効果（相手が初級の組）：そだち +0.36 [+0.10, +0.61]、勝点 +0.016 [+0.005, +0.026]
- 初級に対する中級の勝点：0.552 → 0.568
- デッキ間の勝点の変化：±3.1 ポイント以内
- 能力値を選ぶカードがないデッキ（メイン成長・なかま・こいびと・そだち獲得）は、試合が一切変わらない
- 判断時間の増加はない

## 保存互換性
| 対象 | 影響 |
|---|---|
| hotseat の保存（hotseat-1〜6、legacy） | なし（エンジンは不変） |
| CPU対戦の保存（`cpu-match-1`） | 外枠は不変。`policy` 欄の値に `heuristic-2` が加わる |
| 旧版（heuristic-1）の途中保存 | **再開できる**（従来の実装のままなら、版を上げた時点で拒否されていた）。続きは heuristic-1 で指すので、保存した時のCPUのまま終局する |
| 操作記録の再生 | 方針を使わない操作列の再生なので、どの版でも同じ |
| 反復監視（`guard.seen`）の鍵 | 観測にかくとうバトル等の `variantCond` が増えるため、旧保存の鍵とそれらの局面の鍵が一致しなくなる。反復回数の数え直しになるだけで、安全側の監視（1ターン512回・同一局面3回）は維持される |
| 新しい保存を古いアプリで開く場合 | 古いアプリは `heuristic-2` を知らないため「CPU保存形式が異なります」で拒否する（データは失われない。新しいアプリでは開ける） |
| 戦績 | 形式は不変。方針の版は記録しないので、採用後は「中級」の集計に新旧が混ざる |
| 固定400戦の証拠 | 影響なし（別実装・別母集団。ファイルも変更なし） |

## 正式マージの可否
- **技術的にはマージ可能な状態です。** 全テスト548件、Pages の梱包・検証、実験版との同一性224/224はすべて合格し、正式ルール・カード・デッキ・保存形式は変えていません。
- マージ前に本人の確認が必要な点：
  1. 戦績の「中級」に新旧の方針が混ざること（版を戦績へ記録する変更は今回していない）
  2. 新しい保存を古い公開版で開くと拒否されること（公開を更新すれば解消）
  3. 実機（iPhone Safari）でのCPU対戦の通し確認。CPUの処理時間は変わらない見込みだが、本PRでは実機確認をしていない
