## 1. CPU評価欠陥の原因

【事実】
1. `cpu-observation.mjs` は `effectiveRule(s, source, RULES[cardId])` で各行動の規則を求めます。
2. 旧規則6種（I-c_coin2, G-hit-blow, G-area-claim, E-first-date, G-animal-shogi, G-archery-3d）は `RULES` に定義がありません。効果はエンジン本体（`engine.mjs` 105–109行で候補生成、179–188行で解決）に直接書かれています。
3. `effectiveRule` の引数既定値 `base={}` によって、`undefined` は `{}` になります。`hints({})` は `{steps:[],handCost:false,…}` という空だが真値のhintを返していました。
4. `cpu-policy.mjs` の旧カード向け本文フォールバックは `if(!a.program&&c)` のときだけ働くため、一度も実行されませんでした。
5. その結果、評価値は常に `0−3−時×係数` の負になり、ターン終了（0点）に必ず負けていました。

同じ空hintは、旧規則能力 `C-cat_friend`（`kind:'ability'`）にも渡っていました。

## 2. 修正（CPU評価のみ）

| ファイル | 処理 |
|---|---|
| `cpu-observation.mjs` `hints()` | 空の規則 `{}` を「規則なし」(`null`) として返します。これが根本原因の修正です。実際の規則を持つカードのhintは変わりません |
| `cpu-observation.mjs` `legacyHint()`（新規） | `kind:'play'` の6種について、エンジンの解決処理を既存のhint語彙で表します。使うのは行動者自身の公開viewだけです（下表） |
| `cpu-policy.mjs` | op `chance`（確率pで子stepsの価値）を1行追加しました |

| カード | エンジンの解決 | CPUに渡すhint | 何も起きない場合 |
|---|---|---|---|
| ラッキーコイン | 山札上を公開して下へ。メインならそだち+5、それ以外なら1枚引く | `coin`。同じ解決のG-sugoroku-raceと同じ評価 | 山札0 → 空 |
| ヒット&ブロー | 宣言種と一致すれば手札へ＋そだち+5、不一致なら山札下へ＋1枚引く | `draw 1`（どちらでも1枚増える）＋`chance(p) growth 5`。pは自分の既知カード（手札・場・捨て札）のうち宣言種の割合 | 山札0 → 空 |
| じんとり | 自分の場（メイン・こいびと・セカイ・なかま・準備枠）が7枚以上でそだち+10、9枚で+15 | `growth 10/15` | 7枚未満 → 空 |
| はじめてのデート | 対象こいびとが交際0なら1枚引き、そだち+5 | `draw 1, growth 5` | 交際0以外 → 空 |
| どうぶつしょうぎ | 捨て札のなかまを手札へ、山札上1枚を見る | `move→hand`, `look` | – |
| アーチェリー | 相手の時2以下の準備枠カードを捨て札へ | `move→discard`（相手対象） | – |

- 6種に一律の加点はしていません。数値は既存の評価関数（growth・draw・move・coin・look）がそのまま計算します。
- 合法手・時コスト・発動条件の判定は従来どおりエンジンだけが行います。時不足や条件不成立の手は候補に出ません。
- カード効果・ルール・状態遷移・save形式・`POLICY_VERSION` は変更していません。`POLICY_VERSION` を据え置いたのは、既存のCPU保存を拒否しないためです。
- 非公開情報: 相手の手札・山札順・seed・伏せ札の実体は使いません。ヒット&ブローのpも自分の既知カードだけから計算します。

## 3. テスト

【事実】`node --test prototypes/card-game/tests/*.test.mjs` は **364/365 PASS** でした。
失敗の1件は修正前から既知の `catalog.test.mjs`（`check-design-data.py` が `FUN_ITEMS` を見つけられない）で、今回の作業とは無関係です。

新規 `tests/cpu-legacy-cards.test.mjs` は 6/6 PASS です。
1. 6種すべてに空でない専用hintが付きます（根本原因の回帰テスト）。
2. 有効な局面では、デート・じんとり・コイン・アーチェリーをターン終了より優先して選びます。
3. 無意味な局面では選びません（交際2のデート、場6枚のじんとり、山札0のコイン）。時不足と条件不成立では候補そのものがありません。
4. ヒット&ブローの宣言は、相手の手札と山札順を変えても観測と判断が変わりません。7宣言のpの合計は1です。
5. デートは応答窓とチェーンを通って解決し、そだち+5・手札±0になります。両席とも観測と判断ができます。
6. 標準デッキで、CPU席A/B × 初級/中級の4通りが完走し、途中の保存復帰と保存再生が一致し、旧規則カードを実際に使います。

既存テストの変更は1件です（削除なし）。`ui-field-declaration.test.mjs` の「7宣言の選択がseedでばらつく（`seen.size>1`）」は、修正前に全宣言が同点（−5.6）だったことによる副産物でした。これを「seedに依らず同じ宣言を選び、山札順を変えても観測・判断が同一」に変えました。テスト名の目的（山札順を見ずに合法な宣言から選ぶ）は維持しています。
