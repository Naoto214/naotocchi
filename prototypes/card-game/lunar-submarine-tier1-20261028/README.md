## 3. 保存互換性の対応

- **対戦の版は増やしていません**（`hotseat-4` のまま、`RULE_VERSIONS` 不変）。
- 理由：保存は「版・seed・デッキ・操作列」だけで、カード本文は保存に入りません。2枚のルールプログラムも不変なので、すべての版の旧保存は同じ操作列で同じ盤面・同じ結果に再生されます。旧保存（既存の固定保存を含む）の操作列・盤面・結果は書き換えていません。
- 証拠：本文変更前の main のエンジンで、hotseat-2／3／4 の保存を各2件（2枚とも使われた CPU 同士の対戦）作り、`tests/lunar-submarine-saves.json` に固定（作成手順 `tools/make-legacy-saves.mjs`）。このブランチで復元すると、保存文字列・結果・そだち・盤面／記録のhash・全状態のhash がすべて一致。
- **見つかった点（不一致ではない）**：対戦状態の履歴（`history` の発動記録）は、発動時のカード本文の**写し**を持っています（`engine.mjs` の `recordActivation`）。このため旧保存を新しいエンジンで再生すると、その写しだけが新本文になります。この写しはルール・条件・CPU・戦績・画面のどこからも読まれないことを確認しました（テストで「違いはその写しだけ」を固定）。ぴょんぴょんジャンプ改訂（PR #452）の旧保存確認も同じく盤面・結果・記録で比較していたため、方式は前例と同じです。
- 本文hashに依存する検証器：`docs/card-game/tools/check-design-data.py` に改訂478の照合を追加し、過去の固定hash（96/97・476・477）はこの改訂前の本文に戻して照合します（版ごとの照合を維持）。`tests/doodle-jump.test.mjs` の「main 518037d6 と同じ」固定値も、2枚を改訂前の本文に戻して照合するようにしました（固定値は不変）。
- 変えていない過去資料：`docs/content-provenance-20261021/`（10/21時点の出典表。ぴょんぴょんジャンプの旧本文も残っている過去版で、#460 の方針どおり原本不変更）、`docs/card-game/data/` の固定400戦・proxy 検証の証拠。
