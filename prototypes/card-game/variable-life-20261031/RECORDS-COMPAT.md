# 正式戦績・保存の互換性の設計（VERSION 6、2026-11-04）— 新カード7種類を正式に追加する場合

**設計と試作での確認だけです。** 正式の `records.mjs`・保存形式・452枚は変更していません。

試作のコードは `lib/records-compat-proto.mjs`、確認は `lib/records-compat-test.mjs`（`evidence/records-compat.txt`、11項目合格）です。

## 1. 現状の調査（正式のコード）
| 保存するもの | 形式 | 新カードを足すと | 対応 |
|---|---|---|---|
| **戦績**（`records.mjs`、`naotocchi-card-records-v1`） | version 1。ファイルに**全カードの並べ替え一覧（catalog）**を入れ、デッキと使用はその**番号**で持つ | ① 読み込みは「保存された catalog が今の一覧と完全に一致」を条件にしている → **カードを1枚でも足すと、既存の戦績がすべて読めなくなる**。② 番号の上限 451、使用一覧 452件まで。③ ラウンドは10まで | **形式の更新が必要** |
| 対戦の保存（`records-match.mjs`、hotseat／cpu） | seed・コマンド・デッキ（カードIDの文字列）・ルールの版 | ID は文字列なので、番号の問題はない。既存の保存は自分のルールの版のまま再生される | 新カードの規則を、新しいルールの版として足す。既存の版は変えない |
| マイデッキ（`my-decks.mjs`） | カードIDの文字列 | 新カードを入れたデッキも保存できる（`validateDeck` が新カードを知っていれば） | そのまま |
| CPU デッキ（`cpu-decks.mjs`） | カードIDの文字列。過去の一覧は `CPU_DECK_HISTORY` に残す | 正式7デッキを変えるなら、版を足して過去の一覧を残す（既存の仕組み） | 変更する場合だけ |

**新カードを足したときに既存の番号がずれるか：**
- カードの番号は「全IDの並べ替え順」です。新しいID（例：`E-hayajimai`）は既存のIDの間に入ります。
- 試算では、**既存452枚のうち420枚の番号がずれます**（確認項目5）。

**試遊版の問題：** VERSION 1〜4 の試遊版で、2戦目以降の戦績が保存できなかったのはこのためです（番号の上限 451）。VERSION 5 で、試遊版の写しだけ直しました。

## 3. 方式の比較
| 方式 | 内容 | 既存の戦績 | 今後の追加 | 欠点 |
|---|---|---|---|---|
| A. 今の形式のまま、catalog に足す | version 1 のまま一覧を更新 | **読めなくなる**（一覧が一致しない） | 毎回同じ問題 | 採用できない |
| B. 番号台帳（固定の番号表）を作る | version 2。正式452枚は今の番号0〜451で固定し、新カードは452〜に割り当てる。ファイルには台帳の版だけ入れる | 読める（v1 の catalog が台帳 v1 と一致すれば、番号はそのまま） | 台帳の末尾に足すだけ | 台帳の管理が必要。台帳の誤りは番号の取り違えになる |
| **C. カードIDを文字列で保存（推奨・試作済み）** | version 2。デッキ辞書と使用一覧を ID の文字列で持つ（デッキ辞書で重複は1回だけ） | 読める（v1 は v1 の catalog で番号を ID に戻す） | **何もしなくてよい**（ID が変わらない限り） | ファイルが少し大きい（デッキ辞書は共有なので影響は小さい） |

**推奨は C** です。番号のずれの問題がなくなり、マイデッキ・対戦の保存とも同じ「ID の文字列」で統一できます。

## 4. 移行の手順案（正式採用時。本人の承認後）
1. `records.mjs` の読み込みを、次のとおりにする。
   - **version 1**：今と同じ条件（catalog が正式452枚と一致）で読む。
   - **version 2**：ID の文字列で読む。
2. 書き込みは version 2 にする。最初の書き込みの前に、元の version 1 を既存のバックアップキー（`-backup`）に残す（既存の仕組み）。
3. 条件を広げる：ラウンドの上限 10→12、使用一覧の上限 452→カードの総数。知らない ID は今と同じく拒否する。
4. **古い版のアプリは version 2 を読まずに拒否します**（誤読しない。確認項目11）。戻せない更新なので、書き出し（既存の戦績ファイルの書き出し）を案内する。
5. 対戦の保存は、新カードの規則を**新しいルールの版**として足す。既存の保存は、元の版で再生する（今の `RULE_VERSIONS` の仕組み）。

## 5. 試作での確認（`evidence/records-compat.txt`、11項目合格）
- 正式の `records.mjs` が書いた version 1 を、試作がそのまま読めた（デッキ・使用・結果が正式の読み込みと一致）。
- version 1 の catalog は正式452枚で、台帳 v1 と同一だった。
- 新カードの ID 案は既存と重ならなかった。並べ替え番号のままでは420枚の番号がずれることも確かめた。
- version 2 で、新カード入りのデッキと R12 の対戦を保存し、読み直せた。既存の2件も変わらなかった。
- 次のものは拒否した：知らない ID、catalog の違う version 1、R13。
- 正式の version 1 の読み込みは、version 2 を拒否した。
