# 保存互換性（設計メモ。正式の保存形式は変更していない）

## 1. 実験での事実（確認済み）
- 対戦の保存は、正式と同じ `{version, seed, decks, commands}` です（`engine.save`）。**最終ラウンド・上限などの `life` の状態は保存せず、復元時にコマンドを再生して作り直します。** したがって、保存の形（キー・版名 `hotseat-6`）は変わりません。
- 実験の全対戦（試験運転672戦＋本実行）で、終局時に `save`→`restore` して、結果と保存文字列が一致するかを照合しています（`runs/*.jsonl.gz` の `replay`）。R11・R12で終わった試合、110維持・120維持で終わった試合も含みます（件数は REPORT）。
- **新カードを含まない対戦では、実験エンジンの保存は正式と1文字も違いません。** A0（新カードなし）の写しの保存sha256が、PR #495 の G-A（無改変 main・heuristic-2 と一致済み）と一致しました（168試合、`results/summary.json` の `equivalence`）。
- 新カード（`X-*`）を含むデッキの保存は、**正式エンジンでは開けません**（`validateDeck` が未対応カードとして拒否）。実験の保存が正式の環境に混ざることはありません。

## 2. 正式に採用する場合に必要な変更（今回は行っていない）
| 場所 | 現在 | 必要な変更 | 互換性への影響 |
|---|---|---|---|
| `full-catalog.mjs`・`rules.mjs` | 452枚 | 新カードを追加（ID を新設） | 追加だけなら、既存の保存の再生結果は変わらない（既存デッキに新カードは入っていない） |
| `engine.mjs` の状態 | 固定値 10・100 | `life`（最終ラウンド・上限・維持値）を状態に持たせる。初期値 10・100・100 | 保存の形は不変（再生で作る）。新カードの無い対戦は同一結果（実験で確認） |
| `engine.validate` | ラウンド≤10・時≤10・そだち≤100 | ラウンド≤最終ラウンド（最大12）・時≤12・そだち≤現在の上限（最大120） | 緩める方向なので、既存の保存は通る |
| `VERSION`（`hotseat-6`） | — | **上げなくてよい見込み。** 既存カードの挙動は変わらず、延長・解放は新カードを使ったときだけ起きるため。ただし「さいごのじかん」の本文を「最終ラウンド」へ変える場合は、既存カードの挙動が変わるので版を上げる（旧保存は旧版で再生） | — |
| `records.mjs`（戦績） | `round≤10`・`growth≤100` を検証 | `round≤12`・`growth≤120` へ緩める | **古い公開版で新しい戦績（R11・R12・そだち110以上）を読み込むと「対戦結果が不正です」で失敗する。** 新しい版で古い戦績は読める |
| 戦績の書き出し（pack） | カタログIDの一覧を同梱 | 新カードIDが一覧に増える | 一覧を同梱しているので、読み込み側は対応可能 |
| CPU（`cpu-policy.mjs`） | 上限100・最終ラウンド10を固定値で使う | 上限・最終ラウンドを状態から読む＋新カードの評価。**方針の版を上げる**（heuristic-3）。保存済みの CPU 対戦は、保存時の版のまま再開（PR #493 と同じ仕組み） | 方針の版の扱いは既存の仕組みで対応できる |
| `cpu-session.mjs` | `cpu-match-1` | 変更不要 | — |
| 画面 `ui-presentation.mjs` | `ROUND n/10` | `ROUND n/最終ラウンド`。延長・上限の表示 | 表示のみ |
| ルールブック・チュートリアル・学習画面 | 「10ラウンド固定」「R10は早期勝利なし」「そだち最大100」 | 可変制の説明（RULINGS.md §0） | 文言のみ |

## 3. 判断が必要な点
- 新カードを正式に加えるなら、戦績の検証を緩めた版を先に公開し、その後に新カードを解禁する（古い版で新しい戦績を開く問題を避ける順番）。
- 「さいごのじかん」を最終ラウンド基準にするか（版の更新が必要になるか）は、ルール面の判断と合わせて決める。
