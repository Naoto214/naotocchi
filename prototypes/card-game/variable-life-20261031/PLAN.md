# 実験計画（本実行の前に固定、2026-10-31）— 人生延長カード・そだち上限解放カードによる 10／11／12 ラウンド可変制

**目的：** 「通常は10ラウンド・100歳・そだち100で終わり、特定のカードを使ったときだけ最大12ラウンド・120歳・そだち上限120まで延ばせる」方式が、現行ルールより面白いかを確かめる。
**正式カード452枚・正式ルール・正式CPU（heuristic-2）・正式7デッキ・保存形式・固定400戦・PR #495 の資料・main・本番Pagesは変更しない。** 新カードは実験用の隔離ビルドの中だけで定義する。
本人の正式決定（10R・100歳・そだち100・100維持）を覆すための実験ではない。

## 1. 基準と隔離
- main `7c1f18c7`（PR #493 統合後。作業開始時の最新 remote main。PR #495 の G120 と同じ基準）。CPU は正式の **heuristic-2**（中級対中級）。
- `lib/build-life.mjs` が正式モジュールを `git show` で `build/<条件>/`（git管理外）へ写し、次だけを足す（前後で正式ファイルの sha256 を照合）。
  - `full-catalog.mjs`：実験用の仮カード4枚（`X-life-extend`・`X-cap-raise`・`X-life-both`・`X-blank`）を末尾に追加。正式452枚は無変更。
  - `engine.mjs`：対戦状態に `life`（最終ラウンド・各席のそだち上限・維持勝利の値）を持たせ、`10`・`100` の固定値をそこから読む。初期値は 10・100・100。
  - `effects.mjs`：3つの効果（延長・上限解放・両方）と使用条件。
  - `cpu-observation.mjs`・`cpu-policy.mjs`：**実験専用のCPU補助**。判断方法は heuristic-2 のまま、CPU内のルール定数（最終ラウンド10・上限100）を `life` から読み、新しい3効果に評価式（`lifeValue`）を与える。新カードが無い対戦では正式CPUと同一。
- **等価性（実施済み）：** 試験運転で、A0（新カードなし）の写しの保存sha が PR #495 の G-A（無改変main・heuristic-2 と168/168一致済み）と **56/56 一致**。

## 4. 評価指標（`analyze_life.py`）
- 終了ラウンドの分布（10・11・12）、延長の発生率、R12 到達率、延長した席・ラウンド・そのときの点差
- 維持勝利（100／110／120）の発生率、維持の開始と阻止（上限解放で途切れた回数を含む）
- 接戦（点差10以内）、引き分け、**終盤の逆転**（実際の最終ラウンドの2ラウンド前の暫定勝者と最終勝者が異なる割合）、**延長による逆転**（R10終了時点の暫定勝者と最終勝者が異なる割合、延長した試合のみ）

- 推定プレイ時間（PR #495 と同じ仮定）、決定数、時の失効率、R11・R12 の行動（手番あたり行動数・パスだけの手番・そだちの伸び）
- 新カード：引いた席の割合、使った割合、**引いたのに使わず終わった割合**、1枚も使われなかった試合の割合、延長した側の勝率（延長時に負けていた側）、片方だけ新カードを引いた試合での得点率（引けない側の不利）

## 5. 動作検証（実施済み）
`lib/smoke.mjs`（`evidence/smoke.txt`、26項目すべて合格）：R9では延長不可、R10で延長→R11、同じラウンドに2回目は不可、R10後攻の自分のターン中に延長→最終比較せずR11へ、R11の時11・R12の時12、R12で延長不可・R12後攻の終了で最終比較、100維持（R5）、上限解放で維持が途切れる・そだちは不変、110維持・120維持、上限を超えるそだちは validate で不正、自分だけ解放、延長後のR10では維持勝利あり、A4、しかける版の発動。
保存→復元は、全対戦の終了時に `save`→`restore` で結果と保存文字列が一致するかを照合する（`replay`）。

## 6. 判断の枠組み（事前に固定）
現行 A0 を基準とし、次をすべて満たす方式だけを「有望」とする。
1. **固定12Rと同じにならない：** 12ラウンドで終わる試合が 25% 以下、かつ延長（11R以上）が 10%〜50% の範囲。
2. **接戦**（点差10以内）が A0 より 3pt を超えて下がらない（95%CI の上限が −3pt 未満なら不合格）。
3. **デッキ間の幅**（得点率の最大−最小）が A0 より 0.03 を超えて広がらない。
4. **先攻得点率**が 0.47〜0.53。
5. **推定プレイ時間**の増加が平均 +3分 以内。
6. **維持勝利**が 1%〜8%。
7. 加点：終盤の逆転・延長による逆転が増え、新カードが「引いたのに使えない」割合が低いこと。
そだちが増えたこと自体は改善と数えない。時計のデザインはゲームバランスを悪くする理由にしない。

## 7. 限界（事前に明記）
CPU同士の結果であり、人の判断とは違う。延長・上限解放の使いどころは実験専用の評価式（`lifeValue`）で決まり、その出来に結果が左右される（式は build-life.mjs に記載）。正式カードの CPU 判断・ラウンド依存の終盤評価（R8以降のそだち重視）は正式のまま。
