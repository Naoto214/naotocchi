# 実験計画（実行前に固定・2026-10-29）

恋人の別れペナルティ3案（A・B・C）を、**実際に別れが起きる対戦**で比べる計画です。結果を見る前にこの文書を書き、対戦数・比較方法・主要指標を決めました。

## 1. 比べる案

| 記号 | 内容 | 隔離環境での作り方 |
|---|---|---|
| A | 現行。結婚前の別れ−10・離婚−10 | 正式エンジンの写し。挙動は変えず、記録用の呼び出しだけを加える（正式版と保存hash一致を確認） |
| B | 結婚前の別れ（交際0〜3）−5・離婚−10 | 写しの別れ処理の値だけを変更 |
| C | 現行−10＋試作カード「円満な別れ」 | 写しにカードを1枚追加。できごと・すぐつかう・時1。「自分の交際中のこいびと1枚を対象として発動できる。対象を持ち主の手札に戻す。この効果で別れる場合、そだち−10を受けない。」 |
| C2 | C の制限版（代替案は1つだけ） | 同じカードに「相手のターンに」を付ける。自分のターンの入れ替え（出し直し）を封じ、すれちがいへの応答だけを残す |
| Cx | 対照 | C と同じ枠に、−10を免除しない同型カードを入れ、CPUは使わない。デッキの2枚を替えた影響だけを測る |

時コストは1（同じ恋人補助の「はじめてのデート」「なかなおり」と同じ。すれちがいの2より軽い）。

## 2. デッキ（すべて公式CPUデッキから明示した入れ替えだけで作る）

- 恋人側X：`partner`（公式「こいびと・交際」、こいびと6枚・らぶれたー2）、`balance`（公式「バランス」、こいびと3枚）。
- C・C2・Cx の X：`partner` は なかなおり2→円満な別れ2、`balance` は ヒット＆ブロー2→円満な別れ2。
- 相手側Y：公式4デッキにすれちがい2枚を入れる（ちょうせん：としをとったじぶん2／そだち獲得：ミニゴルフ2／アイテム：ごもく2／こいびと・交際：なかなおり2）。
- 強制検証の相手：ちょうせん＋すれちがい3（同名上限）。

## 3. 対戦の種類と数（小規模・試行段階）

| 名前 | 内容 | 案 | 数 |
|---|---|---|---|
| N1 自然・中級 | X2種×Y4種＝8組。各組10グループ×先後入替 | A・B・C・C2・Cx | 160戦×5＝800戦 |
| N2 自然・初級 | 同じ8組・同じseed | A・B・C | 160戦×3＝480戦 |
| F 強制・中級 | X＝partner、Y＝すれちがい3。Yは「Xの恋人が交際k（k＝0〜3、4＝結婚）の時だけ」すれちがいを使う。各段階12グループ×先後 | A・B・C | 120戦×3＝360戦 |
| P 悪用・中級 | X＝ねこ社長3・円満な別れ3の恋人デッキ。出し直しを機械的に繰り返す腕（loop）と、使わない腕（noloop） | C:loop・C:noloop・C2:loop | 40戦×3＝120戦 |

合計1,760戦。

- 共通乱数：同じグループは案が違っても同じ山札順seed・同じCPU判断seed。C系のXはなかなおり（またはヒット＆ブロー）と同じ位置に円満な別れが入るので、それ以外の初期配札は同じ。
- 拡張の規則（1回だけ）：N1 の主要指標（下記）の95%信頼区間の半幅が0.08を超えた場合、A・B・C だけ N1 を各組30グループへ増やす。それ以上は行わない。

## 4. CPUの扱い（判断の弱さとカードの価値を分けるため）

- CPU判断方式（`cpu-policy.mjs` heuristic-1）は写しをそのまま使う。変更しない。
- すれちがいは、CPUが自然に使う（自然対戦）。CPUは「相手が受ける−10」を評価しないので、使う時期は時間の余りに左右される。そこで強制検証では使う時期を交際段階で固定し、カードの効果そのものを測る。
- 円満な別れは、現行CPUの評価では自分の恋人を手札に戻す価値が負になり、使われない。実験用の規則として「相手のすれちがいが自分の恋人を対象にしてチェーンにあり、らぶれたーが付いていない時だけ応答で使う」を加える（C・C2）。Cx の対照カードは使わない。
- 悪用検証の loop 腕は「自分の恋人がねこ社長で、出し直せる時は必ず円満な別れを使う」機械的な規則。CPUより悪用に積極的な上限側の見積もり。

## 5. 主要指標と分析

- 主要指標：恋人側Xの得点率（勝ち1・引き分け0.5）の、案どうしの差（B−A、C−A、C−Cx）。同じグループ・同じ先後の試合を対にした差の平均と95%信頼区間（対の差の正規近似）。
- 別れが起きた試合だけの比較も示す（別れが起きない試合は、AとBで同じ結果になるので差は0）。
- 副指標：別れ・離婚の回数、交際段階別の別れ、結婚率、結婚までのターン、恋人の滞在ターン、2枚目以降の恋人の配置率、終局時に手札に残る恋人、別れによるそだち損失（0未満にならない分を除いた実際の値）、再配置の回数、配置時効果（ねこ社長）の再発動、らぶれたー・サボテンの置換と円満な別れの応答の回数、初期手札（恋人・すれちがいの有無）別の得点率、先攻・後攻別の得点率。
- 判定の考え方：別れ−10が「厳しすぎる」と言えるのは、(1) 別れが起きた試合で恋人側の得点率が大きく下がり、(2) 結婚前の早い段階（交際0〜1）の別れでも回復できないほどの差がある場合。単に差があるだけでは緩和の根拠にしない。

## 6. 守ること

- 正式カード452枚・エンジン・CPU・保存形式・固定400戦の証拠は変更しない。写しは `build/`（git管理外、`lib/build-variants.mjs` で再生成）。
- 写しを作る前後で、正式ファイル全部のsha256が一致することを確かめる。
- A の写しは、正式エンジンと同じ試合で保存hashと結果が一致することを確かめる。

## 7. 追加計画（F の結果を見た後・F2 の実行前に固定）

F（すれちがいを交際段階で縛る方式）は、Yがその段階の時にすれちがいを持っていない試合が多く、狙った段階の別れが段階あたり3〜16回しか起きませんでした。段階別の比較には足りないため、次の F2 を1回だけ追加します。F の結果は捨てずにそのまま報告します。

- F2 注入・中級：X＝partner（C系は partner+AM）、Y＝公式「ちょうせん」（すれちがいなし）。Yの自分のターンで、Xの恋人が初めて交際k（k＝0〜3、4＝結婚）になっていて、Yの時が2以上ある時点を「注入点」とする。
- 腕：A:none（注入しない）・A:inject・B:inject・Cx:none・Cx:inject・C:inject。inject は注入点でYの手札の最後の1枚をすれちがいに置き換え、すぐ使う（テストの固定局面と同じ置き換え方。保存の再生は対象外）。none は注入点を記録するだけ。
- 各段階20グループ×先後＝40戦、6腕×5段階＝1,200戦。
- 比較：A:inject−A:none（別れ1回の損失）、B:inject−A:inject（B 案で取り戻せる分）、C:inject−Cx:inject（円満な別れで取り戻せる分。デッキは同じ）。注入点が記録された対だけを使う。
