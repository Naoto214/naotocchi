80pxで14分類を誰もが瞬時に識別できるとまでは判断しない。本文の精読は拡大前提。通常320pxの70枚ではカード名とイラストの重なり、本文枠あふれをDOM寸法で検出しなかった。コストの白文字問題はこの寸法検査では検出できず、実画像で確認した。今回は既存5案の比較を維持するため修正で隠していない。

注意する組合せ: ひと／こいびと、けもの／なかま／あそび、あいてむ／できごと、セカイ／できごと。むしは明るい金縁と近いが広い上部の黄色が有効。みずべ／うみは色面が増えると水色と青の区別が強まる。げんそう／ふしぎは明度差が助ける。

金縁・植物SVGは保持され、320pxで葉と線の細部を確認できる。80pxでは植物の細部そのものは判読困難。中央の絵の位置・面積は全案同一で、本文の明るさも維持される。深緑盤面では暖色・水色が見つけやすい一方、くさは盤面と近くなるため金縁が輪郭の手掛かりになる。

2型参考表示では暖色・緑系が近づき、ABでも色だけの識別は不十分。メイン8属性の既存マーク形状は保持。非メイン6分類は現行テンプレートでは分類名バッジが中心で、全14種に同程度の形状冗長性があるわけではない。80pxで小さなマーク／分類名を読み分ける負担は残る。当事者による識別試験は未実施。

## 取得・検証方法と限界

保存済みcomparison.htmlをそのまま新規Siteのindex.htmlへ配置。ブラウザ実行ファイル取得はCDNからZIPでなく「Site Unavailable」HTMLが返る環境制約。クラウドChromeのHTTPS経路で解決した。

全ページスクリーンショットAPIはタイムアウトしたため、表示領域を順に撮影し、読み取ったscrollYで結合した。APIのJPEG出力をPNG化。出力が1348×926へ縮小される場合は観測した1363×936 CSS viewportへ復元して切り出した。PNGはネイティブの無圧縮ブラウザ出力ではなく、JPEG由来の微小な圧縮／補間を含む。色の正確なHEX検証はCSS／トークンで行い、画素から判定していない。横並びは同じ撮影カードを無変更で再配置。通常サイズは320 CSS pxであり、600px印刷マスターではない。

320/390/430pxはiframeのCSS幅検証。実機iPhone、Safari/WebKit、タッチ操作の試験ではない。小画面では既存比較ページの見出しが縦長になるが、80pxカードは一覧で折り返せる。最終評価はiPhone Safariで行う。

[ブラウザ検証](browser-verification.json)、[画像寸法／SHA256](image-manifest.json)、[テスト結果](test-results.json)、[回帰ログ](regression.log)。旧verification.jsonのfalse値は構造検証単体の出力であり、今回の実描画記録はbrowser-verification.jsonを正とする。
