## 5. 読み取り

1. 【事実】勝率が上がった案は、どれもコネクトフォーを含む。恋人を6枚に減らしただけのL6n は L10 と同じ水準（−0.024 ± 0.021）。恋人8枚のままコネクトフォーを入れたL8cf は +0.099。**勝率の改善は恋人を減らしたことではなく、空いた枠のコネクトフォー（1試合あたり約0.6回使用、各+10）によるもの**。
2. 【事実】恋人を減らすと余る恋人は確実に減る（10枚 3.57 → 6枚 約2.3〜2.4 → 4枚 約1.3 → 2枚 0.39）。結婚率は、6枚まではほぼ維持（97.5〜98.1%）、4枚で93%台、2枚で72%に落ちる。
3. 【事実】同じ6枚でも、2種×3枚（L6）の恋人能力の記録は4種（L6k4）より多い（2.69 対 1.91）。勝率・結婚率は同じ。交際段階で働くシカ・ワシを複数枚入れる方が、恋人の能力を使えている。
4. 【事実】4枚以下では、初期手札に恋人がいるかどうかで成績と結婚率の差が大きくなる（L4：得点率差0.096、L2：結婚率64%）。
5. 【推論】数値の小さな差（例：L6cf と L8cf、L6 と L4）は標準誤差の範囲で、優劣は付けられない。

## 6. 採用した構成と判断

**L6cf を採用した。** 恋人は シカ3・ワシ3 の6枚（2種）。

- 現行10枚から外したもの：ロボット2・ねこ社長2。
- 空いた4枠：コネクトフォー2、あたらしいであい+1（2→3）、おべんとうばこ1。
- 恋人以外の既存30枚は変更なし。

判断の理由：

1. 【事実】終局時に余る恋人が1試合あたり1.2枚減り（3.57→2.39）、使ったカードの種類が増えた（8.7→10.0）。結婚率は97.5%を保っている。
2. 【事実】同seed比較で現行より +0.090 ± 0.024。ただし、この改善の大部分はコネクトフォーによるもので、恋人を減らしたこと自体は勝率に中立（§5の1）。
3. 【推論】L8cf も勝率は同水準だが、余る恋人が3.05枚とほとんど減らず、今回の目的（無駄な手札を減らす）に合わない。L4・L4cf は余剰をさらに減らすが、結婚率が93%台に落ち、初期手札への依存が強まる。6枚は、恋人が他のデッキ（2〜3枚）よりはっきり多く、交際の補助カード（デート3・記念日3・なかなおり2・おみあいチケット2・らぶれたー2・あたらしいであい3）と合わせて恋人デッキの個性を保てる。
4. 【推論】同名を3枚ずつにすると、狙った恋人（交際2・3で山札を見るシカ、結婚後に毎ターン引くワシ）を引ける確率が上がり、恋人の能力が実際に使われる。

- `cpu-decks.mjs`：`partner` の40枚を L6cf に変更し、`version:'2026-10-25'` を付けた。説明文にコネクトフォーを追記。デッキID `partner` と名前「こいびと・交際」は変えていない。
- 旧40枚は `CPU_DECK_HISTORY.partner`（版 `2026-10-22`）として残す。`cpuDeckVersion(id, cards)` で、40枚が現行・旧版・どちらでもないかを返す。
- `cpu-session.mjs`：途中保存の照合を「現行の40枚と一致」から「現行または旧版の40枚と一致」に変更。旧構成で始めた途中保存は、その40枚のまま再開できる。新しい構成に置き換えることはない。どちらにも一致しない40枚は、従来どおり「CPUデッキ情報が対戦と一致しません」で拒否する。
- 新しい対戦は、おまかせ・指定・固定のどれでも新しい40枚を使う。
- 戦績：記録には実際の40枚とデッキID `partner` を保存する方式のままなので、旧構成・新構成の対戦はどちらも「相手の戦略デッキ別」の同じ欄に入る。デッキ名・戦績・対戦履歴の形式は変わらない。

## 9. 残る課題

- CPUは おみあいチケット（全案で1試合0.01〜0.16回）と なかなおり（0回）をほとんど使わない。カードの問題か、CPU判断の問題かは未確認。今回はCPU判断を変えない範囲なので、構成から外していない。
- はじめてのデートも、引いた枚数の約半分が使われずに残る（交際0の間に使う必要がある）。
- どのCPUデッキにも すれちがい が無く、別れ・離婚の影響は今回も測れていない（PR #440 の課題のまま）。
- 比較は中級×中級、他の6デッキとの対戦だけ。人との対戦での楽しさ（余った恋人への不満が減ったか）は実機試遊で確認が必要。
- 勝率の改善は主にコネクトフォーによる。他のデッキとの強さの釣り合い（こいびとデッキが強くなりすぎていないか）は、今回の差（得点率0.48→0.57）を含めて今後の総当たりで確認する余地がある。
