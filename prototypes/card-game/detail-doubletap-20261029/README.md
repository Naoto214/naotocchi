# カード詳細のダブルタップ拡大・縮小（2026-10-29）

PR #477 の公開後、本人の iPhone Safari で「ピンチでは拡大できるが、1回タップ・ダブルタップでは拡大できない」と分かった件への追加改善です。

方針: 既存のピンチ操作はそのまま、カードのダブルタップで拡大・縮小できるようにする。

## 原因

1. **iOS Safari はタップを「クリック」として通常の要素へ送らない。** 拡大は、ページ全体（document）で受けた click でカードのタップを判定していました。iOS Safari は、ボタン・リンクでもなく、指カーソル（cursor:pointer）もない要素には、document に付けた click を送りません。カード（div）はこれに当たるため、Chromium では動いても iPhone では反応しませんでした。
2. **縦画面ではカードが既に画面幅いっぱいのことが多い。** 「拡大＝幅いっぱい」だったため、拡大しても大きさが変わらず、拡大自体を受け付けていませんでした。

## 変更

| 項目 | 内容 |
|---|---|
| ダブルタップ | カードを0.35秒以内に2回、ほぼ同じ場所（36px以内）でタップすると拡大／元の大きさ。指を当てた位置がそのまま指の下に来るように拡大する |
| 判定の方法 | ポインターイベント（iOS でも通常の要素に届く）で判定。2本指（ピンチ）・指の移動（12px超）・長押し（0.5秒超）・ゆっくり2回・離れた2か所は対象外 |
| シングルタップ | カードを1回タップしても何も起きない（以前の Chromium での「1回タップで拡大」はなくした）。盤面・手札・操作ボタンのタップは変更なし |
| 拡大の大きさ | 幅いっぱいが今の1.25倍以上なら幅いっぱい（横画面は従来どおり）。そうでなければ1.5倍にし、カードの部分を縦横にスクロールして読む |
| ページ全体のズーム | カード上ではダブルタップ・ピンチでページ全体がズームしない（下の追加修正を参照）。カードの外のピンチは従来どおりページ全体を拡大できる |
| 文字選択 | カードのダブルタップで文字が選択されないようにした |
| 縦画面のボタン | 「＋ 拡大」は従来どおり（出る条件も同じ）。拡大中に「－ 縮小」は出さない（最終修正で撤廃） |
| 横画面 | ボタンは出さない（前回の方針どおり）。ダブルタップで拡大・縮小 |
| キーボード | Enter／スペースで拡大・縮小（従来どおり） |
| 閉じる | 拡大中も「盤面へ ×」が押せる。閉じて次に開くと通常表示 |

変更したファイル: `app.mjs`（ダブルタップ・ピンチの判定、アニメーション）、`ui-viewport.mjs`（拡大の大きさ・ピンチの範囲・ボタンを出す条件）、`style.css`（カードの1行）、`ui-presentation.mjs`（読み上げ文「ダブルタップで拡大／縮小」）。

## 追加修正：ピンチ後のダブルタップ・なめらかさ（本人の iPhone 確認を受けて）

本人の確認で、ダブルタップの繰り返しは正常でした。問題は次の2点でした。

- ピンチアウトで拡大した後にダブルタップすると、元に戻らずさらに拡大される。
- ダブルタップの拡大・縮小が瞬間的で、少しカクつく。

### 原因（3種類のズームの区別）

| ズーム | 何が大きくなるか | 状態の持ち主 |
|---|---|---|
| Safari 標準のピンチ（ページ全体のズーム） | 画面全体。`visualViewport.scale` が1より大きくなる | Safari。JavaScript から安全に読み戻したり、元に戻したりする手段がない |
| カード独自の拡大（ダブルタップ） | カード詳細のカードだけ | ゲーム（`data-stage-zoom`） |
| ダブルタップによる Safari のページズーム | 画面全体 | 前回の修正（`touch-action`）で、カード上では起きない |

カード上のピンチは Safari 標準のページ全体のズームで、ダブルタップはカード独自の拡大でした。二つが別の状態だったため、ピンチで画面全体が大きい状態でダブルタップすると、カード独自の拡大が上乗せされていました。

### 変更

- **カード上のピンチはカード自体を拡大する。** 通常の大きさ〜3倍（ダブルタップの拡大がそれより大きければその倍率）で、指の動きに合わせて拡大します。
  - ダブルタップと同じ状態を使うので、ピンチアウト後のダブルタップは元の大きさに戻ります。
  - ピンチインで通常の大きさまで戻ります。それより小さくはなりません。
  - カードは `touch-action: pan-x pan-y`（スクロールだけ許す）にし、iOS の gesture イベントもカード上では止めます。これで Safari のページ全体のズームが重なりません。
- **カードの外でのピンチは Safari 標準のまま**（ページ全体のズーム）です。
  - Safari のページ全体のズームは、JavaScript から安全に元へ戻せません。そのため、カードの外でページ全体を拡大してからカードをダブルタップした場合、ページ全体の倍率はそのまま残ります（カードは通常⇄拡大を切り替えます）。
- **拡大・縮小のアニメーション（0.26秒）。** 両方向とも、元の大きさから新しい大きさへなめらかに変わります（この時点では FLIP 方式。最終修正で、変形だけで動かして最後に確定する方式に変えました。下記）。
  - 指を当てた位置（ピンチは2本の指の間）のカードが、指の下に残ります。
  - ピンチは指に合わせて大きさが変わるので、指を離しても位置は飛びません。
  - 「視差効果を減らす」の設定では、アニメーションを省きます。

## 最終修正：なめらかさ・右下の白い表示崩れ・「－ 縮小」の撤廃（本人の iPhone 確認を受けて）

本人の確認で、ダブルタップの拡大・縮小の切り替え自体は正常でした。残った問題は次の3点です。

- 拡大・縮小がまだ少しカクつく。
- 縦画面でダブルタップまたはピンチで拡大すると、カードの右下に白い領域が出る。
- 拡大中の「－ 縮小」ボタンは不要。

### カクつきの原因

前回の方式（FLIP）は、拡大・縮小のたびに次の3つを**最初の1コマに同時に**行っていました。

1. カードの実際の大きさ（レイアウト）を変える。
2. 新しい大きさでカードの絵と文字を描き直す（3倍密度で 501×752px のカードなら約1500×2260 画素）。
3. スクロール位置を補正する。

そのうえで、変形（transform）で元の大きさから動かしていました。iPhone では、この最初の1コマの描き直しが間に合わず、動き出しで止まります（拡大時に特に重い）。縮小時も、最初に小さく描き直した絵を引き伸ばしてから戻すため、ぼやけてから急にくっきりしていました。

### 白い表示崩れの原因（推定）

カードの面（`.card-face`）は、角丸（`border-radius`）・はみ出しの切り取り（`overflow: hidden`）・`isolation` を持ち、その外側の入れ物が変形（`transform: scale`）で大きさを決めています。

前回は、カードの変形が動いている間（ダブルタップの動き・ピンチ中の指への追従）に、その下のレイアウトを変えていました。iOS Safari は、変形が動いている要素を別の層として扱い、その中の角丸の切り取りや描画済みの範囲を、古い大きさのまま使い続けることがあります（WebKit の既知の描画の不具合の型）。

その結果、新しく広がった右下の範囲が描かれず、カードの面の明るい地色（クリーム〜白のグラデーション）だけが見えていた、と考えています。ダブルタップとピンチの両方で起き、右下に出るという症状とも合います。

この不具合は WebKit 固有で、Chromium では修正前も再現しません（[bottom-right/](bottom-right/) の修正前後の比較を参照）。原因は推定で、**本人の iPhone での確認が必要**です。

### 改善内容（方式）

**動きは、今描かれているカードの変形だけで行い、実際の大きさとスクロール位置は、動きが終わった後に1回だけ変える**ようにしました。

1. 拡大・縮小の行き先（大きさ・位置・スクロール）を先に測る。測るために一時的にレイアウトを変えますが、同じ処理の中で元に戻すので、画面には出ません。
2. 今のカードの描画のまま、変形だけで行き先まで0.26秒で動かす。GPU の合成だけで済み、描き直しもスクロールの変更もありません。
3. 動き終わったら、同じ1コマの中で、実際の大きさ・スクロール位置を確定し、変形を外す。見た目は変わらず、新しい大きさでくっきり描き直されます。

この方式では、カードに変形や動きが残っている間にレイアウトが変わることはありません。確定の時点では、カードはもう別の層ではありません。

- 拡大の途中は、今の絵を引き伸ばすため一瞬やわらかく見え、動き終わりにくっきりします（写真アプリの拡大と同じ考え方）。
- ピンチは、指の動きに合わせて変形だけで追従し、指を離した後に同じ方法で確定します。範囲外（通常未満・最大超え）なら、範囲内へなめらかに戻します。
- 動きの途中でダブルタップやピンチをすると、今の動きをその場で確定してから次の動きを始めるので、状態が壊れません。
- 動きの速さ: 0.26秒、`cubic-bezier(.25,.8,.25,1)`（動き出しが速く、終わりがゆっくり）。

### 「－ 縮小」ボタンの撤廃

拡大中は、縦画面・横画面とも「－ 縮小」ボタンを出しません。戻るときはダブルタップ（またはピンチイン）です。拡大していないときの縦画面の「＋ 拡大」は従来どおりです。
