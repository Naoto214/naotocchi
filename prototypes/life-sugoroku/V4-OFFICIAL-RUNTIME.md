# V4 isolated official runtime

Adopts quick `eat`, `dodge`, `clean`, `charge`, `jump`, `button`, `coins`, `flee`, `slice`, `defend`, and normal `lights-out`. Quick uses the original supported `makeQuickRun({only,total:3,levelEvery:2})`; normal uses the original MINIGAMES entry. No alternate rules or synthetic scores. `official/quick.js` Git blob 2906c37fe9086726085f9b98a7c8d43300b13cc6 and `official/games.js` blob fdcf8c5ce6ee7211a28d729bd08af7e1e7a20548 are unchanged source copies from main 81c044a9977dbd013f1632372a72785b540fb463.

## Node

Import `createNodeOfficialRuntime` from `official-runtime-v4.mjs`; await it for each fresh seat/replay. `start({gameId,seed,cpu:false,difficulty:'normal',inputs?,frame?})`, `step(frameCount=1)`, `input({type,x,y})`, `snapshot()`. All returned snapshots contain gameId, unsigned seed, difficulty, cpu, frame, journal inputs, pendingInputs, done, and score/summary when the original callback completes. Each input is `{frame,type,x,y}` using official logical coordinates (320px wide; 300px quick, 320px lights). Human input queues to the next simulation frame. Pointer types: pointerdown/move/up/cancel. Inputs maintain original order within a frame.

Restore by making a fresh runtime and `start(savedSnapshot)`; this reconstructs original closures/RNG, timers, animation, and CPU state by replaying every fixed frame. Continue with `step()`. Do not reward on restore; the tournament owner should apply results once using its own round identity. To replay CPU input as a human journal, set cpu:false. Invalid IDs, seeds, difficulty, unordered/malformed journals, frame counts and oversized journals are rejected; supplied scores are ignored and recomputed. Runtime instances are intentionally single-use.

## Browser integration

Import `mountOfficialFrame` from `official-host-v4.js`. Await `mountOfficialFrame(parentElement,{onSnapshot,onError})`, then `await host.start(options)`. `host.frame` is an iframe with exactly sandbox="allow-scripts"; no same-origin permission, main scripts or storage. The adapter loads source files via parent fetch and inlines them into the opaque sandbox. Server must serve these files. Host methods: `pause()`, `resume()`, `snapshot()` (asynchronous callback), `destroy()`. Await `host.ready` if needed. Remount a fresh host before starting another seat or restoring. Messages carry `official-ready`, `official-snapshot` or `official-error`; parent and child validate the sender window. No runtime writes to storage. Persist received snapshots through the tournament's V4 save path.

`createOfficialRuntime({realm,container,context})` is the shared lower-level API. Never pass parent/globalThis: it replaces realm-local Math.random, performance, RAF and timeout functions. Node creates a fresh vm context and fake canvas/DOM. Browser uses real original rendering/input wrappers in its disposable iframe. Fixed 60Hz frames consume rendering RNG identically during replay; shared fixed canvas dimensions apply to all seats. Timers and RAF are virtual; CPU randomness is separately seeded. Browser uses a fixed 60Hz wall-clock accumulator independent of 30/60/120Hz native RAF. Long stalls clamp catchup to 250ms; hidden or paused sessions reset the clock without catchup.

## CPU and verification

Quick CPUs query original target() hints and dispatch real pointer sequences through original handlers. Lights CPU observes only rendered on/off border strokes and row-chases all 32 first rows to find a minimum legal solution. Thinking delay, skipped opportunities and lights mistakes differ by easy/normal. Scores only originate in original completion callbacks. Lights uses independent thinking/move intervals: normal 120–210 frames (2–3.5s), easy 180–300 frames (3–5s), including initial thought. Quick cadence is unchanged. A 20-seed run (game seed=CPU seed=1…20) produced normal scores 76 for every seed (2 of 3 boards each); easy scores 76,52,52,52,52,52,52,76,52,52,52,52,10,51,52,76,52,76,52,52 (four 2-board results, fifteen 1-board results, one 0-board result). All scores are original callback outcomes; pacing, existing decision mistakes, and the original 45s limit produce these results. No claim of human fairness is made without player data. No performance parity claim is made.

`node --test tests/life-sugoroku/official-v4.test.mjs` validates pinned bytes, deterministic CPU results/journals for every selected game, human journal replay, restored frame/CPU continuation, completion within 50 simulated seconds, and host sandbox declarations. Browser rendering/audio/mobile QA has not been performed. Audio is silent unless the parent supplies the optional callbacks described below. No additional normal games are adopted. Future source upgrades require explicit provenance/hash update and revalidation. A hard 3600-frame (60s) ceiling prevents unbounded execution; currently selected original games complete before it.

Browser host reuses verbatim formal style.css ranges in official/host.css for quick overlays, headers, hints and canvas. Only responsive host layout is added. Snapshots emit on the next executed frame after trusted human input, as well as every 30 frames and completion.

`cpuSeed` is an optional unsigned32 seat seed persisted in snapshots, defaulting to game seed. Different seats may share identical game RNG conditions but use distinct deterministic CPU decision streams. `host.speed(value)` accepts integer 1–60 only for CPU seats; it executes every fixed frame (including official draws/timers/input) faster. Human seats reject fast-forward. Speed is playback-only and does not change saved simulation state or scores. Node callers can batch step(n) with the same semantics.

Completion freezes the public frame at the original callback; extra step calls and post-completion input leave its snapshot unchanged. Snapshots additionally serialize `pendingInputs` accepted but not yet dispatched. Restore forwards this array alongside `inputs`, preserving the immediate-input boundary. `flushInputs()` advances exactly one frame when queued input exists; explicit browser snapshot/pause calls flush before sending. Board observation accepts canonical native canvas rgba serialization (spacing and leading decimal zero). `createNodeOfficialRuntime({canonicalCanvasColors:true})` exercises native-like getter behavior for parity tests.

Optional `onSound(name)` / `onVoice(text,options)` callbacks on createOfficialRuntime (and Node adapter) receive live official cues outside replay only. onVoice returns false when unavailable, true/undefined when handled; missing voice uses the original cue chime. mountOfficialFrame accepts the same callbacks and forwards source-validated official-sound / official-voice messages from its sandbox; configured parent voice is treated as available. Parent audio must use its own isolated state/randomness. Without callbacks the host remains silent. No original audio source or formal rules/rewards are modified.

For pending-input snapshots, preserve both `inputs` (dispatched history) and `pendingInputs` (accepted future events) when saving/restoring. `snapshot()` itself does not advance time. `flushInputs()` explicitly dispatches pending next-frame input once, then returns the updated snapshot; repeated flushing with no pending input leaves the frame unchanged. Browser pause and explicit snapshot requests use this flush so the returned save reflects the last accepted pointer.

Synthetic journal/CPU pointers dispatch while the canvas temporarily reports its fixed logical rect (320×official height), restoring the native DOM method immediately afterward. This keeps original quick/private and normal/common pointer wrappers correct when synchronous replay occurs inside a hidden/not-yet-laid-out iframe whose native bounding rect is0×0. Trusted pointer capture still measures the real responsive rect before queueing logical input. Optional runtime `inspect()` returns only rendered board cells and visible lights HUD labels for verification, never private game state. Regression uses the reported seed1485323743/frame911 two-click journal and verifies original HUD `て2／さいてい5` and exact visible board equivalence under0×0 layout. Real browser recheck is required; this regression models the layout failure.
