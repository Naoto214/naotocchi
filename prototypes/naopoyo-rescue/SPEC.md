# なおぽよ。正準仕様 — 2026-10-22

全12面、8列×6行、固定配置・追加ランダムなし。正式4種族（犬・さかな・ペンギン・かえる）、成長段階1〜8。同種同段階を合体し、トゲで分裂して、星型出口から全員を救出する。
この文書は現行仕様。過去のPLAN・REPORTの4方向分解・角抜け禁止・永続開門は当時の記録であり、現行ルールに優先しない。

## 移動：移動先1マスだけで判定

`engine.mjs` の `move` をエンジン・ドラッグ・ボタン・解答再生・探索の共通判定とする。整数の上下左右＋斜め8方向、1回1マス。盤面外・2マス以上の飛び越しは不可。

| 移動先 | 結果 |
| --- | --- |
| 空きマス | 移動 |
| 岩・壁 | 拒否 |
| 魔法門 | 現在のキャラが条件一致したときだけ通行 |
| トゲ | 進入後に分裂。1段階ならそのまま |
| 同種・同段階のキャラ | 1〜7なら1段階合体。8同士は拒否 |
| 異種・異段階のキャラ | 拒否 |
| 星型出口 | 条件一致で救出。合体が同時なら合体後の段階で出口判定 |

斜めの横・縦に隣接する2マスは通行判定に使わない。片側・両側に岩や不適合の門があっても、移動先が通行可能なら移動できる。岩の角抜けは正式な合法操作。通路の制約は全ステージ共通のこのルールと地形で作る。
重力面の既存の上昇資格（下記）は保持する。これは斜め専用の障害物判定ではなく、上方向の操作に共通の足場条件である。

## 入力

B方式のドラッグを維持。`input.mjs` は連続座標の線分を格子境界で補間し、高速でも通過マスを飛ばさない。同時に縦横境界を横切る場合は斜め1歩にする。
隣接セルの角を指がかすめただけで誤進入しないよう、既存の角を切り落とした選択領域を使う。これは地形を参照しない入力の選択処理であり、角抜け禁止ではない。各選択先は必ず `move` に渡し、補間途中で独自の岩・門判定をしない。
同じ連続した線分・折れ点を高速／低速／coalescedイベントで送ったとき、同じ状態になる。端末が報告しなかった曲がり角までは復元できない。操作中1.4倍表示、合体・分裂後も操作IDを維持。

## 合体・分裂・門・救出

総量は `rescued + Σ 2^(level-1)`。合体・分裂・落下・救出を通して保存する。拒否した操作は状態を変えない。
トゲは実際にそのマスへ進入したときだけ発動する。2以上なら1段下の2体を進入前のマスとトゲに置き、トゲ側を継続操作。隣接・角の通過・静止だけでは分裂しない。事前シルエットなし。
門・出口は `conditions.mjs` の種族／exact／min／max条件を共有。数値は1〜8、表示は `=2`／`≥2`／`≤2`／`ALL`。種族と段階は両方一致が必要。ALLは全段階を意味し、種族指定があればその種族に限る。
門は消費せず、毎回進入キャラの条件を再判定する。`open` は通過済み記録・演出用で、全員への永久通行許可ではない。門の中で分裂した子は外へ出られるが、再進入には現在の条件が必要。進入元の門に退出条件は加えない。
出口はキャラを除去し、その総量を救出済みに加える。全員脱出でクリア。既存のrequired門通過フラグも維持するが、門必須性をこのフラグだけで成立させない。

## 地形と重力

07・11・12はx=3の列（座標0始まり）を盤面端まで塞ぎ、(3,2)だけを門とする。10は同じ列の(3,2)と(3,4)を門とする。07・10・12の旧凹凸を直線に戻し、斜めの迂回を地形でなくす。その他の配置・条件・背景は維持。
重力なしが標準。09のみ下向き重力。上方向は足元が支えられ、左右いずれかに足場がある場合に1マス登れる。仲間も足場になる。指を離すと下から順に安定するまで落下し、合体・トゲ・出口も処理。落下循環時は操作前へ戻す。

## Undo・保存・互換性

Undoは落下込み1ドラッグ単位、最大80。リトライ／「はじめから」は現行の固定配置を生成。取消・画面離脱はドラッグ確定＋落下。キー `naopoyo-rescue-v1`、version 1と既存JSON形式を維持。
既存の受理対象に加え、PR #418 `702721a` の07・10・12の正確な旧配置を受理。旧途中データの地形・キャラ・Undo・クリア記録をそのまま保持し、新しい壁の中にキャラを強制配置しない。旧配置の間も移動ルールは新ルールを共通適用するため、旧面には迂回が残りうる。「はじめから」で門必須の新配置になる。以前から存在する10の魚門追加移行は変更しない。
未知の地形・不正状態は受理しない。保存容量不足は通知してプレイ継続。本編・CARD GAME・旧パズルの保存には接続しない。

## 検証の基準

`solutions.json` の12面の操作列を実際の `move`／`release` で再生し、全員脱出・総量・門通過履歴を確認。実appのpointerハンドラーでも高速・低速・coalescedで再生する。
門閉鎖探索は8方向・合体・分裂・重力の実エンジンを用い、通常入力以上に広い操作集合を調べる。requiredフラグを利用せず、全員の救出が不可能か確認。全探索完了だけを不可能の証明とし、上限到達は未証明。10は各門を1つずつ閉鎖しても完走できないことを検証。
iPhone Safariでの描画・指の感触は自動検証と区別し、実機QAで確認する。
